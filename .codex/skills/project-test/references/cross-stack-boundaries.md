# 跨边界测试

变更跨层契约、通信或宿主协作行为时使用。从类型、schema 和实际调用链确认字段、错误、事件与兼容规则的拥有者，以及生产者、消费者各自承担的行为。

## 两侧观察

|变化|生产者证据|消费者证据|
|---|---|---|
|字段|实际输出及默认语义|按契约处理存在、缺失或未知字段|
|事件|实际事件名与载荷|订阅后的公开状态|
|错误|实际状态码和错误体|映射、展示或重试行为|
|写入|校验、持久化状态和失败结果|请求载荷与成功 / 失败状态|
|初始化|分片、顺序与完成信号|合并后的公开状态|

选择变化实际涉及的行为。生产者测试调用真实产出入口，消费者测试使用符合契约的输入；两侧契约测试通过后，再判断传输本身是否仍有风险。

## 真实环境的触发条件

|风险|追加证据|
|---|---|
|JSON、二进制、日期等编解码变化|真实编码与解码 round-trip|
|重连、握手、进程启动或宿主加载顺序变化|对应集成或跨进程 smoke|
|事务、锁、文件权限等环境语义变化|对应存储或系统环境中的结果|
|第三方服务缺少稳定测试环境|fake 契约证据，以及未验证的真实集成范围|

重复、乱序、部分成功、取消、回滚与版本兼容等分支，由公开契约、历史缺陷或本次变化的风险决定是否覆盖。按仓库验证入口执行相关两侧测试、类型或 schema 检查，以及被风险触发的集成验证。
