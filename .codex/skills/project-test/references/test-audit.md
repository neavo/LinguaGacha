# 测试审查与整理

审查、合并、清理或重构已有测试时使用。以当前行为和风险防护评价测试价值，结合公开入口、相关实现及历史缺陷证据判断。

## 判断价值

- 测试证明的行为、边界或历史缺陷仍然有效，场景能够从真实入口触达。
- 主要断言能揭示该行为的错误；只有独立契约要求精确值时，合理调优预设才应导致失败。
- 删除、合并或弱化测试后失去的风险防护能够明确说明。仅凭静态阅读认为不可达时，先核对入口和历史缺陷。
- 多层测试是否重复，取决于观察的契约；同一实现可以同时需要规则测试与真实导出载荷测试。

## 候选信号

|信号|判断与处理|
|---|---|
|只有非空、存在或长度断言|检查它是否足以证明目标语义，必要时补公开结果|
|只检查 mock 调用、连续替换多个领域模块|确认调用是否属于契约；业务结果使用真实轻量逻辑验证|
|读取私有字段、绕过构造后手工补状态|从公开构造和观察入口验证，保留初始化语义|
|固定睡眠、依赖执行顺序或共享状态|检查完成信号、隔离与清理；定位可复现的失败条件|
|导出常量与同值字面量比较、多层复制预设|寻找独立预期和消费行为；缺少风险价值时删除重复断言|
|多个用例只替换无语义数据|合并或参数化同一行为，保留有意义的边界|
|helper 隐藏输入和断言、一个用例混合独立行为|让准备和失败原因可见，按行为或成本拆分|
|内存数据库、fake timer 或文件 mock 代表真实环境|核对是否足以证明方言、锁、事件循环、路径或权限语义|

这些信号用于定位候选项；mock、参数化和分层本身可以是合适的测试设计。

## 整理与交付

有价值且稳定的测试保留；目标有价值但观察或隔离脆弱的测试修改；证明同一行为的重复用例合并；失败原因、执行成本或责任边界不同的用例按需拆分；失效或缺少风险价值的用例删除。

改善可测性时可提取纯规则、显式传入已有的副作用来源或收口重复分支，保持公开行为与持久化语义。按仓库入口验证目标和受影响范围，交付实际调整、依据以及仍未确认的风险。
