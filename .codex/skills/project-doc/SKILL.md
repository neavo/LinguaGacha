# 项目长期文档治理

本技能只治理 `docs/` 下的工程长期文档。目标不是让文档更满，而是减少未来维护误判：每条稳定工程事实只有一个权威归宿，修改优先删除、合并、迁移和压缩。

## 目标形态与唯一归宿

```text
docs/
  ARCHITECTURE.md
  CLI.md
  BACKEND.md
  FRONTEND.md
  WORKFLOW.md
```

| 信息回答的问题 | 唯一归宿 |
| --- | --- |
| 系统分层、进程拓扑、跨层边界、运行时主链路 | `docs/ARCHITECTURE.md` |
| CLI 入口、命令协议、临时工程、资源、输出和平台启动器 | `docs/CLI.md` |
| 后端公开协议、状态拥有者、唯一写入口、任务、数据库和 `.lg` 存储 | `docs/BACKEND.md` |
| Electron / preload / renderer、共享运行态、页面 query、导航和样式消费 | `docs/FRONTEND.md` |
| 阅读路径、验证矩阵、文档同步和交付自检 | `docs/WORKFLOW.md` |

同一段内容涉及多个归宿时拆开；其它长期文档只保留定位所需的短引用。

## 体系外边界

- `AGENTS.md` 是始终加载的仓库行动规则，不属于上述目标形态，也不受长期文档“单一归宿”约束。本技能只在入口变化时检查它的链接，不得因为 `docs/` 有相近内容而删减其自足行动约束。
- `DESIGN.md` 是 Impeccable 设计流程的可选产物，可能不存在或独立变化；它与 `PRODUCT.md` 等流程产物都不属于工程长期文档，五份文档不得依赖固定产物存在，也不吸收其正文。
- README、生成物、归档、任务临时材料、外部规范镜像、用户明确保留材料和独立样例不自动成为工程长期文档。

## 收录闸门

一条信息必须同时满足四项才进入长期文档：

| 判断问题 | 不满足时 |
| --- | --- |
| 不知道它会改错落点、边界、契约或验证吗？ | 删除 |
| 它无法从代码、目录、类型名或局部实现直接看出吗？ | 删除 |
| 它描述当前稳定事实，而不是历史过程、本次改动或临时状态吗？ | 删除或改写 |
| 它有且只有一个固定归宿吗？ | 拆分、合并、迁移或删除 |

新增内容必须替换、合并、迁移或压缩既有信息，或补上会导致维护误判的真实缺口。“更完整”“更保险”“顺便提醒”不是收录理由。

## 执行顺序

1. 定义本轮信息集合：规则、入口、链接、表格、章节和叙事。
2. 为每条信息选择五份文档中的唯一归宿；没有归宿的不进入长期文档。
3. 先删除不合格内容，再合并重复、迁移错位、压缩低密度叙事。
4. 只根据当前代码、现有权威文档或用户明确确认补写稳定缺口。
5. 检查目标形态、相对链接，以及 README、`AGENTS.md`、脚本提示、测试断言和技能提示中的入口引用。
6. 回看 diff，确认没有制造新的并行规则、固定外部产物依赖或历史叙事。

结构性文档任务若没有发生删除、合并、迁移或压缩，默认尚未完成；现状已经干净时应明确说明证据。

## 各归宿边界

### `docs/ARCHITECTURE.md`

保留进程拓扑、跨层依赖、运行时主链路和专题地图。不展开命令字段、协议字段、状态表、页面算法或验证矩阵。

### `docs/CLI.md`

保留文件进出型 CLI 的 `--cli` 分发、参数、同步 job、临时 `.lg`、资源注入、输出协议、退出码和平台启动器。说明 CLI 如何复用 `BackendServices` 与任务链路，不承载 HTTP / SSE、数据库或 renderer 正文。

### `docs/BACKEND.md`

保留 API Gateway、HTTP / SSE、错误边界、领域状态、唯一写入口、任务运行态、数据库与 `.lg` 物理存储。只记录会影响跨模块判断的协议和失败语义，不写字段大全、完整 schema 或局部算法。

### `docs/FRONTEND.md`

保留桌面宿主接入、传输入口、前端共享运行态、事件恢复、页面 query、导航、session UI 状态和样式消费落点。后端协议只短链到 `BACKEND.md`，视觉方向留给当前任务输入、既有界面证据和适用设计流程。

### `docs/WORKFLOW.md`

保留工程维护任务的阅读路径、分层验证矩阵、文档同步入口、删除检查和交付自检。不复述专题正文或本技能的完整收录规则。

## 必须重组的信号

- 同一主题在两份或更多长期文档中重复出现。
- 新规则只能靠“补充、另外、注意、同时”塞入既有段落。
- 章节仍按旧目录、历史来源或已失效系统形态组织。
- 表格和列表持续增长，却没有改变维护判断。
- 专题文档承载 Agent 行动规则，或 `ARCHITECTURE.md` 展开专题正文。
- 文档把某个可选产品或设计产物写成恒定入口。

遇到这些信号时重写信息块，不局部追加一句。

## 证据与删除

- 代码是真相来源；文档冲突时回到当前实现，证据不足列为未决。
- 删除入口或正文前，确认稳定工程事实已进入唯一归宿或不满足收录闸门。
- 全文检查 README、`AGENTS.md`、脚本报错、测试断言、技能提示和文档链接，不删除工具链入口、外部流程入口、用户指定保留文件或生命周期未明的材料。
- 删除后，需要进入工程维护流程的任务仍应能从 `docs/WORKFLOW.md` 找到 `ARCHITECTURE.md` 或对应专题文档。

## 交付格式

只汇报信息集合变化：

- 删除：不合格信息、重复正文或旧入口。
- 合并：被收成唯一权威的重复规则。
- 迁移：移动到新归宿的信息。
- 压缩：被改成判断规则的长段、表格或历史叙事。
- 补写：新增缺口及证据。
- 保留：看似可疑但仍保留的理由。
- 未决：证据不足而未写入的问题。
- 验证：目标形态、链接、引用、脚本提示、测试断言和 diff。
