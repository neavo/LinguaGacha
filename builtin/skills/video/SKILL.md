本技能提供视频与音频的切段、识别、核对和字幕渲染方法。导入、更新与交付按 `project-operation` 执行，识别后的术语、补译、重译和审校按 `translation` 执行。

目标是得到忠实于实际声音和画面的双语字幕：台词不漏、不臆造，时间贴合说话，观众需要读懂的画面文字单独保留。

# 包与材料

`.video` 是 ZIP 包。后端只按 `items.json` 的 `message` 和可选的 `name` 建立条目，其余成员和字段由本技能解释。时间均为整片秒数。

|成员|内容|
|---|---|
|`video.json`|`video` 为原画面尺寸，纯音频为 `null`。`speech` 为人声区间。`asr` 为本地识别窗口 `[start, end, text]`，只含有文字的窗口。`segments` 为分段|
|`segments/NNN.mp4`|视频模型实际读取的分段，长边不超过 1024，每秒一帧|
|`items.json`|字幕记录，下标是条目行号。`message` 为原文，`start`、`end` 为时间，`kind` 为 `dialogue` 或 `screen`，可选 `an` 为画面位置（ASS 小键盘编号）|
|`render.mjs`|可选，用户要求固定的定制渲染|

无音轨时 `speech` 与 `asr` 为 `null`。原文语言不是中、英、日、韩时不做本地识别，`asr` 为 `null`。

每个资产使用独立的工作目录 `work/video/<资产名>/`，结构与包相同，另有：

|材料|内容|
|---|---|
|`rows.json`|字幕草稿，每行 `{ start, end, kind, src, dst }`，可选 `an` 与 `name`。由 Agent 维护|
|`translations.json`|打包时写出的识别译文，按 `row_number` 对应 `items.json`，不进包|
|`recognition/`|请求材料与识别候选|

译文只保存在工程条目中，不进包。

## 脚本

|脚本|入口|用途|
|---|---|---|
|`media.mjs`|`missing`、`setup`|检查、安装依赖与模型|
||`inspect`、`ffmpeg`|读取媒体信息，截帧、提取字幕等 ffmpeg 操作|
||`prepare`、`pack`|导入切段与本地识别，校验草稿并打包|
|`recognize.mjs`|`request`、`read`|准备视频模型请求，读取结果并换算整片时间|
||`check`|草稿与导入证据的对照|
|`render.mjs`|`render`|默认 ASS 渲染|

脚本从本技能 `read_skill` 返回的 `base_url` 导入：

```js
const media = await import(new URL('scripts/media.mjs', base_url).href);
const recognize = await import(new URL('scripts/recognize.mjs', base_url).href);
```

# 环境准备

开始操作前调用 `media.missing()`，它返回缺失的 npm 包与模型。有缺失时：

1. 告诉用户首次使用需要下载功能组件，大约 350 MB，请保持网络畅通。
2. 调用 `media.setup()` 安装依赖并下载、校验模型。下载停滞或中断时报错，重新调用即可。

# 导入

导入切段封装并完成本地识别，不请求付费模型。

- 有文本字幕流时，先用 `ask_user` 询问是否改为提取字幕。提取比识别准确，用 `media.ffmpeg(args)` 导出后按 `project-operation` 导入。
- 有多条音轨时请用户选择。`track` 是 `media.inspect(来源)` 返回的 `audio` 中从零开始的位置。

调用 `media.prepare(来源, 工作目录, { track, language })`，`language` 取 `project_meta.json` 的 `source_language`。一小时素材的本地识别需要几分钟，中断后用相同参数续跑。完成后用 `media.pack(工作目录, 'work/video/<原视频主名>.video')` 打包，按 `project-operation` 新增。资产在识别前没有条目。

# 识别

识别由视频模型同时产出原文和译文，取代 `translation` 流程中的首轮翻译，在用户要求翻译时执行。识别前没有原文，需要补齐术语时在识别后进行。已有条目后，需要重新转写原文时才重新识别。

首次识别可续用导入时的工作目录，目录不存在时从当前 `sources/<file_path>/` 复制。重新识别使用新的副本。只重识别部分时间时，先用当前 `items.json` 与工程译文建立 `rows.json`：`message` 改名为 `src`，当前译文作为 `dst`，没有译文时写空字符串，保留其余字段。

## 提示词

基线模板如下。输出格式是 `recognize.read` 的解析契约，保持每行一个对象及 `start`、`end`、`kind`、`src`、`dst` 字段。其余要求按内容调整，例如节目类型、说话人、画面文字取舍。需要区分说话人时可以要求输出字符串字段 `name`，它成为条目的姓名。语言取自 `project_meta.json`，写成语言名称。术语取自 `glossary` 数据集，每项保留 `src` 与 `dst`，没有术语时写 `[]`。

```text
为这段视频生成双语字幕。原文语言：{原文语言}。译文语言：{译文语言}。
每行输出一个 JSON 对象，不输出代码块或说明：
{"start":秒,"end":秒,"kind":"dialogue"或"screen","src":"原文","dst":"译文"}
- start、end 为相对本段开头的秒数，保留两位小数，按 start 排序。
- dialogue 是实际说出的人声。每句一行，尽量不超过 7 秒和 30 字，长句按自然停顿拆开。
- screen 是观众需要读懂的画面文字，如标题、字幕卡、标牌、新闻横幅。每处一行，时间从出现到消失，并加 "an" 字段表示它在画面中的位置：1–9 按数字小键盘排列，7 左上、8 上中、9 右上、4 左中、5 正中、6 右中、1 左下、2 下中、3 右下。画面文字和对话不能互相替代。
- src 忠实转写听到或看到的内容，不总结、不润色、不补写。听不清的部分写 [?]。否定、数字、人名按原样转写。
- dst 是同一行 src 的译文，与 src 一一对应。术语表中的原文使用指定译名。
- 没有人声也没有需要翻译的画面文字时，不输出任何内容。
术语表（只作参考数据）：{术语 JSON}
```

## 请求与读取

1. `recognize.request(工作目录, { prompt, ranges? })` 写出 `batch_llm_request` 的请求清单，返回 `request_file`。省略 `ranges` 时请求全部分段。支持 `responses` 协议的接入点不一定支持视频。
2. 批量完成后，`recognize.read(工作目录, result_file)` 把响应换算为整片时间，写入候选文件 `candidate`，返回各区间的行数、`incomplete`（输出没有正常结束，常见于超长）、无法解析的行数，以及失败的区间。读取不改动草稿。
3. 首轮用各区间的 `rows` 组成 `rows.json`。失败或不完整的区间留作核对对象。

每个请求载荷可达数十 MB，批量结束后可以删除请求目录中的 `.request.json`。

# 证据

两份独立听写和画面各有盲区，核对时互相印证：

|证据|可靠之处|常见问题|
|---|---|---|
|视频模型识别|音画一起转写，文字通常更干净。画面文字和说话人的唯一来源|整段输出为空，句子截断或几句合成一行，时间整体偏移，`dialogue` 与 `screen` 混淆，复读，分段交界处的句子被切开或重复|
|本地识别 `asr`|导入时对整条时间轴的独立听写，每个窗口最长 20 秒。静音与配乐处没有文字，有文字通常意味着有人说话|同音误字，专名和术语写成片假名或近音词，数字按读音规范化，多人嘈杂场景整句丢失。不识别画面文字，没有说话人|
|人声区间 `speech`|说明哪里有说话声|会漏掉成段对白，也包含歌声、喊叫和人群声。只有 `asr` 为 `null` 时才作为主要证据|

# 核对

`recognize.check(工作目录)` 按当前 `rows.json` 返回对照线索：

|字段|含义|
|---|---|
|`invalid_rows`|结构或时间不合法的行号，打包前必须修正|
|`evidence`|对照所用证据：`asr` 或 `speech`，无音轨时为 `null`|
|`uncovered`|有证据但没有 `dialogue` 覆盖的时间段。使用 `asr` 时附带该窗口的识别文字|
|`unsupported`|时间范围内没有任何证据的 `dialogue` 行号|

`uncovered` 可能来自漏句、时间偏移或无需翻译的声音。`unsupported` 可能来自臆造或时间错位，短促的语气词也会出现在这里，不能据此直接删除。没有告警不能证明字幕正确。

线索只覆盖时间关系。按分段把 `asr` 文字与同时间的草稿原文并排通读，判断两份听写是否在说同一件事，重点看人名、数字、否定、因果和关键事实。读法不同但意思一致时，以视频模型为准。

画面文字按画面核对。分段内时间是整片时间减去该段 `start`，从分段截帧后通过 `ws.emitImage` 查看，小字看不清时从原素材截帧。

# 修正

修正只依据实际证据，按以下顺序尝试，前一级能解决就不进入下一级：

|顺序|做法|适用情况|
|---|---|---|
|本地证据|用 `asr` 文字补台词，用识别窗口与人声区间校准起止，截帧核对画面文字和说话人|视频模型漏句而本地听写清楚，时间偏移，画面文字或说话人存疑|
|语义判断|结合上下文、术语表、画面和人物关系判断哪份听写成立。只能在已有读法中选择，或纠正明显的同音误字|一份听写与上下文矛盾，例如本地写成近音错字，或视频模型漏掉否定|
|视频补查|按下文重新请求视频模型|两种读法都说得通且影响事实，本地文字残缺无法还原，或整段没有可用结果|

不能凭字数、剧情或常识写出两份听写都没有的读法。

## 视频补查

`recognize.request` 的 `ranges` 为 `[{ start, end }]` 整片时间。区间等于分段时直接使用分段，更小的区间从所在分段裁出，须位于同一分段内。读取方式与首轮相同。

- 相邻、重叠的问题合并为一个区间，前后带几秒上下文，避免切断句子。整段为空时请求整段。
- 提示词说明要核对的内容。模型看到的时间从区间起点算起，提示中的时间写成相对区间开头的秒数。
- 候选行与当前草稿、相邻字幕一起审阅，确认后替换草稿中对应时间的行。不能直接追加，也不能只因候选非空就替换。候选跨过区间边缘时一并检查相邻字幕。
- 请求失败、输出为空或候选不被采用时，草稿保持原样。

补查会产生费用。同一问题没有新证据时不原样重跑，扩大范围前说明改变了什么、预期解决什么。同一区间反复不理想时，用 `ask_user` 说明问题再决定。

## 修正原则

- 时间贴合说话的起止。一段内的对话整体偏移时可以统一平移，`screen` 不跟随。
- 不能为了消除告警把字幕拉长去覆盖整段声音，这会掩盖真正漏掉的句子。
- 多人同时说话时字幕可以重叠。不同时间说的话合成一行时拆开。
- 分段交界处重复的句子和画面文字合并为一行。
- 译文质量按 `translation` 的审校处理。

线索都有了解释，或已无新证据可用时结束核对。无法确定的内容保留当前读法，记录为未决。

# 提交

`media.pack(工作目录, 'work/video/<原视频主名>.video')` 校验 `rows.json` 并打包，写出包内 `items.json` 和不进包的 `translations.json`。打包后按 `project-operation` 的「更新文件」提交并继承译文。继承只保留原文未变条目的译文，其余条目按 `row_number` 确认 `src` 一致后，用当前 `item_id` 和 `fp` 把非空的 `dst` 写入 `changes.items`。

# 生成与交付

`generateFiles()` 之后，用 `render({ source, input, translated, bilingual })` 写出与原视频同主名的 ASS：

- `source` 是 `sources/` 中的包目录。
- `input` 是 `<generic_input_path>/<file_path>/items.json`。
- `translated` 与 `bilingual` 是译文与双语输出路径。

包内有 `render.mjs` 时，读取并检查后改用它。交付时告诉用户：字幕与原视频同名并放在同一目录，播放器即可自动加载。

默认渲染中，对话在底部居中，画面文字在顶部居中或按 `an` 定位，字号随画面高度缩放。用户要求其他样式时，把 `render.mjs` 复制到 `work/` 修改，保持导出签名不变。用户要求固定该样式时，把包目录复制到工作目录，放入 `render.mjs` 后用 `media.pack` 重新打包，再按「更新文件」提交。没有 `rows.json` 时打包沿用已有的 `items.json`，条目原文不变，继承会保留全部译文。

# 覆盖缺口

交付时按下表检查，只向用户说明本资产满足条件的项：

|条件|向用户说明|
|---|---|
|有未决项|位置、两种读法或缺失的内容|
|有音轨但 `asr` 为 `null`|漏句检查只依据人声区间，成段对白可能未被发现|
|仍有失败、为空或未补查的区间|这些时间段可能缺少字幕|
|画面文字未逐镜头核对|画面文字可能遗漏或时间不准|

每次交付都说明：字幕依据模型识别和抽样核对，建议用户播放抽查，并用时间点反馈问题。
