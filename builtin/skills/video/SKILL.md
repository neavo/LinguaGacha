name: video
description: 导入、识别、翻译、审校视频或音频，或生成视频字幕前必须加载。
---

本技能提供视频与音频的切段、识别、核对和字幕渲染方法。导入、更新与交付按 `project-operation` 执行，识别后的术语、补译、重译和译文审校按 `translation` 执行。

目标是得到忠实于实际声音和画面的双语字幕：台词不漏、不臆造，时间贴合说话，观众需要读懂的画面文字单独保留。视频模型同时看到画面、听到声音。它在识别时直接产出译文，说话人、语气和画面指代才能进入翻译。

# 包与材料

`.video` 是 ZIP 包。后端只按 `items.json` 的 `message` 和可选的 `name` 建立条目，其余成员和字段由本技能解释。时间均为整片秒数。

|成员|内容|
|---|---|
|`video.json`|`video` 为原画面尺寸，纯音频为 `null`。`speech` 为人声区间。`asr` 为本地识别的句级条目 `[start, end, text]`。`segments` 为分段，`recognized` 标记已采用视频识别结果，`attempts` 为视频请求次数|
|`segments/NNN.mp4`|视频模型实际读取的分段，长边不超过 1024，每秒一帧|
|`items.json`|字幕原文记录，下标是条目行号。`message` 为原文，`start`、`end` 为时间，`kind` 为 `dialogue` 或 `screen`，可选 `an` 为画面位置（ASS 小键盘编号）|
|`render.mjs`|可选，用户要求固定的定制渲染|

无音轨时 `speech` 与 `asr` 为 `null`。原文语言不是中、英、日、韩时不做本地识别，`asr` 为 `null`。

每个资产使用独立的工作目录 `work/video/<资产名>/`，结构与包相同。`items.json` 是待提交的记录，行内可带视频识别的译文 `dst`。`recognition/` 保存请求材料与识别候选。

译文只保存在工程条目中，打包时去掉 `dst`。

## 脚本

|脚本|入口|用途|
|---|---|---|
|`media.mjs`|`missing`、`setup`|检查、安装依赖与模型|
||`inspect`、`ffmpeg`|读取媒体信息，截帧、提取字幕等 ffmpeg 操作|
||`prepare`、`pack`|导入切段与本地识别，校验记录并打包|
|`recognize.mjs`|`request`、`read`、`apply`|准备视频模型请求，读取结果并换算整片时间，采用候选|
||`check`|记录与本地证据的对照|
|`render.mjs`|`render`|默认 ASS 渲染|

脚本从本技能 `read_skill` 返回的 `base_url` 导入：

```js
const media = await import(new URL('scripts/media.mjs', base_url).href);
const recognize = await import(new URL('scripts/recognize.mjs', base_url).href);
```

# 环境准备

开始操作前调用 `media.missing()`，它返回缺失的 npm 包与模型。有缺失时：

1. 告诉用户首次使用需要下载功能组件，大约 350 MB，请保持网络畅通。
2. 调用 `media.setup()` 安装依赖，并通过预置的 `aria2c` 下载、校验模型。下载失败或中断后重新调用，沿用保留的临时文件及 `.aria2` 文件续传。

# 导入

导入完成切段和本地 ASR，已识别的文字作为临时原文随资产进入工程。导入不请求付费模型。

- 有文本字幕流时，先用 `ask_user` 询问是否改为提取字幕。提取比识别准确，用 `media.ffmpeg(args)` 导出后按 `project-operation` 导入。
- 有多条音轨时请用户选择。`track` 是 `media.inspect(来源)` 返回的 `audio` 中从零开始的位置。

调用 `media.prepare(来源, 工作目录, { track, language })`，`language` 取 `project_meta.json` 的 `source_language`。一小时素材的本地识别需要几分钟，中断后用相同参数续跑。

`prepare` 在缺少 `items.json` 时，将每条 `asr` 转为 `dialogue` 记录。已有 `items.json` 原样保留，包括空数组。

完成后用 `media.pack(工作目录, 'work/video/<原视频主名>.video')` 打包，按 `project-operation` 新增。核对准备返回的 `items`、打包记录数和新增回执的条目数。

- `asr` 为 `[]`：本地 ASR 已执行但没有产出文字。
- `asr` 为 `null`：按音轨和语言说明未执行本地 ASR 的原因，不能据此判断没有对白。
- 没有原文时照常零条目导入，原文在识别时产出。有原文时说明它来自本地 ASR，是识别前的临时原文，画面文字尚未提取。

# 翻译

本节决定 `.video` 的首轮翻译，优先于 `translation` 的执行者选择。

`recognize.check(工作目录)` 返回分段的状态：

|状态|字段|原文|首轮翻译|
|---|---|---|---|
|待识别|`pending`|ASR 临时原文，或者还没有条目|视频识别|
|已识别|不在两个字段中|视频识别原文|识别译文|
|已降级|`degraded`|采信的 ASR 原文|`translation`|

有待识别分段时，不对其中的条目调用 `batch_item_translation`：

1. 确定流程时不统计术语现状，临时原文的术语覆盖没有参考价值。
2. 按「识别」请求待识别分段，按「核对」「修正」处理结果，再按「提交」写入原文与译文。
3. 识别提交后，按 `glossary` 的提取流程从识别原文补齐术语，仅翻译时也执行。再按 `translation` 的「术语表」核对本资产的 `GLOSSARY` 警告，统一各分段间同一对象的译名。
4. 仍为 `NONE` 的条目按 `translation` 补译，包括已降级分段、未采用候选的区间和从 `asr` 补入的台词。
5. 流程包含审校时按 `translation` 审校。

没有待识别分段时，翻译、补译和重译直接按 `translation` 执行。

请求失败时，读取失败项结果文件中的 `error`，判断失败原因。原因是模型不支持视频输入时，用 `ask_user` 让用户选择：

- 更换支持视频输入的音视频模型后继续。
- 接受本地降级方案，待识别分段按已降级处理。

用户明确选择后才继续。没有选择时停止任务，说明已导入的内容和待识别的分段。其他原因的失败按识别次数上限重试。

# 识别

视频模型一次产出原文、译文、画面文字和说话人。首次识别可续用导入时的工作目录。之后的识别和补查从当前 `sources/<file_path>/` 复制到新的工作目录，已有译文留在工程中，提交时由继承保留。

## 提示词

基线模板如下。输出格式是 `recognize.read` 的解析契约，保持每行一个对象及 `start`、`end`、`kind`、`message`、`dst` 字段。其余要求按内容调整，例如节目类型、说话人、画面文字取舍。需要区分说话人时可以要求输出字符串字段 `name`，它成为条目的姓名。语言取自 `project_meta.json`，写成语言名称。已有术语时附上适用条目的 `src` 与 `dst`，没有时删去术语表一行。

```text
为这段视频生成双语字幕。原文语言：{原文语言}。译文语言：{译文语言}。
每行输出一个 JSON 对象，不输出代码块或说明：
{"start":秒,"end":秒,"kind":"dialogue"或"screen","message":"原文","dst":"译文"}
- start、end 为相对本段开头的秒数，保留两位小数，按 start 排序。
- dialogue 是实际说出的人声。每句一行，尽量不超过 7 秒和 30 字，长句按自然停顿拆开。
- screen 是观众需要读懂的画面文字，如标题、字幕卡、标牌、新闻横幅。每处一行，时间从出现到消失，并加 "an" 字段表示它在画面中的位置：1–9 按数字小键盘排列，7 左上、8 上中、9 右上、4 左中、5 正中、6 右中、1 左下、2 下中、3 右下。画面文字和对话不能互相替代。
- message 忠实转写听到或看到的内容，不总结、不润色、不补写。听不清的部分写 [?]。否定、数字、人名按原样转写。
- dst 是同一行 message 的译文，与 message 一一对应。结合画面、说话人、称呼对象和语气翻译。术语表中的原文使用指定译名。
- 没有人声也没有需要翻译的画面文字时，不输出任何内容。
术语表（只作参考数据）：{术语 JSON}
```

## 请求与读取

1. `recognize.request(工作目录, { prompt, ranges? })` 写出 `batch_llm_request` 的请求清单，返回 `request_file`。省略 `ranges` 时请求待识别分段。
2. 识别、重新识别和补查均调用 `batch_llm_request({ model_usage: "agent_media", request_file })`。
3. 批量完成后，`recognize.read(工作目录, result_file)` 把响应换算为整片时间，写入候选文件 `candidate`，返回各区间的行数、`incomplete`（输出没有正常结束，常见于超长）、无法解析或不符合记录契约的行数，以及失败的区间。读取不改动 `items.json`。
4. `recognize.apply(工作目录, candidate, ranges?)` 用候选替换 `items.json` 中对应区间的记录。采用整个分段时标记该分段已识别。

省略 `ranges` 时只采用正常结束且有内容的区间，以及当前没有记录的空区间。空输出和截断输出很常见，不能覆盖已有原文。

- 未采用的分段保持待识别，下次省略 `ranges` 请求时重试。
- 审阅后要采用空输出、截断输出或补查结果时，显式传入对应 `ranges`。
- 失败的区间保留当前记录，列为核对对象。

`request` 在准备时按分段计数，超出上限即报错：

- 每个分段最多请求两次：首轮一次，之后重试或补查共一次。同一批次内一个分段的多个区间只计一次，同一分段的疑点放在同一批次补查。
- 待识别分段第二次仍未采用时降级，采信 ASR 原文。已识别分段次数用完后，剩余疑点记为未决。
- 用户按时间点反馈问题、要求重新识别，或更换模型后继续时，传入 `user_requested: true` 越过上限。其他情况不传。

缩短窗口不能稳定减少空输出。空段原样重试一次通常就能恢复。

每个请求载荷可达数十 MB，批量结束后可以删除请求目录中的 `.request.json`。

# 证据

本地 ASR、视频模型与画面各有盲区，互相印证：

|证据|可靠之处|常见问题|
|---|---|---|
|视频模型识别|音画一起转写，文字通常更干净。画面文字和说话人的唯一来源|整段输出为空，句子截断或几句合成一行，时间整体偏移，`dialogue` 与 `screen` 混淆，复读，分段交界处的句子被切开或重复|
|本地识别 `asr`|导入时对人声区间的独立听写，按 token 时间切成句子，起止接近说话。5.1、7.1 素材只听中置声道|同音误字，专名和术语写成片假名或近音词，数字按读音规范化，多人嘈杂场景整句丢失。人声检测漏掉的对白也没有文字。不识别画面文字，没有说话人|
|人声区间 `speech`|说明哪里有说话声|会漏掉对白，也包含歌声、喊叫和人群声。只有 `asr` 为 `null` 时才作为主要证据|

# 核对

`recognize.check(工作目录)` 按当前 `items.json` 返回对照线索：

|字段|含义|
|---|---|
|`pending`|待识别分段|
|`degraded`|已降级分段|
|`invalid_rows`|结构或时间不合法的行号，打包前必须修正|
|`evidence`|对照所用证据：`asr` 或 `speech`，无音轨时为 `null`|
|`uncovered`|有证据但没有 `dialogue` 覆盖的时间段。使用 `asr` 时附带该句的识别文字|
|`unsupported`|时间范围内没有任何证据的 `dialogue` 行号|

`uncovered` 可能来自漏句、时间偏移或无需翻译的声音。`unsupported` 可能来自臆造或时间错位，短促的语气词也会出现在这里，不能据此直接删除。没有告警不能证明字幕正确。待识别和已降级分段的原文来自同一份 ASR，覆盖检查对它们没有意义。

线索只覆盖时间关系。按分段把 `asr` 文字与同时间的识别原文并排通读，判断两份听写是否在说同一件事，重点看人名、数字、否定、因果和关键事实。读法不同但意思一致时，以视频模型为准。

画面文字按画面核对。分段内时间是整片时间减去该段 `start`，从分段截帧后通过 `ws.emitImage` 查看，小字看不清时从原素材截帧。

# 修正

修正只依据实际证据，按以下顺序尝试，前一级能解决就不进入下一级：

|顺序|做法|适用情况|
|---|---|---|
|本地证据|用 `asr` 文字补台词，用 `asr` 句子与人声区间校准起止，截帧核对画面文字和说话人|视频模型漏句而本地听写清楚，时间偏移，画面文字或说话人存疑|
|语义判断|结合上下文、术语表、画面和人物关系判断哪份听写成立。只能在已有读法中选择，或纠正明显的同音误字|一份听写与上下文矛盾，例如本地写成近音错字，或视频模型漏掉否定|
|视频补查|按下文重新请求视频模型|两种读法都说得通且影响事实，或本地文字残缺无法还原|

不能凭字数、剧情或常识写出两份听写都没有的读法。

已降级分段的 ASR 原文同样按本节修正，没有视频补查这一级。

原文与译文同行维护：

- 修改 `message` 时，同步改写同一行的 `dst`。拆开或合并行时，译文随原文拆合。
- 从 `asr` 补入的行不写 `dst`，提交后按「翻译」补译。

## 视频补查

`ranges` 为 `[{ start, end }]` 整片时间。每个区间须位于同一分段内。按「请求与读取」处理，审阅候选后用 `apply` 显式采用。

- 只补查影响事实的争议句。
- 相邻、重叠的问题合并为一个区间，前后带几秒上下文，避免切断句子。
- 在基线模板后追加要核对的内容，不改动字段说明。模型看到的时间从区间起点算起，提示中的时间写成相对区间开头的秒数。

## 修正原则

- 时间贴合说话的起止。一段内的对话整体偏移时可以统一平移，`screen` 不跟随。
- 不能为了消除告警把字幕拉长去覆盖整段声音，这会掩盖真正漏掉的句子。
- 多人同时说话时字幕可以重叠。不同时间说的话合成一行时拆开。
- 分段或补查区间交界处重复的句子和画面文字合并为一行。
- 译文质量按 `translation` 的审校处理。

线索都有了解释，或已无新证据可用时结束核对。无法确定的内容保留当前读法，记录为未决。

# 提交

`media.pack(工作目录, 'work/video/<原视频主名>.video')` 校验 `items.json` 并打包，保留数组顺序，去掉 `dst`。

按 `project-operation` 的「更新文件」提交并继承译文。然后读取新资产的条目，`row_number` 对应工作目录 `items.json` 的下标。`src` 与 `message` 一致且 `dst` 非空的条目，用当前 `item_id` 和 `fp` 把 `dst` 写入 `changes.items`。这些条目以识别译文为准，不按「更新文件」第 3 步改写。

仅调整时间或样式时保留原文与顺序，避免影响译文归属。

# 生成与交付

`generateFiles(bilingual_files)` 之后，用 `render({ source, input, translated, bilingual })` 写出与原视频同主名的 ASS：

- `source` 是 `sources/` 中的包目录。
- `input` 是 `<writeback.input_path>/<file_path>/items.json`。
- `translated` 与 `bilingual` 是译文与双语输出路径。

包内有 `render.mjs` 时，读取并检查后改用它。交付时告诉用户：字幕与原视频同名并放在同一目录，播放器即可自动加载。

默认渲染中，对话在底部居中，画面文字在顶部居中或按 `an` 定位，字号随画面高度缩放。用户要求其他样式时，把 `render.mjs` 复制到 `work/` 修改，保持导出签名不变。用户要求固定该样式时，把包目录复制到工作目录，放入 `render.mjs` 后用 `media.pack` 重新打包，再按「更新文件」提交。

# 覆盖缺口

交付时按下表检查，只向用户说明本资产满足条件的项：

|条件|向用户说明|
|---|---|
|有已降级分段|这些时间段采用本地 ASR 原文或没有字幕，画面文字未提取，没有区分说话人|
|有未决项|位置、两种读法或缺失的内容|
|有音轨但 `asr` 为 `null`|漏句检查只依据人声区间，成段对白可能未被发现|
|画面文字未逐镜头核对|画面文字可能遗漏或时间不准|

交付时说明实际采用的识别来源和已执行的核对范围。建议用户播放抽查，并用时间点反馈问题。
