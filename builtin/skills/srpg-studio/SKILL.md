内置解析器不识别 SRPG Studio 游戏，游戏本体文本经 `generic-package` 封装为 `.generic` 通用包进入工程。本技能提供 SRPG Studio 在各阶段的方法。

# 来源调查

## 目录特征

|文件或目录|含义|处理|
|---|---|---|
|`data.dts`|主归档，含地图、事件、数据库、脚本、插件与素材|本体文本主容器，封装为通用包|
|`runtime.rts`|引擎公共运行时资源包|通常不含本作独有正文，原样保留|
|`game.exe`、`<游戏名>.exe`|引擎可执行程序，含原生窗体与底层提示|原样保留|
|`game.ini`|运行配置，常见 CP932 编码|保留原文件与配置键名；如需中文说明，另行整理独立文档|
|`localization.dat`|部分新版附带，常见为 16 字节全零占位|确认其内容前，不假设它承担正文翻译|
|`environment.evs`、`system.dat`、`Save/`|环境数据与存档|不处理|
|根目录 `.txt`|说明书、操作指南、职员表等，常见 CP932 编码|解码核验无乱码后按普通文本导入，不放入游戏通用包|

## 版本与容器分界

先读取 `data.dts` 文件头，按版本代际确定解包方式：

|版本范围|文件头与加密特征|解析方式|
|---|---|---|
|`fileVersion >= 1301`|带 `SDTS` 魔数；脚本与项目段用 RC4 新密钥 `_dynamic`，其余资源段用 16 字节 `customKey`|使用 `SRPG-ToolBox`（`SRPG_Unpacker.exe`）解包与封包|
|`1140 <= fileVersion < 1301`|带 `SDTS` 魔数；使用 RC4 旧密钥 `keyset`|使用 `SRPG-ToolBox` 解包与封包|
|`fileVersion < 1140`（如 `1.048`）|无 `SDTS` 魔数；整档用 Windows CryptoAPI RC2-CBC 加密（零 IV）|先核对是否带头部 16 字节 XOR，再解密解析|

版本核对要点：

- **超前版本**：
  - `SRPG-ToolBox` 声明支持至 `1322`（`0x52A`）。
  - 遇到更高小版本（如 `1323` / `0x52B`）时工具会报版本警告，先用代表样本验证解包、导出与重封包往返。
- **无魔数旧版密钥**：
  - RC2-CBC 密钥为 `UTF-16LE("_dummy")` 前 6 字节的 MD5，使用零 IV。
  - 不同早期构建的头部前 16 字节可能带 XOR，也可能不带；按默认带 XOR 解包失败时，尝试直接整档解密。
- **无魔数旧版布局**：
  - 解密后前 32 字节依次为 `fileVersion`、`loadRuntime`、`projectDataAddress` 与 5 个段标志。
  - 其后接 35 项旧段表，表尾 `0xAC` 为数据区基址；段表末项指向脚本段，脚本段之后即为 `project.dat`。

## 文本来源

`data.dts` 内的候选文本分布在以下位置：

|来源|内容|提取原则|
|---|---|---|
|`project.dat`|地图、事件、数据库、标题、命令布局与系统词汇|经 `-c` 导出 JSON 或直接定位二进制文本槽，按字段筛选|
|`Script/constants/constants-stringtable.js`|引擎系统界面字串表（存读档、提示、菜单说明等）|提取显示文本；跳过纯符号与通用缩写（如 `Lv`、`Ex`、`HP`、`%`）|
|`Plugin/*.js`|插件硬编码的菜单、提示与战斗浮字|按消费代码筛出显示字面量；跳过 `root.log` 调试输出与程序键|
|`customParameters` 内嵌字面量|部分插件在对象参数字符串中写入显示名或配置|仅在确认用于界面显示且不兼作内部查找键时提取|
|`project.dat` 未导出字段|工具 `-c` 可能漏掉个别文本，如滚动职员表 `getStaffRollString()`|扫描 `project.dat` 的 UTF-16LE 字符串并与已导出集合比对补漏|
|`Graphics/`、`UI/` 图像|标题美术、立绘与插图装饰字|默认保留原图；仅在用户明确要求处理图中文字时按 `image` 另行评估|

### `project.dat` 常见导出文件归属

常规待译范围：

|类别|常见文件|主要内容|
|---|---|---|
|标题与全局|`titles.json`|`windowTitle`、`gameTitle`、`saveFileTitle`|
|地图与据点|`Maps/map_*.json`、`Base/`|章节名、地图名、胜负条件、单位名、据点与地图事件对白|
|回想与书签|`Extra/recollection.json`、`bookmark.json`、`bookmarkevents.json`|回想剧情与书签事件|
|数据库|`players.json`、`classes.json`、`classtypes.json`、`weapons.json`、`items.json`、`skills.json`、`states.json`、`difficulties.json`|角色、职业、装备、技能、状态与难度；`NPCSettings/` 仅提取玩家可见角色|
|界面与词汇|`CommandLayout/*.json`、`ResourceLocation/strings.json`|命令按钮与系统显示词|

默认排除或须核对消费点的范围：

- `Variables/`（变量编辑器名）与 `fonts.json`（字体族名，见「字体」）。
- `Base/autoevents.json` 等仅含脚本代码的事件。
- 事件对象的 `comment`、`type` 与编辑器事件列表名。
- `classesgroups.json`、`ResourceLocation/screens.json`（常为内部转职分组键或编辑器标签，确认显示给玩家后再提取）。
- `customParameters` 代码体、资源路径，以及 `ダミー`、`デバッグ` 等占位项。

派生 `speaker` 字段：

- 工具导出消息事件里的 `speaker` 是反查出的展示上下文，不对应独立存储槽。
- 可写入通用包条目的 `name` 供翻译参考（排除 `No Speaker`、`Unknown_*` 等占位值），但不向 `speaker` 写回。
- 游戏中实际显示的说话人姓名来自 `players.json`、`NPCSettings/` 与地图单位的 `name` 字段。

# 导入准备

## 单包与自包含

- **合并单包**：`data.dts` 内的全部可译来源（项目数据、系统字串表、插件与补查文本）必须封装进同一个 `.generic` 包，只产出一个 `data.dts`。分包写回会互相覆盖 `data.dts`
- **工具与随包材料**：
  - `SRPG_Unpacker.exe`来自 https://github.com/Sinflower/SRPG-ToolBox
  - 依赖该工具写回时，将冻结底稿 `data.dts`、工具、许可与 `writeback.mjs` 一并打包，并在写回脚本中校验工具 SHA-256
- **脚本定位**：使用 JS 解析器（如 `acorn`）提取脚本字面量，在私有坐标中保存文件路径、字符区间与原字面量，避免正则误改注释或键名
- **未导出文本写回点**：工具 `-c` 漏导出的文本（如滚动职员表），可在对应脚本的最终显示调用点写回，或在局部字节替换路线中直接改写 `project.dat`

## 写回路线选择

### 路线一：工具往返（现代版本）

适用于 `SRPG_Unpacker.exe` 能完整解包并往返的现代归档：

|步骤|命令|作用|
|---|---|---|
|1. 解包归档|`SRPG_Unpacker.exe <data.dts> -o <解包目录>`|展开资源、脚本、`project.dat` 与 `config.json`|
|2. 导出补丁|`SRPG_Unpacker.exe <解包目录>/project.dat -c -o <补丁目录>`|生成可编辑 JSON 补丁树|
|3. 应用补丁|`SRPG_Unpacker.exe <解包目录>/project.dat -a -o <补丁目录>`|将改好的 JSON 写回 `project.dat`|
|4. 重新封包|`SRPG_Unpacker.exe <解包目录> -o <输出.dts>`|打包生成新的 `data.dts`|

- 对单独的 `project.dat` 执行 `-c` 或 `-a` 时，其同目录须存在对应的 `config.json`（提供 `fileVersion`、`segments` 等参数）。

### 路线二：局部字节替换（旧版或工具失步时）

当 `SRPG-ToolBox` 解析旧版 `project.dat` 失步（例如报 `End of file reached`）时，按以下步骤处理：

1. **定位失步点**：
   - 运行 `-c` 时附带 `--log-mem-data`，查看 `SRPG_MemDataLog.txt` 末尾记录。
   - 核对最后一个正常文本与失步结构体（例如 `1.048` 的 `UNITCONDITIONDATA` 比工具预期多 2 个 DWORD）。
2. **区分验证器与写回器**：
   - 修补并编译的解析器仅用于定位字段偏移和验证最终档案读至 EOF。
   - 不要用它执行 `-a` 整体重序列化旧版 `project.dat`——旧版重序列化往往连原文都无法逐字节一致。
3. **局部替换文本槽**：
   - `project.dat` 中的文本槽为 `uint32` 字节长度前缀（含末尾 `\0`）+ UTF-16LE 正文 + `\0`。
   - 按验证过的精确偏移原地替换文本并重写长度前缀，其余字节原样拼接。
4. **同步容器偏移**：
   - 旧版脚本段同样采用 `uint32` 长度前缀 + 带 `\0` 的 UTF-16LE。
   - 脚本段长度变化时，按该版本容器头布局更新项目块偏移（例如无魔数旧版位于 `0x08`、相对 `0xAC` 的偏移），再整档加密。

## 插件按名引用调查

提取前在 `Plugin/*.js` 与事件脚本中搜索 `getName()` 及数据库名称比较：

- 仅作内部查找键的名称（如转职分组名 `ClassChangeGroupName`）保持原值。
- 既显示又被插件按名查找的名称（如转职自动换装插件查找的武器名），翻译后须保证不重名冲突，并在插件查找入口建立原名到译名映射，或同步协调引用处。

# 原稿与条目

## 对白姓名

- 条目的 `name` 仅作翻译上下文，实际改名通过角色、NPC 和地图单位条目生效。
- 部分游戏会把说话人直接写在正文首行（如 `角色名\n「对白」`），翻译与审校时须保留首行姓名。

## 英文界面项

- `constants-stringtable.js`、`difficulties.json` 与插件中常含英文界面词，例如 `no data`、`Chapter`、`File`、`Press Space`、`PLAYER`、`ENEMY`、`Normal`、`Easy`。
- 非英语源工程中，这类条目常被默认判为 `LANGUAGE_SKIPPED`。
- 翻译阶段须筛出其中的可见界面项单独补译；`HP`、`Lv`、按键名和网址等固定标识保持原样。

## 同文异义

- 同一原文常兼作不同设定或界面词，最常见如 `ロード`（职业「领主」与菜单「读取存档」）。
- 避免放任重复条目按 `DUPLICATED` 盲目继承同一译文，按包内坐标分别确认并独立定稿。

## 控制符保护

本引擎无内置 `text-preserve` 预设。翻译前扫描工程中实际出现的控制符，按 `text-preserve` 添加自定义保护规则：

- 常见消息控制符：`\fw[n]`、`\fs[n]`、`\sp[n]`、`\at[n]`、`\cdb[n]`、`\va1[n]`～`\va6[n]`、`\T`、`\.`、`\_`。
- 常见脚本占位符：`%s`、`%d`、`{0}`。
- 单字母控制符须加边界限制（如 `\T(?![A-Za-z])`），避免误匹配普通字母。

# 翻译后检查

译文写入后，用脚本对最新快照批量核对：

|检查|方法|处理|
|---|---|---|
|控制符与换行|检查本次条目的 `TEXT_PRESERVE`、`LINE_COUNT_MISMATCH` 警告，并比对反斜杠控制符、占位符与原文行数（含分页空行）|恢复损坏的控制符、占位符与原文行数|
|英文界面与首行姓名|复查 `LANGUAGE_SKIPPED` 中的显示项，以及原文首行带说话人的对白|补译遗漏的英文界面，补回误删的首行姓名|
|同文异义与按名冲突|按包内坐标核对跨语境重复项，以及参与插件按名查找的对象译名|拆分串译的重复项；消除按名查找对象的译名碰撞并核对映射覆盖|

# 写回与验证

## 脚本写回

- 写回 `Script/`、`Plugin/` 和内嵌 `customParameters` 的 JS 字符串字面量前，先确认原文件编码（现代解包通常为 UTF-8，无魔数旧版内部为 UTF-16LE）。
- 除常规 JS 字符串转义外，额外转义 `\u2028` 与 `\u2029`（旧版 JS 引擎将其视为行终止符），禁止写入 `\0` 或孤立代理项。
- 每个修改过的脚本必须通过 JS 语法校验（如 `new vm.Script(code, { filename })`）。

## 归档核对

- **工具应用顺序**：采用工具往返路线时，修改完 `-c` 导出的 JSON 后，必须执行 `-a` 应用回 `project.dat`，再重新封包 `data.dts`。
- **工具往返核对**：
  - 重新解包新生成的 `data.dts` 并再次 `-c` 导出 JSON，逐文件核对修改字段值。
  - 比对导出 JSON 时忽略 `message` 事件命令的派生 `speaker` 字段，避免因单位改名触发误报。
  - 对未修改的 `Graphics`、`Material`、`Script`、`Plugin` 等全部资源核对 SHA-256。
- **局部替换核对**：
  - 核对未修改区间与底稿逐字节一致。
  - 按新偏移重新读回全部目标文本槽，确认 UTF-16LE 内容与译文一致。
  - 使用结构验证器解析新 `project.dat` 至 EOF。

## 副本实机验证

- 在工作区建立完整游戏副本（保持原游戏目录不变），仅替换副本中的 `data.dts` 后启动，检查窗口标题、菜单界面与字体渲染。
- 若当前运行环境无法捕获游戏窗口，如实记录为未完成实机画面验证，不越权断言显示正常。

# 字体

- 字体槽位配置位于 `project.dat` 导出的 `fonts.json`，默认常见日文字体为 `ＭＳ ゴシック`。
- 如需切换中文字体，写回时仅替换目标字体槽的 `fontName`（例如改为目标系统已安装的 `Microsoft YaHei`），保留原字体槽数量、字号及其他参数。
- 局部字节替换路线未改动字体槽，或未完成实机画面确认时，在「交付说明」中提醒用户进游戏核对显示。

# 交付说明

每次交付都说明安装方式与适用范围：

- 先备份原游戏目录，仅将导出的 `data.dts` 覆盖到游戏副本中与可执行程序同级的位置。
- 保留原版可执行程序、`runtime.rts`、`game.ini` 与存档等其余文件。
- 补丁仅适用于本次对应的游戏版本，例如体验版补丁不可直接覆盖正式版。

此外，只向用户说明本游戏满足条件的项：

|条件|向用户说明|
|---|---|
|档案版本高于工具声明上限，或旧版采用结构修补与局部替换|说明版本差异，建议在游戏内确认剧情、菜单与战斗流程|
|调整了字体配置，或未完成实机窗口与画面验证|需要在游戏中确认中文显示正常、无缺字或截断|
|未处理贴图文字、原生窗体资源或底层引擎提示|标题美术、插图文字和底层系统弹窗仍显示原文|
|未逐章实机通关测试，或翻译了可能影响存档识别的名称|建议备份旧存档并在游戏中抽查关键流程|
