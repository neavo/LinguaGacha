# 条目翻译

本流程为条目写入译文，适用于翻译、补译、续做和重译。流程到报告现状为止，不审校译文。

- 术语见 `SKILL.md`。
- 译文按 `writing-guide` 的 `references/translation-guide.md` 形成。
- 格式专属要求按已加载的格式技能执行。

## 1. 确定目标

用一个 `workspace_run` 脚本读取 `project_meta` 和各状态的条目数，按用户请求确定目标：

|请求|默认目标|
|---|---|
|翻译、续做|状态为 `NONE` 的条目|
|补译、重译|用户指定的条目|

- 用户按文件、状态、文本条件或排除项限定范围时，在同一脚本中解析为 `item_id` 列表。
- 范围内有 `ERROR` 条目且用户没有决定时，说明数量，并用 `ask_user` 提供重试或跳过选项。
- `PROCESSED`、`EXCLUDED`、`RULE_SKIPPED`、`LANGUAGE_SKIPPED`、`DUPLICATED` 只在用户指定时，或经第 4 步「可见文本补漏」确认后纳入。

开始翻译前只确认格式、范围和数量。不通读正文，不分析人物、剧情或警告，不搜索原稿。

## 2. 选择执行者

从上到下选择第一条符合的条件：

|条件|执行者|
|---|---|
|本次不直接写入工程|Agent|
|用户对译文提出了工程提示词之外的要求|Agent|
|目标不超过一个业务单元|Agent|
|其余情况|`batch_item_translation`|

## 3. 翻译

### 批量翻译

按工具说明调用 `batch_item_translation`：

- 未限定范围时，用 `item_statuses: ["NONE"]` 选择目标。用户决定重试时，加入 `"ERROR"`。
- 限定范围时，用 `item_ids` 传入目标。

工具返回后，按返回的条目统计记录成功和失败数量，失败条目不自动重试。

### Agent 翻译

逐个业务单元执行：

1. 读取本单元的原文、现有译文、姓名和适用术语。
2. 个别条目缺少决定译法的事实时，用 `@lg/workspace/item-contexts` 的 `queryItemContexts` 查询邻近语境。仍无法确定时，将条目记为未决，不写入。
3. 形成译文，用脚本按「条目约束」检查结构，修正不符合的条目。
4. 按 `分组与提交` 提交，并核对回执。

### 条目约束

|约束|要求|
|---|---|
|边界|每条原文对应本条的完整译文。保留条目的边界、顺序、行数和换行|
|跨条目语境|可以结合跨条目语境理解内容。只按用户的明确要求改变结构|
|保护结构|控制符、占位符、标签、转义和其他保护结构保持位置与边界|
|标点|引号、括号可以转换为目标语言的同类形式。原文的半边结构和跨条目延续的结构保持原样|
|姓名|`name_dst` 只写姓名译文。称谓、头衔、敬称和解释留在正文的对应位置|
|提交字段|按 `ws.contract.changes.items.updates.reference` 提交字段修改或显式状态意图|

## 4. 可见文本补漏

同时满足以下条件时，执行已加载格式技能的「可见文本补漏」一节，格式技能没有这一节时跳过：

- 请求为翻译或续做，用户没有限定范围。
- 最新快照中已没有 `NONE` 条目。

## 5. 翻译后检查

执行已加载格式技能的「翻译后检查」一节，格式技能没有这一节时跳过。

## 6. 交付

用脚本读取最新快照，按 `item_id` 去重后说明：

- 目标总数，以及已翻译、失败、未决和剩余的数量
- 每部分的执行者
- 翻译后检查的结论和修正数
- 未决目标和未决事项的缺失事实
- 格式技能要求的其他交付内容

最后用 `ask_user` 询问是否继续审校译文。
