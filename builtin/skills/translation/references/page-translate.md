# 页面翻译

本流程为页面形成完整译稿，适用于翻译、补译、续做和重译。页面全部由 Agent 处理。流程到报告现状为止，不审校译稿。

- 术语见 `SKILL.md`。
- 译文按 `writing-guide` 的 `references/translation.md` 形成。
- 原稿读取、译稿写法和预览方法按已加载的格式技能执行。

## 页面模型

每个页面保存以下字段，字段结构以 `ws.contract.changes.pages.updates.reference` 为准：

|字段|含义|
|---|---|
|`translation`|页面的处置|
|`reviewed`|是否完成审校，由审校流程设置|
|`notes`|随 `.lg` 保存的未决、续做和跨页说明|

`translation` 的取值决定页面的处置：

|`translation` 值|处置|
|---|---|
|`null`|待处理，导出时暂用原页。改回此值会清除已完成的处置|
|`kind` 为 `translate`|输出属于本页的译稿，译稿内容可以为空|
|`kind` 为 `keep`|确认保留原页，`reason` 记录依据|
|`kind` 为 `omit`|按用户要求省略原页，`reason` 记录原因|

按以下规则使用页面模型：

- 译稿、保留和省略都计入完成。
- `reviewed` 和 `notes` 不影响完成率。
- 每次修改都准备所属页面的完整页面载荷，局部修改也一样。
- 页面载荷中的译稿始终是本页的完整最终内容。

### 跨页内容

跨页内容可以整体归入其中一页：

- 其余被接管的页面使用空译稿。
- 在相关页面的 `notes` 中记录内容的来源与去向。
- 生成输出时跳过空译稿，前后译稿直接衔接。
- 调整跨页归属后，检查整组内容的覆盖。

### 原稿页与输出页

- 内容归属按原稿页追踪。
- 视觉问题按输出页定位。
- 输出页数和页码会随排版变化。
- 覆盖范围按原稿页去重统计。

## 1. 确定目标

用一个 `workspace_run` 脚本读取 `project_meta` 和 `pages` 的处置统计，按用户请求确定目标：

|请求|目标|
|---|---|
|翻译、续做，未限定范围|`translation` 为 `null` 的页面|
|补译|遗漏内容所属的原稿页|
|重译|用户指定的页面，只替换用户允许替换的处置|

开始翻译前只确认格式、范围和页数。

按原稿顺序将目标分成业务单元，按原稿页计数。跨页段落、表格和图注涉及的页面放在同一单元。

## 2. 翻译

逐个业务单元执行：

1. 按格式技能提取本单元的文字与结构。多栏、图表、公式、扫描页、没有提取到文字或内容归属不清时，结合原页图像确认。需要时读取单元外的相邻页面。
2. 按证据选择处置：

   |证据|处置|
   |---|---|
   |有待翻译的内容|准备完整译稿，覆盖正文、标题、列表、表格、数字、单位、图注、注释和引用|
   |确认无需翻译|保留原页|
   |用户要求省略|省略页面|
   |缺少决定性事实|`translation` 保持 `null`，在 `notes` 中记录未决|

3. 为每个页面准备完整页面载荷，`reviewed` 设为 `false`。跨页来源与去向写入 `notes`。
4. 按「提交规则」提交，并按逐页回执核对。

### 提交规则

- 通过 `ws.contract.changes.pages.updates.path` 指定的 JSONL 提交。
- 每个页面在同一批次只提交一次。
- 调整跨页归属时，同批提交涉及的全部页面。
- 逐页回执决定实际接受和拒绝的页面。
- 审批和 `applied.pages.updated` 按实际变化的页面数计数。
- 部分成功涉及跨页内容时，检查遗漏和重复，恢复一致的归属。

## 3. 翻译后检查

执行已加载格式技能的「翻译后检查」一节，格式技能没有这一节时跳过。

## 4. 交付

用脚本读取最新快照，按原稿页说明：

- 目标页数，以及已处置（译稿、保留、省略）、未决和剩余的页数
- 翻译后检查的结论和输出页数量
- 未决页面和未决事项的缺失事实
- 格式技能要求的其他交付内容

最后用 `ask_user` 询问是否继续审校译稿。
