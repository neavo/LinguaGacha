# 页面翻译

本流程为页面形成完整译稿，适用于翻译、补译、续做和重译。页面全部由 Agent 处理。

- 术语见 `SKILL.md`。
- 译文质量按 `writing-guide` 的 `references/translation-guide.md` 判断。
- 原稿读取、译稿写法和预览方法按已加载的格式技能执行。

## 页面模型

每个页面保存以下字段，字段结构以 `ws.contract.changes.pages.updates.reference` 为准：

|字段|含义|
|---|---|
|`translation`|页面的处置|
|`reviewed`|是否完成内容检查，不证明语义完整|
|`notes`|随页面保存的待办与续做说明|

`translation` 的取值决定页面的处置：

|`translation` 值|处置|
|---|---|
|`null`|待处理，导出时暂用原页。改回此值会清除已完成的处置|
|`kind` 为 `translate`|输出属于本页的译稿，译稿内容可以为空|
|`kind` 为 `keep`|确认保留原页，`reason` 记录依据|
|`kind` 为 `omit`|按用户要求省略原页，`reason` 记录原因|

按以下规则使用页面模型：

- 译稿、保留和省略都计入完成。
- `reviewed` 和 `notes` 不影响完成率。
- 每次修改都准备所属页面的完整页面载荷，局部修改也一样。
- 页面载荷中的译稿始终是本页的完整最终内容。

### 跨页内容

跨页内容可以整体归入其中一页：

- 其余被接管的页面使用空译稿。
- 在相关页面的 `notes` 中记录内容的来源与去向。
- 生成输出时跳过空译稿，前后译稿直接衔接。
- 调整跨页归属后，检查整组内容的覆盖。

### 原稿页与输出页

- 内容归属按原稿页追踪。
- 视觉问题按输出页定位。
- 输出页数和页码会随排版变化。
- 覆盖范围按原稿页去重统计。

## 1. 确定目标

通过 `ws.contract` 读取 `project_meta` 和 `pages`，确定原稿顺序、页面范围和现有处置。再按用户请求确定目标：

|请求|目标|
|---|---|
|翻译，未限定范围|`translation` 为 `null` 的页面|
|补译|遗漏内容所属的原稿页|
|重译|用户指定的页面，只替换用户允许替换的处置|
|续做|对照最新快照、`notes` 和业务工作材料，找出剩余目标和未决目标|

续做时，未提交的变更清单和已保存的页面分开判断。跨页内容结合已有的来源与去向记录判断覆盖。

按以下规则将目标分成业务单元：

- 单元规模按 `分组与提交` 执行，按原稿页计数。
- 跨页段落、表格和图注涉及的页面放在同一单元。
- 需要时读取单元外的页面补充语境。

## 2. 阅读原稿

按连贯内容组织页面。跨页段落、表格和图注连同相邻页面一起理解。

按格式技能提取文字与结构，再按以下情况补充查看原页图像：

|情况|处理|
|---|---|
|多栏、图表、公式、扫描页或阅读顺序不明|结合原页图像确认|
|没有提取到文字|查看原页图像中的正文、标注与图例|
|提取的文字不完整，或内容归属不清|补看原页图像和必要的相邻页面|

补查后仍缺少决定性事实时，将页面记为未决。

## 3. 形成译稿

按 `translation-guide` 形成译文，并使用适用的术语。检查以下内容是否完整：

- 正文、标题和列表
- 表格、数字和单位
- 图注、注释和引用

允许按目标语言重新排版。段落与图表保持可理解的关联。

按证据选择处置：

|证据|处置|
|---|---|
|有待翻译的内容|准备完整译稿|
|确认无需翻译|保留原页|
|用户要求省略|省略页面|
|缺少决定性事实|`translation` 保持 `null`，在 `notes` 中记录未决|

局部草稿放在 `work/`。

## 4. 检查与提交

逐个业务单元执行以下步骤：

1. 完成内容检查后，更新 `reviewed`。
2. 将未决和续做事项写入 `notes`。
3. 按格式技能预览发生排版变化的内容。
4. 发现问题后修正，并重新查看受影响的输出。
5. 内容、跨页覆盖和必要的视觉检查都通过后，按 `分组与提交` 提交。

预览时重点查看以下内容：

- 跨页归属
- 长表格和公式
- 大图的图注
- 背景
- 译文与保留原页的衔接

统一提交或 `report` 任务时，将本单元检查通过的变更清单保存到业务工作材料。保存后再处理下一单元。`report` 任务预览草稿。

### 提交规则

- 通过 `ws.contract.changes.pages.updates.path` 指定的 JSONL 提交。
- 每个页面在同一批次只提交一次。
- 调整跨页归属时，同批提交涉及的全部页面。
- 逐页回执决定实际接受和拒绝的页面。
- 审批和 `applied.pages.updated` 按实际变化的页面数计数。

每次写入并读取回执后，执行以下步骤：

1. 按逐页回执核对成功和失败。
2. 读取最新快照，核对用户范围内页面的处置和待办。
3. 部分成功涉及跨页内容时，检查遗漏和重复，恢复一致的归属。

## 5. 记录

业务工作材料按页面身份保存以下内容：

- 未提交的变更清单
- 每个目标的证据和当前结论
- 实际写入的结果和剩余问题
- 待处理的关联问题，包括发现依据、影响范围、检查方法和当前状态

未提交的草稿与已写入的页面载荷分开记录。视觉检查记录实际查看的输出范围和未决问题。

页面需要长期保留的内容来源、去向和待办写入相关页面的 `notes`：

- `translation`、`reviewed` 和 `notes` 随 `.lg` 保存。
- `work/` 按对话保留在本机，重开后可以继续使用。
- 对话重置、工作区清理或迁移后材料缺失时，依据工程现值和已保存的 `notes` 恢复。

## 6. 关联检查

阅读、翻译和预览时发现以下线索，需要检查其他页面：

|线索|检查对象|
|---|---|
|可靠的术语、图文对应或跨页组织|同类页面，按内容与结构确认适用|
|遗漏、错列或分页问题|相关结构|
|特殊版式等反例|同类页面的处理边界|
|新的语境、术语或跨页结构事实|受影响的译稿与输出|

页面归属、译稿或未决结论变化时，跟进由此产生的新问题。

关联检查遵守以下规则：

- 检查发现新问题时，继续处理。
- 原问题修正后，仍要完成已经产生的后续检查。
- 所有相关影响都有结论后，才结束关联检查。
- 合并等价问题，复用有效证据。
- 只重查变化影响的部分。

## 7. 结束与交付

结束前对照全部目标和问题记录，逐项确认：

- 每个目标页面都有检查过的处置，或记为未决。
- 内容覆盖完整，必要的视觉检查已通过。
- 已发现的关联影响都有检查结论。

还有可以执行的剩余工作时，继续处理。

交付时按原稿页说明以下内容：

- 处理范围和当前处置
- 完成结果、未完成页和续做条件
- 已处理页与剩余页的合计是否等于目标页数
- 内容阅读和视觉检查各自覆盖的范围
- 输出页数量
- 格式技能要求的其他交付内容
