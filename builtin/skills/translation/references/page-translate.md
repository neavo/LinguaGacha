# `pages` 翻译

Agent 为工程内的 `page` 翻译、补译、续做或重译，按 `page` 身份定位内容并核对完整译稿与预览。

## 目标解析与续做恢复

按 `ws.contract` 读取 `project_meta` 与 `pages` 快照，结合用户请求确定原稿顺序、页面范围和现有处置。明确要求翻译且未限定范围时，以当前待译内容为目标。补译按指定遗漏定位所属原页，重译按指定原页及允许替换的处置定位。续做结合已保存处置及 `notes` 恢复待处理和未完成内容，工作草稿与已保存事实分别判断。

按用户范围和原页身份确定实际处理集合。跨页内容结合已有来源与去向记录判断覆盖，局部补译或重译也形成所属原页的完整载荷。

按全局 `业务单元与提交` 的页面默认规模分组，用 `file_path` 与原稿 `page` 确定页面身份并计数。将跨页段落、表格和图注涉及的页面放在一起处理，按需读取组外页面补充语境。分别记录原稿页与排版后的输出页，按原稿页身份去重后统计覆盖范围。

## 阅读与翻译

按连贯内容组织 `pages`，跨页段落、表格和图注连同相邻页理解。先提取文字与结构，多栏、图表、公式、扫描页和阅读顺序不明处结合原页图像确认。没有提取文字时仍需看图核对正文、标注和图例。

形成译文时核对正文、标题、列表、表格、数字、单位、图注、注释与引用的完整性，使用适用术语。允许按目标语言重排版，段落与图表保持可理解的关联。

根据证据确定 `page` 的处置：有待翻译内容时准备完整译稿，确认无需翻译时保留原页，按用户要求省略页面。

提取的文字不完整，或阅读顺序、内容归属不清楚时，补看原页图像及必要邻页。仍缺少决定性事实时，将页面记为待处理，记录已查材料、具体缺口和继续条件。继续处理可独立确定的页面。

跨页内容可整体归入其中一页，为已接管 `page` 准备空译稿，并在相关 `notes` 中说明来源与去向。检查整组覆盖，保存涉及的全部 `pages`。局部草稿先放在 `work/`，`page` 载荷中的译稿始终是该页的完整最终内容。

## 检查与关联处理

完成内容检查后更新 `reviewed`，未决和续做事项写入 `notes`。使用 PDF 预览查看发生排版变化的风险内容，重点核对跨页归属、长表格、公式、大图图注、背景及译文与保留原页的衔接。发现问题后修正并重新查看受影响输出。

当前单元通过内容、跨页覆盖及必要视觉检查后，按全局 `业务单元与提交` 安排提交。跨页调整时，一同准备所有相关页面的完整载荷。

默认提交本单元并核对结果，再进入下一单元。统一提交时，先保存方案再处理下一单元。`report` 预览并保存草稿方案后，继续处理剩余页面。

写入后按逐页回执核对成功和失败，再读取最新快照核对用户范围的 `page` 处置与待办。部分成功涉及跨页内容时检查遗漏和重复，恢复一致的归属。

根据阅读、翻译与预览结果检查关联问题：

- 用可靠术语、图文对应和跨页组织检查同类 `pages`，按内容与结构确认适用性。
- 发现遗漏、错列和分页问题时，核验相关结构。
- 遇到特殊版式等反例时，调整处理边界。
- 新语境、术语或跨页结构事实改变已有判断时，核对受影响的译稿与输出。

记录关联问题的触发依据、范围、核验方法、受影响 `pages` 与当前结果。`page` 归属、译稿或未决变化产生的新问题继续跟进，即使原问题已修正，也要完成已产生的后续检查。等价问题合并，有效证据复用，变化只重查受影响部分。

按 `page` 身份保存方案、证据、实际结果和剩余问题。长期续做所需的内容来源、去向及待办写入相关页的 `notes`。工作草稿与实际保存的载荷分别记录。

## 完成检查与交付

结束前对照完整目标及问题记录，逐项确认：

- 每个目标 `page` 均有经过核对的处置或明确的未决说明。
- 内容覆盖完整，必要的视觉检查通过。
- 已发现的关联影响均有核验结果。

有可执行的剩余工作时继续处理。未决事项说明已查内容和继续条件。

交付时按原稿页说明处理范围、当前处置、完成结果、未完成页和续做条件。核对已处理与剩余页的合计是否与目标页数一致。说明内容阅读与视觉检查各自覆盖的范围，并列出输出页数量。需要正式 PDF 时，由用户通过应用导出。
