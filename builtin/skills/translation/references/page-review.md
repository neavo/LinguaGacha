# 页面审校

本流程对照原稿、已有或拟议的译稿和渲染结果，检查、审校和修正页面的内容与视觉呈现。

- 术语见 `SKILL.md`，页面模型见 `references/page-translate.md` 的「页面模型」。
- 译文质量按 `writing-guide` 的 `references/translation.md` 判断。
- 原稿读取、预览方法和格式专属的检查点按已加载的格式技能执行。

## 任务范围

按用户要求确定任务范围：

- 用户未限定范围时，覆盖当前工程全文
- 用户指定问题时，围绕该问题及其必要关联开展调查
- 优先进行程序化批量探查，仅在用户明确要求或无法程序化批量探查时逐条进行语义分析

## 自启发循环

- 从任务目标、已有材料、调查结果和覆盖缺口中提炼可用于后续探查的特征模式或具体线索，称之为 `种子`
- 根据种子发现下一批需要调查的目标，再从调查与处理结果中提炼新的种子
- 重复前述过程，直到任务目标完成且所有种子均已消耗，称之为 `自启发循环`

## 种子账本

种子账本保存在 `work/TASKNAME-seeds.json`，通过 `workspace_run` 读写：

- 账本记录实时调查状态，必须每轮更新，禁止跨轮补写
- 轮次从 `1` 开始，新增或需要重新调查的种子设为 `consumed = false`
- 完成取证、结果处理和后续种子提炼后，将目标种子设为 `consumed = true`，尚需补查或受阻的种子保持 `consumed = false`
- 同轮处理多个种子、搜索或采样均计为一轮，`completedRounds` 在本轮完成时增加 `1`

账本示例：

```jsonc
{
  "completedRounds": 1,   // 已完成的轮次，包含入口轮次
  "seeds": {
    "1": [                // 发现种子的轮次
      {
        "pattern": "筛选相邻原页中表头重复的表格，对照译稿与渲染结果，核验续页数据行是否完整、归属是否正确。",
        "consumed": false
      }
    ]
  }
}
```

## 循环执行

### 循环入口

任务从以下循环入口开始处理：从至少 3 个不连续的内容区域中分散采样至少一个业务单元作为本轮数据集

### 循环轮次

每次按顺序完整执行以下步骤称之为一个 `循环轮次`，每个循环轮次必须以写入 `种子账本` 文件作为结束：

1. 轮次开始时，从循环入口开始或者读取 `种子账本` 中未消耗的 `种子`
2. 根据 `种子` 中的特征模式进行探查，形成审查结论，准备变更数据并 `apply` （如有）
3. 回看探查与处理过程，提炼新的 `种子`，更新 `completedRounds` 的数值和已消耗 `种子` 的状态
4. 写入 `种子账本` 文件

重复执行循环轮次，直到同时满足：

1. 任务目标全部完成
2. 本轮没有新的 `种子` 产生，账本中所有 `种子` 均已消耗
3. 包含入口轮次在内，至少进行过 3 个轮次的循环探查，即 `completedRounds >= 3`

轮次不足且没有未消耗种子时，从至少 3 个不连续的内容区域中分散采样至少一个业务单元作为本轮数据集

## 领域参考

循环入口与后续种子调查都按下文取证、判断和验收。相关模式可以合批调查。

### 种子探查

种子探查可以从以下方向展开，但是无需局限于此，错误、正确案例和不同处理方式都可以提供线索：

- **扩展同类**：从内容或版式案例中提取可检索的特征，调查其他相似页面。
  - 例如：发现跨页表格遗漏续页首行后，定位其他带重复表头的跨页表格，核验数据行是否完整。
- **核验差异**：发现同类内容或结构处理不同时，调查差异是否符合各自语境与版式条件。
  - 例如：同系列图注分别出现在图前与图后时，核验图文对应关系和阅读顺序。
- **追查关联**：确认新的术语条件、内容归属或跨页关系后，调查受该发现影响的其他页面与输出。
  - 例如：确认某页的续表已归入前页后，核验相关译稿是否遗漏或重复，并检查相邻内容的衔接。

### 取证与判断

|情况|取证方法|
|---|---|
|提取的文字不完整，或阅读顺序、内容归属不清|对照原页图像和必要的相邻页面，再核对译稿和对应的输出|
|跨页段落、表格或图注的关联不清|读取相关原页的完整语境，再核对已有的来源与去向记录|
|没有提取到文字|查看原页图像中的正文、标注与图例|

- **判断标准**：术语、指代和原文歧义按 `writing-guide` 的 `references/translation.md` 判断。依据见其中的「命题、身份与语境」和「术语与译名」。术语表的命中与缺失警告按 `SKILL.md` 的「术语表」核对。
- **证据不足**：无法确定修正时，将页面记为未决。

### 内容与视觉核对

程序化探查用于定位页面、识别结构和统计数量。内容与视觉结论来自实际阅读原稿、译稿和渲染结果。

|检查方向|判断重点|
|---|---|
|内容完整与归属|正文、标题、列表、图注和注释是否遗漏、重复、错列或归属错误|
|语义与数据对应|命题、指代、术语、数字、单位、表格、公式和引用是否准确对应|
|跨页连续性|段落、表格、注释和图文关系是否完整承接，来源与去向是否一致|
|页面处置|保留原页、省略页面和空译稿是否有充分依据。接管的内容是否完整出现在对应页面|
|视觉与阅读顺序|栏序、分页、遮挡、图文位置、公式，以及译文与保留原页的衔接是否影响阅读|
|变更清单变化|译稿、内容归属或未决结论的变化是否影响已有结论。页面数量相同时也要核对内容与关系|

### 成果验收

- **调查完整**：每个目标都有修正、保留或未决结论。
- **记录完整**：业务工作材料按页面身份保存发现、结论、证据和变更清单。内容检查结果写入 `reviewed`，未决与续做说明写入 `notes`。
- **载荷完整**：修改时准备相关页面的完整页面载荷。调整跨页归属时，同批准备全部受影响页面的载荷，并检查整组内容的覆盖。
- **视觉成立**：按格式技能预览发生排版变化的内容。修正后，重新查看受影响的输出。
- **提交与结果**：当前单元通过内容、跨页覆盖和必要的视觉检查后，按 `分组与提交` 提交。部分成功时，处理遗漏、重复和归属不一致。
- **关联复查**：最终载荷、跨页归属或新证据改变已有判断时，复查受影响的页面与输出。复查后提炼后续种子。

调查范围尚未覆盖、验收发现遗漏、不一致或待核验事实时，补充或更新种子，继续调查。

## 交付

提供种子账本和业务工作材料链接，并说明：

- 实际调查范围与覆盖程度，区分程序扫描、内容阅读和视觉检查
- 原稿页与输出页各自的检查范围
- 主要发现、修正或保留的依据，以及未决事项。没有发现问题时，说明检查依据
- `reviewed` 的记录情况
- 任务完成或受阻的情况，区分拟议方案与实际写入结果
- 格式技能要求的其他交付内容
