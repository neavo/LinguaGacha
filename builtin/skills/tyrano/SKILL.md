本技能只提供 TyranoScript 引擎知识，翻译、审校和提交流程按 `translation` 执行。

# 原稿与条目

每个游戏是一个工程资产，条目的 `file_path` 指向整个游戏，原稿成员位于 `sources/<file_path>/`。应用目录 `<app>` 为 `resources/app`，网页版或工程目录布局时为空：

|成员|内容|
|---|---|
|`<app>/data/**/*.ks`|场景脚本，包括 `scenario/`、`system/` 和 `others/plugin/` 下的系统场景、宏和插件场景|
|`<app>/data/**/*.js`|游戏自有脚本与插件|
|`<app>/data/system/Config.tjs`|引擎配置，只有 `System.title` 产生条目|

原件直接可读，没有投影。`<app>/tyrano/` 下的引擎、第三方库和素材不在原稿中，路径列在 `sources/<file_path>/game_files.reference.txt`。附加原稿的扫描范围是 `<app>/data/`。

场景按引擎的解析规则拆分，一个条目对应一个原始文本节点或参数值：

- 正文在 `[r]`、`[p]`、`[l]` 等标签处断开，一句话可能分成多个条目。译文保持各片段的语序和衔接，不增加换行。
- `#名字:表情` 行设置说话人，`*标签|标题` 是跳转目标，`;` 与 `/* */` 是注释，行首 `_` 保留前导空白。
- `[iscript]` 到 `[endscript]` 之间的内容按 JavaScript 执行，`[html]` 到 `[endhtml]` 之间的内容按 HTML 插入。

# 默认状态

导入按原文所在的标签、参数和代码位置区分用途：

|用途|来源|默认状态|
|---|---|---|
|`text`|普通正文，`glink`、`ptext`、`mtext`、`tb_ptext_show`、`dialog`、`ruby` 的 `text`，`title` 的 `name`，`text` 的 `val`，`System.title`|`NONE`|
|`name`|`#` 行的名字，`chara_new` 的 `jname`，`chara_ptext` 的 `name`|`RULE_SKIPPED`|
|`parameter`|`voconfig` 的 `name`（语音查找键，只含 ASCII 也产生条目），以及其他标签参数中含非 ASCII 字符的值，例如宏参数、角色 ID、文件名|`RULE_SKIPPED`|
|`code`|`[iscript]` 与 `.js` 中的字符串，`exp`、`cond`、`preexp` 参数，以 `&` 开头的表达式，`[html]` 中的内容|`RULE_SKIPPED`|

只含 ASCII 的其他参数与以 `%` 开头的宏参数引用不产生条目，可审校范围以实际产生的条目为准。`RULE_SKIPPED` 表示需要按用途判断，其中也可能有玩家可见文本，放行后照常写回。

# 依赖协调

同一原文既显示、又被比较或查找时，只译其中一处会改变游戏行为。比较值和查找键与显示位置使用同一译文，各自通过条目提交。证据不足时报告位置和原因，不回退已有译文。

## 姓名与语音

`chara_new` 的 `name` 是角色 ID，`jname` 是显示名。`#` 行和 `chara_ptext` 的名字等于某个 `jname` 时先换成对应 ID，再按 ID 取角色并显示其 `jname`，没有对应角色时直接显示该文字。`[voconfig name=…]` 按名字登记自动语音，`#` 行的名字须与登记的键一致。没有角色定义的名字也可能是语音键。

1. 角色 ID 保持原值。
2. 翻译 `jname` 时，用原 `jname` 搜索全部 `#` 行、`chara_ptext`、`[chara_config]` 和脚本中的比较，把按显示名引用的位置一起改成同一译名。
3. 改动 `#` 行前，确认它不是角色 ID 或 `f.`、`sf.` 变量比较值，并核对同名的 `voconfig` `name` 条目。两者是同一个查找键，修改时一起改成相同的值。直接显示的名字与 `jname` 使用相同译名。
4. 动态名字、重复定义和同名歧义保留原样并列为未决。

# 写回限制

写回优先保留普通脚本写法。正文、姓名和参数无法直接表示时，产品自动改写成 `&String.fromCharCode(…)` 或 `[text val="…"]`，重新导入时还原为文字。

以下译文无法写回，会使译文生成失败：

- `code` 参数条目只能用普通写法写回。新版引擎的译文不能含 `\`，也不能同时含 `"`、`'` 和反引号。
- 旧版引擎的 `code` 参数译文不能含空格、`#`、`[`、`]`，也不能同时含 `"` 和 `'`。
- 原文含换行的脚本字符串改写后变成一行，会改变场景的节点序号。这类条目保留原文。
- `System.title` 的译文不能含 `;`、`"`、`=`、`//`、换行或首尾空白。原文两侧的引号、分号与注释照常保留。

# 可见文本补漏

候选为含源语言文字的 `RULE_SKIPPED` 条目，按原文在原稿中的位置区分用途，`name` 条目按「依赖协调」处理。按候选位置找到读取它的代码：

|位置|读取方式|调查重点|
|---|---|---|
|宏调用参数|`[macro name=X]` 定义标签 `X`，宏体中的 `%参数` 在调用时代入|在全部 `.ks` 中找到宏定义，追踪 `%参数` 进入的标签|
|插件标签参数|插件 `.js` 通过 `tyrano.plugin.kag.tag.X` 定义标签|按插件代码判断参数用途|
|`[iscript]` 与 `.js` 中的字符串|显示文本常经 `tf.`、`f.`、`sf.` 变量，由 `[emb exp="…"]`、`ptext` 或 jQuery 写入页面|从显示位置反查赋值|
|`exp`、`cond`、`preexp` 参数与 `&` 表达式|整个值是 JavaScript|只改其中的显示字符串|
|`[html]` 内容|整段插入页面|只改标签之间的文字，标签与属性保持原样|

找到读取代码后，按读取结果判定：

|读取结果|判定|
|---|---|
|进入正文、`ptext`、`glink`、`[emb]`、对话框或页面元素|`显示`，由 Agent 翻译。译文须满足「写回限制」|
|用作 `storage`、`target`、`name`、变量名、选择器、类名、文件名、比较值或查找键|`保留`。与显示位置共用同一原文时，按「依赖协调」处理|
|找不到读取代码|`保留`，记录搜索范围|
|有读取代码，但用途无法确认，例如按动态键读取|`未决`|

# 翻译后检查

译文写入后，对本次写入的条目及其依赖位置执行以下检查，用脚本批量完成：

|检查|方法|处理|
|---|---|---|
|文本保护与行数|读取 `warnings` 数据集中本次条目的 `TEXT_PRESERVE` 和 `LINE_COUNT_MISMATCH`|恢复原文中受保护的片段，删除新增的换行|
|姓名依赖|对本次写入的 `name` 条目和补漏的 `显示` 条目，用原文搜索 `#` 行、`chara_ptext`、`voconfig` 和脚本中的比较|按「依赖协调」处理，证据不足时列为未决|
|查找键冲突|收集 `jname`、`#` 行名字、`voconfig` 的 `name` 和参与比较的条目译文，找出不同原文得到相同译文的情况|调整译文，使它们互相区分|
|写回限制|核对 `code` 条目、原文含换行的脚本字符串和 `System.title` 的译文|按「写回限制」改写。无法改写的条目恢复为 `dst: ""`、`status: "EXCLUDED"`|

# 覆盖缺口

交付时按下表检查，只向用户说明本游戏满足条件的项：

|条件|向用户说明|
|---|---|
|`source_issues.jsonl` 有本游戏的记录，或有语法错误、未产生条目的脚本块|涉及的成员和脚本块，其中的文字可能仍显示原文|
|脚本加载 `<app>/data/` 外或扩展名不是 `.ks`、`.js` 的文本文件|这些文件不在原稿中，其中的文字仍显示原文|
|脚本用 Canvas 或插件自行绘制文字|字体工具只替换标准文字控件的字体，这些文字可能缺字|
|补漏中发现远程加载或运行时拼出的文本|这些文本没有完整条目，游戏中可能仍显示原文|

每次交付都说明：

- 可见文本补漏和依赖协调依据静态代码调查，无法证明没有遗漏。建议用户在游戏中抽查，并用截图定位遗漏。
