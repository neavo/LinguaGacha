后端负责保存底稿与固化条目；格式调查、语义判断、定位解释和写回由 Agent 完成。本技能提供 `.generic` 通用包的容器契约与各阶段通用方法，若任务涉及特定格式或游戏引擎（或包内定位说明已指定），一并加载对应格式技能。

# 来源调查

导入时按 `project-operation` 的完成依据调查全部候选来源；补漏或修订已有通用包时，只调查受影响的材料。

- 结合对应格式或引擎技能、文件清单与消费代码，定位文本所在的文件与对象类型。
- 未命中的文件或对象类型，按类型给出抽样依据，说明为何不含待译文本。
- 结合消费代码、编码、结构和上下文区分显示文本、资源路径、程序标识与控制片段；无法可靠判断的内容记录依据与缺口。
- 同一个值同时用于查找和显示时，保留原值，在最终显示处映射译文。

# 导入准备

构造或归一化 `.generic` 时，先调用 `@lg/generic` 的 `describe_package()` 获取当前字段声明。

## 包契约

`.generic` 是 ZIP 容器，成员分工如下：

|成员|要求|
|---|---|
|`items.json`（根目录）|使用 `GenericItems` 数组，数组下标为稳定条目行号；`message` 为正文，`name` 为可选姓名，其余 JSON 字段为写回所需的私有定位|
|底稿与写回材料|包含底稿字节、写回程序、依赖声明与定位说明；源文件若占用固定入口名，放入子目录|

- **隔离边界**：私有定位仅保留在包内，不进入工程公开条目；包内不保存工程译文、翻译状态、数据库 `item_id` 或本次任务临时材料。
- **自包含恢复**：`work/` 仅属于当前工程，会随重置对话或工作区回收清理。包内须记录 npm / Python 依赖的名称与版本，并在定位说明中写明适用的格式或引擎技能，确保重置对话、清理工作区或换机后仅凭包内材料即可写回。
- **安全前提**：执行包内已有写回程序前，必须先读取检查源码。

## 解包与分包原则

- **旧包解包**：用 `@lg/generic.unpack()` 将现有包展开到新的 `work/` 目录（该入口只检查容器）。结合实际材料与消费代码理解旧字段，能可靠映射时重构为当前材料，无法可靠映射时保留未决，不补默认值也不要求后端兼容。
- **分包粒度**：独立文件分别成包，便于单独替换；共享索引、字符串表或跨文件偏移且须共同写回的材料放在同一包。
- **冻结底稿**：先冻结选定的底稿字节再提取，确保解析结果严格对应包内同一份底稿。

## 封包流程

按需使用 Node、`@lg/uv`、`@lg/npm` 和第三方库完成提取与封包：

1. 按「代表样本确认方法」验证解析、语义判断与写回方法。
2. 确认可翻译字段，保持每条记录的私有定位与数组顺序（私有定位可表达索引、字段、偏移或其他实际坐标，由 Agent 解释）。
3. 调用 `@lg/generic` 的 `read_generic_items()` 校验完整记录数组。
4. 调用 `@lg/generic.pack()` 将专用材料目录封装为 `.generic`。
5. 提交前校验容器结构、定位对应关系和提取语义，并按「全量清单确认覆盖」核对范围；空数组只表示本次无记录，不能作为调查完成或无需翻译的证据。
6. 产出的包交回 `project-operation` 识别、提交并完成导入收尾。

# 原稿与条目

- 通用包原稿展开在 `sources/<file_path>/`，条目 `row_number` 与 `items.json` 的数组下标一一对应，私有定位只保留在包内。
- 发现遗漏、误提取、定位变化或缺少写回材料时，重新生成完整通用包，按 `project-operation` 的「更新文件」提交。
- 不得把数据库 `item_id` 当作原文件坐标，也不得直接按旧行号搬运译文。

# 写回与验证

在 `project-operation` 的「导出与交付」中，消费本次 `generateFiles()` 返回的写回输入 `<writeback.input_path>/<file_path>/items.json`（与源包记录数和顺序一致，`message` 与 `name` 已替换为当前最终文本，私有定位来自源包）。默认只产出单语，仅当对应格式技能声明双语写回能力时产出双语。

1. 读取写回输入，脚本仅按私有定位写回包内底稿。
2. 在 `work/` 中完成写回，按实际格式处理长度、偏移、索引、编码、转义、校验和及字段间依赖。
3. 按下文三类验证核对成果；写回输入和未还原的底稿属于工作材料。

以下三类依据各自证明一件事，不能互相替代。需要运行验证时执行有界验证并记录尚未覆盖的路径；遇到依赖缺失、解析失败或生成失败时检查实际产物，修复后从可靠材料继续。

## 代表样本确认方法

每种格式或对象类型先用代表样本确认解析、语义判断与写回方法，样本须覆盖可变长度、列表、可选字段等影响布局的情况：

- **无损往返**：未改动时验证往返，无损区域逐字节一致，重新序列化区域核对结构与字段值。
- **真实译文往返**：用真实变化的译文写回并重新读取；原文不变的往返不能证明写回有效。
- **格式与边界检查**：文本样例核对编码、语法、引用和控制标记；二进制样例至少核对本次触及的长度与索引约束。
- **语义抽查**：结合消费代码或领域证据抽查漏提取与误识别；抽查用于确认方法，不替代全量清单。

## 全量清单确认覆盖

列出全部候选文件或对象，每项记录定位与依据并归入以下一类：

|类别|要求|
|---|---|
|已提取|记录进入的通用包与私有定位|
|有依据地排除|说明不含待译文本或不处理的原因|
|解析失败|记录失败原因，转入单独调查|

仍有解析失败或未归类的候选时，不能报告来源已全部处理，须按 `project-operation` 的完成依据说明剩余范围；已提取部分全部写回成功，不代表来源中的文本已全部处理完成。

## 机械比较确认写回

写回验证聚焦实际改动与可能受影响的区域，不盲目解析无关文件：

- **改写与波及区域**：重新读取实际写入的记录，逐条核对定位、目标字段与写入值；涉及长度、偏移或索引重算时，一并核对受影响区域的记录。
- **原样保留区域**：写回范围外且须原样保留的对象、区域或文件，直接比较字节或哈希，确认无意外变动。
- **独立恢复验证**：至少一次脱离既有 `work/` 产物，仅凭工程包内材料完成真实译文写回，确认重置对话、清理工作区或换机后仍可独立恢复。
