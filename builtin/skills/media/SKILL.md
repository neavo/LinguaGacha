本技能提供视频与音频的本地识别、画面文字识别与翻译、核对、字幕渲染和纯音频的双语成片方法。导入、更新与交付按 `project-operation` 执行，翻译、术语与审校按 `translation` 执行，画面文字的翻译时机以本技能为准。

目标是得到忠实于实际声音和画面的原文条目：台词不漏、不臆造，时间贴合说话，观众需要读懂的画面文字单独保留，并在识别时一并译出。对白来自本地 ASR，画面文字由本地检测定位、你看图识别，最终条目由你结合 ASR、硬字幕和画面文字判断产出。下文的步骤是建议，按素材实际情况取舍。

素材分两支：`media.inspect(来源)` 返回的 `video` 不为 `null` 时是视频，否则是纯音频，含封面图片的音频也是纯音频。不按扩展名判断。

|分支|识别|交付|
|---|---|---|
|视频|对白与画面文字|译文 ASS、双语 ASS|
|纯音频|只有对白，不执行任何画面步骤|译文 ASS、双语 ASS 和烧录双语字幕的 MP4|

# 包与材料

`.media` 是 ZIP 包，视频和纯音频共用。后端只按 `items.json` 的 `message` 和可选的 `name` 建立条目，其余成员和字段由本技能解释。时间均为整片秒数，零点与音频一致。包内不含原文件，生成字幕只需要包，生成成片还需要原文件。

|成员|内容|
|---|---|
|`media.json`|识别证据与原文件身份，见下表|
|`items.json`|字幕原文记录，数组下标就是条目的 `row_number`|
|`render.mjs`|可选，用户要求固定的定制渲染|

`media.json`：

|字段|内容|
|---|---|
|`source`|原文件身份：`path`、`size`、`mtime_ns`、`track`、`language`。复核和成片时据此找回原文件|
|`duration`|时长|
|`video`|原画面尺寸 `{ width, height }`，纯音频为 `null`|
|`speech`|人声区间 `[[start, end]]`|
|`asr`|本地识别的句子 `{ start, end, text, tokens }`。`tokens` 是文字 token 的 `[原文, 起点]`，不含标点|
|`text`|画面文字区间 `{ id, start, end, at, box }`，纯音频为 `null`|

- 无音轨时 `speech` 与 `asr` 为 `null`。
- `text` 来自 1 fps 检测，`start` 是首次检测到的秒数，`end` 是最后一次检测到的秒数加 1，起止各有约 1 秒误差。`at` 是文字框最大的一帧，`box` 是区间内文字框的并集，归一化为 `[x0, y0, x1, y1]`。

`items.json` 的每行：

|字段|要求|
|---|---|
|`start`、`end`|`0 ≤ start < end ≤ duration`|
|`kind`|`dialogue`（说出的话）或 `screen`（画面文字，只用于视频）|
|`message`|非空原文|
|`name`|可选，说话人|
|`box`|可选，只用于 `screen`，格式同 `text[].box`。生成字幕时译文贴着它摆放|

每个资产使用独立的工作目录 `work/media/<资产名>/`。视频的工作目录中除包成员外还有 `text/<id>.jpg`（区间代表帧的裁图）、`sheets/`（图集）和 `translations.json`（待写入工程的画面文字译文）。两支都可能有 `recognition/`（视频模型补查材料）和 `decoder.json`（本素材的解码方式选择）。这些不打包。

## 脚本

|脚本|入口|用途|
|---|---|---|
|`media.mjs`|`missing`、`setup`|按用途检查、准备依赖与模型|
||`inspect`、`ffmpeg`|读取媒体信息，截帧、提取字幕等 ffmpeg 操作|
||`prepare`|本地识别对白，视频同时检测画面文字，生成初始 `items.json`|
||`scan`、`sheets`、`refine`|仅视频：重新检测画面文字并生成裁图、拼图集、校准 `screen` 行的起止时间|
||`locate`、`relink`|找回原文件，或改用新路径|
||`pack`|校验记录并打包|
|`recognize.mjs`|`check`|记录与本地证据的对照|
||`request`、`read`、`apply`|视频模型补查，仅用户要求时使用|
|`render.mjs`|`render`|默认 ASS 渲染|
|`visualize.mjs`|`visualize`|仅纯音频：用双语 ASS 生成可视化 MP4|

识别、检测与成片的计算由应用 SDK `@lg/media` 执行，`media.mjs` 负责工作目录、来源身份与打包。脚本从本技能 `read_skill` 返回的 `base_url` 导入：

```js
const media = await import(new URL('scripts/media.mjs', base_url).href);
const recognize = await import(new URL('scripts/recognize.mjs', base_url).href);
```

# 环境准备

`media.missing(用途)` 只读检查，返回缺失的 npm 包、Python 包与模型。`media.setup(用途)` 安装依赖，通过预置的 `aria2c` 从多个镜像下载并校验模型，再测量本机适合用 CPU 还是 GPU。用途是数组，只准备当前步骤需要的部分：

|用途|用于|
|---|---|
|`ffmpeg`|`inspect`、`ffmpeg`、`relink`|
|`speech`|识别对白。识别模型有数百 MB，是最大的一项|
|`text`|视频的画面文字检测、`scan`、`sheets`、`refine`|
|`visualize`|纯音频成片，不含模型|

1. 先准备 `ffmpeg`，用 `inspect` 确定分支。
2. 识别前按分支准备：视频有音轨时 `['speech', 'text']`，视频无音轨时 `['text']`，纯音频只要 `['speech']`。`render` 不需要准备，成片只需要 `visualize`。
3. 用 `missing` 检查当前用途的资源缺口。有缺口时，告诉用户需要下载的大约 500M 的组件，提醒用户保持网络畅通。资源齐全时也调用 `setup`。它会复用有效配置。配置失效时重新校准。
4. 下载失败或中断后重新调用，沿用保留的临时文件续传。只有 GPU 组件下载失败时，它仍完成 CPU 准备，日志说明原因，再次调用会重试 GPU。

`missing` 返回空只表示可以计算，不代表已启用 GPU。运行中 GPU 出错时，本次计算自动改用 CPU 完整重跑，之后也不再使用出错的 GPU 配置。硬件解码出错时同样改用软件解码重跑。日志会说明实际采用的配置，不需要你处理。报错提示组件未就绪时，按错误中列出的用途重新调用 `setup`。

# 准备

- 有文本字幕流时，先用 `ask_user` 询问是否改为提取字幕。提取比识别准确，用 `media.ffmpeg(args)` 导出后按 `project-operation` 导入。
- 有多条音轨时请用户选择。`track` 是 `inspect` 返回的 `audio` 中从零开始的位置。
- 有音轨时支持中、英、日、韩原文，以及 `ALL` 自动识别。其他语言会使 `prepare` 报错，告诉用户本功能不支持该语言的对白。

调用 `media.prepare(来源, 工作目录, { track, language })`，`language` 取 `project_meta.json` 的 `source_language`。它运行本地 ASR，视频同时运行画面检测，不请求付费模型。一小时素材通常需要几分钟，没有 GPU 或 4K 素材更久，开始前告诉用户。中断后用相同参数续跑，已完成的部分不再重复。

`prepare` 在缺少 `items.json` 时，把每条 `asr` 转为 `dialogue` 记录。已有 `items.json` 原样保留，包括空数组。`asr` 为 `[]` 表示执行了识别但没有产出文字，如实告诉用户，不编造条目。

# 对白

两支共用。

1. 通读 `asr`，了解内容、人物和术语，留意近音误字、写成片假名的专名和断成两半的句子。
2. 修正对白。拆句、合句时按 `asr[].tokens` 取切点，起止尽量贴合人声区间。专名和误字逐行结合上下文改，不对全部对白做正则替换：替换会叠加或误伤包含同一串字的其他词。视频按「画面文字」把硬字幕作为第二份证据。
3. 调用 `recognize.check(工作目录)` 查看线索。线索都有解释，或没有新证据可用时结束。

`check` 返回：

|字段|含义|
|---|---|
|`invalid_rows`|结构或时间不合法的行号，打包前必须修正|
|`uncovered`|被 `dialogue` 覆盖不到一半的 ASR 句子，附识别文字|
|`unsupported`|时间范围内没有任何人声的 `dialogue` 行号|

`uncovered` 可能来自漏句、时间偏移或无需翻译的声音。`unsupported` 可能来自臆造、时间错位或人声检测漏掉的短句。没有告警不能证明字幕正确。

避坑：

- ASR 可能出现近音误字，也可能把专名、术语写成片假名或近音词。数字可能按读音规范化。多人嘈杂时可能整句丢失。人声检测漏掉的对白没有文字。5.1、7.1 素材只听中置声道。ASR 没有区分说话人。
- 只在 ASR、硬字幕和画面中已有的读法里选择，或纠正明显的同音误字。
- 不要为了消除 `check` 的告警把字幕拉长，这会掩盖真正漏掉的句子。多人同时说话时字幕可以重叠。
- `items.json` 的下标是 `row_number`，重新打包时改变顺序会影响译文继承。只调整时间或样式时保持原文与顺序。

只来自 ASR 的对白，只在用户要求时按 `translation` 翻译。用户只要求导入或识别时，对白停在导入完成。

# 画面文字

仅视频。纯音频跳过本节，也不提示「没有识别画面文字」。

1. 用 `media.sheets(工作目录)` 生成图集，它返回 `[{ file, ids }]`。按返回的 `file` 分批用 `ws.emitImage` 查看，每次 `workspace_run` 最多 10 张。按下文逐个区间判断，识别时同时形成译文。
2. `screen` 行写好后，用 `media.refine(工作目录, 行号数组)` 校准起止时间。它直接写回 `items.json`。`unresolved` 列出未能校准的行，这些行保留原时间。边界超出原时间前后 1 秒，或条目中点未检测到文字时，校准会失败。

需要判断的画面文字包括标题、字幕卡、招牌、名片、文稿、新闻横幅，以及动态漫画的气泡、旁白、内心独白、拟声词和拟态词。竖排、倾斜和装饰性字体同样判断，文字框很高或很窄都不是排除依据。

|观察到的内容|处理|
|---|---|
|可辨认且承载信息的画面文字|写成 `screen`，`box` 取自区间，时间先用区间的起止|
|对白硬字幕，或与同段实际说出的对白完全对应的气泡|作为对白的第二份证据，对照 ASR 修正 `dialogue`，不另写 `screen`。断行可以按它调整，时间仍以 ASR 为准|
|气泡含有未说出的部分，或属于独立叙述|保留独立的 `screen`，附近有声音不是去掉它的理由|
|画面与配音表达不完全一致|按实际信息分别判断，不只凭相似词或时间重叠去重|
|拟声、拟态文字|画面表达本身就是证据，没有相应声音也写成 `screen`。有声音但画面没有对应文字时不臆造|
|台标、水印、无意义的背景字、纯装饰图形、无文字的动作线、误检|忽略|

- 按语言、气泡和版面确定阅读顺序。检测编号只用于定位。
- 检测只给位置。人脸、衣服、动画人物和纹理可能被误检，确认没有字即可跳过。
- 一个区间不等于一句话。同一位置换字时，结合前后帧拆分内容与时间，不把两句并成一条拉长显示。同一句因漏检或镜头移动拆成多个区间时，结合图像与实际持续时间合并。文字相同的不同出现可能各有含义，例如同一帧两处「ドン」，不只凭字符串去重。
- 高瘦或很大的区域在图集里会缩得很小。单独 `emitImage` 对应的 `text/<id>.jpg`，仍不够时用 `media.ffmpeg()` 从 `media.locate(工作目录)` 返回的原文件按 `at` 截帧，需要上下文时再扩大取帧范围。仍看不清或读法不确定时放弃，记录位置和原因，不拼凑。
- 检测为 1 fps，短于一秒的文字可能漏掉。出现快闪、转场或叙事缺少文字线索时，截帧补查该片段，不逐帧遍历全片。
- 你不能看图时停止看图，告诉用户画面文字没有识别。对白与避让不受影响。
- 硬字幕不一定是逐字转写。日本综艺的テロップ常是强调或概括，按 `screen` 判断是否保留，不要替换对白。官方硬字幕也可能是精简版。
- 译文语言的硬字幕（例如日片配中文字幕）不是原文，不能写进 `message`。生成字幕时仍会避开它。
- 区间起止有约 1 秒误差，不能直接作为对白时间。只在硬字幕里出现的对白，先用区间时间，再对齐到最近的人声区间边界。

## 画面文字译文

识别画面文字的同时形成译文并写入工程，用户只要求导入或识别时也一样，无需另问。它不触发 `translation` 的流程询问，也不因此询问是否审校。

- 形成译文前加载 `writing-guide`，并按 `translation` 的「术语表」读取适用术语。
- 目标语言取 `project_meta.json` 的 `target_language`。
- 每条译文对应该行的完整原文。对照修正到 `dialogue` 的气泡，只有译文覆盖该行完整原文时才写入，不把局部画面文字的译文当成整句对白的译文。
- 拟声词、拟态词按语境翻译。只有需要稳定复用的特定表达才按 `glossary` 加入术语。

# 导入与更新

`media.pack(工作目录, 'work/media/<原文件主名>.media')` 校验 `items.json` 并打包，保留数组顺序。首次导入按 `project-operation` 新增，重新处理已导入的资产时按「更新文件」提交并继承译文。核对打包记录数和回执条目数。

视频有画面文字译文时，原文的拆分、合并和排序完成后，把译文按最终行号写入工作目录的 `translations.json`，每项为 `{ row, message, dst }`，`message` 是该行完整原文。导入后写入：

1. 从最新快照按回执中资产实际的 `file_path` 和 `row_number` 找到条目，核对 `src` 与 `message` 一致。
2. 用当前的 `item_id` 和 `fp`，按 `ws.contract.changes.items.updates.reference` 提交 `dst`。原文与译文相同的条目照常提交。
3. 核对回执与最新快照，已识别、已写入、未决和提交失败的条数都要有归属。原文与译文都入库后，才说画面文字已双语导入。

恢复：

- 回执 `parse_failed` 时资产已在工程中，按 `project-operation` 处理，不重复新增。
- 译文提交失败或 `fp` 失效时，保留资产和 `translations.json`，重读快照后只续做尚未写入的行。原文已变化的行重新判断对应关系，不按旧行号覆盖。
- `translations.json` 丢失时，从工程原稿和原文件重新取得证据，不覆盖工程中已有的译文。
- 「更新文件」继承到的译文保留，用户修订过的译文不批量覆盖。仍没有译文的画面文字按本节补齐，包括新增内容。

# 复核与重新处理

已导入的资产从 `sources/<file_path>/` 复制到新的工作目录。纯音频直接定位原文件并检查对白。视频的工作目录没有裁图，先准备 `text` 并调用 `media.scan(工作目录)` 重新生成。不同设备或版本可能选用不同的检测模型，新结果的区间编号和框可能与之前不同，只在本次结果内使用。

`scan`、`refine`、视频模型补查和音频成片都按 `media.json` 的 `source` 找回原文件。`media.locate(工作目录)` 在原文件不存在或大小、修改时间变化时报错。此时用 `ask_user` 请用户提供新路径，再调用 `media.relink(工作目录, 新路径)`。它核对时长、画面尺寸和所选音轨后更新 `source`。不要自行搜索同名文件替代。资产已导入时，重新打包并按「更新文件」提交，新路径才保存进工程。

# 视频模型补查

只在用户明确要求时使用，例如某段音乐或嘈杂场景 ASR 完全失效，用户要求改用视频模型识别。纯音频同样可用。它会花费额度，次数由用户决定。

1. `recognize.request(工作目录, { prompt, ranges })` 从原文件裁出 `ranges`（`[{ start, end }]` 整片时间，每段不超过 210 秒）并写出请求清单，返回 `request_file`。
2. 调用 `batch_llm_request({ model_usage: "agent_media", request_file })`。
3. `recognize.read(工作目录, result_file)` 把响应换算为整片时间写入候选文件 `candidate`，返回各区间的行数、`incomplete`（输出没有正常结束）、无法解析或不符合契约的行数，以及失败的区间。
4. 审阅候选后，`recognize.apply(工作目录, candidate, ranges)` 用完整且非空的候选替换区间内的 `dialogue`。区间内的 `screen` 保持不变。

基线提示词如下。输出格式是 `read` 的解析契约。语言名称取自 `project_meta.json`，模型看到的时间从区间起点算起。需要区分说话人时可以要求输出字符串字段 `name`。

```text
转写这段视频中实际说出的对白。语言：{原文语言}。
每行输出一个 JSON 对象，不输出代码块或说明：
{"start":秒,"end":秒,"kind":"dialogue","message":"原文"}
- start、end 为相对本段开头的秒数，保留两位小数，按 start 排序。
- 每句一行，尽量不超过 7 秒和 30 字，长句按自然停顿拆开。
- 忠实转写，不总结、不润色、不补写。听不清的部分写 [?]。否定、数字、人名按原样转写。
- 没有人声时不输出任何内容。
```

空输出和截断很常见，不能覆盖已有原文。请求载荷可达数十 MB，批量结束后可以删除请求目录中的 `.request.json`。

# 生成与交付

`generateFiles(bilingual_files)` 之后，用 `render({ source, input, translated, bilingual })` 写出与原文件同主名的 ASS：

- `source` 是 `sources/` 中的包目录。
- `input` 是 `<writeback.input_path>/<file_path>/items.json`。
- `translated` 与 `bilingual` 是译文与双语输出路径，先写到 `work/` 中核对。

包内有 `render.mjs` 时，读取并检查后改用它。字幕只来自写回输入，不从 `asr` 或旧的 `translations.json` 重建，尚未翻译的条目按写回输入的内容如实呈现。

视频默认渲染中，对白在底部居中。与同一时间检测到的文字区域重叠时，该条改用约 75% 不透明的底框，换行和双语的多行文字共用一个底框。双语时原文在前、译文在后。带 `box` 的 `screen` 译文优先放在原文框下方，并避开同时出现的其他文字。下方放不下时改放上方。两侧都没有空位时优先保证译文可见。没有 `box` 的 `screen` 在顶部居中。字号随画面高度缩放。

纯音频默认按 1920×1080 成片排版：深色字在底部居中，双语时译文在上、原文在下，原文字号较小。原文与译文相同时只显示一份。长句按画面宽度换行，两种语言作为一个整体上移，不会互相重叠。

用户要求其他样式时，把 `render.mjs` 复制到 `work/` 修改，保持导出签名不变。用户要求固定该样式时，把包目录复制到工作目录，放入 `render.mjs` 后重新打包。再按「更新文件」提交。

## 音频双语成片

纯音频资产在两份 ASS 核对完成后，默认再生成一份双语 MP4。它不改动工程和 ASS，失败时只需重跑这一步。

```js
const { visualize } = await import(new URL('scripts/visualize.mjs', base_url).href);
const result = await visualize({ source: 包目录, bilingual: 双语ASS, fonts: ws.fontsDirectory, output: 'work/media/<原文件主名>.mp4' });
```

- `source` 是含 `media.json` 的包目录或工作目录。它按 `source` 找回原文件和所选音轨，并准备 `visualize` 用途，不需要识别模型。首次生成前按「环境准备」检查该用途，有缺失时先告诉用户。
- 画面是带品牌的亮色固定背景、跟随当前声音起落的频谱竖条和烧录的双语字幕，1920×1080、16 fps。用户要求的定制字幕同样直接烧录。
- 音轨能直接封入 MP4 时原样复制，否则转为 AAC 128 kbps。返回的 `audio` 为 `copy` 或 `aac`，`duration` 是成片时长。
- 成片先在输出旁生成并检查，通过后才替换同名旧成片。失败或取消不会留下半成品，也不会删除旧成片。
- 耗时随素材时长增长，长音频开始前告诉用户。多个资产依次生成，不并行启动。
- 原文件找不到时按「复核与重新处理」请用户提供新路径，在工作目录副本中 `relink` 后以该目录为 `source` 重跑。仍无法取得原文件时，先交付两份 ASS，说明成片未完成。
- 没有对白的纯音乐仍可生成，字幕为空，交付时说明。

交付时单语目录放译文 ASS，双语目录放双语 ASS 与双语 MP4，各自保留资产的相对路径。

交付时告诉用户：视频字幕与原视频同名并放在同一目录，播放器即可自动加载。音频成片已烧录双语字幕，播放器自动加载同名 ASS 时会叠字，播放成片时关闭外挂字幕。

# 覆盖缺口

交付时按下表检查，只向用户说明本资产满足条件的项：

|条件|向用户说明|
|---|---|
|对白来自本地 ASR|没有区分说话人|
|有尚未翻译的条目|范围，以及它们在字幕中按写回内容呈现|
|有放弃或存疑的画面文字|位置和原因|
|有画面文字译文未写入|范围和原因，原文已导入|
|没能看图|画面文字没有识别|
|纯音频成片未生成|原因与已交付的 ASS，补齐后可只重跑成片|
|纯音频的音轨转为 AAC|原音轨无法直接封入 MP4|
|没有识别到对白|成片字幕为空|
|有未决项|位置、两种读法或缺失的内容|

交付时说明实际采用的识别来源和已执行的核对范围。建议用户播放抽查，并用时间点反馈问题。
