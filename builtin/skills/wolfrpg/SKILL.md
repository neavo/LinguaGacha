本技能只提供 WOLF RPG Editor 引擎知识，翻译、审校和提交流程按 `translation` 执行。

# 原稿与条目

每个游戏是一个工程资产，条目的 `file_path` 指向整个游戏。`sources/<file_path>/` 包含 `Data/BasicData/` 下的 `.dat`、`.project` 和各地图 `.mps`。解析器支持的成员旁有投影 `<成员路径>.reference.json`。解析失败时不生成投影，失败记录在 `source_issues.jsonl`。配套文件缺失时投影仍写出结构，但 `usage` 不代表实际用途，该成员同样记录在 `source_issues.jsonl`。投影包含：

- `data`：解析后的结构。公共事件和地图事件的指令为 `{ code, integers, strings }`，数据库为类型、字段、数据名与字符串值。
- `strings`：全部可编辑槽位，每项为 `{ text, location, usage, context }`。`usage` 为 `text` 或 `metadata`，`context` 说明来源。

`sources/<file_path>/game_files.reference.txt` 每行列出一个游戏目录中的文件路径，路径相对游戏根目录。导入时读取失败的文件仍列在清单中。指令和数据库中的素材路径通常省略开头的 `Data/`。较早导入的工程没有该文件。

附加原稿的扫描范围是游戏根目录。

`location` 是投影中的零基物理下标，`kind` 的含义如下：

|`kind`|来源|
|---|---|
|`database_string`|`.dat` 的字符串值，`context` 为「类型 / 数据名 / 字段」|
|`database_type`、`database_record`、`database_field`|`.project` 的类型名、数据名、字段名|
|`common_name`、`common_command`|`CommonEvent.dat` 的事件名、指令字符串，`command` 是 `data.events[event].commands` 的下标|
|`map_name`、`map_graphic`、`map_command`|地图事件名、页面行走图、指令字符串|
|`game_string`、`tileset_string`|`Game.dat`、`TileSetData.dat`|

# 默认状态

`usage` 为 `text` 的位置产生的条目默认 `NONE`，其余默认 `RULE_SKIPPED`：

|`NONE`|`RULE_SKIPPED`|
|---|---|
|文章 `101`、选项 `102`|事件名、`.project` 的全部名称|
|`150` 字符串图片的显示文字|`250` 数据库操作、`210` 公共事件调用、`212`/`213` 标签等其他指令的字符串参数|
|`122` 直接赋值的字符串|音效、图片等文件名参数，行走图，图块|
|`.dat` 中字段类型为字符串的值|`.dat` 中文件或其他类型字段的值，以及被公共事件拼入资源路径的字段值|
|`Game.dat` 的标题等文本槽|未在 `SysDatabase` 地图设定中登记的地图的全部条目，这些地图不会被游戏加载|

`103` 注释、`106` 调试指令和公共事件说明不产生条目。

# 引擎依赖

## 按名引用

WOLF 用字符串在运行时查找对象：

- `250` 的 `strings[1]`–`strings[3]` 非空时，按名称指定数据库的类型、数据和字段，为空时按 `integers` 中的编号指定。
- `210` 的字符串参数依次传入被调用事件的 `\cself[5]`–`\cself[9]`，被调用事件可能显示它们，也可能把它们用作查找键。`integers[0]` 常为 `500000 + 公共事件编号`。
- 变量编号 `1600000 + k` 表示所在公共事件的 `\cself[k]`。`250` 的 `integers` 末项是接收或写出的变量。

## 锚定组

原文相同的全部条目构成一个同原文组。组内任一条目来自 `DataBase`、`CDataBase` 或 `SysDatabase` 的 `.dat` 或 `.project` 时，称为锚定组：

- 按名引用都以指令字符串的形式产生条目。锚定组整组使用同一译文时，查找关系保持成立，因此整组可以安全翻译。
- 批量翻译只写入组内的 `NONE` 成员，同组的 `.project` 名称、`250`、`210` 等 `RULE_SKIPPED` 成员仍为原文，查找会断开。
- 资源路径组不适用本规则。

## 资源路径

以下条目是文件路径或路径组件，永不翻译：

- 原文含资源扩展名，例如 `.png`、`.ogg`、`.wav`、`.mp3`、`.txt`、`.dat`、`.mps`。`101` 文章和 `102` 选项除外。
- 拼接路径的代入值：指令字符串可以把变量与固定片段拼成路径，例如 `\cself[06]\cself[11]_\cself[12].ogg`。代入值不含扩展名，也是路径组件。
  - 同一公共事件中由 `250` 从数据库读入 `\cself[k]` 的字段，导入时已默认 `RULE_SKIPPED`。
  - 其余来源需要追踪：`\cself[5]`–`\cself[9]` 来自调用方 `210` 的对应参数，`\s[k]` 是全局字符串变量，需要在全工程中追踪赋值，`\cdb[...]` 直接指定数据库字段。
  - 用 `game_files.reference.txt` 核实拼接结果是否为现有文件。清单不存在或拼不出完整路径时，结合代入值与模板判断拼接结果是否为路径，例如值含目录分隔符，或与固定片段相接后形如素材文件名。确认后，对应参数和字段值都按资源路径处理。

# 可见文本补漏

候选为含源语言文字的 `RULE_SKIPPED` 条目，排除资源路径和未登记地图，按来源判定：

|来源|判定方法|
|---|---|
|锚定组中尚未翻译的成员|整组安全，但多为字段名、管理用数据名等内部标签。找到显示位置时判为 `显示`|
|`210` 字符串参数|读取被调用事件中对应 `\cself[5]`–`\cself[9]` 的用途。进入 `101` 或 `150` 显示文字时判为 `显示`。用作按名查找、比较或路径时，按锚定组或资源路径处理|
|其他指令参数|追踪读取该值的指令，用途无法确认时判为 `未决`|

`显示` 条目所在同原文组的其余成员由「翻译后检查」补齐。

# 翻译后检查

译文写入后，用脚本对最新快照按表中顺序检查，修正后重新提交，直到每项结果为零：

|检查|方法|处理|
|---|---|---|
|资源路径|有译文的条目中，属于「资源路径」的条目|恢复原文：`dst: ""`，`status: "EXCLUDED"`|
|同原文冲突|同原文组内存在多个不同的非空译文|统一为同一译文。本次写入是用户要求的重译或审校中有依据的修正时，整组采用新译文。其余情况保留本次写入前已有的译文，旧译文不存在或不止一个时，按语境选定并在交付中说明|
|锚定组补齐|有译文的锚定组中译文为空的成员|写入组内的同一译文|
|非锚定混合组|同原文组内已有译文，同时有译文为空的 `RULE_SKIPPED` 成员|按「按名引用」核对空成员的用途，需要同步的写入同一译文，证据不足时列为未决|
|控制符|本次写入条目的 `TEXT_PRESERVE` 和 `LINE_COUNT_MISMATCH` 警告|恢复原文中的控制符和换行|

# 覆盖缺口

交付时按下表检查，只向用户说明本游戏满足条件的项：

|条件|向用户说明|
|---|---|
|`source_issues.jsonl` 有本游戏的记录|涉及的成员，其中的文字可能仍显示原文|
|本次翻译了数据库名称|旧存档中按名称保存的数据可能对不上|
|`game_files.reference.txt` 列出原稿以外的文本文件|其中的文字仍显示原文|

每次交付都说明：

- 可见文本补漏、拼接路径和按名引用依据静态追踪，无法证明没有遗漏或错配。建议用户在游戏中抽查，并用截图定位问题。
