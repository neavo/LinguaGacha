# 技能安装指南

## 准备来源

- 用户提供文本时，将其整理为根目录带 `SKILL.md` 的包。
- 用户上传技能文件或压缩包时，从 `uploads/` 读取，在 `work/` 中准备。
- GitHub 来源明确仓库、版本和包路径。用户给出目录地址时保留指定版本。分支含斜线或地址不能唯一解析时，核实仓库引用和实际路径。未指定版本时读取仓库默认分支。
- 用工作区的 `fetch` 读取公开 GitHub API 或下载归档，用预装的 `jszip` 读取 ZIP。仅提取选中的技能包及其内部资源，保留文件层级和原始字节。需要鉴权但当前环境没有可用方式时，说明缺少的访问条件，并请用户提供可读来源或上传包。
- 解包前检查条目的原始路径与目标位置，使用 `jszip` 时检查 `unsafeOriginalName`，拒绝绝对路径、父级跳转和链接条目。全部文件应落在选定暂存目录内。

仅生成草稿或交付可分享的包时，保存在 `work/` 并说明位置。

## 检查适用性与冲突

核对根目录 `SKILL.md` 的元数据与引用资源，再核对技能实际需要的工具、依赖和执行方式。需要适配时，依据用户要求读取 [技能编写指南](authoring.md)，调整为当前应用支持的形式。

查看当前技能目录及 `ws.userSkillDirectory` 中的实际包，按 `SKILL.md` 的 `name` 检查逻辑冲突，同时检查目标路径。关闭或被覆盖的用户包也参与冲突检查。

已有同名用户包时，按用户意图更新该包或选择新名称。与内置技能同名会让用户包优先生效，只有用户要求覆盖该能力时采用此名称。修改已有包前读取其当前内容。

## 写入用户目录

新包在 `work/` 准备完整后，使用 `fs.mkdtemp(path.join(ws.userSkillDirectory, ".install-"))` 创建隐藏暂存目录，将包内容复制进去，检查根 `SKILL.md` 和引用资源，然后在用户技能根内重命名为正式目录。使用当前任务创建的确切路径清理失败暂存内容。

用户要求整包替换时，先在同一技能根准备新包，将旧包保留在隐藏备份目录以便替换失败后恢复，成功后清理本次备份。发生中断后先读取磁盘现状，再决定恢复或继续安装。

## 验证结果

安装程序返回后，用 `read_skill` 核对实际生效的正文、包位置和必要资源，避免把同名内置回退包误认为安装成功。读取失败时检查元数据、目录层级、忽略规则和启用状态。扫描到达技能包后停止深入，隐藏目录、`node_modules` 和忽略规则排除的目录不会成为技能。

文件更新沿用既有启停与排序偏好。包已安装但关闭时，说明需要在技能管理页启用。脚本的运行验证按编写指南执行。
