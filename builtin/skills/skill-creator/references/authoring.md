# 技能编写指南

## 内容与触发

围绕用户实际要重复完成的任务组织技能。明确输入、预期结果和必要的领域判断，只补充会改变执行决策的信息。用户提供的案例用于理解需求，个别案例中的偏好只有在用户要求时才上升为通用规则。

`description` 同时描述能力和适用请求，保持简短、容易区分。正文维护工作方法和完成依据，较长的条件性流程放入参考文件并说明读取时机。共享内容只有一个归宿。

## 包结构

技能包根目录的 `SKILL.md` 以两行 `---` 包围 YAML 元数据，其后为 Markdown 正文。

- `name` 最长 64 个字符，使用小写字母、数字和分隔单词的单个连字符，首尾为字母或数字。
- `description` 非空，最长 1024 个字符。使用 YAML 字符串，正确引用冒号等特殊字符。
- 新包目录以名称命名，已有包继续沿用实际位置，名称与目录可以不同。
- `references/` 保存按需读取的流程和领域知识，`assets/` 保存输出所需模板或素材。
- `scripts/` 用于可复用或需要确定性执行的算法，采用当前 Node 环境和预装依赖。普通文件操作可以在工作区程序中直接完成。

## 资源与程序

从 `read_skill` 的 `base_url` 定位原包资源和脚本，使用 `new URL("scripts/example.mjs", base_url)` 导入。相对资源基于 `import.meta.url` 定位，当前工作目录属于工作区。

编写程序时按当前工具声明核对包名和 `ws` 接口，工程数据结构通过 `ws.contract` 指向的参考读取，技能中的流程与术语使用实际接口名称。

## 检查与迭代

用有代表性的请求检查：是否会选中这个技能，是否能找到需要的参考，是否能用当前工具完成任务，结果是否符合用户目标。运行新建或修改的脚本，以小样本验证有意义的行为。

修改已有技能先读取当前磁盘内容并检查引用关系，保留仍被使用的资源、无关内容与元数据。重要文件先写同目录临时文件再替换。需要替换整个包时读取 [技能安装指南](installation.md)。根据实际失败修正具体流程，保持指令规模与任务相称。
