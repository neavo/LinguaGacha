本技能只提供 Escude 引擎知识。导入、通用数据封装与写回按 `project-operation` 和 `generic-data` 执行，翻译与审校按 `translation` 执行。

内置解析器不识别 Escude 游戏，文本都经通用数据进入工程。

# 识别

资源封包文件头为 `ESC-ARC2` 等标记。不同版本结构不同，以目标构建的读取代码和实际文件为准。

# 封包索引

引擎通常对封包目录做二分查找，比较方式是区域相关的 ANSI 字符串比较：

- 重新封包时，目录条目的排序必须与运行时比较规则一致，包括大小写和代码页下的无符号字节序。排序不一致时，包内存在的文件也会查找失败。
- 封包后对全部条目模拟一次二分查找，确认都能命中，且没有因代码页转换产生的同名冲突。

# 编码与字库

- 用 Shift-JIS 字节索引自绘字库的游戏，不能只把脚本改成 GBK 或 UTF-8。脚本编码、字库格位、绘字和宽度测量必须使用同一套映射。
- 检查新字形的边界与字距，避免越出格位污染相邻字符。
- 姓名、选项和定长数据库字段有字节上限。
- 窗口标题、系统弹窗和原生控件可能直接调用系统接口绘字，不经过自绘字库，单独核对它们的编码转换。

# 覆盖缺口

交付时只向用户说明本游戏满足条件的项：

|条件|向用户说明|
|---|---|
|修改了字库或编码映射|需要在游戏中确认中文显示正常|
|原生窗口未处理|窗口标题、系统弹窗可能仍为原文或乱码|
