# 可见文本来源与补漏

## 来源地图

|来源|引擎事实|调查重点|
|---|---|---|
|事件指令|地图事件页、`CommonEvents.json`、`Troops.json` 战斗事件页都有指令列表，移动路线中也有脚本|完整遍历全部事件来源|
|`355`/`655` 脚本、`111` 脚本条件、移动路线脚本|字符串字面量拆成条目，模板字符串拆成固定片段|片段顺序不能变，按拼接后的完整句子审阅|
|`122` 变量操作的脚本操作数|表达式中的字符串存入变量|追踪变量的赋值、复制、替换和读取，直到显示位置|
|MV `356` 插件指令|整串文字，插件通常按空格拆分参数|译文不能增减空格|
|MZ `357` 插件指令|运行时读取参数对象，后面的 `657` 只是编辑器显示的「键 = 值」|翻译 `357` 参数对应的条目，`657` 条目保持跳过|
|`108`/`408` 注释、数据库 `note`|插件按首行标记或标签读取|按 `SKILL.md` 判断混合条目|
|插件参数|只有 `js/plugins.js` 中 `status` 为 `true` 的插件会加载，嵌套 JSON 按叶子拆成条目|只调查已启用的插件|
|插件与脚本源码|作者常把菜单和提示集中写在常量对象中|从显示调用反查常量|
|自定义数据表|插件可以通过 `DataManager._databaseFiles` 等方式，把 `data/` 中任意名称的文件加载到 `$data…` 全局对象|从加载代码和 `$data…` 的引用找到数据表，再判断字段用途|

RGSS 的事件指令编号与上表相同。`122` 的脚本操作数只存在于 VX Ace，数据库 `note` 只存在于 VX 和 VX Ace，插件指令和插件参数不适用。

可见文本也可以经间接路径显示，以下路径的输入字符串都属于正文：

- 先存入变量、数组或对象，之后由 `\V[n]`、界面或履历显示。
- 由插件用 `replace` 代入模板，例如 `{city}`、`[word]` 的替换值。
- 由文字图片插件绘制成图片，例如 `DTextPicture`。

发现路径的一端时，追踪到另一端。`System.json` 中的变量名只能辅助定位，字符串也可能是资源名、状态值或比较键，最终按读取代码判断。

## 补漏流程

1. 收集候选：用脚本列出含源语言文字的 `RULE_SKIPPED` 条目，并按来源地图归类。源语言为日文时，假名和汉字都参与匹配。这批候选就是验收范围。
2. 判定候选：按 `SKILL.md` 的「默认跳过位置的可见文本」把每个候选判为以下一种，并记录依据。读取代码相同的候选可以一起判定。
   - `显示`：读取代码会把它显示给玩家。
   - `保留`：确认不显示或必须原样，包括找不到读取代码的位置。
   - `未决`：有读取代码，但用途无法确认，例如按动态键读取。
3. 翻译 `显示` 条目：只含显示文字的条目用 `batch_item_translation` 的 `item_ids` 翻译，其余按 `translation` 的「Agent 翻译」处理。
4. 核对覆盖：每个候选都有判定后，补漏才算完成。`保留` 和 `未决` 条目不修改。

交付时按来源类别列出候选、显示、保留和未决的数量，以及没有调查到的范围。
