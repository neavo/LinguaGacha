本技能只提供 RPG Maker 引擎知识，翻译、审校和提交流程按 `translation` 执行。

# 原稿与条目

每个游戏是一个工程资产，条目的 `file_path` 指向整个游戏，原稿成员位于 `sources/<file_path>/`：

|引擎|数据与事件|插件与脚本|
|---|---|---|
|MV、MZ|`data/*.json`，MV 可能带 `www/` 前缀。事件指令为 `list[]` 中的 `code` 与 `parameters`|`js/plugins.js` 保存插件参数，`js/plugins/*.js` 为插件源码|
|XP、VX、VX Ace|`Data/` 下每个数据文件对应一份只读 JSON 明文 `<原文件名>.json`。对象写作 `$class` 与 `$fields`，字段名带 `@`，`$ref` 指向首次出现的位置|`Data/<脚本档案>/NNNN.rb`，脚本名称见同目录 `scripts.json`|

条目不带原稿坐标，按以下方法定位来源：

- 用 `src` 搜索 `sources/<file_path>/`。
- 原文含反斜杠、换行或引号时，原稿中可能是转义形式，改用其中一段纯文字搜索。
- `row_number` 按成员和出现顺序递增，相邻条目通常属于同一文件或同一事件。

条目的默认状态由来源位置决定：

|默认 `NONE`|默认 `RULE_SKIPPED`|
|---|---|
|数据库标准显示字段：角色名称、昵称、简介，职业、技能、物品、武器、防具、敌人、状态的名称、说明与战斗消息|数据库 `note` 与插件扩展字段|
|`System` 的游戏标题、货币单位、用语与分类名称，地图显示名|事件注释 `108`、`408`|
|显示文字 `101`、`401`（含 MZ 姓名框），滚动文字 `105`、`405`|插件参数与插件指令参数|
|显示选项 `102`，对应的 `402` 分支标签由工程同步写回|脚本 `355`、`655`，条件分支、变量操作和移动路线中的脚本，插件与 RGSS 脚本源码中的字符串|
|改名 `320`、改昵称 `324`、改简介 `325`|其他指令参数，例如条件分支 `111` 中比较的角色名|

`RULE_SKIPPED` 只是默认值，其中可能包含两类需要处理的文本：

- 玩家可见文本，见「插件参数、`note` 与注释」。
- 必须与已译文本同步的比较值，见「跨位置依赖」。

# 跨位置依赖

同一原文既用于显示、又被程序比较或查找时，只译其中一处会改变游戏行为。这些位置组成一组，按以下规则处理：

- 所有位置都有对应条目可写时，统一写入同一译文。
- 任一位置没有对应条目可写，或依赖尚未查清时，整组保留原文并列为未决。

常见的依赖关系：

|显示位置|依赖位置|
|---|---|
|角色名称、`320` 改名|条件分支 `111` 的角色名比较，脚本中对 `name` 的比较|
|显示选项 `102`|插件或脚本按选项文字判断分支|
|物品、技能、状态等数据库名称|插件参数、`note` 或脚本按名称查找数据库对象|
|事件写入变量的字符串|后续条件分支或脚本对该变量的比较|

查找步骤：

1. 用原文搜索 `sources/<file_path>/` 中的全部出现位置，包括插件和脚本源码。
2. 判断每个位置的用途：显示、比较、查找键还是资源名。
3. 需要同步的位置作为一组，通过各自的条目一起提交。

作为查找键或比较值的不同原文不能译成同一个值，否则会命中错误对象，或让原本互斥的条件同时成立。

# 插件参数、`note` 与注释

这些位置默认跳过，但插件常用它们存放帮助文字、任务描述、菜单命令、姓名框和提示。按以下步骤逐个插件判断：

1. 在插件源码或 RGSS 脚本中找到读取该参数或标签的代码。
2. 按读取结果的用途处理：
   - 绘制到窗口或消息中时，翻译可见部分，标签名、参数键和分隔符保持原样。
   - 用作文件名、开关键、对象名称或比较值时，按资源或跨位置依赖处理。
   - 找不到读取代码时，保留原文并列为未决。

一个插件的标签语法结论，只在确认另一处由相同代码读取后才能复用。

# 控制符与消息窗口

只使用原文已有的控制符。各控制符的含义与处理方式如下：

- `\N[n]`、`\P[n]` 在运行时代入角色名、队员名：保持引用，玩家可改名的角色只能使用引用。
- `\V[n]`、`\G` 显示变量值、货币单位：调整语序时与所修饰的词一起移动。
- `\C[n]`、`\I[n]`、`\{`、`\}`、`\FS[n]` 控制颜色、图标、字号：作用范围覆盖译文中的同一段意思。
- `\.`、`\|`、`\!`、`\>`、`\<`、`\^` 控制等待、等待输入、即时显示和不等待关闭：放在译文对应的停顿处，数量不变。
- 插件新增的控制符：含义按插件代码判断。

消息窗口的显示限制：

- 引擎不自动换行，`401` 的每一行就是窗口中的一行。
- 消息窗口默认每页 4 行，显示脸图时可用宽度更短，译文过长时先调整措辞。
- 数据库名称、选项和菜单用语显示在固定宽度窗口中，过长会被压缩或截断。

# 审校检查点

- 角色名、选项和数据库名称的译文与其依赖位置一致。
- `RULE_SKIPPED` 条目中由插件绘制的可见文本没有漏译。
- 选项译文的肯否、对象和代价与 `402` 分支之后的实际事件一致。
- `\N[n]` 没有被固定译名替换。
- 固定姓名没有被写成其他角色的引用。

# 覆盖缺口

交付时说明以下未覆盖范围：

- `*.error.json` 记录的解析失败成员，以及有语法错误、未产生条目的脚本。
- 数据、插件和脚本以外的文件，以及图片中的文字。
- 需要同步但没有条目可写的依赖位置。
