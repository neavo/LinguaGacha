# 文本参与的运行逻辑

参与运行逻辑的文本在翻译后仍须指向原有对象，并触发原有分支：

- 查明文本的定义、赋值、读取和比较位置，用相同原文定位候选，再核对变量传递、字符串拼接和名称映射形成的依赖。
- 核对 `actor` 姓名、改名事件与姓名判断条件，翻译后的姓名须与对应条件中的比较值一致。
- 核对选项文字与插件中的字符串判断，翻译后的选项值须仍能匹配对应分支。
- 保持不同逻辑值的区别，检查不同原文是否被译成同一个值，导致对象查找出现歧义或原本互斥的条件同时成立。
- 对按 ID 或索引关联的对象，保持原有关联，根据读取该文本的代码，判断显示文字是否还参与其他逻辑。
- 将需要协调修改的位置作为一组核验，存在不可写位置或尚未查明的依赖时，保留维持对应关系所需的原文，并说明未决位置与缺失证据。

# 可译正文与程序协议

翻译可见正文时，保持程序协议有效，插件参数、`note`、事件注释、脚本字符串和嵌套 JSON 中可能同时包含这两类内容：

- 根据读取该文本的代码，确定可见正文、资源引用、查找键、指令名、比较值和协议参数各自的用途与可修改范围。
- 保持标签结构有效，并完整翻译其中的可见正文，重点检查被整段保护的帮助文字、姓名框和任务描述。
- 按使用位置判断字符串用途，将已确认的插件语法用于其他位置前，核对两处代码是否按相同方式读取文本。

# 动态代入与显示交互

翻译后，动态代入仍须指向原有对象，显示效果与交互时机仍须符合原意：

- 保持变量、角色引用和格式占位符的标识、数量及所属文本，动态角色名继续使用对应引用。
- 根据处理文本的代码，判断格式参数是否允许重排，以及控制符是否要求固定顺序。
- 核对颜色、字号、等待和即时显示等效果的作用范围，同时检查对应控制符的数量与位置。
- 核对反斜杠、参数和定界符的解析结果，区分转义后的可见字符与实际控制结构。
- 调整换行或分页时，结合目标消息窗口、插件和导出行为，核对消息边界与交互时机。

# 显示内容与实际行为

选项、任务提示和说明应准确表达实际事件行为：

- 核对人物、对象、数量、条件、肯否及结果，重点检查选项指向的角色、接受或拒绝的事项，以及支付、获得和消耗的对象。
- 核对连续消息、滚动文本和动态拼接的表达是否完整衔接，按实际执行关系判断不同事件页、条件分支和剧情阶段的语境。

# 名称与身份一致性

同一角色、物品、技能、装备、状态、职业或地点，在相同身份与语境下使用一致译名：

- 根据角色记录与改名事实确定姓名译法：核对姓名字段、对白正文、选项、介绍与插件显示文本，重点检查选项中的姓名是否指向正确角色。
- 保持昵称、别名和伪装身份与角色的对应关系，并核对其适用的剧情阶段。
- 玩家自定义姓名保持动态引用。
- 数据库名称与正文中的引用保持对应，简称应明确指向原有对象，参与程序判断的名称同时满足运行逻辑约束。

# 工程中的判断边界

- 通过 `sources` 调查原稿，通过现有 `items` 提交工程修正
- 对 `RULE_SKIPPED` 条目，根据实际显示或逻辑用途判断实际是否存在漏翻
- 将未形成条目的来源、解析失败及不可写的依赖列为覆盖缺口，审校结论应明确已检查范围与未决范围
