本技能只提供 RPG Maker 引擎知识，翻译、审校和提交流程按 `translation` 执行。

# 原稿与条目

每个游戏是一个工程资产，条目的 `file_path` 指向整个游戏，原稿成员位于 `sources/<file_path>/`：

|引擎|数据与事件|插件与脚本|
|---|---|---|
|MV、MZ|`data/*.json`，MV 可能带 `www/` 前缀。事件指令为 `list[]` 中的 `code` 与 `parameters`|`js/plugins.js` 保存插件参数，`js/plugins/*.js` 为插件源码|
|XP、VX、VX Ace|`Data/` 下每个数据文件对应一份 JSON 明文 `<原文件名>.json`。对象写作 `$class` 与 `$fields`，字段名带 `@`，`$ref` 指向首次出现的位置|`Data/<脚本档案>/NNNN.rb`，脚本名称见同目录 `scripts.json`|

`sources/<file_path>/game_files.txt` 每行列出一个游戏目录中的文件路径。路径相对游戏根目录，包含图片、音频等素材。较早导入的工程没有该文件。

插件参数、`note` 和脚本字符串中的嵌套 JSON 按叶子拆成多个条目。默认翻译字段即使形似 JSON，也整段保存为一个条目。

# 默认状态

条目的默认状态由来源位置决定，数据库字段与事件文本分别判断：

- 文件身份决定数据库字段规则：只有数据目录下的直接成员套用标准数据库字段白名单，子目录中的同名文件只按事件结构识别事件文本。
- 事件结构决定事件文本规则：任何数据文件中的事件指令都按指令代码判断。

|默认 `NONE`|默认 `RULE_SKIPPED`|
|---|---|
|标准数据库的默认翻译字段：角色名称、昵称、简介，职业、技能、物品、武器、防具、敌人、状态的名称、说明与战斗消息|数据库 `note` 与插件扩展字段|
|`System` 的货币单位、用语与分类名称，地图显示名，MV、MZ 的游戏标题|XP、VX、VX Ace 的游戏标题|
|显示文字 `101`、`401`（含 MZ 姓名框），滚动文字 `105`、`405`|事件注释 `108`、`408`，插件参数与插件指令参数|
|显示选项 `102`，对应的 `402` 分支标签由工程同步写回|脚本 `355`、`655`，条件分支、变量操作和移动路线中的脚本，插件与 RGSS 脚本源码中的字符串|
|改名 `320`、改昵称 `324`、改简介 `325`|其他指令参数，例如条件分支 `111` 中比较的角色名|

`NONE` 条目也可能被程序比较或查找，`RULE_SKIPPED` 条目中也可能有玩家可见文本。放行后的条目不会再因 `EV001`、`0=` 这类外观被过滤，但仍受源语言设置约束，混合语言或不含源语言文字的条目可能是 `LANGUAGE_SKIPPED`。

# 依赖协调

同一原文既用于显示、又被程序比较或查找时，只译其中一处会改变游戏行为：

1. 用原文搜索 `sources/<file_path>/` 中的全部出现位置，包括插件和脚本源码。
2. 按实际读取该值的代码，判断每个位置是显示、比较、查找键还是资源名。
3. 比较值和查找键使用与显示位置一致的译名，通过各自的条目提交。证据不足时报告位置和原因，不回退已有译文。

原文相同不能单独证明存在依赖，只有语境和程序约束一致时才一起协调。不同原文作为查找键或比较值时，不能译成同一个值。

常见依赖位置：

|主题|依赖位置|
|---|---|
|角色名|数据库初始名、`320` 改名、`111` 条件分支的名称比较、脚本中的 `setName` 或 `name =` 赋值，以及 `303` 名称输入。允许玩家改名的角色在对白中只能使用 `\N[n]`|
|名称关系|同一角色可以在不同阶段使用多个名字，每个名字分别对应自己的依赖位置|
|分类名|`equipTypes`、`skillTypes`、`weaponTypes`、`armorTypes`、`elements` 等可能被插件、`note` 或脚本按名称引用，例如 `<属性威力:陰>` 引用属性名|
|XP 标签惯例|XP 脚本常把属性名、状态名当作标签判断。只有读到按名称比较或查找的代码，才算依赖|
|脚本文本|RGSS 优先调查 `Vocab` 模块、`$game_message.add`、`draw_text`。MV、MZ 优先调查 `TextManager`、`$gameMessage.add`、`drawText`、`drawTextEx`、`addCommand`、`setText`。模块名或字符串形状不能单独证明用途|
|游戏标题|MV 在非本地模式下，内置存档识别会比较存档中的标题与当前标题，即使没有插件也存在这一依赖。RGSS 标题可能被脚本用作窗口标识或传给系统接口。MV、MZ 核心 JS 不在原稿中，搜索不到不能证明没有依赖|

# 默认跳过位置的可见文本

插件参数、`note`、注释和脚本默认跳过，但插件和脚本常用它们存放菜单、提示、帮助和资料。可见文本的来源如下：

|来源|引擎事实|调查重点|
|---|---|---|
|事件指令|地图事件页、`CommonEvents.json`、`Troops.json` 战斗事件页都有指令列表，移动路线中也有脚本|完整遍历全部事件来源|
|`355`/`655` 脚本、`111` 脚本条件、移动路线脚本|字符串字面量拆成条目，模板字符串拆成固定片段|片段顺序不能变|
|`122` 变量操作的脚本操作数|表达式中的字符串存入变量|追踪变量的赋值、复制、替换和读取，直到显示位置|
|MV `356` 插件指令|整串文字，插件通常按空格拆分参数|译文不能增减空格|
|MZ `357` 插件指令|运行时读取参数对象，后面的 `657` 只是编辑器显示的「键 = 值」|翻译 `357` 参数对应的条目，`657` 条目保持跳过|
|`108`/`408` 注释、数据库 `note`|插件按首行标记或标签读取|按下文的混合条目规则处理|
|插件参数|只有 `js/plugins.js` 中 `status` 为 `true` 的插件会加载|只调查已启用的插件|
|插件与脚本源码|作者常把菜单和提示集中写在常量对象中|从显示调用反查常量|
|自定义数据表|插件可以通过 `DataManager._databaseFiles` 等方式，把 `data/` 中任意名称的文件加载到 `$data…` 全局对象|从加载代码和 `$data…` 的引用找到数据表，再判断字段用途|

RGSS 的事件指令编号与上表相同。`122` 的脚本操作数只存在于 VX Ace，数据库 `note` 只存在于 VX 和 VX Ace，插件指令和插件参数不适用。

可见文本也可以经间接路径显示，以下路径的输入字符串都属于正文：

- 先存入变量、数组或对象，之后由 `\V[n]`、界面或履历显示。
- 由插件用 `replace` 代入模板，例如 `{city}`、`[word]` 的替换值。
- 由文字图片插件绘制成图片，例如 `DTextPicture`。

发现路径的一端时，追踪到另一端。`System.json` 中的变量名只能辅助定位，字符串也可能是资源名、状态值或比较键。

按读取方逐个判断：

1. 找到读取该位置的插件、脚本或事件代码。
2. 按读取结果的用途处理：
   - 显示到窗口、消息、文字图片或履历中时，翻译显示部分。
   - 用作文件名、开关键、对象名称、比较值或插件识别标记时，保持原样，或按「依赖协调」处理。
     - 字符串去掉扩展名后，与 `game_files.txt` 中某个路径去掉扩展名后的最后一段或几段相同时，通常是资源名。例如 `Actor1` 对应 `img/faces/Actor1.png`。再结合读取代码确认。
   - 在已启用的插件和脚本中找不到读取代码时，保持跳过，并记录搜索范围。
3. 同一条目同时包含程序结构和显示文字时，只翻译显示部分：
   - `108` 与后续 `408` 是同一个条目。插件可能用首行精确识别注释块，例如 `選択肢ヘルプ`、`EVM:`，首行保持原样。
   - 标签键、参数键、分隔符和资源值保持原样，每个标签按读取代码分别判断。
   - 单行 `<键:值>` 整体受默认文本保护，批量翻译不会改动其中的值。值为显示文字时，由 Agent 翻译。

一个插件的读取结论，只在确认另一处由相同代码读取后才能复用。

# 控制符与占位符

- 默认控制符不区分大小写，`\n` 后面跟着 `[` 时是 `\N[n]`，不是换行。
- MV、MZ 的 `%1`、`%2` 可以随语序移动。RGSS 中按位置代入的 `%s`、`%d` 不能交换顺序，需要换序时只能调整措辞。
- 默认保护只覆盖常用格式占位符。空格标志等特殊格式脱离调用语境无法与普通百分号正文区分，核查消费方式后按 `text-preserve` 添加自定义保护。

# 可见文本补漏

候选为含源语言文字的 `RULE_SKIPPED` 条目，按「默认跳过位置的可见文本」的来源归类和判定。

# 翻译后检查

翻译流程写入译文后，对本次写入的条目及其依赖位置执行以下检查，用脚本批量完成：

|检查|方法|处理|
|---|---|---|
|控制符与占位符|读取 `warnings` 数据集中本次条目的 `TEXT_PRESERVE` 和 `LINE_COUNT_MISMATCH`|按「控制符与占位符」恢复|
|名称依赖|对本次写入的数据库名称、分类名和 `320`、`324` 条目，用原文搜索 `sources/<file_path>/` 中的比较、查找、`note` 标签和脚本位置|按「依赖协调」协调，证据不足时列为未决|
|比较值冲突|收集参与比较或查找的条目译文，找出不同原文得到相同译文的情况|调整译文，使它们互相区分|
|插件识别标记|对含程序结构的条目，核对首行标记、标签键和技术值与原文一致|恢复原样|
|游戏标题|MV、MZ 的标题条目是否已翻译|不修改，在交付中说明存档识别的影响|

# 审校检查点

执行「翻译后检查」的全部检查，并按「默认跳过位置的可见文本」核对默认跳过位置有无漏译。

# 覆盖缺口

交付时说明以下未覆盖范围：

- `*.error.json` 记录的解析失败成员，以及有语法错误、未产生条目的脚本。
- MV、MZ 核心 JS 与 `Game.ini` 的标题等不产生条目的文件，数据、插件和脚本以外的文件，以及图片中的文字。
- 证据不足、保持未决的依赖，以及需要协调但没有条目可写的位置。这些位置无法通过修改原稿补写。
- 可见文本补漏依据静态代码调查，无法证明没有遗漏。建议用户在游戏中抽查，并用截图定位遗漏。
