本技能只提供 RPG Maker 引擎知识，翻译、审校和提交流程按 `translation` 执行。

# 原稿与条目

每个游戏是一个工程资产，条目的 `file_path` 指向整个游戏，原稿成员位于 `sources/<file_path>/`：

|引擎|数据与事件|插件与脚本|
|---|---|---|
|MV、MZ|`data/*.json`，MV 可能带 `www/` 前缀。事件指令为 `list[]` 中的 `code` 与 `parameters`|`js/plugins.js` 保存插件参数，`js/plugins/*.js` 为插件源码|
|XP、VX、VX Ace|`Data/` 下每个数据文件对应一份 JSON 明文 `<原文件名>.json`。对象写作 `$class` 与 `$fields`，字段名带 `@`，`$ref` 指向首次出现的位置|`Data/<脚本档案>/NNNN.rb`，脚本名称见同目录 `scripts.json`|

条目不带原稿坐标，按以下方法定位来源：

- 用 `src` 搜索 `sources/<file_path>/`。
- 原文含反斜杠、换行或引号时，原稿中可能是转义形式，改用其中一段纯文字搜索。
- `row_number` 按成员和出现顺序递增，相邻条目通常属于同一文件或同一事件。
- 插件参数、`note` 和脚本字符串中的嵌套 JSON 按叶子拆成多个条目。默认翻译字段即使形似 JSON 也整段保存为一个条目。

条目的默认状态由来源位置决定，数据库字段与事件文本分别判断：

- 文件身份决定数据库字段规则：只有数据目录下的直接成员套用标准数据库字段白名单，子目录中的同名文件只按事件结构识别事件文本。
- 事件结构决定事件文本规则：任何数据文件中的事件指令都按指令代码判断。

|默认 `NONE`|默认 `RULE_SKIPPED`|
|---|---|
|标准数据库的默认翻译字段：角色名称、昵称、简介，职业、技能、物品、武器、防具、敌人、状态的名称、说明与战斗消息|数据库 `note` 与插件扩展字段|
|`System` 的货币单位、用语与分类名称，地图显示名，MV、MZ 的游戏标题|XP、VX、VX Ace 的游戏标题|
|显示文字 `101`、`401`（含 MZ 姓名框），滚动文字 `105`、`405`|事件注释 `108`、`408`，插件参数与插件指令参数|
|显示选项 `102`，对应的 `402` 分支标签由工程同步写回|脚本 `355`、`655`，条件分支、变量操作和移动路线中的脚本，插件与 RGSS 脚本源码中的字符串|
|改名 `320`、改昵称 `324`、改简介 `325`|其他指令参数，例如条件分支 `111` 中比较的角色名|

默认状态只表示是否默认参与翻译：

- `NONE` 条目也可能被程序比较或查找，例如角色名、分类名。
- `RULE_SKIPPED` 条目中可能有玩家可见文本，也可能有必须与已译文本协调的比较值。
- 放行后的条目不会再因 `EV001`、`0=` 这类外观被过滤，但仍受源语言设置约束。混合语言文本或不含源语言文字的条目可能是 `LANGUAGE_SKIPPED`，审校遗漏时先检查这一原因。

# 语义审校流程

同一原文既用于显示、又被程序比较或查找时，只译其中一处会改变游戏行为。按以下步骤调查：

1. 用条目原文搜索 `sources/<file_path>/` 中的全部出现位置，包括插件和脚本源码。
2. 判断每个位置的用途：显示、比较、查找键还是资源名。用途以实际读取该值的代码为准。
3. 确认需要协调的具体条目，以及它们和哪一个原名构成依赖。
4. 通过各自的条目提交协调后的译文。
5. 复核相关位置，报告已协调的依赖、未决事项和覆盖缺口。

处理原则：

- 证据充分时协调相关译文，比较值和查找键使用与显示位置一致的译名。
- 分别说明普通显示差异与程序依赖的影响，前者只影响观感，后者会改变分支、查找或存档行为。
- 证据不足时报告位置和原因，保留用户当前的编辑决定，不为未查清的依赖回退已有译文。
- 语义未决事项不阻塞译文生成。

不同原文作为查找键或比较值时，不能译成同一个值，否则会命中错误对象，或让原本互斥的条件同时成立。

# 领域知识

|主题|审校重点|
|---|---|
|角色名|数据库初始名、`320` 改名、`111` 条件分支的名称比较、脚本中的 `setName` 或 `name =` 赋值，以及 `303` 名称输入。允许玩家改名的角色在对白中只能使用 `\N[n]`|
|名称关系|按具体原名和实际消费关系关联条目。同一角色可以在不同阶段使用多个名字，每个名字分别对应自己的依赖位置|
|分类名|`equipTypes`、`skillTypes`、`weaponTypes`、`armorTypes`、`elements` 等是否被插件、`note` 或脚本按名称引用|
|XP 标签惯例|XP 脚本常把属性名、状态名当作标签判断。只有读到按名称比较或查找的代码，才算依赖|
|脚本文本|优先调查 RGSS 的 `Vocab` 模块、消息添加调用和窗口绘制调用，例如 `$game_message.add`、`draw_text`。模块名或字符串形状不能单独证明用途|

# 游戏标题

引擎事实：

- 标题是否绘制在标题画面或窗口中，取决于引擎版本、配置和实际消费位置。
- MV 在非本地模式下，内置存档识别会比较存档中的标题与当前游戏标题。即使没有插件，这一依赖也存在。
- MV、MZ 核心 JS 不在采集范围，搜索不到相关代码不能证明没有依赖。
- RGSS 标题还可能被脚本用作窗口标识，或转换编码后传给系统接口，需要结合实际脚本判断。

处理方式遵循「语义审校流程」的处理原则，判断时同时考虑部署方式和存档要求。

# 插件参数、`note` 与注释

这些位置默认跳过，但插件常用它们存放帮助文字、任务描述、菜单命令、姓名框和提示。按以下步骤逐个插件判断：

1. 在插件源码或 RGSS 脚本中找到读取该参数或标签的代码。
2. 按读取结果的用途处理：
   - 绘制到窗口或消息中时，在对应条目的译文中翻译可见部分，标签名、参数键和分隔符保持原样。
   - 用作文件名、开关键、对象名称或比较值时，按资源或语义审校流程处理。
   - 找不到读取代码时，保持当前状态并列为未决。

一个插件的标签语法结论，只在确认另一处由相同代码读取后才能复用。

# 控制符与消息窗口

只使用原文已有的控制符和格式占位符。各控制符的含义与处理方式如下：

- `\N[n]`、`\P[n]` 在运行时代入角色名、队员名：保持引用，玩家可改名的角色只能使用引用。
- `\V[n]`、`\G` 显示变量值、货币单位：调整语序时与所修饰的词一起移动。
- `\C[n]`、`\I[n]`、`\{`、`\}`、`\FS[n]` 控制颜色、图标、字号：作用范围覆盖译文中的同一段意思。
- `\.`、`\|`、`\!`、`\>`、`\<`、`\^` 控制等待、等待输入、即时显示和不等待关闭：放在译文对应的停顿处，数量不变。
- MV、MZ 的 `%1`、`%2` 与 RGSS 的 `%s`、`%d`、`%02d`、`%1$s` 由程序代入数值或名称：保持原样和数量，可随语序移动。按位置代入的 `%s` 不能交换顺序，需要换序时只能调整措辞。
- 默认保护只覆盖常用格式占位符。空格标志等特殊格式脱离调用语境无法与普通百分号正文区分，核查消费方式后按 `text-preserve` 添加自定义保护。
- 插件新增的控制符：含义按插件代码判断。

消息窗口的显示限制：

- 引擎不自动换行，`401` 的每一行就是窗口中的一行。
- 消息窗口默认每页 4 行，显示脸图时可用宽度更短，译文过长时先调整措辞。
- 数据库名称、选项和菜单用语显示在固定宽度窗口中，过长会被压缩或截断。

# 审校检查点

- 角色名、分类名、选项和数据库名称的译文与其依赖位置一致。
- 不同原名没有被译成同一个比较值。
- `RULE_SKIPPED` 条目中由插件或脚本绘制的可见文本没有漏译。
- 选项译文的肯否、对象和代价与 `402` 分支之后的实际事件一致。
- `\N[n]` 没有被固定译名替换，固定姓名没有被写成其他角色的引用。

# 覆盖缺口

交付时说明以下未覆盖范围：

- `*.error.json` 记录的解析失败成员，以及有语法错误、未产生条目的脚本。
- MV、MZ 核心 JS 与 `Game.ini` 的标题等不产生条目的文件，数据、插件和脚本以外的文件，以及图片中的文字。
- 证据不足、保持未决的语义依赖，以及需要协调但没有条目可写的位置。这些位置无法通过修改原稿补写。
