# `items` 翻译

为已明确范围内的 `item` 形成完整译文。

## 目标与执行方式

通过 `ws.contract` 读取 `project_meta`、`items` 和关联 `warnings`。按已明确的范围与修改要求，将文件、`item`、状态、文本条件和排除项解析为实际目标，以稳定的 `item` 身份去重，正文与姓名属于同一对象。

失败 `items` 是否重试沿用用户已明确的决定。尚无决定时，说明数量并用 `ask_user` 提供处理或跳过选项。排除、规则跳过、语言跳过和同文重复项依据用户范围与工程契约确定去向。

先核对 `run_batch_item_translation` 对状态、范围与写入方式的支持，再按规模选择执行方式：

- 只读方案、已有成功译文的重译，以及批量工具无法表达的要求由 Agent 处理。
- 对符合工具条件的待译或已授权失败目标，小范围由 Agent 处理。超过一个业务单元且提交安排合适时，使用批量工具。
- 混合目标分别安排，保留每个目标的去向。

## Agent 形成译文

按文件与 `item` 顺序组织业务单元，读取原文、现有译文、姓名和必要语境。参与者、指代或剧情事实不足时，用 `@lg/workspace/item-contexts` 的 `queryItemContexts` 补充邻近语境，围绕具体缺口继续取证。

形成正文与姓名的完整译文，同时遵守 `item` 约束：

- 每条原文对应本条完整译文，保留 `item` 边界、顺序、行数和换行。结合跨 `item` 语境理解内容，按用户明确要求处理结构变化。
- 控制符、占位符、标签、转义与保护结构保持位置和边界。引号、括号可以转换为同类目标语言形式，原文半边或跨 `item` 延续结构仍需保留。
- `name_dst` 承载姓名译文，正文中的称谓、头衔、敬称和解释留在对应正文位置。
- 按 `ws.contract.changes.items.updates.reference` 所述格式准备完整最终字段，只提交需要变化的字段。正文修改、接受失败 `items` 的现有非空译文及人工状态的副作用由写入契约处理。

每个目标保留需要修改、保持现状或缺少决定性事实的当前结论。保存完整新值，未决对象说明缺失事实与已完成的补查。核对含义、结构、关系、术语和表达质量后提交当前单元或保存方案，继续剩余目标。

按稳定 `item` 身份保存完整方案、证据和实际结果，待处理问题保留触发依据、范围、方法、受影响对象与当前结果。工作材料按任务规模组织，可恢复剩余目标与执行去向。

## 批量结果

批量调用前将范围解析为明确目标，核对失败 `items` 的处理决定。结束后读取最新事实，对照工具结果核对成功、失败、排除与剩余目标。记录实际读取和语义判断的范围，从已读译文与关联警告中发现的具体线索进入后续处理。出现新的失败目标时，沿用用户已有的重试决定。缺少决定时，先询问再安排重试。

## 关联问题与后续处理

根据本次翻译、语境读取和结果核对中发现的线索，记录并执行关联检查：

- 后文确认了姓名或关系时，核验已使用该译名或指代的目标。
- 发现结构损坏或命题错配时，补查相同条件下的相关表达。
- 发现可靠译法时，检查同系列表达和人物声音的一致性，并按语境与阶段确认适用性。

新证据改变身份、译法、结构、待写入值或未决结论时，核验本次范围内受影响的正文与姓名。原问题修正后，继续完成已产生的后续检查。核验产生新问题时继续处理，直到相关影响均有当前结果。等价问题合并，有效证据复用，只重查变化影响的部分。

发生写入后核对真实成功对象、译文、关联 `warnings` 及字段副作用，处理回执指出的失败。写入后发现的问题同样进入关联处理，修改已有结果时使用最新事实和指纹。

## 完成检查与交付

结束前对照完整目标及问题记录，逐项确认：

- 每个目标均有实际结果或明确的未决说明。
- 待写入方案完整且通过检查。
- 批量结果已核对。
- 已发现的关联影响均有核验结果。

发现可执行的剩余工作时继续处理。未决事项说明决定性缺失事实、已完成的补查和继续条件。

说明目标覆盖与实际语义判断范围、执行方式、实际完成和剩余内容，区分方案、本轮批量统计与工程累计进度。
