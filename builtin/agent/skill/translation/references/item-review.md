# `items` 审校

本流程用于检查、审校和修正工程中的已有或拟议译文。

## 任务范围

按用户要求确定任务范围：

- 用户未限定范围时，覆盖当前工程全文。
- 用户指定问题时，围绕该问题及其必要关联开展调查。
- 默认进行程序化批量探查。仅在用户明确要求或无法程序化批量探查时逐条进行语义分析。

## 冷启动

用户指定问题或对象时，先调查指定目标及其必要关联。在任务范围内按以下方式选择冷启动数据：

- 有相关警告时，从警告关联的 `item` 开始调查。按条目身份去重，合并同一条目的多个 `warnings`，读取原文、译文和必要语境。超过一个业务单元时分批处理。
- 没有相关警告时，在任务范围内分散采样。结合文件或章节结构、来源位置和内容分布选择不同区域，按 `item` 身份去重计数，合计至少一个业务单元。范围内适用条目不足一个单元时，全部读取。

在每个采样位置读取语境完整的连续片段，补齐必要的邻近条目和关联对象。一个采样业务单元可以包含多个位置的片段。

工程警告针对已写入的值，审校拟议方案时要根据拟议值重新判断。按下文领域要求判断初始材料，再从成立的问题、误报、正确译法和其它结果中提炼种子。

## 种子发现思路

冷启动和后续调查都可参考以下思路寻找种子。根据任务目标和当前证据按需选择，也可沿材料揭示的其他关系展开。

- **警告线索**：从成立问题、误报及其关联关系寻找适用条件，调查同类用法。
- **信息完整**：从遗漏、增添、重复，以及数字、单位、限定条件和局部片段的对应关系寻找问题模式。
- **结构保持**：从 `item`、换行、控制符、占位符、标点及跨 `item` 延续结构寻找损坏或正确保持的规律。
- **命题关系**：从参与者、施受、归属、修饰，以及否定、数量、时间、因果和情态的作用对象寻找关联句式。
- **身份与指代**：从人物关系、剧情阶段、姓名、称谓、代词、别名和术语条件寻找身份与固定译名的适用边界。
- **表达与功能**：从自然表达、人物声音、语气、强度、文本用途、同系列译名和替代表达寻找一致性线索。正确译法、同词异义和有意保留的不规则表达都可启发调查。
- **事实与方案变化**：从新语境、关系、术语条件、覆盖缺口和提交后事实变化寻找需要重查正文与姓名的对象。

例如，发现施受关系译反后，调查相同句式。若结果显示错误与视角切换后的主语省略有关，再调查这一组合条件，并用正确译法和反例核验边界。

## 种子账本与循环执行

通过 `workspace_run` 将种子账本保存在 `work/TASKNAME-seeds.json`，并在循环中实时更新：

- 先将种子写入账本，再取证和判断。
- 得出新增或修改种子的结论时，立即写入账本。

|账本字段|含义|
|---|---|
|`completedRounds`|已完成的总轮数，用正整数记录，包含冷启动|
|`seeds.ROUND[]`|目标轮次的种子数组，`ROUND` 为正整数，表示目标轮次|
|`seeds.ROUND[].pattern`|非空字符串，简明扼要的描述种子模式|
|`seeds.ROUND[].consumed`|布尔值，完成取证、结果处理和后续种子提炼后为 `true`，尚需处理时为 `false`|

### 1. 冷启动后初始化

冷启动完成后，设置 `completedRounds = 1`。从实际结果中提炼种子，将其 `consumed` 设为 `false`，并按目标轮次加入 `seeds`。

### 2. 每轮推进

1. 通过 `workspace_run` 读取账本，选择 `consumed === false` 的种子。相关模式可以合批调查。若 `completedRounds < 2` 且没有未消耗种子，先补入并保存种子，再取证：
   - 还有材料未检查时，选择尚未检查的业务单元，补入调查种子。
   - 材料已全部读取时，围绕已有结果的关系、反例或适用边界，补入复核种子。
2. 调用工具取得本轮证据，读取返回结果。按下文领域要求读取原译文与语境，形成正文和姓名的修正、保留或未决结论，并按单元安排处理方案与提交。
3. 从错误、正确案例、反例、关系和证据缺口中提炼后续模式，合并等价模式并复用有效证据。将新增种子的 `consumed` 设为 `false`，将同类实例补充到业务工作材料中。新事实要求重查已有模式时，更新该模式，并将其 `consumed` 设为 `false`。发现范围外的问题时，记录调查理由，交由用户决定。
4. 按处理结果更新种子状态：完成取证、结果处理和后续提炼的种子设为 `consumed = true`，仍需补查或受阻的种子设为 `consumed = false`。
5. 本轮完成后，执行 `completedRounds = completedRounds + 1`。

同轮处理多个种子、搜索或采样都计为一轮。仅在完成本轮后更新 `completedRounds`。

在业务工作材料中按轮号保存取证结果的位置、对象结论、方案、实际处理范围、未决事项和后续模式，用对象身份关联种子。没有新增模式时，记录结束该调查方向的依据。

### 3. 结束检查

准备结束时，通过 `workspace_run` 重新读取磁盘账本，核对字段是否符合约定，输出已完成轮数和未消耗种子，并检查以下条件：

- 已完成至少两轮调查，即 `completedRounds >= 2`。
- `seeds` 中各轮的全部种子均满足 `consumed === true`。

读取工具返回的检查结果。两个条件均成立时，结束自启发循环。还有条件未满足时，继续调查。

交付前，核对轮数是否与逐轮记录一致，并确认调查覆盖用户要求的范围、成果满足领域要求。还有指定对象、成果缺口或写入后新事实需要处理时，补充或更新种子，继续调查并重新检查。在业务工作材料中保存检查结果的位置，以及循环结束或受阻的依据。

## 领域判断与成果核验

冷启动和种子调查都按以下要求处理目标。

按稳定 `item` 身份保存完整发现集合、正文与姓名的当前结论、证据和待写入字段。分别记录程序扫描与实际语义阅读的范围。

### 1. 读取证据

调查条件可以用程序定位目标时，扫描声明范围内的全部数据并读完所有分页。模型根据原文和必要语境判断。

需要核对参与者、身份和上下文衔接时，先用 `@lg/workspace/item-contexts` 的 `queryItemContexts` 取得邻近语境，再补查影响判断的缺失事实。结合人物关系、语境和剧情阶段，判断已有译法是否适用。

补查后仍有歧义时，检查已有译法是否忠实保留了歧义，以及证据是否支持修正。仍无法判断时，记录缺失事实、已查语境、已尝试的解释和继续条件。继续处理可独立确定的条目。

警告线索按以下问题核验：

|警告|需要核验的问题|
|---|---|
|`SIMILARITY`|是否漏翻，原文信息与功能是否已表达|
|`FOREIGN_CHAR_RESIDUE`|是否局部漏翻，是否存在浊音、语气词残留等|
|`TEXT_PRESERVE`|是否存在无需翻译的结构文本被误翻|
|`GLOSSARY`|术语落实情况是否正确合理|
|`PUNCTUATION_MISMATCH`|标点符号的结构、位置及用法是否正确|
|`RETRY_THRESHOLD`|最终放行的译文是否正确，然后提交任意变更将次数置零|
|`LINE_COUNT_MISMATCH`|原文与译文的行数是否对齐|

### 2. 判断、修正与单元提交

按稳定 `item` 身份为正文与姓名形成一个当前结论：修正、保留或未决。保存判断依据和完整待写入字段，按以下要求修正：

- 保留 `item`、行数、换行及保护结构边界。
- 姓名槽位只保存姓名，称谓和解释在对应正文中表达。
- 按原文中的实际作用保留半边标点与跨 `item` 结构。

逐项核对当前单元中正文与姓名的结论、修正依据和完整待写入字段，通过后按全局 `业务单元与提交` 安排提交。默认提交本单元并核对结果，再进入下一单元。统一提交时，先保存方案再处理下一单元。`report` 保存检查通过的方案后，继续调查。

按 `ws.contract.changes.items.updates.reference` 所述契约处理字段、人工状态、接受译文、重试计数和同文组副作用。实际写入后核对译文、`warnings` 及相关副作用。

### 3. 核对成果

- 记录实际调查范围、证据和种子的处理结果。
- 核对用户指定目标和全部发现对象的当前结论。
- 完成当前种子涉及的对象处理。遇到阻碍时，在业务工作材料中说明原因，并将对应种子保留为未消耗。
- 核验方案变化对相关对象的影响。
- 检查最终待写入字段。

核对用户要求的逐条覆盖、当前种子的检查范围与修改影响。发现缺口时完成对应调查和判断，实际写入产生的新事实同样用于种子提炼。

## 交付

交付时提供种子账本和业务工作材料链接，并说明：

- 代表性模式，以及循环结束或受阻的依据。
- 实际调查、程序扫描和语义判断的范围。
- 代表性问题、修正与保留数量、未决事项和实际写入结果。

按 `item` 身份统计方案中的修正、保留和未决数量，每个条目只计入一类。条目仍有影响结论的未决问题时，将其计入未决，并保存已经确定的修正。

核对三类数量的合计是否与实际已判断条目数一致，并说明尚未判断的范围。问题类型和警告可以重叠，说明各自的统计方法。按回执统计实际写入数量。

记录拟议方案时注明它与工程现值的区别。没有发现问题时，说明实际检查范围与依据。完成范围内每个适用条目的判断后，才称完成全量逐条审校。
