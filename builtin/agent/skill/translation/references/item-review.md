# `items` 审校

按已明确的审校范围和覆盖要求调查已有或拟议译文，在允许修改的范围内形成修正。

## 范围与覆盖

从完整的 `items` 中确定范围内的目标，再按 `item` 身份关联 `warnings`。已有正文译文或姓名译文的条目都可进入审校。

审校拟议方案时，按 `item` 身份关联工程并记录译文来源。工程警告针对已写入的值，需要根据拟议值重新判断。

- 普通主动审校：核验警告，并从原文、译文和文件结构独立发现问题，实际阅读适用的无警告译文。
- 用户要求逐条审校：范围内每个符合条件的目标都要形成语义判断。
- 用户指定问题、`item` 或修正建议：围绕指定范围取得证据与形成处置。

取证和修正分别遵守已明确的语境范围与可修改字段。程序扫描与实际语义阅读的覆盖分别记录，抽样发现不能作为已完成全量逐条检查的依据。

## 调查与判断

主动审校从以下方向建立具体检查，定点任务围绕指定问题选择适用方向：

- **信息完整**：原文信息是否遗漏、增添或重复？数字、单位、限定条件和局部片段是否落实？
- **结构保持**：`item`、换行、控制符、占位符及标点作用范围是否正确？跨 `item` 延续结构是否保留？
- **命题关系**：参与者、施受、归属和修饰关系是否准确？否定、数量、时间、因果和情态作用于哪里？
- **身份与指代**：姓名、称谓、代词、别名及术语身份是否符合语境、人物关系和当前阶段？固定译名是否在适用条件下落实？
- **表达与功能**：译文是否自然，并保留声音、语气、强度和文本用途？可靠表达在相关用法中是否仍然适用？

对程序能够定位的模式，扫描声明范围内的全部数据并读完所有分页。模型根据原文和必要语境判断。

按任务规模保存全部发现对象、成员去向、证据、当前结论和待写入字段。待查问题记录触发依据、范围、核验方法、受影响对象和当前结果，同时保存分页位置与剩余对象，便于恢复进度。

|警告|需要核验的问题|
|---|---|
|`SIMILARITY`|是否漏翻，原文信息与功能是否已表达|
|`FOREIGN_CHAR_RESIDUE`|是否局部漏翻，是否存在浊音、拟音、语气词残留等|
|`TEXT_PRESERVE`|控制符、占位符等保护结构是否损坏|
|`GLOSSARY`|当前语境是否适用术语及其条件，固定译名是否落实|
|`PUNCTUATION_MISMATCH`|引号、括号等结构及作用范围是否正确|
|`RETRY_THRESHOLD`|达到重试阈值后的非空译文能否接受，处置按写入契约完成|
|`LINE_COUNT_MISMATCH`|`item` 内行数与换行是否对齐|

`warnings` 是问题线索，状态用于解释工程事实。没有警告的译文也可能存在关系错配、身份错误或表达偏移。

需要参与者、身份和连续性证据时，先用 `@lg/workspace/item-contexts` 的 `queryItemContexts` 取得邻近语境，再补查决定性缺口。已有译法的适用边界由人物关系、语境与剧情阶段证明。

## 判断与单元提交

按稳定 `item` 身份为正文与姓名形成一个当前结论：修正、保留或未决，并保存依据和完整待写入字段。修正保留 `item`、行数、换行及保护结构边界，姓名槽位只保存姓名，称谓和解释在对应正文中表达。原文半边标点与跨 `item` 结构按其实际作用保留。

按文件和 `item` 顺序组织业务单元，按通用的 `业务单元与提交` 流程检查和提交。字段、人工状态、接受译文、重试计数和同文组副作用按 `ws.contract.changes.items.updates.reference` 所述契约处理。实际写入后核对译文、`warnings` 及相关副作用。

## 查明关联问题

每批判断、修正与写入核对后，检查以下关联：

- 信息遗漏、施受关系译反、称谓不符和结构损坏等错误，启发相同句式、关系或结构下的关联检查。
- 正确译文中的同系列译名、人物声音和替代表达提供一致性线索，调查范围内其它相关用法并核验适用边界。
- 同词异义、关系变化和有意保留的不规则表达等反例，要求核对拟议修正的适用条件及相关对象。
- 新关系、术语条件、剧情事实、覆盖缺口和提交后的事实变化，要求重查受影响 `item` 的正文与姓名。

记录问题的触发依据、范围、方法及受影响对象，实际执行并更新结论和方案。原问题已经修正时，仍完成已产生的后续检查。新对象、关系、待写入值、处置、未决或待查问题发生变化时，核验受影响的内容，并根据实际结果更新结论。

后续调查产生的新问题继续处理，等价问题合并，有效扫描与判断复用，事实变化只重查相关部分。定点任务的关联调查保持在用户指定边界内。

## 验收与交付

结束审校阶段前，按调查与方案的最终状态核对完整范围，并保存以下依据：

- 已记录实际调查范围，以及适用警告和探索方向的证据与结果。
- 用户指定目标和全部发现对象均有当前结论。
- 全部后续问题均有处理结果或未决说明。
- 已核验方案变化对相关对象的影响。
- 最终待写入字段已通过检查。

仍然有效的证据可以复用。

有可执行的待查问题、待判断对象或尚未核验的方案变化时继续处理，再验收受影响部分并核对完整范围。仅缺决定性外部事实时，未决写明缺失事实、已查内容、已尝试处理方式和继续所需条件。

上述验收用于确认审校阶段完成。拟议方案与工程现值分别记录。

交付说明实际调查、程序扫描和语义判断范围、代表性问题、修正与保留数量、未决及真实写入结果。只有逐项判断完整时，才称完成全量逐条审校。
