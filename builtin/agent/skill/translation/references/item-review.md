# `items` 审校

本流程用于检查、审校和修正工程中的已有或拟议译文。

## 任务范围

按用户要求确定任务范围：

- 用户未限定范围时，覆盖当前工程全文
- 用户指定问题时，围绕该问题及其必要关联开展调查
- 优先进行程序化批量探查，仅在用户明确要求或无法程序化批量探查时逐条进行语义分析

## 自启发循环

- 从任务目标、已有材料和调查结果中提炼可用于后续探查的特征模式或具体线索，称之为 `种子`
- 根据种子发现下一批需要调查的目标，再从调查与处理结果中提炼新的种子
- 重复前述过程，直到任务目标完成且所有种子均已消耗，称之为 `自启发循环`

## 种子账本

种子账本保存在 `work/TASKNAME-seeds.json`，通过 `workspace_run` 读写：

- 种子账本是实时状态机而非汇总报告，必须每轮更新，禁止跨轮补写
- 轮次从 `1` 开始，新增或需要重新调查的种子设为 `consumed = false`
- 完成取证、结果处理和后续种子提炼后，将目标种子设为 `consumed = true`，尚需补查或受阻的种子保持 `consumed = false`

账本示例：

```jsonc
{
  "completedRounds": 1,   // 已完成的轮次
  "seeds": {
    "1": [                // 发现 `种子` 的轮次
      {
        "pattern": "筛选原文同时含「毎日」和「最大」的条目，核验译文是否保留每日数量上限及其适用对象。",
        "consumed": true
      }
    ]
  }
}
```

## 循环执行

### 循环入口

任务从以下循环入口开始处理：

- 存在与 `item` 相关 `warnings` 时，使用警告条目作为本轮数据集
- 不存在与 `item` 相关 `warnings` 时，从至少3个不连续的内容区域中分散采样至少一个业务单元作为本轮数据集

### 循环轮次

每次按顺序完整执行以下步骤称之为一个 `循环轮次`，每个循环轮次必须以写入 `种子账本` 文件作为结束：

1. 轮次开始时，从循环入口开始或者读取 `种子账本` 中未消耗的 `种子`
2. 根据 `种子` 中的特征模式进行探查，形成审查结论，准备变更数据并 `apply` （如有）
3. 回看探查与处理过程，提炼新的 `种子`，更新 `completedRounds` 的数值和已消耗 `种子` 的状态
4. 写入 `种子账本` 文件

重复执行循环轮次，直到同时满足：

1. 任务目标全部完成
2. 本轮没有新的 `种子` 产生，账本中所有 `种子` 均已消耗
3. 包含入口轮次在内，至少进行过 3 个轮次的循环探查，即 `completedRounds >= 3`

轮次不足且没有未消耗种子时，从至少 3 个不连续的内容区域中分散采样至少一个业务单元作为本轮数据集

## 领域参考

### 种子探查

种子探查可以从以下方向展开，但是无需局限于此，错误、正确案例和不同处理方式都可以提供线索：

- **扩展同类**：从错误或正确案例中提取可检索的特征，调查其他相似条目。
  - 例如：发现“每日”漏译后，检索 `毎日`，核验其他译文是否保留时间限制。
- **核验差异**：发现同词异译或同类结构处理不同时，调查差异是否符合各自语境。
  - 例如：检索 `先輩`，结合指向对象核验“学长／学姐”的译法。
- **追查关联**：确认新的身份、术语条件或结构关系后，调查受该发现影响的其他条目。
  - 例如：确认别名对应的角色后，检索该别名，复核相关译名与指代。

### 取证与对象判断

- **参与者与上下文**：参与者、身份、指代或上下文衔接不清时，使用 `@lg/workspace/item-contexts` 的 `queryItemContexts` 查询邻近语境。
- **姓名与固定译名**：结合人物关系、剧情阶段、身份与术语适用条件，判断姓名、称谓或固定译名是否适用。
- **原文歧义**：原文存在多种合理解释时，核验译文是否保留原有歧义，以及现有证据是否足以支持收窄解释。
- **证据不足**：无法确定修正时，将结论保留为未决，并说明缺失事实与判断依据。

### 警告速查

警告项目是否需要修正取决于原文、译文与必要语境：

|警告|判断重点|
|---|---|
|`SIMILARITY`|是否存在漏翻，原文信息与功能是否已表达|
|`FOREIGN_CHAR_RESIDUE`|是否存在局部漏翻、浊音、重音或语气词残留|
|`TEXT_PRESERVE`|无需翻译的结构文本是否被误翻|
|`GLOSSARY`|术语落实是否正确，当前语境是否符合术语的适用条件|
|`PUNCTUATION_MISMATCH`|标点的结构、位置与作用是否符合原文，是否涉及半边标点或跨条目结构|
|`RETRY_THRESHOLD`|最终放行的译文是否正确，然后提交任意变更将次数置零|
|`LINE_COUNT_MISMATCH`|原文与译文的行数是否对齐，换行及跨行结构是否完整|

### 成果验收

- **调查完整**：实际调查范围与证据相符，每个目标均有修正、保留或未决结论，未决事项说明缺失事实与继续条件。
- **译文成立**：结合原文、译文与必要语境，核验信息完整性、术语适用性、指代与歧义，以及保护结构、标点和换行。
- **修正有据**：每项修改均有对应问题与证据，保留原状的结论有判断依据，警告处理符合具体语境。
- **结果一致**：`report` 核对最终方案，`apply` 按回执与最新事实核对实际结果。修改或新证据影响其他条目时，复查关联对象并提炼后续种子。

调查范围尚未覆盖、验收发现遗漏、不一致或待核验事实时，补充或更新种子，继续调查。

## 交付

提供种子账本和业务工作材料链接，并说明：

- 实际调查范围与覆盖程度，区分程序扫描和逐条语义判断
- 主要发现、修正或保留的依据，以及未决事项。没有发现问题时，说明检查依据
- 任务完成或受阻的情况，区分拟议方案与实际写入结果
