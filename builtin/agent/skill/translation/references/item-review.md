# `items` 审校

本流程用于检查、审校和修正工程中的已有或拟议译文。

## 任务范围

按用户要求确定任务范围：

- 用户未限定范围时，覆盖当前工程全文
- 用户指定问题时，围绕该问题及其必要关联开展调查
- 默认进行程序化批量探查，仅在用户明确要求或无法程序化批量探查时逐条进行语义分析

## 自启发循环

- 从任务目标、已有材料和调查结果中提炼可用于后续探查的特征模式或具体线索，称之为提炼 `种子`
- 根据种子发现下一批需要调查的目标，再从调查与处理结果中提炼新的种子
- 重复前述过程，直到任务目标完成且所有种子均已消耗，称之为 `自启发循环`

种子探查可以从以下方向展开，也可以沿材料揭示的其他关系展开：

- **警告线索**：从成立问题、误报及其关联关系寻找适用条件，调查同类用法
- **信息完整**：从遗漏、增添、重复，以及数字、单位、限定条件和局部片段的对应关系寻找问题模式
- **结构保持**：从 `item`、换行、控制符、占位符、标点及跨 `item` 延续结构寻找损坏或正确保持的规律
- **命题关系**：从参与者、施受、归属、修饰，以及否定、数量、时间、因果和情态的作用对象寻找关联句式
- **身份与指代**：从人物关系、剧情阶段、姓名、称谓、代词、别名和术语条件寻找身份与固定译名的适用边界
- **表达与功能**：从自然表达、人物声音、语气、强度、文本用途、同系列译名和替代表达寻找一致性线索。正确译法、同词异义和有意保留的不规则表达都可启发调查
- **事实与方案变化**：从新语境、关系、术语条件、覆盖缺口和提交后事实变化寻找需要重查正文与姓名的对象

种子账本保存在 `work/TASKNAME-seeds.json`，通过 `workspace_run` 读写：

- 种子账本是实时状态机而非汇总报告，必须每轮更新，禁止跨轮补写
- 轮次从 `1` 开始，新增或需要重新调查的种子设为 `consumed = false`
- 完成取证、结果处理和后续种子提炼后，将目标种子设为 `consumed = true`，尚需补查或受阻的种子保持 `consumed = false`

账本示例：

```jsonc
{
  "completedRounds": 1,   // 已完成的轮次
  "seeds": {
    "1": [                // 发现 `种子` 的轮次
      {
        "pattern": "原文同时出现时间限制词（日语示例：一日、毎日、一週間、毎週）与数量限制词（日语示例：まで、以内、限り、最大）。筛选同时命中两类词的条目，核验译文是否保留时间范围、数量上限及其适用对象。",
        "consumed": true
      }
    ]
  }
}
```

## 循环执行

### 循环入口

任务从以下循环入口开始处理：

- 存在与 `item` 相关 `warnings` 时，使用警告条目作为本轮数据集
- 不存在与 `item` 相关 `warnings` 时，从至少3个不连续的内容区域中分散采样至少一个业务单元作为本轮数据集

### 循环轮次

1. 轮次开始时，从循环入口开始或者读取 `种子账本` 中未消耗的 `种子`
2. 根据 `种子` 中的特征模式进行探查，形成审查结论，准备变更数据，然后提交变更
3. 回看探查与处理过程，提炼新的 `种子`，更新 `completedRounds` 的数值和已消耗 `种子` 的状态，然后写入 `种子账本` 文件

每次完整的执行前述步骤称之为一个循环轮次，重复执行循环，直到同时满足：

1. 任务目标全部完成
2. 本轮没有新的 `种子` 产生，账本中所有 `种子` 均已消耗
3. `completedRounds >= 3`，即包含入口轮次在内，至少进行过 3 个轮次的循环探查

轮次不足且没有未消耗种子时，从未检查材料或已有结论的适用边界中提炼调查种子并保存

## 领域参考

### 警告速查

警告项目是否需要修正取决于原文、译文与必要语境：

|警告|判断重点|
|---|---|
|`SIMILARITY`|是否存在漏翻，原文信息与功能是否已表达|
|`FOREIGN_CHAR_RESIDUE`|是否存在局部漏翻、浊音、重音或语气词残留|
|`TEXT_PRESERVE`|无需翻译的结构文本是否被误翻|
|`GLOSSARY`|术语落实是否正确，当前语境是否符合术语的适用条件|
|`PUNCTUATION_MISMATCH`|标点的结构、位置与作用是否符合原文，是否涉及半边标点或跨条目结构|
|`RETRY_THRESHOLD`|最终放行的译文是否正确，然后提交任意变更将次数置零|
|`LINE_COUNT_MISMATCH`|原文与译文的行数是否对齐，换行及跨行结构是否完整|

### 语境与歧义

|场景|可用信息与判断依据|
|---|---|
|参与者、身份、指代或上下文衔接不清|`@lg/workspace/item-contexts` 的 `queryItemContexts` 可提供邻近语境|
|姓名、称谓或固定译名是否适用|人物关系、剧情阶段、身份与术语适用条件|
|原文存在多种合理解释|译文是否保留原有歧义，现有证据是否足以支持收窄解释|
|证据不足以确定修正|结论可保留为未决，并说明缺失事实与判断依据|

## 交付

提供种子账本和业务工作材料链接，并说明：

- 实际调查范围与覆盖程度，区分程序扫描和逐条语义判断。
- 主要发现、修正或保留的依据，以及未决事项。没有发现问题时，说明检查依据。
- 任务完成或受阻的情况，区分拟议方案与实际写入结果。

数量按 `item` 身份去重统计，实际写入数量以回执为准。只有完成范围内全部适用条目的判断，才称完成全量逐条审校。
