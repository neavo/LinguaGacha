# `items` 审校

本流程用于审校工程中的已有或拟议译文。按用户要求确定审校范围，未限定时覆盖当前工程全文。从下文列出的冷启动方向取证并形成种子，通过自启发循环持续调查和修正问题。用户要求逐条审校时，对范围内每个适用条目完成所要求的判断。

用户指定问题或对象时，围绕指定目标及其必要关联开展调查。按用户指定的优先顺序安排执行。取证遵守可读取的语境范围，修改遵守可修改的对象与字段边界。

## 自启发循环的概念

|概念|在本流程中的含义|
|---|---|
|冷启动方向|本流程预设的条目审校调查入口，用于从实际材料中形成第一批种子|
|种子|基于原译文、语境和结构证据形成的调查线索。描述要调查的语义或结构关系、适用条件和核验方法。种子可以来自冷启动调查，也可以来自后续轮次的结果|
|调查结果|正文与姓名的修正、保留或未决判断，以及语境、译法和结构证据。正确案例、错误、反例、关系、排除依据和证据缺口都参与后续种子提炼|
|自启发循环|应用种子取得证据，判断并处理结果，再从结果中提炼新种子或更新已有种子，逐轮继续|
|轮次|以一组种子为输入，完成这些种子的应用、结果处理和后续种子提炼的一次执行过程。一轮可以跨多个批次、工具调用和提交|

调查依据、对象关系、适用条件或核验方法发生实质变化时，形成新种子或更新已有种子。同类实例补充到对应调查结果中，新旧比较覆盖全部历史轮次。

## 冷启动方向

从完整的 `items` 中确定范围内已有正文译文、姓名译文或拟议译文的适用条目。审校拟议方案时，按 `item` 身份关联工程并记录译文来源。

沿以下适用方向读取实际材料并形成种子。用户指定问题时，结合该问题选择方向：

- **警告线索**：按 `item` 身份关联 `warnings`，结合原文、译文和必要语境核验警告。从成立问题、误报和关联关系中提炼种子。工程警告针对已写入的值，审校拟议方案时根据拟议值重新判断。
- **信息完整**：对照原译文检查遗漏、增添和重复，核对数字、单位、限定条件及局部片段。
- **结构保持**：检查 `item`、换行、控制符、占位符和标点的作用范围，核对跨 `item` 延续的结构。
- **命题关系**：核对参与者、施受、归属、修饰关系，以及否定、数量、时间、因果和情态的作用对象。
- **身份与指代**：结合人物关系和剧情阶段，核对姓名、称谓、代词、别名及术语的身份与固定译名条件。
- **表达与功能**：判断译文是否自然，是否保留声音、语气、强度和文本用途，调查可靠表达在相关用法中的适用条件。

按文本用途与文件结构选择材料，实际阅读无警告译文，为各适用方向取得证据。正确案例和反例边界同样用于形成种子。

警告线索按以下问题核验：

|警告|需要核验的问题|
|---|---|
|`SIMILARITY`|是否漏翻，原文信息与功能是否已表达|
|`FOREIGN_CHAR_RESIDUE`|是否局部漏翻，是否存在浊音、语气词残留等|
|`TEXT_PRESERVE`|是否存在无需翻译的结构文本被误翻|
|`GLOSSARY`|术语落实情况是否正确合理|
|`PUNCTUATION_MISMATCH`|标点符号的结构、位置及用法是否正确|
|`RETRY_THRESHOLD`|最终放行的译文是否正确，然后提交任意变更将次数置零|
|`LINE_COUNT_MISMATCH`|原文与译文的行数是否对齐|

## 工作记录

在本任务的 `work/` 子目录中，每轮保存一份 `Round` 记录，按执行顺序排列。沿冷启动方向形成的种子填入第一轮的 `seeds`。通过文件位置和对象标识引用证据与业务成果。

```ts
type Seed = {
  id: string;
  description: string; // 调查线索、适用条件及核验方法
  basis: string[];     // 来源证据或结果位置
};
type Round = {
  seeds: Seed[];       // 本轮需要处理的种子
  results: string[];   // 按种子关联的检查范围、处理结果和证据位置
  findings: string;    // 提炼结果及其与已有种子的比较依据
  next: Seed[];        // 下一轮的新种子或更新后的种子
  remaining: string[]; // 尚未完成的工作或受阻原因
};
```

种子通过 `id` 关联记录。更新时记录变化与依据，保留此前轮次的描述和结果。轮次记录同时保存分页位置、已处理对象与剩余工作。

按稳定 `item` 身份保存完整发现集合、正文与姓名的当前结论、证据和待写入字段。分别记录程序扫描与实际语义阅读的范围。

## 每轮执行

### 1. 应用种子并读取证据

种子中的条件可以用程序定位目标时，扫描声明范围内的全部数据并读完所有分页。模型根据原文和必要语境判断。

需要参与者、身份和连续性证据时，先用 `@lg/workspace/item-contexts` 的 `queryItemContexts` 取得邻近语境，再补查决定性缺口。已有译法的适用边界由人物关系、语境与剧情阶段证明。

### 2. 判断、修正与单元提交

按稳定 `item` 身份为正文与姓名形成一个当前结论：修正、保留或未决。保存判断依据和完整待写入字段，按以下要求修正：

- 保留 `item`、行数、换行及保护结构边界。
- 姓名槽位只保存姓名，称谓和解释在对应正文中表达。
- 按原文中的实际作用保留半边标点与跨 `item` 结构。

按文件和 `item` 顺序组织业务单元，按通用的 `业务单元与提交` 流程检查和提交。字段、人工状态、接受译文、重试计数和同文组副作用按 `ws.contract.changes.items.updates.reference` 所述契约处理。实际写入后核对译文、`warnings` 及相关副作用。

### 3. 核对本轮成果

- 记录实际调查范围、适用冷启动方向的证据与结果，以及本轮种子的应用结果。
- 核对用户指定目标和全部发现对象的当前结论。
- 完成本轮种子涉及的对象处理，将受阻事项写入 `remaining`。
- 核验方案变化对相关对象的影响。
- 检查最终待写入字段。

核对用户要求的逐条覆盖、当前种子的检查范围与修改影响。发现缺口时完成对应调查和判断，实际写入产生的新事实同样用于本轮提炼。

### 4. 提炼后续种子

从本轮错误、正确译法、反例和方案变化中检查以下种子来源：

- 信息遗漏、施受关系译反、称谓不符和结构损坏等错误，启发相同句式、关系或结构下的关联检查。
- 正确译文中的同系列译名、人物声音和替代表达提供一致性线索，调查范围内其它相关用法并核验适用边界。
- 同词异义、关系变化和有意保留的不规则表达等反例，要求核对拟议修正的适用条件及相关对象。
- 新关系、术语条件、剧情事实、覆盖缺口和提交后的事实变化，要求重查受影响 `item` 的正文与姓名。

例如，发现施受关系译反后，形成调查相同句式的种子。若后续结果显示错误与视角切换后的主语省略有关，再形成调查这一组合条件的种子。修正结果、正确译法与反例共同支持下一轮调查。

按以下步骤整理本轮提炼结果：

1. 从本轮结果中提炼种子，与全部已有种子比较，在 `findings` 中记录依据。
2. 合并等价种子，复用有效证据。条件或证据变化时，记录种子的更新。
3. 对范围外发现单独说明理由，交由用户决定。
4. 将新增或实质更新的种子写入 `next`。

完成本轮处理后，根据 `next` 接续执行：

- `next` 有内容时，建立下一份 `Round`，将这些种子填入新一轮的 `seeds` 并执行。
- `next` 为空时，按下节的自启发循环停止条件作出判断。

## 自启发循环停止条件

完整执行本轮种子的应用、结果处理与后续种子提炼，并与全部已有种子比较后，既无法产生新种子，也没有形成需要继续调查的已有种子更新，自启发循环才停止。

在 `findings` 中记录无法继续提炼的证据与比较依据，此时 `next` 为空。

## 交付

交付说明循环执行轮次、代表性种子及停止或受阻依据，并提供执行记录链接。说明实际调查、程序扫描和语义判断范围、代表性问题、修正与保留数量、未决及真实写入结果。拟议方案与工程现值分别记录，只有逐项判断完整时才称完成全量逐条审校。
