# `pages` 审校

本流程对照原稿、已有或拟议译稿及渲染结果，检查、审校和修正内容与视觉呈现。

## 任务范围

按用户要求确定任务范围：

- 用户未限定范围时，覆盖当前工程全文。
- 用户指定问题时，围绕该问题及其必要关联开展调查。
- 默认进行程序化批量探查。仅在用户明确要求或无法程序化批量探查时逐条进行语义分析。

## 种子定义

种子是用于推进后续调查的具体线索。它来自任务目标、已有材料、调查结果或覆盖缺口，说明接下来调查哪些对象或条件，以及需要核验什么问题。错误、正确案例、反例、关系和未检查范围都可以产生种子。种子的判断结果由后续取证确定。

围绕同一调查问题合并等价种子，同类实例记录在业务工作材料中。出现需要独立核验的新条件、关系或边界时，新增种子或更新已有种子。

## 冷启动

用户指定问题或页面时，先调查指定目标及其必要关联。在任务范围内按以下方式选择冷启动数据：

- 有相关警告时，从警告关联的原稿 `page` 开始调查。按原稿页身份去重，合并同一原稿页的多个警告，并关联对应输出。超过一个业务单元时分批处理。
- 没有相关警告时，在任务范围内分散采样。结合文件结构、来源位置和页面内容分布选择不同区域，按原稿页身份去重计数，合计至少一个业务单元。范围内适用原稿页不足一个单元时，全部读取。

在每个采样位置保留完整页面语境，补齐跨页段落、表格和图文归属所需的邻页。一个采样业务单元可以包含多个位置的页面。

对照原页文字、图像、译稿和渲染结果，结合已有问题记录判断，记录原页与输出页的对应关系和各自数量。按下文领域要求判断初始材料，再从问题、正确输出、版式例外和其它结果中提炼种子。

## 种子发现思路

冷启动和后续调查都可参考以下思路寻找种子。根据任务目标和当前证据按需选择，也可沿材料揭示的其他关系展开。

- **内容完整与归属**：从正文、标题、列表、图注和注释的完整性与归属寻找遗漏、重复、错列或错误接管，核对保留、省略及空译稿处置的依据。
- **语义与数据对应**：从命题、指代、术语、数字、单位、表格、公式和引用寻找对应关系。正确术语、同系列标题和可靠表达也可启发关联检查。
- **跨页连续性**：从段落、表格、注释及图文关系的跨页承接寻找问题与正确组织方式，调查它们在相关页面中的适用条件。
- **视觉与阅读顺序**：从栏序、分页、遮挡、图文位置、公式和保留原页衔接寻找影响阅读的版式条件。特殊版式、低频结构与正确布局都可提供线索。
- **事实与方案变化**：从新语境、`page` 归属、待写入载荷和未决变化寻找需要重查的页面与输出。`pages` 数量相同也可能发生内容与关系变化。

## 种子账本与循环执行

通过 `workspace_run` 将种子账本保存在 `work/TASKNAME-seeds.json`，并在循环中实时更新：

- 先将种子写入账本，再取证和判断。
- 得出新增或修改种子的结论时，立即写入账本。

### 1. 冷启动后初始化

冷启动完成后，设置 `completedRounds = 1`。从实际结果中提炼种子，将其 `consumed` 设为 `false`，并按目标轮次加入 `seeds`。

提炼示例如下：

|材料|初查发现|
|---|---|
|原稿第 4 页的表格以 `Small: 10` 结束，第 5 页重复表头 `Size / Price` 后列出 `Medium: 15` 和 `Large: 20`。对应译稿与输出只有「小号：10」和「大号：20」。|跨页表格遗漏了续页首行「中号：15」。|

```jsonc
{
  "completedRounds": 1, // 已完成的总轮数，正整数，包含冷启动
  "seeds": {
    "2": [ // 目标轮次，以正整数的字符串形式作为键，每轮对应一个种子数组
      {
        "pattern": "初查发现原稿第 4 至 5 页的跨页表格在输出中遗漏「Medium: 15」一行，该行位于续页重复表头之后。调查任务范围内带重复表头的跨页表格，对照原页、译稿和输出核验续页数据行是否完整、是否归入正确表格。", // 非空字符串，描述调查对象或条件，以及需要核验的问题
        "consumed": false // 完成取证、结果处理和后续种子提炼后为 true，尚需处理或受阻时为 false
      }
    ]
  }
}
```

### 2. 每轮推进

1. 通过 `workspace_run` 读取账本，选择 `consumed === false` 的种子。相关模式可以合批调查。若 `completedRounds < 2` 且没有未消耗种子，先补入并保存种子，再取证：
   - 还有材料未检查时，选择尚未检查的业务单元，补入调查种子。
   - 材料已全部读取时，围绕已有结果的关系、反例或适用边界，补入复核种子。
2. 调用工具取得本轮证据，读取返回结果。按下文领域要求对照原页、译稿与输出，处理内容、跨页归属和版式问题，并按单元安排处理方案与提交。
3. 按种子定义提炼后续调查方向，复用有效证据。新增种子或新事实要求重查已有种子时，保存相应内容并将其 `consumed` 设为 `false`。发现范围外的问题时，记录调查理由，交由用户决定。
4. 按处理结果更新种子状态：完成取证、结果处理和后续提炼的种子设为 `consumed = true`，调查结论为保留原状时同样适用。仍需补查或受阻的种子设为 `consumed = false`。
5. 本轮完成后，执行 `completedRounds = completedRounds + 1`。

同轮处理多个种子、搜索或采样都计为一轮。仅在完成本轮后更新 `completedRounds`。

在业务工作材料中按轮号保存取证结果的位置、对象结论、方案、实际处理范围、未决事项和后续模式，用对象身份关联种子。没有新增模式时，记录结束该调查方向的依据。

### 3. 继续调查与收敛判断

每轮完成后，通过 `workspace_run` 重新读取账本，核对字段、轮数与逐轮记录，并检查：

- `completedRounds < 2` 时，按「每轮推进」补充调查。
- 仅当 `completedRounds >= 2`、本轮无新种子、全部种子满足 `consumed === true`，且任务范围与成果要求均已满足时，结束循环。
- 有新种子、`consumed === false` 的种子、覆盖缺口或待核验的新事实时，补充或更新种子，不受轮数限制继续调查。

读取工具返回的检查结果，按结果推进。受阻时，对应种子保持 `consumed = false`，记录阻碍与继续条件。在业务工作材料中保存检查结果的位置，以及结束或受阻的依据。

## 领域判断与成果核验

冷启动和种子调查都按以下要求处理目标。

按稳定 `page` 身份保存完整发现集合、当前结论、证据和完整待写入载荷。分别记录原稿范围、内容阅读和视觉检查的范围。

### 1. 对照内容与输出

根据初始材料或当前种子定位相关原页、译稿和对应输出，核对正文、标题、列表、图注、表格、公式以及跨页归属。

用程序取得位置和数量，再阅读必要内容与渲染结果。记录程序定位、语义阅读和视觉检查各自的范围。

提取结果、阅读顺序或归属有疑点时，补查原页图像、邻页和对应输出。图像、宿主能力或原稿证据仍不足时，记录已查材料、具体缺口和继续条件。继续处理可独立确定的页面。

### 2. 判断、修正与单元提交

对每个目标或已发现问题形成修正、保留或未决结论。修改时保存相关页完整载荷，跨页归属变化核对所有受影响 `pages`。内容核对结果写入 `reviewed`，未决与续做说明写入 `notes`。

当前单元通过内容、跨页覆盖及必要视觉检查后，按全局 `业务单元与提交` 安排提交。跨页调整时，一同准备所有相关页面的完整载荷。

默认提交本单元并核对结果，再进入下一单元。统一提交时，先保存方案再处理下一单元。`report` 保存检查通过的草稿方案后，继续调查。

按以下要求核对修改结果：

- 对修改后的风险输出重新预览。只读方案使用草稿预览。
- `apply` 按逐页回执与最新快照核对写入结果。
- 跨页写入部分成功时，恢复完整的内容覆盖和一致的归属。

### 3. 核对成果

- 记录实际内容阅读与视觉检查的范围、证据和种子的处理结果。
- 核对指定目标和全部发现对象的当前结论。
- 完成当前种子涉及的对象处理。遇到阻碍时，在业务工作材料中说明原因，并将对应种子保留为未消耗。
- 核验最终载荷与跨页归属对相关内容的影响。

核对用户要求的逐页覆盖、当前种子涉及的输出和方案影响。重新预览有风险的输出。内容完整性或归属发生变化时，处理全部受影响的原页，并用新事实提炼种子。

## 交付

交付时提供种子账本和业务工作材料链接，并说明：

- 代表性模式，以及循环结束或受阻的依据。
- 原稿范围、实际内容阅读和视觉检查的范围。
- 主要问题、实际修正和未决事项。
- `reviewed` 的记录情况和任务完成率。

按原稿页身份统计修正、保留和未决数量，每页只计入一类。页面仍有影响结论的未决问题时，将其计入未决，并保存该页已经确定的修正。

核对三类数量的合计是否与实际已判断原稿页数一致，说明尚未判断的范围。问题类型可以重叠，另行统计输出页数量。按逐页回执统计实际写入数量。

记录拟议方案时注明它与工程现值的区别。没有发现问题时，说明实际内容阅读与视觉检查的范围和依据。完成全部指定原页及对应输出所要求的内容与视觉判断后，才称完成全量逐页检查。
