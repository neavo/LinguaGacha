# `pages` 审校

本流程对照原稿、已有或拟议译稿及渲染结果，检查、审校和修正内容与视觉呈现。

## 目标与范围

用户要求审校时，按其要求确定范围，未限定时覆盖当前工程全文。用户指定问题时，围绕该问题及其必要关联开展调查。用户要求逐页审校时，覆盖指定范围内全部原页及对应输出，完成所要求的内容与视觉判断。

从 `pages` 按对象身份解析范围内的实际目标，读取 `page` 处置、`reviewed` 和 `notes`。审查草稿时记录方案来源，并将其与工程现值区分。`reviewed` 是已有核对记录，当前修改或新证据仍需判断影响。

按全局 `业务单元与提交` 的页面默认规模分组，用 `file_path` 与原稿 `page` 确定页面身份并计数。将跨页段落、表格及图文归属相关的页面放在一起判断，按需读取组外页面补充语境。将输出页、问题与证据关联到原稿页，按原稿页身份去重后统计覆盖范围。

## 冷启动

用户指定问题或页面时，先调查指定目标及其必要关联。审校时优先核验可用的相关警告或已有问题记录，并关联对应原页与输出。

没有相关线索时，在任务范围内按文件结构、来源顺序和内容分布合理均匀采样。实际读取至少一个完整业务单元，保留完整语境和对象关联。

对照原页文字、图像、译稿和渲染结果，调查跨页结构时一并读取必要邻页。记录原页与输出页的对应关系和各自数量。按下文领域要求判断初始材料，再从问题、正确输出、版式例外和其它结果中提炼种子。

## 种子发现思路

冷启动和后续调查都可参考以下思路寻找种子。根据任务目标和当前证据按需选择，也可沿材料揭示的其他关系展开。

- **内容完整与归属**：从正文、标题、列表、图注和注释的完整性与归属寻找遗漏、重复、错列或错误接管，核对保留、省略及空译稿处置的依据。
- **语义与数据对应**：从命题、指代、术语、数字、单位、表格、公式和引用寻找对应关系。正确术语、同系列标题和可靠表达也可启发关联检查。
- **跨页连续性**：从段落、表格、注释及图文关系的跨页承接寻找问题与正确组织方式，调查它们在相关页面中的适用条件。
- **视觉与阅读顺序**：从栏序、分页、遮挡、图文位置、公式和保留原页衔接寻找影响阅读的版式条件。特殊版式、低频结构与正确布局都可提供线索。
- **事实与方案变化**：从新语境、`page` 归属、待写入载荷和未决变化寻找需要重查的页面与输出。`pages` 数量相同也可能发生内容与关系变化。

例如，从表格跨页遗漏形成调查同类表格的模式。若结果显示重复表头与单元格承接共同触发遗漏，再调查这一组合条件，并核验对应原页和输出。

## 种子列表与循环执行

在本任务的 `work/` 子目录中维护一份种子列表。每个种子只记录以下两项：

|字段|含义|
|---|---|
|模式|根据实际材料或调查结果提出规律、关系或问题，写清触发证据、调查对象、适用条件和核验方法|
|是否消耗|是否已完成该模式的取证、结果处理和后续种子提炼|

将新增种子标为未消耗。冷启动完成后，至少再完成一轮调查，包括取证、结果处理和后续种子提炼。

初始结果暂时无法形成关联种子时，从尚未检查的材料中寻找线索：选择另一个能补充调查视角的业务单元，记录待查模式，再读取材料并判断。

已读完任务范围内的材料并完成所需核验时，记录完成依据。材料或工具受阻时，记录未完成的调查和继续所需的条件。

按以下步骤循环调查：

1. 选择未消耗的种子，按下文领域要求取证、判断并处理结果。相关模式可以合批调查。
2. 从错误、正确案例、反例、关系和证据缺口中提炼后续模式，与已有种子比较。合并等价模式，复用有效证据，将新模式加入列表。同类实例补充到业务工作材料中。
3. 新事实改变已有模式的适用条件或结论，需要重查时，更新该模式并标为未消耗。发现范围外的问题时，说明调查理由，交由用户决定。
4. 完成取证、结果处理和后续提炼后，将对应种子标为已消耗。根据新事实仍需补查该模式时，将它保留为未消耗。继续处理列表中未消耗的种子。

直接更新种子列表。在业务工作材料中保存证据、对象结论、完整方案、实际处理范围和具体未决事项，用文件位置和对象身份关联这些记录。

### 循环结束与任务完成

结束自启发循环前，确认以下条件均已满足：

- 已消耗列表中的全部种子。
- 已完成冷启动后的至少一轮调查，或已读完任务范围内的材料并完成所需核验。

将未完成或受阻的种子保留为未消耗。暂停调查时，说明原因和继续所需的条件。

交付前，核对用户要求的覆盖范围和领域成果。还有指定对象需要处理时，继续完成判断，并用新事实补充或更新种子。在业务工作材料中记录循环结束或受阻的依据。

## 领域判断与成果核验

冷启动和种子调查都按以下要求处理目标。

按稳定 `page` 身份保存完整发现集合、当前结论、证据和完整待写入载荷。分别记录原稿范围、内容阅读和视觉检查的范围。

### 1. 对照内容与输出

根据初始材料或当前种子定位相关原页、译稿和对应输出，核对正文、标题、列表、图注、表格、公式以及跨页归属。

用程序取得位置和数量，再阅读必要内容与渲染结果。记录程序定位、语义阅读和视觉检查各自的范围。

提取结果、阅读顺序或归属有疑点时，补查原页图像、邻页和对应输出。图像、宿主能力或原稿证据仍不足时，记录已查材料、具体缺口和继续条件。继续处理可独立确定的页面。

### 2. 判断、修正与单元提交

对每个目标或已发现问题形成修正、保留或未决结论。修改时保存相关页完整载荷，跨页归属变化核对所有受影响 `pages`。内容核对结果写入 `reviewed`，未决与续做说明写入 `notes`。

当前单元通过内容、跨页覆盖及必要视觉检查后，按全局 `业务单元与提交` 安排提交。跨页调整时，一同准备所有相关页面的完整载荷。

默认提交本单元并核对结果，再进入下一单元。统一提交时，先保存方案再处理下一单元。`report` 保存检查通过的草稿方案后，继续调查。

按以下要求核对修改结果：

- 对修改后的风险输出重新预览。只读方案使用草稿预览。
- `apply` 按逐页回执与最新快照核对写入结果。
- 跨页写入部分成功时，恢复完整的内容覆盖和一致的归属。

### 3. 核对成果

- 记录实际内容阅读与视觉检查的范围、证据和种子的处理结果。
- 核对指定目标和全部发现对象的当前结论。
- 完成当前种子涉及的对象处理。遇到阻碍时，在业务工作材料中说明原因，并将对应种子保留为未消耗。
- 核验最终载荷与跨页归属对相关内容的影响。

核对用户要求的逐页覆盖、当前种子涉及的输出和方案影响。重新预览有风险的输出。内容完整性或归属发生变化时，处理全部受影响的原页，并用新事实提炼种子。

## 交付

交付时提供种子列表和业务工作材料链接，并说明：

- 代表性模式，以及循环结束或受阻的依据。
- 原稿范围、实际内容阅读和视觉检查的范围。
- 主要问题、实际修正和未决事项。
- `reviewed` 的记录情况和任务完成率。

按原稿页身份统计修正、保留和未决数量，每页只计入一类。页面仍有影响结论的未决问题时，将其计入未决，并保存该页已经确定的修正。

核对三类数量的合计是否与实际已判断原稿页数一致，说明尚未判断的范围。问题类型可以重叠，另行统计输出页数量。按逐页回执统计实际写入数量。

记录拟议方案时注明它与工程现值的区别。没有发现问题时，说明实际内容阅读与视觉检查的范围和依据。完成全部指定原页及对应输出所要求的内容与视觉判断后，才称完成全量逐页检查。
