# `pages` 审校

本流程对照原稿、已有或拟议译稿及渲染结果，审校内容与视觉呈现。按用户要求确定审校范围，未限定时覆盖当前工程全文。从下文列出的冷启动方向取证并形成种子，通过自启发循环持续调查和修正问题。用户要求逐页审校时，覆盖指定范围内全部原页及对应输出，完成所要求的内容与视觉判断。

用户指定问题时，围绕该问题及其必要关联开展调查。优先处理某类页面表示顺序，用户明确限定页面时按该边界处理。取证遵守可读取的语境范围，修改遵守可修改的对象与字段边界。

## 自启发循环的概念

|概念|在本流程中的含义|
|---|---|
|冷启动方向|本流程预设的页面审校调查入口，用于从实际材料中形成第一批种子|
|种子|基于原稿、译稿和渲染证据形成的调查线索。描述要调查的内容归属、跨页关系或版式条件，以及核验方法。种子可以来自冷启动调查，也可以来自后续轮次的结果|
|调查结果|内容与视觉判断、修正或保留处置，以及原页与输出的对应关系。正确案例、错误、反例、关系、排除依据和证据缺口都参与后续种子提炼|
|自启发循环|应用种子取得证据，判断并处理结果，再从结果中提炼新种子或更新已有种子，逐轮继续|
|轮次|以一组种子为输入，完成这些种子的应用、结果处理和后续种子提炼的一次执行过程。一轮可以跨多个批次、工具调用和提交|

调查依据、对象关系、适用条件或核验方法发生实质变化时，形成新种子或更新已有种子。同类实例补充到对应调查结果中，新旧比较覆盖全部历史轮次。

## 冷启动方向

从 `pages` 按对象身份解析范围内的实际目标，读取 `page` 处置、`reviewed` 和 `notes`。审查草稿时记录方案来源，并将其与工程现值区分。`reviewed` 是已有核对记录，当前修改或新证据仍需判断影响。

结合内容风险与实际版式选择代表 `pages`，跨页结构连同相关页调查。保留原页与输出页的对应关系，分别记录两者数量。

将译稿与原页文字、图像及必要邻页对照，沿以下适用方向取证并形成种子。用户指定问题时，结合该问题选择方向：

- **内容完整与归属**：核对正文、标题、列表、图注和注释的完整性与归属，检查保留、省略及空译稿处置的事实依据。
- **语义与数据对应**：核对命题、指代、术语、数字、单位、表格、公式和引用，判断表达是否符合内容用途。
- **跨页连续性**：调查段落、表格、注释及图文关系的跨页承接，核对原页与输出页之间的遗漏、重复和错误接管。
- **视觉与阅读顺序**：检查渲染后的栏序、分页、遮挡、图文位置、公式和保留原页衔接，判断是否支持正确阅读。

初始材料包含实际存在的不同版式、低频结构和可靠输出。逐个为适用方向取得证据，并调查正确布局的适用边界。

## 工作记录

在本任务的 `work/` 子目录中，每轮保存一份 `Round` 记录，按执行顺序排列。沿冷启动方向形成的种子填入第一轮的 `seeds`。通过文件位置和对象标识引用证据与业务成果。

```ts
type Seed = {
  id: string;
  description: string; // 调查线索、适用条件及核验方法
  basis: string[];     // 来源证据或结果位置
};
type Round = {
  seeds: Seed[];       // 本轮需要处理的种子
  results: string[];   // 按种子关联的检查范围、处理结果和证据位置
  findings: string;    // 提炼结果及其与已有种子的比较依据
  next: Seed[];        // 下一轮的新种子或更新后的种子
  remaining: string[]; // 尚未完成的工作或受阻原因
};
```

种子通过 `id` 关联记录。更新时记录变化与依据，保留此前轮次的描述和结果。轮次记录同时保存分页位置、已处理对象与剩余工作。

按稳定 `page` 身份保存完整发现集合、当前结论、证据和完整待写入载荷。分别记录原稿范围、内容阅读和视觉检查的范围。

## 每轮执行

### 1. 应用种子并对照内容与输出

按种子定位相关原页、译稿和对应输出，核对正文、标题、列表、图注、表格、公式以及跨页归属。

用程序取得位置和数量，实际阅读必要内容与渲染结果。分别记录程序定位、语义阅读和视觉检查范围。图像、宿主能力或原稿证据不足时，保存具体缺口。

### 2. 判断、修正与单元提交

对每个目标或已发现问题形成修正、保留或未决结论。修改时保存相关页完整载荷，跨页归属变化核对所有受影响 `pages`。内容核对结果写入 `reviewed`，未决与续做说明写入 `notes`。

按通用的 `业务单元与提交` 流程检查和提交，当前单元需通过内容及必要视觉检查。按以下方式核对修改结果：

- 对修改后的风险输出重新预览。只读方案使用草稿预览。
- 按逐页回执与最新快照核对写入结果。
- 跨页修改部分成功时，恢复完整的内容覆盖和一致的归属。

### 3. 核对本轮成果

- 记录实际内容阅读与视觉检查的范围、适用冷启动方向的证据与结果，以及本轮种子的应用结果。
- 核对指定目标和全部发现对象的当前结论。
- 完成本轮种子涉及的对象处理，将受阻事项写入 `remaining`。
- 核验最终载荷与跨页归属对相关内容的影响。

核对用户要求的逐页覆盖、当前种子涉及的输出及方案影响。风险输出重新预览，完整性和归属变化对应的全部原页均需处理，所得新事实进入种子提炼。

### 4. 提炼后续种子

从本轮问题、正确输出、版式例外和归属变化中检查以下种子来源：

- 遗漏、错列、图注归属和分页问题启发同结构 `pages` 检查。
- 正确术语、同系列标题、表格对应、引用和跨页组织提供相关 `pages` 的核验线索，其适用性由内容与结构确认。
- 特殊版式、跨页承接和保留原页等例外，要求核对统一修正的适用边界。
- 新语境、`page` 归属、待写入载荷或未决变化要求核验相关页及其输出，`pages` 数量相同也要核对内容与关系的变化。

例如，从表格跨页遗漏形成调查同类表格的种子。若后续结果显示重复表头与单元格承接共同触发遗漏，再形成调查这一组合条件的种子，并核验对应原页和输出。

按以下步骤整理本轮提炼结果：

1. 从本轮结果中提炼种子，与全部已有种子比较，在 `findings` 中记录依据。
2. 合并等价种子，复用有效证据。条件或证据变化时，记录种子的更新。
3. 对范围外发现单独说明理由，交由用户决定。
4. 将新增或实质更新的种子写入 `next`。

完成本轮处理后，根据 `next` 接续执行：

- `next` 有内容时，建立下一份 `Round`，将这些种子填入新一轮的 `seeds` 并执行。
- `next` 为空时，按下节的自启发循环停止条件作出判断。

## 自启发循环停止条件

完整执行本轮种子的应用、结果处理与后续种子提炼，并与全部已有种子比较后，既无法产生新种子，也没有形成需要继续调查的已有种子更新，自启发循环才停止。

在 `findings` 中记录无法继续提炼的证据与比较依据，此时 `next` 为空。

## 交付

交付说明循环执行轮次、代表性种子及停止或受阻依据，并提供执行记录链接。说明原稿范围、实际内容阅读与视觉检查范围、主要问题、实际修正及未决，分别说明 `reviewed` 和完成率。拟议方案与工程现值分别记录，只有全部指定原页及对应输出均完成所要求的判断时，才称完成全量逐页检查。
