# 翻译工作流

本技能拥有工程翻译任务的执行方式、范围、业务单元和结果验收。先选择执行方式；进入 Agent 文本判断路径时，加载并遵循 `self-inspiring` 与 `translation-rules` 技能。

## 1. 执行方式

|用户目标|执行方式|
|---|---|
|开始或继续当前工程普通全量待译范围|调用 `run_batch_translation`，等待终态并报告实际结果|
|指定文件、章节、item 或文本条件的补译|Agent 工作区，按范围内目标规模组织业务单元|
|已有译文的审校、修正、重译或落实审校结论|Agent 工作区|
|指定范围同时补译与审校|同一 Agent 任务内组合两类目标|
|全量翻译后继续审校|批量运行正常结束后读取最新工程事实，继续用户要求的 Agent 审校|

### 批量执行

`run_batch_translation` 承接当前工程普通全量开始或继续翻译，范围和结果契约以该工具为准。工程外文本先导入工程；本技能基于已导入的工程事实工作。

批量分支直接按工具终态与累计进度报告实际完成、失败和停止情况；后续 Agent 判断再加载对应技能与最新快照。取消、超时或用户主动停止时遵循工具的停止语义，暂停依赖该运行的后续工作。运行结束后的失败或剩余条目，按实际状态与用户已要求的各阶段范围处理，并说明尚未完成的范围。

## 2. Agent 任务范围与目标

`scope` 至少记录：

- `result: report / change`；
- 用户要求的工作：补译、审校或两者组合；
- item、状态、文件、警告或文本选择条件；
- 审校目标的 `candidate_policy: all / discovered`，以及是否包含主动发现目标；
- 可写字段、排除项与语境读取边界。

调查范围是证据池，调整范围是可以形成结果的业务表面。范围外 item 只提供已授权的语境、一致性或边界证据。

补译从全部明确的未译目标开始；逐条审查使用 `all`，全部符合条件的 item 都进入目标集合。其余主动审查使用 `discovered`，从警告、分散样本和领域诊断方向实际发现候选；用户限定警告或指定 item 时保持该边界。排除、跳过和重复等条目是否属于目标，按用户范围与当前工程契约确定。

每个 item 记录当前工作 `translate / review`：没有译文且用户要求补译时为 translate，已有译文且用户要求审校时为 review。同一任务可以包含两类目标；正文与姓名字段在同一个 item 结论中最终化。补译所得译文按形成判据核验，用户明确要求后续审校时再依据新事实安排该阶段，并复用仍有效的证据。

## 3. 领域前沿与业务单元

按 `translation-rules` 建立初始检查、独立发现方向和后继启发；按 `self-inspiring` 完整执行每轮探查、对象判断、后继方向生成与回流。

目标按 `project_meta` 的文件顺序和文件内顺序组成稳定业务单元。规模、材料密度与强关联关系共同决定单元大小，采用 System Prompt 的组织原则。每个单元完整处置其中全部 targets；新的工程事实影响已处理对象时，将其重新纳入相应核验。

共同 `scope`、`checks` 与 `targets` 遵循自启发技能。译文 target 保留 item 身份、已完成阶段、当前 translate 或 review 目的、证据、`update / keep / blocked` 结论及必要的拟写字段。当前拟写值与已提交事实分别记录，恢复时依据真实结果继续剩余阶段。

## 4. 业务结果与写入

信息结果累计各业务单元的领域结论。工程变更默认在业务单元完成后，为该单元的必要 item 更新形成并校验提交批次；依据 System Prompt 输出业务结果、提交并处理回执。

`translation-rules` 拥有拟写字段及人工处置含义，实际字段副作用和身份要求以当前 contract 为准。提交后核对实际译文、warnings 与相关字段副作用；新的决定性证据和受影响结论回流自启发前沿。

部分成功后保留实际结果，处理拒绝项与剩余目标。业务单元的写入完成后，继续执行尚未完成的发现和关联核验。

## 5. 任务验收与报告

自启发满足整轮稳定条件后，核对：

- 任务范围与全部适用阶段一致，补译与审校目标均已按用户要求处理；
- 实际候选与 `all / discovered` 策略一致；独立方向、程序扫描和语义样本的实际覆盖可追溯；
- 每个 item 有唯一当前处置，未决写明决定性缺口与解除方式；
- 拟写字段、change 和实际回执可对账，变更符合授权范围；
- 受影响的译文、术语应用、结构与字段副作用已经完成必要核验。

验收产生新对象、关系、边界、拟写值变化或补查方向时，回到自启发循环。信息结果在稳定与验收通过后交付；工程变更同时核对实际写入和剩余目标。

对外报告用户范围、阶段完成情况、实际候选、扫描与语义覆盖、`update / keep / blocked` 数量、主要问题、代表证据及未决。工程变更补充实际写入与尚未落实的目标；批量阶段采用工具返回的累计口径，与 Agent 当前目标的处置计数分别说明。

完成只证明声明范围内所要求的发现与处置已经完成。逐条语义审查的声明只适用于 `candidate_policy: all`，覆盖中存在未决时明确其影响。
