# 翻译工作流

本技能拥有工程翻译任务的执行方式、范围、业务单元和结果验收。先选择执行方式；进入 Agent 文本判断路径时，加载并遵循 `self-inspiring` 与 `translation-rules` 技能。

## 1. 范围确认与执行方式

全量翻译和指定文件、章节、item 或文本条件的补译遵循同一流程。工程外文本先导入工程，再读取当前事实确定范围。

范围内存在失败条目且用户尚未明确是否处理时，调用 `ask_user` 说明失败数量，依次提供「处理失败条目」「保留失败条目」，根据工具返回的决定确定目标。已有明确决定直接沿用；等待、到期和取消遵循 System Prompt 的用户交互规则。

普通待译条目与按已确定的处理决定纳入的失败条目共同构成翻译目标。按 item 身份去重，正文与姓名字段合为一个对象；其它状态按用户明确范围与工程契约处理。

通过程序统计和必要的材料抽样，按 System Prompt 的业务单元组织规则预估规模，在本阶段执行前确定组织依据与执行方式：

|翻译目标规模或用户阶段|执行方式|
|---|---|
|翻译目标为零|报告当前状态，继续用户已要求的其它阶段|
|一个业务单元|Agent 工作区翻译并提交|
|超过一个业务单元|调用 `run_batch_translation` 执行本阶段全部选定翻译目标|
|已有译文审校、修正、明确重译或落实审校结论|Agent 工作区|

组合任务分别组织翻译与审校目标。分流由 Agent 自动完成，执行前说明范围、数量与执行方式，并满足用户明确要求。Agent 内翻译使用当前模型，批量翻译使用保存的批量模型偏好，实际配置由宿主展示。

指定范围先解析为明确 item 身份，再交给批量工具。批量引擎自行提交译文，结果字段与停止语义以工具契约为准；本轮结果和工程累计进度分别解读。正常结束后加载最新事实，继续已授权的后续阶段；停止后暂停依赖该运行的工作，用户主动停止后等待明确的继续要求。

引擎重试结束后报告实际失败与剩余范围，本轮新产生的失败条目不自动启动新阶段。后续处理遵循上述失败条目决定规则。

## 2. Agent 任务范围与目标

`scope` 至少记录：

- `result: report / change`；
- 用户要求的工作：补译、审校或两者组合；
- item、状态、文件、警告或文本选择条件；
- 审校目标的 `candidate_policy: all / discovered`，以及是否包含主动发现目标；
- 可写字段、排除项与语境读取边界。

调查范围是证据池，调整范围是可以形成结果的业务表面。范围外 item 只提供已授权的语境、一致性或边界证据。

补译从全部明确的未译目标开始；逐条审查使用 `all`，全部符合条件的 item 都进入目标集合。其余主动审查使用 `discovered`，从警告、分散样本和领域诊断方向实际发现候选；用户限定警告或指定 item 时保持该边界。排除、跳过和重复等条目是否属于目标，按用户范围与当前工程契约确定。

每个 item 记录当前工作 `translate / review`：普通待译和用户同意重试的失败目标为 translate，已有译文且用户要求审校时为 review。同一任务可以包含两类目标；正文与姓名字段在同一个 item 结论中最终化。补译所得译文按形成判据核验，用户明确要求后续审校时再依据新事实安排该阶段，并复用仍有效的证据。

## 3. 领域前沿与业务单元

`translation-rules` 提供初始检查与独立发现方向，`self-inspiring` 组织探查、判断与回流。业务单元按 `project_meta` 的文件顺序和文件内顺序组成，规模与边界遵循 System Prompt。

共同记录遵循自启发协议；译文 target 另保留当前 `translate / review` 目的、已完成阶段、`update / keep / blocked` 结论与拟写字段。拟写值与实际提交事实分别记录，恢复时据回执继续剩余阶段。

## 4. 业务结果与写入

工程变更默认在业务单元完成后提交该单元的必要 item 更新；信息结果累计单元结论。拟写字段与人工处置含义归 `translation-rules`，提交、部分成功和快照恢复遵循 System Prompt。实际写入后核对译文、warnings 与字段副作用，产生的增量按自启发协议回流。

## 5. 任务验收与报告

满足自启发稳定条件后，核对翻译领域结果：

- 补译、审校及其它适用阶段覆盖用户范围，实际候选符合 `all / discovered` 策略；
- 拟写字段、change 与真实回执可对账；
- 译文、术语应用、结构及字段副作用已完成必要核验。

验收发现新证据或缺口时按自启发协议继续。报告遵循 System Prompt，补充各阶段完成情况、候选策略、`update / keep / blocked` 数量与实际写入。批量阶段的本轮结果、工程累计进度与 Agent 处置计数分别说明；逐条语义审查仅在 `candidate_policy: all` 且实际覆盖成立时声明。
