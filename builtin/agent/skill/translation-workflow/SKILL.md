# 翻译工作流

## 技能加载

加载并遵循 `translation-rules` 技能。

本技能是当前工程翻译任务的流程权威，把用户范围、工程事实和主动发现组织成可追溯、可收敛的任务。

工作流以**自启发循环**为核心：完整消费当前发现前沿，根据结果生成下一轮候选、关系、边界和探查方向，直到全部结果均已回流，并在最近完整一轮保持稳定。

## 1. 路径与执行方式

先根据目标条目的当前译文状态和用户明确范围确定任务路径。两条路径共享范围确认、自启发循环、业务单元、写入和核验协议，执行方式如下：

|路径|目标|用途|执行方式|
|---|---|---|---|
|`translate`|没有译文的条目|形成新译文或补译空缺|Agent 或工作台批量翻译|
|`review`|已有译文的条目|审校、修正、重译或落实审校结论|Agent|

每次工作流运行固定一条路径，目标和结论在该路径内核对。

### 翻译规模

根据用户说明和当前工程事实一次估定 `translate` 的目标规模：

- 约 1000 条以内通常在 Agent 内完成；
- 明显更大的连续目标优先推荐工作台批量翻译；
- 工程内文本直接进入工作台，工程外长文本先导入工程；
- 用户明确要求使用 Agent 时，说明串行处理的时间与成本后执行；
- 同一固定范围沿用首次规模判断。

## 2. 固定范围

`scope` 至少记录：

- `result`: `report` 或 `change`；
- `path`: `translate` 或 `review`；
- item、状态、文件、警告或文本选择条件；
- `candidate_policy`: `all` 或 `discovered`；
- 可写字段与明确排除项；
- 语境读取边界。

调查范围是本次任务的证据池，调整范围是任务可以形成结果的业务表面。范围外 item 只提供语境、一致性或边界证据。

用户要求逐条处理全部范围时使用 `all`，每个符合路径条件的 item 都成为目标；其余主动审查使用 `discovered`，只有警告、分散样本和诊断方向实际命中的 item 成为候选。用户明确限定警告或指定 item 时保持该边界。`translate` 只接收没有译文的条目，`review` 只接收已有译文的条目。

item 是不可拆业务对象；正文和姓名字段可以分别判断，但在同一个 item 结论中最终化。目标按 `project_meta` 的文件顺序和文件内顺序组成稳定业务单元，工程变更结果默认逐业务单元写入。

修改正文译文或确认 `ERROR` 条目的现有非空译文表示接受该结果，项目会完成条目、清除既有重试次数，并在显式状态之后自动协调同文件同原文条目的待翻译代表与重复状态；变更清单只表达 `NONE`、`PROCESSED` 或 `EXCLUDED` 人工状态。

## 3. 工作资产

翻译任务维护 `scope`、`checks`、`targets` 和 `frontier`：

- `checks` 记录发现方向、来源、轮次、范围、方法、完整性、计数和产生的增量；
- `targets` 记录 item 证据，以及 `update`、`keep` 或 `blocked` 的唯一处置；
- `frontier` 记录下一轮检查、受影响 item 和具体补查。

跨快照仍有效的范围、已确认结论、未决和恢复摘要写入 `task/**`；可由当前快照重建的扫描结果、候选队列和待提交 change 写入 `scratch/**`。

## 4. 初始发现前沿

`translate` 从全部明确的未译目标开始，检查结构与保护内容、术语与姓名、必要语境和当前工程风格。

`review` 从已有译文和关联 warning 开始；广泛审查时使用四个具有不同判断对象的独立方向：

- **结构完整性**：warnings、保护结构、外文残留、行数和字段边界；
- **命题与语义关系对应**：主谓、施受、判断与归属、状态与体验主体、存在与位置、修饰关系和作用域，以及否定、数量、时间、因果、情态、不确定性和信息增删；
- **身份、称谓与指代**：结合说话人、受话人、被指对象、人物关系和当前剧情阶段，检查头衔、称谓、敬称、自称、对他人的称呼、人称代词和省略成分；
- **译名与表达一致性**：术语、姓名表记、别名、人物声音、语域和作品风格在相同适用条件下保持一致。

各方向分别记录检查范围、证据和方法。身份、称谓与指代确定参与者是谁，命题与语义关系对应核对这些参与者在原文和译文中的关系；同一 item 可以由多个方向提供证据，但只形成一个 target 和一个最终处置。剧情连续性与邻近文本是判断证据。定点修正、重译和落实审校结论都沿 `review` 路径处理；从用户指定目标、关联 warning 和必要语境开始，任务同时包含主动发现目标时再执行适用的独立方向。

从不同文件、位置和文本形态取得少量分散样本，用于选择适合当前语言、题材和译文状态的具体检查。可程序定位的检查完整扫描固定范围并记录扫描数、命中数、新候选数、分页、耗尽与截断；只能语义判断的视角按实际样本范围报告。

需要补充当前 item 的说话人、受话人、被指对象、命题参与者、人物关系或连续性事实时，先使用 `ws.tool.queryItemContexts` 读取规范邻近上下文；仍缺决定性证据时，围绕缺口补读足以完成判断的最少文本。

## 5. 问题速查表

|警告项目|说明|
|---|---|
|`SIMILARITY`|与原文相似度较高，检查是否存在漏翻|
|`FOREIGN_CHAR_RESIDUE`|译文中存在目标语言书写系统以外的文字，例如中文译文中的日文浊点|
|`TEXT_PRESERVE`|占位符、控制符或格式结构与原文存在差异，检查是否翻译了无需翻译的内容|
|`GLOSSARY`|术语在原文中命中但未在译文中出现，检查术语的落实情况|
|`RETRY_THRESHOLD`|重试次数达到阈值以后自动放行，检查最终收录值是否正确|
|`LINE_COUNT_MISMATCH`|原文与译文行数不同，矫正文本结构使行数对齐|

|条目状态|说明|
|---|---|
|`NONE`|等待翻译|
|`PROCESSED`|翻译成功|
|`ERROR`|翻译失败，需修复|
|`EXCLUDED`|排除的条目，一般无需翻译|
|`RULE_SKIPPED`|按过滤规则跳过的条目，一般无需翻译|
|`LANGUAGE_SKIPPED`|非目标语言的条目，一般无需翻译|
|`DUPLICATED`|重复条目，将复用同值译文，一般无需额外翻译|

## 6. 自启发循环

每轮按以下逻辑运行：

1. 从当前快照读取尚未执行的检查、受影响 item 和具体补查；
2. 合并内容等价且范围、方法和来源相同的检查；
3. 完整消费可程序定位的范围，记录分页、计数和代表证据；
4. 登记新候选、关系、边界、模式和决定性事实；
5. 处置新候选并重新核验受影响结论；
6. 把新模式和后继检查写入下一轮 `frontier`，记录启发来源、调查对象、范围和方法；
7. 保存本轮状态及其完整性回执。

以下增量全部回流下一轮：

- 新候选 item；
- `update`、`keep` 或 `blocked` 结论变化；
- 命题关系、术语、实体身份、说话人、受话人、指代或人物关系变化；
- 结构、语境或适用边界变化；
- 拟写值或未决集合变化；
- 新的可执行检查方向。

同一 item 可以因新的工程证据、关系、边界、受影响结论或写入验证结果重新进入审查。相同证据、范围和方法不重复生成同一检查。

每个后继检查必须能够回答“由什么结果启发、补查什么、使用什么范围与方法”。新模式需要具体工程证据，并通过完整扫描或明确样本边界证明实际适用范围。

### 自启发判例

|本轮事实|后继动作|
|---|---|
|姓名栏与正文对同一实体使用不同译名|核验该实体的其它引用、别名和称谓|
|术语没有落实或表现出多义|核验其它命中及适用语境边界|
|保护结构损坏|检查相同结构、形态变体和文本类型|
|外文残留|检查相同片段、所在文件和同类书写|
|主谓、施受、判断、归属或作用域发生偏移|检查相同结构或形成方式的其它命中|
|称谓、代词或省略成分暴露身份或关系偏移|核验同一说话人、受话人、被指对象及相同关系阶段的其它表达|
|人物声音或语域发生分歧|读取同一说话人或同场景的有限代表文本|
|新上下文改变既有判断|重新核验受影响 target 及其拟写值|
|写入后出现新的决定性 warning|重新核验当前译文和使用相同形成方式的目标|

## 7. 业务单元与写入

先完成确定性程序处理，再按自然文件边界、文本结构和已确认关系组织开放式语义目标。每个业务单元完整处置其中全部 targets，并按 `translation-rules` 的领域判据形成唯一的 `update`、`keep` 或 `blocked` 结论。

信息结果累计各业务单元结论。工程变更结果只为当前业务单元形成必要的 item 更新，并保留当前对象事实身份；字段副作用遵循当前工作区契约。每个业务单元形成并校验一个提交批次。

后续领域核验关注译文实际值、warnings 和字段副作用；新的决定性证据进入发现前沿，未完成的 targets 重新纳入业务单元。

## 8. 发现穷尽与结果验收

只有同时满足以下条件，才能结束自启发循环：

- 初始检查全部完整消费；
- 每个后继检查全部完整消费；
- 适用的独立方向全部完整消费，其结果均已回流；
- 所有扫描分页已消费且没有截断；
- 每个候选都有唯一合法处置；
- 所有受影响的既有结论已经重新核验；
- 每个 `blocked` 都有完整缺口和解除方式；
- 最近完整一轮的候选、结论、关系、边界、未决和补查集合保持稳定；
- 完成判定满足 `round > 0`。

结果验收同时核对固定范围与实际候选、checks 的完整性、targets 的处置总数、change 与拟写值、真实写入回执，以及范围外字段和数据集没有进入变更。

## 9. 收敛与报告

当前前沿清空前保持发现阶段；信息结果在全部业务单元处置完成后核验，工程变更结果在全部业务单元处置完成且写入取得真实回执后核验。

对外报告：

- 固定范围、实际候选和完整性；
- 已执行的独立与后继检查及扫描回执；
- `update`、`keep`、`blocked` 计数；
- 主要问题、代表证据和未决解除方式；
- 工程变更结果的真实写入回执。

完成只证明声明范围经过所选路径的发现覆盖并处置了全部实际候选；逐条语义审查的声明只适用于 `candidate_policy: all`。
