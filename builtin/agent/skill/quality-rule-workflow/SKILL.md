# 质量规则工作流

本技能组织从候选调查到规则、关系整理和实际交付的完整任务。使用 `self-inspiring` 维护调查记录与后继问题；术语判断遵循 `glossary-rules`，文本保护判断遵循 `text-preserve-rules`。关系整理是跨领域的质量环节，使用各领域产生的事实并将新问题回流到对应领域流程。任务类型、CodeAct、提交与异常处理遵循 System Prompt。

## 1. 确定范围并建立记录

|用户要求|默认动作|任务类型|
|---|---|---|
|提取术语|发现应收录的术语、确定译名、检查并写入术语表|`apply`|
|提取文本保护规则|发现需要保护的结构、形成安全表达式、检查并写入规则|`apply`|
|审查规则|检查现有规则，报告问题和建议|`report`|
|审校规则|检查现有规则，发现问题并写入修正结果|`apply`|

术语、名称、译名或实体使用 glossary，控制符、占位符、格式结构或文本保护使用 text_preserve，未限定类型时处理两类规则。用户只调用本技能时，默认维护当前工程两类规则，检查现有规则、发现未覆盖对象并落实必要修改，开始时说明范围。

分别确定调查范围和允许调整的范围，现有规则按以下方式参与：

|任务|现有规则怎样参与|`existing_entry_policy`|
|---|---|---|
|提取新规则|作为匹配、冲突和边界证据|`evidence_only`|
|整体维护、审查或审校|检查范围内全部现有规则|`all`|
|维护指定规则|修改指定对象，其余规则提供证据|`listed`|

规则覆盖、关系和集合最小性共同验收，先处理全部业务单元，再统一准备提交批次。分组遵循 System Prompt，范围与操作遵守用户限制。

从开始调查起持续维护 `self-inspiring` 的 `scope`、`checks`、`targets`，并补充以下领域记录。工作材料和交付正文保存在 `work/**`，提交清单写入 `changes/**`。

|记录|内容|
|---|---|
|`scope`|`result: report / apply`、`kinds`、调查与调整范围、`allowed_actions`、`target_entry_ids`、`existing_entry_policy`、是否发现未覆盖对象|
|质量对象|稳定键、`kind`、`origin: candidate / existing`、已有 `id`（如有）、来源、证据、待解决问题与当前结论|
|`necessity`|`required / not_required / unknown`，是否应收录|
|`resolution`|`direct / conditional / narrowed / split / blocked`，采用直接、条件、收窄、拆分或未决处理；条件处理用于 glossary|
|`action`|形成处置后，候选使用 `create / discard / blocked`，现有对象使用 `keep / update / delete / blocked`；排除保存理由，合并保留覆盖归属|
|`seed`|现有 glossary 条目的发现资格及当前依据|
|`proposals`|规则方案稳定键、类型、完整字段、`covers` 对象键集合、命中与边界依据、`candidate / selected / rejected` 状态|
|实体关系|影响本次规则决策的对象关系，引用对象稳定键和事实证据；记录 `structural / candidate / confirmed` 状态，关系图只展示已确认关系及当前译名|

未按已有 ID 限定时，`target_entry_ids` 为 `null`；单独调用技能的默认任务使用 `existing_entry_policy: all`。对象与方案的键独立于数组顺序，计数与反向覆盖从当前记录计算。

## 2. 发现并处置对象

items 是默认事实来源；缺少片段、顺序、层级或容器结构时依据 `project_meta` 定点读取 sources。初始检查包含指定对象、适用的既有规则核验、独立方向和 `seed: true` 条目启发的关联方向。既有条目暴露的覆盖、冲突与边界问题在声明范围内核验，`seed` 更新与问题回流遵循 `self-inspiring`。

发现未覆盖对象时，至少完成三个范围或方法实质不同的独立工程方向，并满足各领域的证据基础要求。纯既有规则审查、审校或定点维护按声明范围调查。

按当前调查记录组织每批工作：

1. 合批执行已知且独立的发现方法，保存完整候选来源集合，再按领域要求取得计数与必要语境，返回当前批次摘要。各方向分别保留实际范围和依据。
2. 模型逐对象形成处置，更新 `targets`；待判断对象保留具体问题，排除保存理由，合并或拆分保留成员去向。领域理由相同的对象可以批量处置，并保存成员范围。
3. 从当前问题汇总下一批补证，合批匹配、读取上下文并关联共享证据。复用仍有效的判断，返回新证据、反例及理解它们所需的旧结论。
4. 新事实引出可执行问题时进入自启发后继轮次；等价探查复用有效结果，继续处理尚未完成的独立方向和对象。

对象登记后，调用 `ws.tool.groupQualityRuleEntries` 组织结构关系。glossary 使用独立候选与 `seed: true` 既有条目分组，其余规则通过正式匹配提供参考；text_preserve 使用实际调查集合。完整消费工具分页，保留 component 与跨组关系。结构关系只用于组织证据和发现关系候选，不证明实体身份、别名、译名相同或可以合并；语义身份与最终合并由领域判断确定。

同一任务包含两类规则时，术语语境中的固定标记可以启发保护调查，结构槽位中的名称可以启发术语调查；各候选独立通过领域判据。

## 3. 整理关系并回流自启发

关系整理是两类规则共用的质量环节。结构分组产生的 `structural` 关系先组织共同审查；模型根据工程证据形成 `candidate` 关系，完成领域核验后才将其标为 `confirmed`。关系类型只表达当前证据支持的含义，例如同一实体、别名、包含、所属、消歧和共享词根候选；共享词根只能作为候选关系。

初步判断后形成关系图，用于检查重复节点、错误连接、孤立对象、关系冲突、译名不一致和证据缺口。图中发现的新对象、关系、边界、覆盖或决定性事实，登记为 `self-inspiring` 的 `triggered` 检查，指向触发它的对象、关系或证据，并将受影响对象重新加入下一轮。关系变化同步更新规则方案；没有影响领域判断的孤立对象可以保留并记录理由。

关系图可以在调查过程中多次更新。只有最近完整一轮的对象、结论、关系、边界、覆盖、拟写值、未决和补查集合稳定后，才进入共同验收。最终图只使用已确认关系和最终译名，并能通过关系记录追溯到对象及证据；不建立独立于领域对象记录的实体事实源。

## 4. 形成领域规则

从当前对象结论形成完整方案，字段依据与对象证据关联。已有结果仍有效时复用，缺少决定性事实时继续补证，实际未决按领域要求保留。

### 术语：词根、边界与最小集合

1. **确认资格与身份**：逐对象确认资格、译名、关系和处置，建立精确方案的 `covers`；未决对象保留独立身份与补证问题。
2. **形成词根候选**：对已确认属于同一对象或体系的多个词形调用 `ws.tool.deriveCommonLiteralRoots`，按 `glossary-rules` 选择安全的自然边界；没有安全候选时保留精确方案。
3. **检查匹配安全**：用 `ws.tool.matchLiterals` 比较词根与精确分支，核验新增命中、条件适用性及边界反例；不安全时收窄、拆分或保留精确分支。
4. **闭合对象覆盖**：逐对象核对直接、条件或精确分支覆盖，逐规则核对命中安全；无法安全表达的对象保留完整 `blocked` 结论。
5. **最小化集合**：覆盖闭合后删除调整范围内的冗余规则，重新计算 `covers`；出现缺口时回到身份、边界或覆盖步骤。

按 `glossary-rules` 完成每一步的术语资格、身份、译名和关系判断，并将依据与最终方案关联到 `covers`。

影响合并、拆分、译名或消歧的实体关系，随事实判断保存一次，供规则字段和关系整理共同使用。关系变化时更新受影响方案；未确认关系保留补证问题。

### 文本保护

按 `text-preserve-rules` 确认结构身份与逐字保持需求，再形成表达式；每条拟采用表达式独立编译并完整扫描声明范围的原始 `item.src`。表达式非法、不安全或覆盖过宽时收窄、拆分并重新取证；最后核对必须保护对象的表达式覆盖，或保留完整未决说明。详细表达式安全判据归 `text-preserve-rules`。

两类规则的资格、身份、边界、覆盖、字段和未决变化均回流 `self-inspiring`。对象与方案的对应关系由 `covers` 表达，多个精确分支可以共同覆盖一个对象，范围外保留规则参与最终工程集合的覆盖核对。

## 5. 验收并提交

满足 `self-inspiring` 的调查与稳定条件后，从完整发现集合、对象记录和当前方案核对结果。程序负责集合、引用、字段与计数核对，模型负责语义判断；复用有效结果，只处理实际缺口。

|验收内容|通过依据|
|---|---|
|对象完整性|指定对象、检查产生的候选及成员均可关联到当前处置、排除理由、合并归属或完整未决；实际范围、分页、后继问题与记录一致|
|规则正确性|字段完整且有依据，`seed` 与证据一致，选定规则具有领域要求的匹配与语义判断；应收录对象有安全覆盖或完整未决，最小化保住已确认覆盖；保护表达式具有独立安全证据|
|关系与交付完整性|已确认关系、规则字段和当前译名一致；满足绘图条件时，已形成可展示的关系图，节点、边及依据可对应到对象记录；统计和未决说明来自当前记录|
|提交方案一致性|规则类型、操作和范围符合 `scope`；既有集合、目标集合、字段及排序意图可对账，变更清单由已验收方案生成|

完整候选集合是对象核对的起点，选定规则通过 `covers` 关联回它。稳定、完整性和统计摘要由实际检查结果生成。返回验收结论与具体失败项；失败时修正受影响对象，新事实或缺口进入自启发，重新稳定后复用有效结果完成验收。

验收通过后，按 System Prompt 的“交付或提交处理结果”处理。`report` 保存已验收方案并进入交付；`apply` 保存供后续对账的最终方案与证据，生成本批变更清单，说明关键结论并调用提交工具。

## 6. 核对实际结果并交付

发生写入时读取回执，以最新工程事实对照 `work/**` 中的已验收方案，核对实际成功对象的字段、排序、重复和覆盖。匹配证据按领域目的取得或复用，缺口继续调查；方案材料缺失时从保留记录恢复后完成对账。部分成功按回执保留成功事实，修正剩余方案及受影响关系。

从同一份当前记录准备最终回复，按 System Prompt 的展示要求实际输出：

- 候选和既有对象的处置、当前与目标规则数量，说明调查及语义判断的真实范围；对象与规则数量通过覆盖关系分别核对。
- 影响规则选择的代表性依据、词根取舍、必要分支、边界检查或保护表达式安全结论。
- 形成的实体关系图，以最终方案或实际写入后的译名和已确认关系展示；发生部分成功时说明图与实际结果的对应范围。
- 影响完成范围的未决、已完成调查及继续所需条件。

结束时核对领域要求的内容已进入最终回复。工作文件保留完整记录与证据，供后续解释和恢复；工程提交、业务验收及用户交付分别以其实际结果确认。
