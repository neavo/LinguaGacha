# 质量规则工作流

按本技能确定任务默认行为、调查对象、形成规则并检查整个规则集合。调查过程中使用 `self-inspiring` 记录新问题并继续检查；处理术语时加载 `glossary-rules`，处理文本保护时加载 `text-preserve-rules`，按其中的标准判断是否收录以及规则是否安全。

## 1. 确定本次要做什么

任务类型和是否实际写入遵循 System Prompt，本技能补充以下默认行为：

|用户要求|默认动作|任务类型|
|---|---|---|
|提取术语|发现应收录的术语、确定译名、检查并写入术语表|`apply`|
|提取文本保护规则|发现需要保护的结构、形成安全表达式、检查并写入规则|`apply`|
|审查规则|检查现有规则，报告问题和建议|`report`|
|审校规则|检查现有规则，发现问题并写入修正结果|`apply`|

用户只调用本技能时，默认维护当前工程的术语和文本保护规则：检查现有规则，发现尚未覆盖的对象，并落实必要修改，开始时说明这一范围。

## 2. 确定处理范围

先确定规则类型：术语、名称、译名或实体使用 glossary，控制符、占位符、格式结构或文本保护使用 text_preserve，未限定类型时处理两类规则。

分别说明要读取哪些内容，以及可以修改哪些规则，用户指定阶段、对象或允许操作时，遵守这些限制，现有规则按以下方式参与：

|任务|现有规则怎样参与|记录值|
|---|---|---|
|提取新规则|发现未覆盖对象，现有规则默认作为匹配、冲突和边界证据|`evidence_only`|
|整体维护、审查或审校|检查范围内全部现有规则，是否主动提取由用户目标决定|`all`|
|维护指定规则|修改指定对象，其余规则提供证据|`listed`|

质量规则的覆盖、关系与集合最小性需要共同验收，先处理全部业务单元，再检查整个目标集合，验收通过后统一准备一个提交批次，业务单元的分组方式遵循 System Prompt。

## 3. 调查候选和现有规则

items 是默认事实来源；缺少片段、顺序、层级或容器结构时依据 `project_meta` 定点读取 sources。

待调查的检查与对象（发现前沿）包含用户指定对象、既有规则核验、领域规定的独立方向，以及符合 glossary 领域判据的 `seed: true` 条目所启发的关联方向。全部既有条目都参与其适用的覆盖、冲突和边界核验。`seed` 的当前值与证据保存在任务对象中，更新与回流按 `self-inspiring` 执行。

包含发现未覆盖对象的任务，至少完成三个具有实质不同范围或方法的独立工程方向，同时满足各领域的证据基础要求。纯既有规则审查、审校或定点维护依据声明范围建立前沿。

同一任务包含两个领域时，术语语境中的固定标记可以启发保护调查，结构槽位中的名称可以启发术语调查。每个候选独立通过对应领域判据，发现来源与领域结论分别保留。

对象登记后、共同语义核验前，使用 `ws.tool.groupQualityRuleEntries` 取得规范结构关系。glossary 的同类发现分组使用独立候选与 `seed: true` 既有条目；其余条目通过正式匹配参与参考与边界核验。text_preserve 使用实际调查集合。分析集合、目标筛选、分页、组和关系的含义遵循当前工具契约；保留 component 与跨组关系，按来源回流受影响对象。

结构关系说明共同核验原因，语义身份与最终合并由领域证据确定。存在影响合并、拆分、译名或消歧的实体关系时，编纂译文语言的实体关系图；关系过密时用主干图与关系表表达，多个语义簇按需要拆图。形成关系图和规则方案时取得的新事实继续进入自启发循环。

## 4. 形成完整规则

逐个对象作出判断，保存依据和方案。已有证据仍然有效时复用。从这一步填好方案中规则的全部字段，术语包括译名及契约要求的其它内容。尚未拟定译名时继续完成；只有实际缺少证据或用户决定时，才记录为未决。

在自启发每轮对象判断中执行以下领域步骤，使用第 7 节的对象与方案记录保存结果及通过依据。

### 术语：词根、边界与最小集合

1. **确认资格与身份**：逐对象形成资格、译名、关系和处置，建立精确规则的 `covers`；未决保留独立身份与补证结果。
2. **浓缩词根**：对已确认同一对象或规则体系的多个不同合格词形，调用 `ws.tool.deriveCommonLiteralRoots` 形成候选，按 `glossary-rules` 选择最短自然稳定边界。记录候选与精确分支的取舍；没有安全候选时保留精确方案。
3. **检查匹配安全**：调用 `ws.tool.matchLiterals` 完整比较分支与词根覆盖，逐项核验新增命中、条件适用性及同一 item 内的边界反例。每个候选取得自己的安全结论后才可选入方案；失败时收窄、拆分或保留安全分支，新对象和缺口回流。
4. **闭合对象覆盖**：逐对象核对直接、条件或精确分支覆盖，逐规则核对命中安全，确认合并保住全部已确认覆盖；无法安全表达的对象以完整 `blocked` 结论保留。
5. **最小化集合**：覆盖闭合后删除调整范围内的冗余规则，重新计算 `covers` 核对全部对象。必要精确分支与范围外保留规则进入最终集合；缺口回到相应身份、边界或覆盖步骤。

### 文本保护：表达式与独立安全证据

1. 逐对象确认结构身份与逐字保持需求，再形成表达式。
2. 每个拟采用表达式按 `text-preserve-rules` 独立编译，并完整扫描声明范围的原始 `item.src` 行，取得命中分布、代表语境与安全结论。
3. 非法、零长度、危险回溯或吞正文的候选继续收窄或拆分；每个新表达式重新取得自己的扫描证据。保留安全子结构与剩余未决对象。
4. 核对每个必须保护对象的最终表达式覆盖，保留规则也完成验收；表达式自身安全且对象覆盖可追溯后进入目标集合。

两类方案产生的资格、身份、边界、覆盖、拟写字段或未决变化均回流自启发。完整执行独立方向和后继探查，最近整轮稳定后进入集合验收。

## 5. 检查整个规则集合

满足 `self-inspiring` 稳定条件后，构造目标规则集合并程序化核对业务结果：

- 目标、规则类型、既有规则策略与操作符合 scope，范围外规则保持证据身份。
- 初始、独立与后继探查均有完成依据，扫描分页完整，最近整轮无未处理增量，每个对象有唯一当前处置。
- 既有 glossary 对象的 `seed` 与证据、处置一致，受启发候选具有独立资格证据；词根取舍有依据，新增命中已安全分类，实体关系与方案一致。
- 全部应收录对象有安全覆盖或完整未决说明；合并保住已确认覆盖，冗余删除发生在覆盖闭合后，删除后的最终集合重新通过覆盖核对。
- 每条最终 text_preserve 表达式的当前值具有独立编译、完整扫描与命中安全证据，必须保护对象均有覆盖或完整未决说明。
- 方案中每条拟采用的规则都已填好完整字段、确定处理方式并通过安全检查，术语译名已核验。
- 既有集合、最终集合、字段、排序意图与变更清单可对账，未决明确缺失事实、已完成调查及解除方式。

任一项失败时回到对应领域步骤，产生的增量进入自启发后继轮次，重新稳定后再次验收。保留仍有效的领域结果。

## 6. 提交安排与后续检查

整个集合检查通过后，按 System Prompt 的 `交付或提交处理结果`统一处理，写入后检查实际规则的覆盖、排序、重复与集合最小性。

新的覆盖缺口、用户要求或决定性事实进入对应领域步骤，并按自启发流程重新调查和核验。部分成功后，以已成功写入的内容为基线重建剩余方案，继续核对整个集合的覆盖。

按 System Prompt 的范围、数量与证据要求，分别统计候选对象和既有对象的处置，以及当前与目标规则数量；对象与规则通过覆盖关系关联，数量分别核对。补充独立与关联发现的实际覆盖依据，术语结果说明词根取舍、必要精确分支、边界检查与最终覆盖核对结果，文本保护结果说明表达式安全与结构覆盖。

按 System Prompt 的展示要求展示 **代表性关系、实体关系图和实际检查结果**，影响完成范围的未决单独说明，常规对象的完整记录保存在工作文件中，公共提交、异常处理和完成条件遵循 System Prompt。

## 7. 任务记录

使用 `self-inspiring` 的 `scope`、`checks`、`targets` 保存范围、检查和对象结论。本技能补充以下字段：

|记录|内容|
|---|---|
|`scope`|`result: report / apply`、`kinds`、调查范围、允许调整的范围、`allowed_actions`、`target_entry_ids`、`existing_entry_policy`，以及是否发现未覆盖对象|
|质量对象|稳定键、`kind`、`origin: candidate / existing`、已有 `id`（如有）、证据和当前结论|
|`necessity`|`required / not_required / unknown`，对象是否应收录|
|`resolution`|`direct / conditional / narrowed / split / blocked`，采用直接、条件、收窄、拆分或未决处理；条件处理用于 glossary|
|`action`|候选使用 `create / discard / blocked`；现有对象使用 `keep / update / delete / blocked`|
|`seed`|现有 glossary 条目是否具备发现资格及当前依据|
|`proposals`|规则方案的稳定键、类型、完整字段、`covers` 对象键集合、命中与边界证据、`candidate / selected / rejected` 状态|

未按已有 ID 限定时，`target_entry_ids` 为 `null`，单独调用技能的默认任务使用 `existing_entry_policy: all`，并将默认范围写入 `scope`，其余策略按第 2 节和用户要求记录。

对象与规则的覆盖关系从 `covers` 计算，允许多个精确分支共同覆盖一个对象，术语方案分别记录原有覆盖和新增命中的分类，文本保护方案记录每个表达式自身的完整扫描与安全证据，标记为 `required` 的对象必须有选定方案覆盖，或有完整的 `blocked` 说明，既有保留规则也进入最终集合的覆盖核对，保存与恢复按 `self-inspiring` 执行。
