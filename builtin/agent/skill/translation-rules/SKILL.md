# 译文领域判据

## 技能加载

加载并遵循 `writing-guide` 技能，共同文本质量与译名选择使用其中的判据。

本技能负责单个 item 的译文判断与字段形成。

## 1. 领域对象与证据

item 是不可拆的译文对象；`dst` 对应正文，`name_dst` 对应姓名槽位，写入 `status` 表达人工处置。源文本、质量规则和工程结构作为只读事实参与判断。

发生取舍时依次保护：

1. 用户明确要求；
2. 原文事实、命题与语义关系、信息量、不确定性、逻辑和表达意图；
3. 控制符、占位符、标签、转义序列、换行与其它保护边界；
4. 已确认的术语、姓名和实体身份；
5. 语境能够证明的说话人、受话人、被指对象、人物关系、视角、知识边界和剧情连续性；
6. 工程内已经成立的作品风格与目标语言惯例。

后项服务于前项。工程内的决定性反例优先于一般语言经验。警告提供待核验问题的定位与补证入口；最终处置由原文、工程约束与必要语境共同决定。

## 2. 领域发现与证据

补译从明确的未译目标检查结构与保护内容、术语与姓名、必要语境和当前工程风格。审校从已有译文、用户指定问题及关联 warning 建立检查；广泛主动审查完成四个具有不同判断对象的独立方向：

|方向|判断对象|
|---|---|
|结构完整性|保护结构、外文残留、漏翻线索、行数和字段边界|
|命题与语义关系对应|主谓、施受、判断与归属、状态与体验主体、存在与位置、修饰关系、作用域，以及否定、数量、时间、因果、情态、不确定性和信息增删|
|身份、称谓与指代|说话人、受话人、被指对象、人物关系与剧情阶段中的头衔、敬称、自称、人称代词和省略成分|
|译名与表达一致性|相同适用条件下的术语、姓名、别名、人物声音、语域和作品风格|

从不同文件、位置和文本形态取得互补样本，为当前语言、题材与译文状态形成具体检查。能够程序定位的模式取得完整扫描证据，语义判断按实际读取范围成立。同一 item 可以由多个方向提供证据，最终处置由其完整领域事实共同确定。

需要参与者、身份、人物关系或连续性证据时，先使用 `ws.tool.queryItemContexts` 取得规范邻近上下文；仍缺决定性事实时，围绕缺口补读足以判断的最少文本。

正确译文中的同系列译名、命题结构和人物声音可以形成一致性检查依据；错配、歧义和结构损坏形成相同适用条件下的后继调查。范围内的新关系、译法、边界或上下文变化都需要核验相关对象，后继方向和回流由翻译工作流与自启发协议组织。

### 警告与条目状态

警告用于定位待核验问题，处置依据原文、语境和规则适用条件形成：

|警告|核验目的|
|---|---|
|`SIMILARITY`|相似度较高的译文是否存在漏翻|
|`FOREIGN_CHAR_RESIDUE`|目标语言书写系统以外的文字是否为应翻译的残留|
|`TEXT_PRESERVE`|控制符、占位符或格式结构是否损坏|
|`GLOSSARY`|当前语境适用的术语是否落实|
|`RETRY_THRESHOLD`|达到重试阈值后放行的最终值是否正确|
|`LINE_COUNT_MISMATCH`|译文行数与原文是否对齐|

条目状态用于解释当前工程事实，目标资格同时受用户范围约束：

|状态|业务含义|
|---|---|
|`NONE`|等待翻译|
|`PROCESSED`|翻译成功|
|`ERROR`|翻译失败，需要核验或修复|
|`EXCLUDED`|人工排除，通常无需翻译|
|`RULE_SKIPPED`|按过滤规则跳过，通常无需翻译|
|`LANGUAGE_SKIPPED`|非待翻译语言的条目，通常无需翻译|
|`DUPLICATED`|同值重复条目，将复用译文，通常无需额外翻译|

## 3. 一对一映射与结构

- 一条可回写源文本对应一个译文值，沿用原有顺序、行数、换行和条目边界；用户明确改变结构时按其要求处理。
- 每个条目的内容在本条目内完成，跨条目语境只提供判断证据。
- 控制符、占位符、标签、转义序列、格式脚手架、分隔符和已确认的保护结构逐字保持原有位置与边界。
- 结构边界仍需补证时保留已确认部分，并标记决定性缺口。

## 4. 命题、身份与指代

- 先确定原文的命题结构和参与者，再在目标语言中重建等价关系；主谓、施受、判断与归属、状态与体验主体、存在与位置、修饰关系和作用域不得错配。
- 否定、数量、时间、因果、情态和不确定性作用于原文对应的成分，不因目标语言的句式重组而转移。
- 头衔、称谓、敬称、自称、对他人的称呼、人称代词和省略成分，依据语境能够证明的说话人、受话人、被指对象、人物关系和当前剧情阶段形成；关系和礼貌程度按原文功能保留。
- 邻近文本只补充当前 item 判断所需的命题参与者、身份、关系、视角、知识和连续性事实。

## 5. 姓名与术语

- 姓名槽位承载姓名译文，称谓、头衔、敬称后缀和解释文字留在对应正文位置。
- 已有可靠姓名译名时保持同一写法；姓名栏、正文引用、别名和身份关系共同提供一致性证据。
- 形成译文前复用当前事实中与原文匹配的 glossary 应用；完整应用证据存在时直接使用，否则定点匹配相关条目。
- glossary 的条件说明决定译名适用语境；其它义项按上下文和原文功能翻译。

## 6. 处置结论

每个进入翻译或审查的 item 形成唯一结论：

|结论|适用条件|
|---|---|
|`update`|目标需要形成或改变译文，并且工程事实足以形成安全的新值|
|`keep`|已有译文符合要求，或现有证据支持维持当前值|
|`blocked`|目标需要形成或改变译文，但安全新值依赖缺失的决定性事实|

`update` 写明实际变化的 `dst`、`name_dst` 或人工状态；未变化字段保持省略。`blocked` 写明决定性证据缺口和所需补充事实。多个合理方案都满足高优先级目标时保留选择空间，由用户已声明标准或当前工程风格完成收束。

修改正文译文或确认失败条目的现有非空译文表示接受该结果；完成状态、重试次数和同文组协调由项目写入契约处理。人工状态表达用户对该条目继续翻译、接受结果或排除的处置，按当前 contract 的允许值形成。

## 7. 判例

|工程事实|结论|
|---|---|
|保护占位符缺失，其正确位置由原文结构唯一确定|恢复占位符并形成 `update`|
|姓名栏已有可靠译名，正文对同一角色使用另一译名|按共同身份统一，并核验相关引用|
|当前语境适用的术语给出明确目标译名，译文没有落实|形成 `update`|
|原文命中条件术语，但当前属于普通义项，译文准确表达该义项|形成 `keep`；按条件说明解释术语缺失警告|
|相似度警告存在，但原文信息、语气与功能均已保留|形成 `keep`|
|主谓、施受、判断或归属关系在译文中发生错配|恢复原文命题关系并形成 `update`|
|称谓与已经确认的身份、关系或剧情阶段不符|按当前关系修正，并核验相关表达|
|代词译法取决于工作区尚未提供的说话人身份|形成 `blocked` 并记录所需身份事实|
|逐词对应准确，但人物声音和原文功能明显丢失|在信息等价范围内重译并形成 `update`|
