# 翻译任务

为用户确定的目标形成并检查译文，承接全量翻译、补译、失败重试与明确重译。只调用本技能时，默认处理当前工程待译目标。

需要 Agent 形成或判断文本时加载 `translation-rules`，由它加载 `writing-guide`。

## 1. 确定目标

通过 `ws.contract` 定位 `project_meta`、完整 `items` 与关联的 `warnings` 数据集。读取工程语言、文件顺序和条目事实，应用用户指定的文件、章节、item、状态、文本条件和排除要求，确定全部目标、可修改字段及语境读取边界。工程外文本在已授权导入后，依据当前工程事实确定目标。

- 全量翻译、补译：纳入范围内待译条目。
- 失败重试：纳入用户已决定重试的失败条目。范围内存在失败条目且用户尚未决定是否处理时，调用 `ask_user` 说明数量，依次提供「处理失败条目」「跳过失败条目」；已有明确决定直接沿用，等待、到期和取消按工具说明执行。
- 明确重译：按用户范围确定需要重新形成译文的对象，包含其指定的已有成功译文。

目标按稳定 item 身份去重，正文与姓名作为同一个对象处理；允许修改的字段遵循用户限定。其它状态、排除项、跳过项和同文重复项按用户范围与工程契约确定去向。范围外 item 只提供已授权的语境、一致性或边界证据。

从确定范围起保存可恢复的工作事实：

|记录内容|必须能够恢复的事实|
|---|---|
|范围与目标|`scope.result: report / apply`、用户目标、目标身份、可修改字段、排除或合并去向、失败条目决定及语境边界|
|执行安排|各目标采用的执行方式、业务单元与当前剩余工作|
|处理结果|Agent 对正文与姓名的唯一当前 `update / keep / blocked` 结论、完整待写值及证据位置；或批量运行实际结果与目标去向|
|问题与核验|待解决问题、决定性缺口、已完成补证、解除方式，以及新证据影响的对象和核验结果|

记录按任务规模集中保存或按单元组织，稳定身份和完整方案可追溯。工作事实与拟写译文保存在 `work/**`，提交清单写入 `changes/**`。判断结论与实际提交结果分别记录，批量统计按工具结果保存。

## 2. 选择执行方式

先检查工具对目标状态、任务类型、字段与提交安排的支持，再通过计数和必要抽样估算规模，划分业务单元：

|目标与条件|执行方式|
|---|---|
|没有待处理目标|说明当前状态，继续用户要求的其它阶段|
|`report` 中需要形成译文方案|Agent 分析并准备全部目标方案|
|已有成功译文的明确重译，或批量工具无法表达的字段与处理要求|Agent 形成并检查译文|
|符合批量工具资格的待译或已获授权重试目标，只有一个业务单元|Agent 形成并检查译文|
|符合批量工具资格的待译或已获授权重试目标，超过一个业务单元，且写入与提交安排符合请求|调用 `run_batch_translation` 处理这些目标|

混合目标分别按能力安排，保存每个目标的执行去向，覆盖完整任务范围。Agent 使用当前模型，批量工具使用保存的批量模型偏好，实际配置由宿主展示。工具能力不足时，能由 Agent 完成的目标继续按单元推进。

## 3. 形成并检查译文

### Agent 处理

按 `project_meta` 的文件顺序和文件内顺序组织业务单元，每个单元完整处理其全部目标：

1. 取得当前原文、正文与姓名译文、状态及相关警告，补足理解命题、参与者、关系和剧情阶段所需的语境。
2. 形成拟写值前读取或复用适用术语证据，依据 `translation-rules` 检查结构保护、姓名槽位与条件术语边界，形成符合用户要求的完整译文。
3. 核对原文含义、结构、命题关系、身份指代、术语与表达质量，对同一 item 的正文与姓名记录唯一当前结论和依据。缺少决定性事实时先补证，仍无法形成安全结果时保存完整 `blocked` 记录。
4. 核对当前单元全部目标的处理结果，检查失败时补证或修正。新证据影响已处理目标时，按下一节完成关联核验。
5. 到达既定提交位置时，`report` 保存检查通过的方案，`apply` 执行必要提交并记录真实回执与实际结果，继续剩余单元。

### 批量处理

调用 `run_batch_translation` 前把选定范围解析为明确 item 身份，按已有决定提供是否纳入失败条目，批量翻译工具会在运行中直接提交译文。

正常结束后核对本轮目标、成功、最终失败及剩余范围，并读取最新工程事实确认目标去向。引擎重试后的失败结果按实际报告；本轮新产生的失败条目后续处理沿用用户对这些条目的明确决定，缺少决定时说明数量并调用 `ask_user`，不自动开启新的重试阶段。用户停止时汇报当前结果，暂停依赖该运行的工作，等待明确继续要求。

## 4. 核对结果与关联影响

Agent 拟写值按领域判据检查；批量阶段按工具结果和最新工程事实核对实际产出。发生写入时，确认实际成功 item 的译文、warnings 和相关字段副作用。

新证据引出具体关联问题时，记录触发证据、受影响目标和核验方法。例如后文确认了人物姓名或关系，核验本次目标中已经使用该译名或指代的译文；结构损坏或命题错配提示相同适用条件下的目标需要补查。复用仍有效的证据，只重查受影响部分，必要时修正方案或按最新事实重新提交。

核验产生新问题时继续处理，直到已发现的关联影响都有当前结果；决定性外部条件缺失时保存完整未决。翻译完成依据由目标结果和实际发现的问题构成。

## 5. 验收并交付

结束当前翻译阶段前同时确认：

- 全部目标已有实际处理结果或完整未决，排除、合并、失败和剩余对象的去向明确。
- Agent 拟写译文完整并通过适用检查，批量运行结果已核对，已发现的关联影响得到核验。
- 方案与变更清单一致；发生写入的结果已确认，失败或阻塞对象有明确原因和继续条件。

验收出现新证据或缺口时，回到结果核验处理受影响目标。交付说明处理范围、执行方式、实际完成情况、失败或阻塞对象及剩余范围；Agent 判断结论、本轮批量结果、工程累计进度与真实写入分别说明。`report` 交付检查通过的方案及其假设。

阶段结果保留实际完成范围、未完成对象、有效证据及待解决问题，区分工程现值与拟议方案。
