# 译文审校

检查已有译文，主动调查问题或核验指定问题，并完成必要修正。只调用本技能时，默认主动审校当前工程已有译文。

加载 `translation-rules` 进行文本判断，由它加载 `writing-guide`。

## 1. 确定调查范围与对象覆盖

通过 `ws.contract` 定位 `project_meta`、完整 `items` 与关联的 `warnings` 数据集。读取工程语言、文件顺序和条目事实，从范围内已有正文或姓名译文的条目确定调查边界，再按 `item_id` 关联警告。应用用户指定的文件、章节、item、状态、文本条件和排除要求，分别确定调查范围、可修改条目与字段，以及语境读取边界。

按用户要求独立确定本阶段范围，依据最新工程事实和用户指定的待审材料选择输入；已有处理结果与证据经确认仍有效后复用。

审查拟议译文方案时，以工程 item 身份解析用户范围，从方案取得待审正文与姓名；范围内其它已有译文使用工程现值。保存每个对象的译文来源和假设，工程警告只作为当前已写入值的线索，针对拟议值重新判断适用问题。

|用户请求|初始检查|对象覆盖 `candidate_policy`|
|---|---|---|
|普通主动审查、审校，包括限定章节、文件或文本范围|警告核验与四类独立调查，包含适用的无警告译文取证|`discovered`：判断完整发现集合|
|明确逐条审查、审校|上述检查，并将范围内每个符合条件的 item 纳入判断|`all`：全部目标|
|只处理指定警告、item、修正建议|按起始事实解析并保存指定对象身份，围绕指定问题建立检查|`all`：全部指定目标|

`candidate_policy` 只表达对象覆盖要求，初始检查按用户请求确定。指定对象和逐条要求优先于默认策略；定点任务的后继核验保持在指定边界内，其它条目只提供已授权的语境或边界证据。

调查范围保持已确定的条目边界，警告数量用于安排已知风险的处理顺序。调查范围为空时说明实际状态，继续用户要求的其它阶段。

### 可恢复记录

从确定范围起维护以下事实，标识独立于数组顺序，按任务规模集中保存或按检查和对象组织：

|记录|必须能够恢复的事实|
|---|---|
|`scope`|`result: report / apply`、用户请求、调查范围、可修改条目与字段、排除项、语境边界、`candidate_policy: all / discovered`；审查拟议方案时的方案来源和假设|
|`checks`|稳定键、初始或后继来源、具体问题、触发证据、范围与方法、待执行或已完成状态；实际扫描或样本范围、计数、完整发现集合、分页继续位置、产生的对象和变化，以及后继核验结果|
|`targets`|稳定 item 身份、来源检查、证据位置及适用事实；正文与姓名的唯一当前 `update / keep / blocked` 结论、完整待写字段和依据、排除或合并去向；待解决或需重新核验的问题、决定性缺口、已完成补证和解除方式|

`scope` 保存调查边界，`checks` 决定下一步查什么，`targets` 保存对象当前结论。完整发现集合与证据通过稳定键和文件位置关联；分页、排序与摘要只控制本次返回内容，剩余对象和继续位置保存在记录中。领域理由相同的对象可以批量处置并保存成员范围。

工作事实与完整待写译文保存在 `work/**`，提交清单写入 `changes/**`。统计从实际记录计算，判断结论与提交回执分别保存。

## 2. 建立初始检查

开始时说明调查范围、对象覆盖要求和初始检查安排。普通主动审查与审校在处理候选前登记：

- **警告核验**：读取范围内的警告及对应 item，登记提示的问题；没有警告时记录实际结果，继续独立调查。
- **独立调查**：依据 `translation-rules` 的结构完整性、命题与语义关系对应、身份称谓与指代、译名与表达一致性四类判断方向，从原文、译文与工程结构建立具体问题、取证范围和方法。

独立调查从范围内的 `items` 取证，按文件、位置和文本形态选取互补样本。存在无警告译文时，将其纳入实际读取和语义判断；只在警告集合内执行四类判断不足以完成独立调查。某类样本或结构在当前范围不存在时，以工程事实说明适用范围。

能够程序定位的模式完整扫描声明范围，语义判断记录实际读取范围。不同方向可以共享条目、扫描与上下文，独立性由问题和方法体现。`all` 将全部符合条件的目标纳入判断；`discovered` 随实际调查持续发现并登记候选。

只处理指定警告、item 或修正建议时，围绕指定问题和对象建立初始检查，使用适用的领域判据。审校中需要形成修正译文时直接在本流程内完成。

## 3. 执行检查、判断并处理结果

按待查问题推进：执行检查，判断对应条目，形成当前结论，登记新发现引出的具体问题，再检查并处理当前单元结果，继续后继核验。一次工具调用或一次提交可以只完成其中一部分工作。

### 执行待查问题

从 `checks` 读取待执行的问题、范围与方法，从 `targets` 取得需要补证或重新判断的对象。候选暂时为空时继续尚未完成的检查。

合批安排已知且独立的调查，合并范围、问题、方法与事实依据等价的检查。复用有效证据与判断，新用法、反例或事实变化只重查受影响部分。

完整消费声明扫描范围与分页，保存发现集合、计数、证据位置和实际语义读取范围。实际执行并保存结果后将检查标为完成，发现的候选与受影响对象进入 `targets`。

### 按业务单元判断与处理

按 `project_meta` 的文件、条目顺序将待判断对象组织为业务单元，每个单元完整处理其全部目标：

1. 取得当前原文、正文与姓名译文、状态和相关警告，补足命题、参与者、关系和剧情阶段所需的语境。
2. 读取或复用适用术语证据，依据 `translation-rules` 判断当前译文，形成正文与姓名的唯一当前 `update / keep / blocked` 结论，保存完整拟写字段、证据与未决记录。
3. 从当前判断形成具体后继问题，按下一节登记触发证据、范围、方法和受影响对象。
4. 核对当前单元全部目标已有结论，拟写值通过领域检查。失败项先补证或修正；到达既定提交位置时，`report` 保存检查通过的结论与方案，`apply` 完成必要写入。
5. 发生写入时核对真实回执、实际成功 item 的译文、warnings 和相关字段副作用；将新事实或问题登记为后继检查。保存证据和实际结果，继续剩余检查与单元。

警告核验完成、警告清除或单元提交成功后，继续执行尚未完成的独立调查与后继检查。

## 4. 后继检查与影响核验

后继检查必须能说明哪项发现触发它、要验证什么，以及在什么范围采用什么方法：

- 命题错配、身份偏移或结构损坏提示相同适用条件下的错误模式。例如发现一处施受关系译反，按句式或语境条件定位范围内的相似表达，再逐项判断。
- 正确译文中的同系列译名、人物声音和替代表达提供一致性依据，检查其适用边界与相关对象。
- 新关系、术语边界、剧情上下文或提交后的事实变化要求重新核验受影响 item 的正文与姓名。

新 item、译名或结构变体、关系、边界反例、覆盖缺口、替代表达、决定性事实，以及结论、拟写值、未决或待查问题的变化都可能产生增量。保存其去向并执行受影响对象的核验，即使触发问题已经修正，也继续已形成的关联检查。等价检查复用仍有效的结果；重复计数、保存相同记录或重复确认同一事实不产生新任务。

初始调查后至少执行一次实际的后继探查或稳定核验。没有待查问题时，实际核对初始检查覆盖、完整发现集合、全部增量去向和受影响结论，保留依据；有增量时回到上一节处理，再核验其影响。定点任务在用户指定边界内执行相同循环。

## 5. 稳定验收与交付

只有最近一次完整核验同时满足以下条件，当前审校阶段才能结束：

- 初始检查与全部已产生的后继检查已完成，程序扫描分页完整，实际语义判断范围和证据可追溯；普通主动审校已完成警告核验、四类独立调查及适用的无警告译文取证。
- `all` 的全部目标或 `discovered` 的完整发现集合均有唯一当前结论或完整未决，排除与合并成员有去向。
- 新发现对相关对象的影响已核验，当前结论、关系、边界、拟写值和未决有有效依据，最近一次完整核验没有留下可执行的待查问题。
- 拟写字段完整并通过领域检查，方案与变更清单一致；发生写入时实际提交与回执一致，写入后的必要检查已完成。

有待查问题、待判断对象或尚未核验的有效增量时继续处理。验收发现新证据或缺口时登记后继检查，核验受影响对象并完成必要修正后再次验收。仅缺少决定性外部条件时，说明阻塞、已完成范围和解除方式。

交付说明调查范围、`candidate_policy`、实际程序扫描范围和语义判断范围、警告核验与独立调查完成情况、后继检查或稳定核验的代表性依据，以及按 item 唯一当前结论统计的 `update / keep / blocked` 数量。问题类型可以重叠，判断结论与实际写入分别说明。`discovered` 交付实际发现与覆盖；只有 `all` 且确实逐项判断完整时，才声称完成声明范围的全量逐条语义检查。

阶段结果保留实际完成范围、未完成对象、有效证据及待解决问题，区分工程现值与拟议方案。
