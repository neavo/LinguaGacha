# 术语提取与整理

提取术语或系统整理术语规则时，按下文执行自启发循环。执行前读取 `references/rule.md`，按其中的收录、身份、字段和覆盖判据判断对象与方案。

## 任务范围

按用户要求确定任务范围：

- 用户未限定范围时，覆盖当前工程全文。
- 用户指定问题时，围绕该问题及其必要关联开展调查。
- 默认进行程序化批量探查。仅在用户明确要求或无法程序化批量探查时逐条进行语义分析。

## 种子定义

种子是用于推进后续调查的具体线索。它来自任务目标、已有材料、调查结果或覆盖缺口，说明接下来调查哪些对象或条件，以及需要核验什么问题。错误、正确案例、反例、关系和未检查范围都可以产生种子。种子的判断结果由后续取证确定。

围绕同一调查问题合并等价种子，同类实例记录在业务工作材料中。出现需要独立核验的新条件、关系或边界时，新增种子或更新已有种子。

## 冷启动

用户指定对象或问题时，先调查指定目标及其必要关联。在任务范围内按以下方式选择冷启动数据：

- 已有术语规则时，从规则条目开始调查，关联原文命中和必要语境，核查对象资格、字段、身份、关系和覆盖疑点。按规则身份计数，超过一个业务单元时分批处理。
- 尚无术语规则时，从待查原文中分散采样。结合文件或章节结构、来源位置和内容分布选择不同区域，按原文 `item` 或原稿 `page` 身份去重计数，合计至少一个业务单元。范围内材料不足一个单元时，全部读取。

在每个采样位置读取语境完整的连续片段，补齐必要上下文和关联对象。一个采样业务单元可以包含多个位置的片段。

读取原文、译文、姓名和规则证据。调查条目时，主要读取 `items`，缺少结构信息时从 `sources/` 补证。调查页面时，记录证据所在文件、原页码和必要的区域位置。按下文领域要求判断初始材料，再从结果中提炼种子。

## 种子发现思路

冷启动和后续调查都可参考以下思路寻找种子。根据任务目标和当前证据按需选择，也可沿材料揭示的其他关系展开。

- **名称与指代**：从非空姓名栏、命名位置、首次登场、特殊书写和实际指代寻找名称、别称与关联对象。已确认的身份可启发别名、派生称谓和成员命名规律的调查。
- **概念与体系**：从定义、用途和获得、装备、发动等语境寻找作品特有概念，以及并列、层级、对立、所属和派生关系。
- **译法与消歧**：从可靠译法、译名分歧、外文残留、同名异指、别名同指和普通义项寻找线索。正确译法和被排除候选都能帮助调查身份与译法的适用边界。
- **关系与覆盖变化**：从词根新增命中、关系图冲突、覆盖缺口，以及身份、译名、条件、成员归属或未决变化寻找需要重查的对象与方案。对象数量相同也可能发生这些变化。
- **关联保护结构**：同时处理文本保护时，术语附近的固定标记可交由保护流程调查，保护结构槽位中的名称可作为术语候选，各自取得领域证据。

## 种子账本与循环执行

通过 `workspace_run` 将种子账本保存在 `work/TASKNAME-seeds.json`，并在循环中实时更新：

- 先将种子写入账本，再取证和判断。
- 得出新增或修改种子的结论时，立即写入账本。

### 1. 冷启动后初始化

冷启动完成后，设置 `completedRounds = 1`。从实际结果中提炼种子，将其 `consumed` 设为 `false`，并按目标轮次加入 `seeds`。

提炼示例如下：

|材料|初查发现|
|---|---|
|原文：`エレンはヴァレン家の長女。弟はノア・ヴァレン。人々は彼女を「ヴァレン家の令嬢」と呼ぶ。`|已确认艾伦与诺亚是同一家族的姐弟，「ヴァレン家の令嬢」在这段语境中指艾伦。|

```jsonc
{
  "completedRounds": 1, // 已完成的总轮数，正整数，包含冷启动
  "seeds": {
    "2": [ // 目标轮次，以正整数的字符串形式作为键，每轮对应一个种子数组
      {
        "pattern": "初查确认「エレン」与「ノア・ヴァレン」是瓦伦家的姐弟，且「ヴァレン家の令嬢」在该段指艾伦。调查任务范围内包含「ヴァレン」的姓名和称谓，结合语境核验家族成员归属、称谓指向及固定译名的适用条件。", // 非空字符串，描述调查对象或条件，以及需要核验的问题
        "consumed": false // 完成取证、结果处理和后续种子提炼后为 true，尚需处理或受阻时为 false
      }
    ]
  }
}
```

### 2. 每轮推进

1. 通过 `workspace_run` 读取账本，选择 `consumed === false` 的种子。相关模式可以合批调查。若 `completedRounds < 2` 且没有未消耗种子，先补入并保存种子，再取证：
   - 还有材料未检查时，选择尚未检查的业务单元，补入调查种子。
   - 材料已全部读取时，围绕已有结果的关系、反例或适用边界，补入复核种子。
2. 调用工具取得本轮证据，读取返回结果。按下文领域要求判断身份、译名和覆盖，更新对象记录、实体关系图与规则方案。
3. 按种子定义提炼后续调查方向，复用有效证据。新增种子或新事实要求重查已有种子时，保存相应内容并将其 `consumed` 设为 `false`。发现范围外的问题时，记录调查理由，交由用户决定。
4. 按处理结果更新种子状态：完成取证、结果处理和后续提炼的种子设为 `consumed = true`，调查结论为保留原状时同样适用。仍需补查或受阻的种子设为 `consumed = false`。
5. 本轮完成后，执行 `completedRounds = completedRounds + 1`。

同轮处理多个种子、搜索或采样都计为一轮。仅在完成本轮后更新 `completedRounds`。

在业务工作材料中按轮号保存取证结果的位置、对象结论、方案、实际处理范围、未决事项和后续模式，用对象身份关联种子。没有新增模式时，记录结束该调查方向的依据。

### 3. 继续调查与收敛判断

每轮完成后，通过 `workspace_run` 重新读取账本，核对字段、轮数与逐轮记录，并检查：

- `completedRounds < 2` 时，按「每轮推进」补充调查。
- 仅当 `completedRounds >= 2`、本轮无新种子、全部种子满足 `consumed === true`，且任务范围与成果要求均已满足时，结束循环。
- 有新种子、`consumed === false` 的种子、覆盖缺口或待核验的新事实时，补充或更新种子，不受轮数限制继续调查。

读取工具返回的检查结果，按结果推进。受阻时，对应种子保持 `consumed = false`，记录阻碍与继续条件。在业务工作材料中保存检查结果的位置，以及结束或受阻的依据。

## 领域判断与成果核验

冷启动和种子调查都按以下要求处理目标。

在对象记录中保存全部发现对象的来源、当前结论、实体与名称的对应关系、规则方案和覆盖依据。绘图和制定规则时共用这些事实。

### 1. 取证并核验对象

按当前调查对象、范围和核验方法合批取证：

- 条目原文：使用本包 `matchLiterals` 在 `src`、`name_src` 上取得连续字面命中，调用方法见 `references/scripts.md`。按判断目的选择计数或完整位置，并核对完整性。
- 条目语境：使用 `@lg/workspace/item-contexts` 的 `queryItemContexts` 合批查询必要语境。
- 页面文本：按实际提取结果匹配。扫描顺序、连字和断词含糊时，对照图像核验。

读完声明范围内的全部证据。用程序结果核对位置与数量，通过实际阅读判断身份与译法。

为每个候选取得资格证据，逐个确认身份、译名、关系和处置。对低频和单次出现的对象，同样按身份判断是否收录，按频率安排调查顺序。

排除对象时记录理由，合并或拆分时记录成员去向。身份或用法证据不足时，围绕具体歧义补查相关名称、语境与剧情阶段，再按规则判据核验条件说明、收窄或拆分方案。

仍缺少决定性事实时，将对象记为未决，写明缺失事实、已查内容、已尝试方案和继续所需的条件。继续处理可独立确定的对象。

### 2. 更新关系图与规则方案

初步判断身份后，形成 Mermaid 实体关系图，并随身份、关系和译名变化更新：

- 节点表示实体，标签使用当前译名，并保留辨认所需的原名或别名。
- 连线标明工程证据支持的关系与方向。
- 节点和连线均关联到对象记录与证据。
- 未确认的关系加入待查记录，已确认但没有关系的实体使用孤立节点。

没有发现实体时记录调查结果。

核验同一实体、别名、包含、所属和命名体系等关系。需要字符关系线索时，使用本包 `analyzeRelations`，调用方法见 `references/scripts.md`。

将完整结果保存到工作材料，按对象 ID 关联当前目标及相关成员。结合工程语境确认语义关系。检查图中的重复节点、错误连接、关系冲突、译名分歧和证据缺口，并核对孤立对象是否遗漏相关线索。

按规则判据的 `选择词根与精简规则` 制定完整方案，保存最短安全自然词根、必要分支和最终覆盖证据。方案变化时，同步更新受影响的对象与关系。

### 3. 核对成果

|核对内容|当前处理要求|
|---|---|
|调查完整|记录实际调查范围、证据和种子的处理结果。全部发现对象均有结论，后续问题已处理或有具体未决说明|
|关系可信|范围内已确认实体与关系均纳入图，名称归属、关系含义及方向有证据，图中暴露的冲突与缺口已处理或明确未决|
|规则成立|最终方案通过规则判据的对象覆盖与命中安全检查，身份、字段、译名、合并拆分与关系证据一致|
|成果一致|关系图、对象记录、最终方案与覆盖对应一致，节点和连线均可追溯到证据，图能正确显示且展示范围明确|

核对发现遗漏、不一致、未分类命中或方案影响时，先完成具体对象的处理，并将所得证据用于后续种子提炼。

## 提交与交付

处理每个业务单元后，先保存对象结论与规则方案。默认采用全局 `业务单元与提交` 中的统一提交安排。结束自启发循环后，核对完整方案中的实体关系图、名称归属、词根安全和对象覆盖。通过验收后，从方案生成变更清单，按工具契约安排批次并提交。

`report` 完成相同的调查与验收后，交付方案和关系图。

写入后完成以下核对：

- 以最新事实和回执对照方案，核对字段、排序、重复与覆盖，同步关系图中的译名与相关事实。
- 部分成功时记录实际结果，调整尚未成功的方案。
- 将核对产生的新事实用于种子提炼，继续调查受影响的对象，再提交必要修改。

交付时展示已核对的实体关系图，并说明：

- 代表性模式、循环结束或受阻依据，以及种子账本和业务工作材料链接。
- 实际调查、程序扫描和语义判断的范围。
- 已确认实体、名称、身份未明候选与规则各自的数量。
- 主要取舍、采用的词根和必要分支。
- 实际写入结果与未决事项。

`report` 的图对应最终方案，`apply` 的图对应实际结果。部分成功时，标明实际结果和待完成的方案。

记录扫描命中、实际阅读证据和实体判断各自的范围。将名称关联到所属实体，多个名称或命中指向同一实体时，按实体去重。按规则身份统计规则数量。名称归属或规则覆盖有重叠时，说明它们的关系。

每个对象只计入一种处置时，核对各类数量的合计是否与对象总数一致。单独记录身份未明的候选。

核验全部实体关系，并保存覆盖完整范围的图。按以下方式安排展示：

- 大图按实体之间的实际关系分组。正文展示总览与关键关系，提供完整图链接，并说明各图范围及跨图关系。
- 单实体可以展示单节点图。
- 没有发现实体时，说明实际调查结果。
