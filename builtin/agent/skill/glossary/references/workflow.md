# 术语提取与整理流程

本流程调查、提取和整理术语。读取 `references/rule.md`，使用其中的判据判断对象和方案。

## 目标与范围

按 `ws.contract` 查看指定对象、现有规则和可用的 `items/pages`，确定任务目标：提取遗漏术语、整理已有规则，或调查指定对象。根据用户要求确定待查文本与实体、可调整的规则和必要语境。

用户尚未说明目标时，结合工程事实建议提取遗漏术语并整理现有规则，按通用交互规则确认必要决定。目标明确后，选择对应流程：

- 查询、解释、判断或按指定值修改：使用 `references/rule.md` 的 `查询与指定修改`。
- 调查、提取或整理：按下文执行。

已有规则提供身份、译名、覆盖和冲突证据。将对象纳入调整范围时记录理由。在 `report` 与 `apply` 中都要形成、核对并交付实体关系图，随调查结果更新实体、关系和规则。

## 冷启动

根据任务选择起点：

- 用户指定对象或问题时，先调查指定目标及其必要关联。
- 发现遗漏术语时，在任务范围内按文件结构、来源顺序和内容分布合理均匀采样。实际读取至少一个完整业务单元，保留完整语境和对象关联。
- 整理已有规则时，从对象资格、字段、身份、关系和覆盖疑点取证。

读取原文、译文、姓名和规则证据。调查条目时，主要读取 `items`，缺少结构信息时从 `sources/` 补证。调查页面时，记录证据所在文件、原页码和必要的区域位置。按下文领域要求判断初始材料，再从结果中提炼种子。

## 种子发现思路

冷启动和后续调查都可参考以下思路寻找种子。根据任务目标和当前证据按需选择，也可沿材料揭示的其他关系展开。

- **名称与指代**：从非空姓名栏、命名位置、首次登场、特殊书写和实际指代寻找名称、别称与关联对象。已确认的身份可启发别名、派生称谓和成员命名规律的调查。
- **概念与体系**：从定义、用途和获得、装备、发动等语境寻找作品特有概念，以及并列、层级、对立、所属和派生关系。
- **译法与消歧**：从可靠译法、译名分歧、外文残留、同名异指、别名同指和普通义项寻找线索。正确译法和被排除候选都能帮助调查身份与译法的适用边界。
- **关系与覆盖变化**：从词根新增命中、关系图冲突、覆盖缺口，以及身份、译名、条件、成员归属或未决变化寻找需要重查的对象与方案。对象数量相同也可能发生这些变化。
- **关联保护结构**：同时处理文本保护时，术语附近的固定标记可交由保护流程调查，保护结构槽位中的名称可作为术语候选，各自取得领域证据。

例如，确认一个家族名称后，从成员命名规律提炼调查派生称谓的模式。若反例表明同名在不同剧情阶段指向不同实体，再调查按阶段消歧的条件。

## 种子列表与循环执行

在本任务的 `work/` 子目录中维护一份种子列表。每个种子只记录以下两项：

|字段|含义|
|---|---|
|模式|根据实际材料或调查结果提出的规律、关系或问题。写清调查对象、适用条件和核验方法|
|是否消耗|是否已完成该模式的取证、结果处理和后续种子提炼|

将新增种子标为未消耗。冷启动完成后，至少再完成一轮调查，包括取证、结果处理和后续种子提炼。

初始结果暂时无法形成关联种子时，从尚未检查的材料中寻找线索：选择另一个能补充调查视角的业务单元，记录待查模式，再读取材料并判断。

已读完任务范围内的材料并完成所需核验时，记录完成依据。材料或工具受阻时，记录未完成的调查和继续所需的条件。

按以下步骤循环调查：

1. 选择未消耗的种子，按下文领域要求取证、判断并处理结果。相关模式可以合批调查。
2. 从错误、正确案例、反例、关系和证据缺口中提炼后续模式，与已有种子比较。合并等价模式，复用有效证据，将新模式加入列表。同类实例补充到业务工作材料中。
3. 新事实改变已有模式的适用条件或结论，需要重查时，更新该模式并标为未消耗。发现范围外的问题时，说明调查理由，交由用户决定。
4. 完成取证、结果处理和后续提炼后，将对应种子标为已消耗。根据新事实仍需补查该模式时，将它保留为未消耗。继续处理列表中未消耗的种子。

直接更新种子列表。在业务工作材料中保存证据、对象结论、完整方案、实际处理范围和具体未决事项，用文件位置和对象身份关联这些记录。

### 循环结束与任务完成

结束自启发循环前，确认以下条件均已满足：

- 已消耗列表中的全部种子。
- 已完成冷启动后的至少一轮调查，或已读完任务范围内的材料并完成所需核验。

将未完成或受阻的种子保留为未消耗。暂停调查时，说明原因和继续所需的条件。

交付前，核对用户要求的覆盖范围和领域成果。还有指定对象需要处理时，继续完成判断，并用新事实补充或更新种子。在业务工作材料中记录循环结束或受阻的依据。

## 领域判断与成果核验

冷启动和种子调查都按以下要求处理目标。

在对象记录中保存全部发现对象的来源、当前结论、实体与名称的对应关系、规则方案和覆盖依据。绘图和制定规则时共用这些事实。

### 1. 取证并核验对象

按当前调查对象、范围和核验方法合批取证：

- 条目原文：使用本包 `matchLiterals` 在 `src`、`name_src` 上取得连续字面命中，调用方法见 `references/scripts.md`。按判断目的选择计数或完整位置，并核对完整性。
- 条目语境：使用 `@lg/workspace/item-contexts` 的 `queryItemContexts` 合批查询必要语境。
- 页面文本：按实际提取结果匹配。扫描顺序、连字和断词含糊时，对照图像核验。

读完声明范围内的全部证据。用程序结果核对位置与数量，通过实际阅读判断身份与译法。

为每个候选取得资格证据，逐个确认身份、译名、关系和处置。对低频和单次出现的对象，同样按身份判断是否收录，按频率安排调查顺序。

排除对象时记录理由，合并或拆分时记录成员去向。对未决对象，写明缺失事实、已查内容、已尝试方案和继续所需的条件。

### 2. 更新关系图与规则方案

初步判断身份后，形成 Mermaid 实体关系图，并随身份、关系和译名变化更新：

- 节点表示实体，标签使用当前译名，并保留辨认所需的原名或别名。
- 连线标明工程证据支持的关系与方向。
- 节点和连线均关联到对象记录与证据。
- 未确认的关系加入待查记录，已确认但没有关系的实体使用孤立节点。

没有发现实体时记录调查结果。

核验同一实体、别名、包含、所属和命名体系等关系。需要字符关系线索时，使用本包 `analyzeRelations`，调用方法见 `references/scripts.md`。

将完整结果保存到工作材料，按对象 ID 关联当前目标及相关成员。结合工程语境确认语义关系。检查图中的重复节点、错误连接、关系冲突、译名分歧和证据缺口，并核对孤立对象是否遗漏相关线索。

按规则判据的 `选择词根与精简规则` 制定完整方案，保存最短安全自然词根、必要分支和最终覆盖证据。方案变化时，同步更新受影响的对象与关系。

### 3. 核对成果

|核对内容|当前处理要求|
|---|---|
|调查完整|记录实际调查范围、证据和种子的处理结果。全部发现对象均有结论，后续问题已处理或有具体未决说明|
|关系可信|范围内已确认实体与关系均纳入图，名称归属、关系含义及方向有证据，图中暴露的冲突与缺口已处理或明确未决|
|规则成立|最终方案通过规则判据的对象覆盖与命中安全检查，身份、字段、译名、合并拆分与关系证据一致|
|成果一致|关系图、对象记录、最终方案与覆盖对应一致，节点和连线均可追溯到证据，图能正确显示且展示范围明确|

核对发现遗漏、不一致、未分类命中或方案影响时，先完成具体对象的处理，并将所得证据用于后续种子提炼。

## 提交与交付

默认在自启发循环结束且完整方案已核对后，按通用的 `业务单元与提交` 流程提交或交付只读方案。变更清单来自已核对的完整方案。

写入后完成以下核对：

- 以最新事实和回执对照方案，核对字段、排序、重复与覆盖，同步关系图中的译名与相关事实。
- 部分成功时记录实际结果，调整尚未成功的方案。
- 将核对产生的新事实用于种子提炼，继续调查受影响的对象，再提交必要修改。

交付时展示已核对的实体关系图，并说明：

- 代表性模式、循环结束或受阻依据，以及种子列表和业务工作材料链接。
- 实际调查、程序扫描和语义判断的范围。
- 对象与规则各自的数量。
- 主要取舍、采用的词根和必要分支。
- 实际写入结果与未决事项。

`report` 的图对应最终方案，`apply` 的图对应实际结果。部分成功时，标明实际结果和待完成的方案。

核验全部实体关系，并保存覆盖完整范围的图。按以下方式安排展示：

- 大图按实体之间的实际关系分组。正文展示总览与关键关系，提供完整图链接，并说明各图范围及跨图关系。
- 单实体可以展示单节点图。
- 没有发现实体时，说明实际调查结果。
