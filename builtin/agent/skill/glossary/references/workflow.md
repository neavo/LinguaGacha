# 术语提取与整理流程

按用户确定的范围调查、提取和整理术语，使用 `references/rule.md` 判断对象和方案。已有规则提供身份、译名、覆盖和冲突证据。将对象纳入调整范围时，记录理由。

在 `report` 与 `apply` 中，都要形成、验收并交付实体关系图。随调查结果更新实体、关系和规则，让用户能够审阅身份判断与规则取舍。

## 初始调查与保存事实

按工程文件顺序读取原文、译文、姓名与规则证据。条目以 `items` 为主要事实，缺少结构时从 `sources/` 补证。页面证据保留文件、原页码及必要区域位置。

任务包含发现遗漏时，从以下方向建立具体调查，候选按规则判据确认资格与身份：

- **名称与指代**：哪些名称、别称或普通表达指向需要稳定识别的对象？完整读取范围内非空姓名栏，结合命名、首次登场、特殊书写和实际指代取得线索。
- **概念与体系**：哪些定义、用途和关系体现作品特有概念？从获得、装备、发动等语境调查对象，核验并列、层级、对立、所属及派生体系。
- **译法与消歧**：哪些译法已有可靠依据，哪些存在分歧、外文残留或身份混淆？检查同名异指、别名同指及普通义项。

整理既有对象时，先按用户范围核验其资格、字段、关系与覆盖。每个候选都需要自己的资格证据，低频和单次对象按身份判断收录，频率用于安排调查顺序。

从开始调查起保存以下记录，按任务规模组织：

- 全部发现对象、来源和当前结论。
- 实体与名称的对应关系、关系证据、规则方案，以及每个对象由哪些规则覆盖。
- 后续问题的触发依据、范围、核验方法、受影响对象和当前结果。
- 分页位置与未处理对象，便于恢复进度。

图与规则共用同一份事实记录。摘要说明实际展示范围。

## 根据调查结果继续核验

将初始调查取得的候选和问题加入待查记录。每轮依次判断受影响对象、更新关系图与规则方案，再查明新发现的关联问题。一轮可以跨多个批次和工具调用。

### 判断对象与取证

按待查问题合批取证。`item` 原文使用本包 `matchLiterals`（调用见 `references/scripts.md`）在 `src`、`name_src` 上取得连续字面命中，按判断目的选择计数或完整位置并核对完整性。必要语境通过 `@lg/workspace/item-contexts` 的 `queryItemContexts` 合批查询。页面文本按实际提取结果匹配，扫描顺序、连字和断词含糊时对照图像。读完声明范围内的全部证据。用程序结果核对位置与数量，通过实际阅读判断身份与译法。

逐对象确认资格、身份、译名、关系和处置。排除对象时记录理由，合并或拆分时记录成员去向。未决对象写明缺失事实、已查内容、已尝试方案和继续条件。

### 更新关系图与规则方案

初步判断身份后，形成 Mermaid 实体关系图，并随身份、关系和译名变化更新：

- 节点表示实体，标签使用当前译名，并保留辨认所需的原名或别名。
- 连线标明工程证据支持的关系与方向。
- 节点和连线均关联到对象记录与证据。
- 未确认的关系加入待查记录，已确认但没有关系的实体使用孤立节点。

没有发现实体时记录调查结果。

核验同一实体、别名、包含、所属和命名体系等关系。需要字符关系线索时使用本包 `analyzeRelations`（调用见 `references/scripts.md`），完整结果保存到工作材料，按对象 ID 关联当前目标及相关成员，由工程语境确认语义关系。检查图中的重复节点、错误连接、关系冲突、译名分歧和证据缺口，核对孤立对象是否遗漏相关线索。

按规则判据的“选择词根与精简规则”形成完整方案，保存最短安全自然词根、必要分支及最终覆盖证据。方案变化同步更新受影响的对象与关系。

### 查明关联问题

每批对象判断、关系核验与方案调整后，检查以下关联：

- 已证实身份或体系的术语，通过命名槽位、别名、派生形式和关联对象启发调查，核验可靠译法在相关用法中的适用条件。其余已有规则参与译名、冲突与覆盖检查。新事实改变身份或体系时，重新判断收录资格及相关调查方向。
- 被排除候选提供身份与普通义项的边界反例，检查它们是否改变相关对象的收录、消歧或词根选择。
- 词根新增命中、关系冲突、覆盖缺口以及译名、条件、成员归属或未决变化，要求核验相关对象和方案。对象数量相同也要检查这些变化。
- 同时处理文本保护时，术语附近固定标记交由保护流程调查，保护结构槽位中的名称进入术语候选，各自取得领域证据。

将具体问题写入工作记录并执行，新的证据与候选回到对象判断，更新关系图与规则方案并继续提炼问题。图中的缺口和已成立的身份、体系都要检查是否产生后续调查。触发问题已经修正时，仍完成已产生的后续检查。合并等价问题，复用有效证据，只重查事实变化影响的部分。调查保持在用户范围内。

## 整体验收

处理完当前待查问题后，核对完整范围并保存以下验收依据。已有有效扫描可以复用，核对以调查和方案的最终状态为准。

|验收内容|通过依据|
|---|---|
|调查完整|记录实际调查范围及各适用方向的证据和结果。全部发现对象均有结论，后续问题已处理或有具体未决说明|
|关系可信|范围内已确认实体与关系均纳入图，名称归属、关系含义及方向有证据，图中暴露的冲突与缺口已处理或明确未决|
|规则成立|最终方案通过规则判据的对象覆盖与命中安全检查，身份、字段、译名、合并拆分与关系证据一致|
|成果一致|关系图、对象记录、最终方案与覆盖对应一致，节点和连线均可追溯到证据，图能正确显示且展示范围明确|

验收发现遗漏、不一致、未分类命中或尚未核验的变化时，将具体问题送回调查循环，再验收受影响部分并核对完整范围。结束循环前，确认全部可执行的后续问题已处理、相关变化已核验，且整体验收通过。对象数量和扫描结果用于辅助核对。仅缺决定性外部事实的对象保留缺失事实、已查内容、已尝试方案和继续所需条件，按尚未完成的目标交付。

## 提交与交付

默认先完成用户范围内的整体方案验收，再按通用的 `业务单元与提交` 流程提交或交付只读方案。变更清单来自已验收的完整方案。

写入后以最新事实和回执对照方案，核对字段、排序、重复与覆盖，并同步关系图中的译名与相关事实。部分成功时记录实际结果，调整尚未成功的方案。出现新事实或缺口时继续调查，核验影响并通过验收后，再提交必要修改。

交付时展示已验收的实体关系图，并说明：

- 实际调查、程序扫描和语义判断的范围。
- 对象与规则各自的数量。
- 主要取舍、采用的词根和必要分支。
- 实际写入结果与未决事项。

`report` 的图对应最终方案，`apply` 的图对应实际结果。部分成功时，标明实际结果和待完成的方案。

大图按实体之间的实际关系分组，保存覆盖完整范围的图。正文展示总览与关键关系，提供完整图链接，并说明各图范围及跨图关系。单实体可以展示单节点图，没有发现实体时说明调查结果。按阅读需要调整正文展示的规模，同时核验全部关系并保存覆盖完整范围的图。
