# 术语提取与整理流程

本流程按用户确定的范围调查、提取和整理术语，使用 `references/rule.md` 判断对象和方案。从下文列出的冷启动方向取证并形成种子，通过自启发循环持续调查身份、名称、关系和规则覆盖。

已有规则提供身份、译名、覆盖和冲突证据。将对象纳入调整范围时记录理由。在 `report` 与 `apply` 中都要形成、核对并交付实体关系图，随调查结果更新实体、关系和规则。

## 自启发循环的概念

|概念|在本流程中的含义|
|---|---|
|冷启动方向|本流程预设的术语调查入口，用于从实际材料中形成第一批种子|
|种子|基于命名、指代、实体关系或译法证据形成的调查线索。描述要调查的对象、适用条件和核验方法。种子可以来自冷启动调查，也可以来自后续轮次的结果|
|调查结果|候选资格、身份与名称归属、译名、实体关系和规则覆盖的事实与判断。正确案例、错误、反例、关系、排除依据和证据缺口都参与后续种子提炼|
|自启发循环|应用种子取得证据，判断并处理结果，再从结果中提炼新种子或更新已有种子，逐轮继续|
|轮次|以一组种子为输入，完成这些种子的应用、结果处理和后续种子提炼的一次执行过程。一轮可以跨多个批次、工具调用和提交|

调查依据、对象关系、适用条件或核验方法发生实质变化时，形成新种子或更新已有种子。同类实例补充到对应调查结果中，新旧比较覆盖全部历史轮次。

## 冷启动方向

按工程文件顺序读取原文、译文、姓名与规则证据。条目以 `items` 为主要事实，缺少结构时从 `sources/` 补证。页面证据保留文件、原页码及必要区域位置。

任务包含发现遗漏时，沿以下方向实际取证，并根据规则判据形成种子：

- **名称与指代**：完整读取范围内非空姓名栏，结合命名位置、首次登场、特殊书写和实际指代，调查名称、别称及普通表达所指向的对象。
- **概念与体系**：从定义、用途和获得、装备、发动等语境调查作品特有概念，核验并列、层级、对立、所属及派生关系。
- **译法与消歧**：调查可靠译法、译名分歧、外文残留和身份混淆，核对同名异指、别名同指及普通义项。

整理指定对象时，从其资格、字段、身份、关系和覆盖疑点形成种子。每个候选都要取得自己的资格证据。低频和单次对象按身份判断收录，频率用于安排调查顺序。

实际读取各适用方向的材料，结合低频、无警告内容和反例补充调查视角。

## 工作记录

在本任务的 `work/` 子目录中，每轮保存一份 `Round` 记录，按执行顺序排列。沿冷启动方向形成的种子填入第一轮的 `seeds`。通过文件位置和对象标识引用证据与业务成果。

```ts
type Seed = {
  id: string;
  description: string; // 调查线索、适用条件及核验方法
  basis: string[];     // 来源证据或结果位置
};
type Round = {
  seeds: Seed[];       // 本轮需要处理的种子
  results: string[];   // 按种子关联的检查范围、处理结果和证据位置
  findings: string;    // 提炼结果及其与已有种子的比较依据
  next: Seed[];        // 下一轮的新种子或更新后的种子
  remaining: string[]; // 尚未完成的工作或受阻原因
};
```

种子通过 `id` 关联记录。更新时记录变化与依据，保留此前轮次的描述和结果。轮次记录同时保存分页位置、已处理对象与剩余工作。

对象记录保存全部发现对象、来源、当前结论、实体与名称的对应关系、规则方案和覆盖依据。图与规则共用这些事实。

## 每轮执行

### 1. 应用种子并核验对象

按本轮种子的调查对象、范围和核验方法合批取证：

- 条目原文：使用本包 `matchLiterals` 在 `src`、`name_src` 上取得连续字面命中，调用方法见 `references/scripts.md`。按判断目的选择计数或完整位置，并核对完整性。
- 条目语境：使用 `@lg/workspace/item-contexts` 的 `queryItemContexts` 合批查询必要语境。
- 页面文本：按实际提取结果匹配。扫描顺序、连字和断词含糊时，对照图像核验。

读完声明范围内的全部证据。用程序结果核对位置与数量，通过实际阅读判断身份与译法。

逐对象确认资格、身份、译名、关系和处置。排除对象时记录理由，合并或拆分时记录成员去向。未决对象写明缺失事实、已查内容、已尝试方案和继续条件。

### 2. 更新关系图与规则方案

初步判断身份后，形成 Mermaid 实体关系图，并随身份、关系和译名变化更新：

- 节点表示实体，标签使用当前译名，并保留辨认所需的原名或别名。
- 连线标明工程证据支持的关系与方向。
- 节点和连线均关联到对象记录与证据。
- 未确认的关系加入待查记录，已确认但没有关系的实体使用孤立节点。

没有发现实体时记录调查结果。

核验同一实体、别名、包含、所属和命名体系等关系。需要字符关系线索时，使用本包 `analyzeRelations`，调用方法见 `references/scripts.md`。

将完整结果保存到工作材料，按对象 ID 关联当前目标及相关成员。结合工程语境确认语义关系。检查图中的重复节点、错误连接、关系冲突、译名分歧和证据缺口，并核对孤立对象是否遗漏相关线索。

按规则判据的“选择词根与精简规则”形成完整方案，保存最短安全自然词根、必要分支及最终覆盖证据。方案变化同步更新受影响的对象与关系。

### 3. 核对本轮成果

|核对内容|本轮处理要求|
|---|---|
|调查完整|记录实际调查范围、适用冷启动方向的证据与结果，以及本轮种子的应用结果。全部发现对象均有结论，后续问题已处理或有具体未决说明|
|关系可信|范围内已确认实体与关系均纳入图，名称归属、关系含义及方向有证据，图中暴露的冲突与缺口已处理或明确未决|
|规则成立|最终方案通过规则判据的对象覆盖与命中安全检查，身份、字段、译名、合并拆分与关系证据一致|
|成果一致|关系图、对象记录、最终方案与覆盖对应一致，节点和连线均可追溯到证据，图能正确显示且展示范围明确|

核对发现遗漏、不一致、未分类命中或方案影响时，先完成具体对象的处理，并将所得证据用于后续种子提炼。

### 4. 提炼后续种子

从本轮正确判断、错误、排除对象、关系图和规则变化中检查以下种子来源：

- 已证实身份或体系的术语，通过命名槽位、别名、派生形式和关联对象启发调查，核验可靠译法在相关用法中的适用条件。其余已有规则参与译名、冲突与覆盖检查。新事实改变身份或体系时，重新判断收录资格及相关调查方向。
- 被排除候选提供身份与普通义项的边界反例，检查它们是否改变相关对象的收录、消歧或词根选择。
- 词根新增命中、关系冲突、覆盖缺口以及译名、条件、成员归属或未决变化，要求核验相关对象和方案。对象数量相同也要检查这些变化。
- 同时处理文本保护时，术语附近固定标记交由保护流程调查，保护结构槽位中的名称进入术语候选，各自取得领域证据。

例如，确认一个家族名称后，从成员命名规律提炼调查派生称谓的种子。若后续反例表明同名在不同剧情阶段指向不同实体，再形成按阶段消歧的种子。图中的缺口与正确的体系关系都参与提炼。

按以下步骤整理本轮提炼结果：

1. 从本轮结果中提炼种子，与全部已有种子比较，在 `findings` 中记录依据。
2. 合并等价种子，复用有效证据。条件或证据变化时，记录种子的更新。
3. 对范围外发现单独说明理由，交由用户决定。
4. 将新增或实质更新的种子写入 `next`。

完成本轮处理后，根据 `next` 接续执行：

- `next` 有内容时，建立下一份 `Round`，将这些种子填入新一轮的 `seeds` 并执行。
- `next` 为空时，按下节的自启发循环停止条件作出判断。

## 自启发循环停止条件

完整执行本轮种子的应用、结果处理与后续种子提炼，并与全部已有种子比较后，既无法产生新种子，也没有形成需要继续调查的已有种子更新，自启发循环才停止。

在 `findings` 中记录无法继续提炼的证据与比较依据，此时 `next` 为空。

## 提交与交付

默认在自启发循环结束且完整方案已核对后，按通用的 `业务单元与提交` 流程提交或交付只读方案。变更清单来自已核对的完整方案。

写入后完成以下核对：

- 以最新事实和回执对照方案，核对字段、排序、重复与覆盖，同步关系图中的译名与相关事实。
- 部分成功时记录实际结果，调整尚未成功的方案。
- 将核对产生的新事实用于种子提炼，继续调查受影响的对象，再提交必要修改。

交付时展示已核对的实体关系图，并说明：

- 循环轮次、代表性种子、停止或受阻依据，以及轮次记录链接。
- 实际调查、程序扫描和语义判断的范围。
- 对象与规则各自的数量。
- 主要取舍、采用的词根和必要分支。
- 实际写入结果与未决事项。

`report` 的图对应最终方案，`apply` 的图对应实际结果。部分成功时，标明实际结果和待完成的方案。

核验全部实体关系，并保存覆盖完整范围的图。按以下方式安排展示：

- 大图按实体之间的实际关系分组。正文展示总览与关键关系，提供完整图链接，并说明各图范围及跨图关系。
- 单实体可以展示单节点图。
- 没有发现实体时，说明实际调查结果。
