# 自启发

使用已经获得的证据和判断，寻找下一步需要调查的问题，再用新证据检查和修正结论。正确结论、被排除的候选和已知对象的新关系，都可能提示其它问题。

业务工作流先确定任务范围、使用的领域标准和提交安排。本技能说明怎样安排调查、保存记录和判断调查是否完成；规则或译文本身是否合格，由对应领域技能检查。

## 1. 安排初始检查

先记录任务范围 `scope`，明确读取哪些内容、处理哪些对象，以及用户要求完成哪些阶段。

建立以下检查：

- 用户指定对象和现有对象中尚待核验的问题。
- 领域技能要求的独立调查方向与互补样本。各方向应在范围或方法上有实质差异，并有工程事实作为依据。
- 符合领域发现资格的种子所提示的关联问题。

将检查写入 `checks`，将需要判断的对象写入 `targets`。当前要做的工作（发现前沿），就是尚未完成的检查和需要重新判断的对象。关联前沿暂时稳定时，补足尚未执行的独立方向，并把其全部结果纳入后续轮次。

定点任务也执行相同过程，范围保持在用户指定边界内。范围外线索只用于已授权的语境或边界证据，需要扩大修改范围时交由用户决定。

## 2. 自启发循环

初始探查为第 `0` 轮。每轮完整执行当前前沿，轮内按事实依赖顺序处理；本轮产生的增量进入下一轮。轮次对应一次完整的探查、理解、启发与回流过程，可以跨多次工具调用。

每轮执行：

1. 读取当前有效事实、待执行探查和需要重新核验的对象。
2. 合并范围、方法与事实依据等价的探查。已完成证据仍有效时复用；事实依据变化时重新核验受影响部分。
3. 完整消费声明的程序扫描范围与全部分页，记录实际计数和有限代表证据；语义样本记录真实读取范围。按工具定义区分去重对象、字段、片段、组和样例计数。
4. 根据领域判据处置对象，建立或修正身份、关系、边界、覆盖、拟写值与未决。
5. 从本轮事实与判断中主动提炼新的槽位、同系列形式、关系、结构变体、错误模式、替代表达或边界假设，形成可执行的后继探查。
6. 为每项增量确定受影响对象，把后继探查与重新核验要求写入下一轮，并保留具体启发来源。
7. 保存完整本轮结果，核对探查消费情况和变化去向，再进入下一轮。

以下变化全部构成增量：新对象、别名、变体、同名异义、关系、边界反例、覆盖缺口、替代表达、决定性事实，以及对象资格、`seed`、处置、覆盖集合、拟写值、未决集合或后继方向的变化。相同对象可以因其中任何一项变化再次进入判断。

完整计数证明扫描范围；有限样例只证明实际展示和判断过的证据范围。模式推广与覆盖判断必须取得领域要求的完整匹配及必要语义证据。分页中重复出现的关系按身份合并，保留它对相关对象的影响。

## 3. 整轮稳定核验

本轮产生的任何增量都进入下一轮核验；即使本轮已经修正问题，也需继续到最近完整一轮满足下列稳定条件。

第 `0` 轮完成后，至少执行一轮后继探查或稳定核验。当前前沿为空时，明确核对独立覆盖、增量去向和受影响结论；事实依据有效的完整扫描可以复用。

只有同时满足以下条件，才能进入业务结果验收：

- 初始探查和全部后继探查已完成，程序扫描分页完整，样本与截断边界可对账；
- 业务工作流与领域技能要求的独立方向已完整执行，所有结果均已回流；
- 每个实际对象都有领域要求的完整处置，未决写明决定性缺口、已完成调查和解除方式；
- 新对象、关系、边界、替代表达与判断变化都已重新核验相关对象；
- 最近完整一轮的对象、结论、关系、边界、覆盖、拟写值、`seed`、未决和补查集合保持稳定；
- 完成判定满足 `round > 0`，该轮记录能够证明上述核验确已执行。

没有新增对象时仍须核对其它增量。稳定只证明声明范围内既定独立方向和全部自启发产生的可执行方向已经闭合；程序覆盖与逐项语义判断按各自实际范围报告。

## 4. 最终检查发现问题时继续调查

业务工作流检查规则集合、译文或实际写入结果时，可能发现新事实、边界反例或遗漏。将它们登记为新一轮调查依据，重新检查受影响对象。

保留已完成业务单元的真实结果和仍有效的证据，继续处理相关问题。调查完成后，由业务工作流再次检查结果；交付、提交、审批和阻塞处理遵循 System Prompt。

## 5. 保存任务记录

每项记录使用稳定的任务内标识，并保留来源关系。同一对象只维护一个当前结论，汇总计数和反向关系从这些记录计算。

|记录|用途和必要内容|
|---|---|
|`scope`|任务类型 `report / apply`、调查范围、处理范围和发现目标；具体字段由业务工作流补充|
|`checks`|每项检查的键、`origin: initial / independent / triggered`、轮次、范围、方法、依据、`pending / complete`、实际扫描或样本范围、计数、分页完整性，以及发现的对象和变化|
|`targets`|对象的稳定身份、已完成的来源探查、当前证据与领域结论、需要重新核验的内容或决定性缺口|
|领域附加记录|业务工作流要求的规则方案、对象覆盖关系、表达式安全证据或完整待写译文|

独立检查记录工程证据依据；后续检查指向上一轮引出它的具体发现或判断变化，说明要发现或验证什么、在哪个范围使用什么方法。记录随任务规模调整，但必须能解释查过什么、怎样处理对象、为何可以结束。

### 执行过程中

`task/**` 保存跨快照仍有效的范围、用户决定、未决问题、后续调查安排和恢复摘要。`scratch/**` 保存当前快照的完整过程记录、扫描证据、临时方案和变更清单。

脚本按 System Prompt 的返回要求提供下一步所需信息。完整对象记录放在工作文件中，交付摘要根据检查结果和实际发生的工具结果生成。

### 提交或刷新快照前

提交可能销毁快照和过程资产。将提交后核验、继续执行或后续解释需要的对象结论、覆盖依据、方案和继续位置保存到 `task/**`。`scratch/**` 按当前快照生命周期维护，后续不能假定它仍然存在。

### 中断后恢复

1. 读取保留的任务记录，存在实际提交时一并读取回执。
2. 对照最新工程事实检查证据是否仍然有效。
3. 重建已经失效的过程材料，把受影响对象和检查重新标为待处理。
4. 依据可验证的轮次、来源和继续位置恢复执行。

## 6. 判例

|本轮结果|必须形成的后继工作|
|---|---|
|某个术语译法正确，语境暴露了作品特有的命名槽位|从该槽位形成工程探查，独立判断其它候选的资格|
|对象数相同，但身份、覆盖或 `seed` 改变|重新核验受影响对象与关联方向，继续下一轮|
|宽候选被排除，但显露了可区分的结构边界|以新边界形成窄候选并取得其自己的证据|
|关联前沿稳定，独立方向发现单次出现的新概念|登记新对象，生成后继探查并回到普通循环|
|同一结构在译文中出现关系偏移|在范围内查找相同形成方式，逐项核验实际语义|
|目标集合验收发现合并遗漏了已确认对象|回流覆盖缺口，调整方案并重新核验相关对象|
|中断后只有部分探查证据仍有效|复用有效证据，重建失效部分，继续未完成的后继工作|
