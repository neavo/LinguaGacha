# 自启发

本技能拥有自启发循环的发现前沿、轮次、增量回流和稳定判定。业务工作流确定任务范围、领域组合、结果验收与提交安排；领域技能提供发现依据、对象判据和证据方法。按已加载的业务工作流与领域技能执行本协议。

自启发从工程事实形成对象、关系、边界和判断，再把这些认识转化为新的可验证探查方向；新事实继续修正已有认识。正确结论、被排除的候选和已知对象的新关系都可能启发后继调查。

## 1. 范围与发现前沿

业务工作流先固定 `scope`，明确调查范围、调整范围、发现目标和结果形态。前沿由尚未完成的 `checks` 与需要重新核验的 `targets` 组成，直接从当前记录取得。

初始前沿同时接收：

- 用户指定目标、既有对象及其待核验问题；
- 领域技能规定的独立工程事实方向与互补样本；
- 已符合领域条件的发现种子所启发的关联方向。

独立方向直接依据工程事实建立，其范围或方法具有实质差异。领域要求的每类独立方向均须完成；关联前沿暂时稳定时，补足尚未执行的独立方向，并把其全部结果纳入后续轮次。

定点任务在指定范围内完成同样的闭环。新线索落在调整范围外时，只承担已获授权的语境或边界证据；需要扩大任务范围的部分作为附带观察交由用户决定。

## 2. 当前记录与工作资产

任务维护 `scope`、`checks`、`targets` 和必要的领域附加记录。记录使用稳定任务内键与来源关联，保存完整的当前有效状态：

|记录|必要信息|
|---|---|
|`checks`|键、`origin: initial / independent / triggered`、轮次、范围、方法、启发依据、`pending / complete`、实际扫描或样本范围、计数与分页完整性、产生的对象及变化|
|`targets`|稳定身份、已完成的来源探查、当前证据、领域结论、需要重新核验的变化或决定性缺口|
|领域附加记录|由业务工作流声明的规则方案、覆盖关系、表达式证据或译文拟写值|

后继探查的启发依据指向上一轮的具体发现或判断变化，说明要发现或验证什么、在哪个范围使用什么方法。独立方向记录其工程证据基础。汇总计数和反向关系从当前记录计算，同一业务对象保持唯一当前结论。

`task/**` 保存跨快照仍有效的范围、已确认决定、未决、后继调查意图和恢复摘要；`scratch/**` 保存当前快照下的完整过程账本、扫描证据、临时方案与待提交 change。提交或快照刷新前，把仍需延续的调查依据与后继意图收束到 task。恢复时依据当前事实验证记录，重建失效过程资产，并将受影响对象和探查重新置为待处理；轮次与来源以可验证的记录为准。

工作资产的文件读取、写入和失败处理遵循 System Prompt。记录规模随实际任务缩小，但始终能说明检查来源、对象处置和完成依据。

## 3. 自启发循环

初始探查为第 `0` 轮。每轮完整执行当前前沿，轮内按事实依赖顺序处理；本轮产生的增量进入下一轮。轮次对应一次完整的探查、理解、启发与回流过程，可以跨多次工具调用。

每轮执行：

1. 读取当前有效事实、待执行探查和需要重新核验的对象。
2. 合并范围、方法与事实依据等价的探查。已完成证据仍有效时复用；事实依据变化时重新核验受影响部分。
3. 完整消费声明的程序扫描范围与全部分页，记录实际计数和有限代表证据；语义样本记录真实读取范围。按工具定义区分去重对象、字段、片段、组和样例计数。
4. 根据领域判据处置对象，建立或修正身份、关系、边界、覆盖、拟写值与未决。
5. 从本轮事实与判断中主动提炼新的槽位、同系列形式、关系、结构变体、错误模式、替代表达或边界假设，形成可执行的后继探查。
6. 为每项增量确定受影响对象，把后继探查与重新核验要求写入下一轮，并保留具体启发来源。
7. 保存完整本轮结果，核对探查消费情况和变化去向，再进入下一轮。

以下变化全部构成增量：新对象、别名、变体、同名异义、关系、边界反例、覆盖缺口、替代表达、决定性事实，以及对象资格、`seed`、处置、覆盖集合、拟写值、未决集合或后继方向的变化。相同对象可以因其中任何一项变化再次进入判断。

完整计数证明扫描范围；有限样例只证明实际展示和判断过的证据范围。模式推广与覆盖判断必须取得领域要求的完整匹配及必要语义证据。分页中重复出现的关系按身份合并，保留它对相关对象的影响。

## 4. 整轮稳定核验

第 `0` 轮完成后，至少执行一轮后继探查或稳定核验。当前前沿为空时，明确核对独立覆盖、增量去向和受影响结论；事实依据有效的完整扫描可以复用。

只有同时满足以下条件，才能进入业务结果验收：

- 初始探查和全部后继探查已完成，程序扫描分页完整，样本与截断边界可对账；
- 业务工作流与领域技能要求的独立方向已完整执行，所有结果均已回流；
- 每个实际对象都有领域要求的完整处置，未决写明决定性缺口、已完成调查和解除方式；
- 新对象、关系、边界、替代表达与判断变化都已重新核验相关对象；
- 最近完整一轮的对象、结论、关系、边界、覆盖、拟写值、`seed`、未决和补查集合保持稳定；
- 完成判定满足 `round > 0`，该轮记录能够证明上述核验确已执行。

没有新增对象时仍须核对其它增量。稳定只证明声明范围内既定独立方向和全部自启发产生的可执行方向已经闭合；程序覆盖与逐项语义判断按各自实际范围报告。

## 5. 结果验收与回流

稳定后由业务工作流验收目标集合与业务结果。关系整理、规则覆盖、译文核验或实际写入结果产生新事实、边界或缺口时，把它作为新一轮依据，重新进入自启发循环。已经完成的业务单元保留真实结果，受影响结论继续核验。

信息结果在循环稳定且领域验收通过后交付；工程变更依照业务工作流的提交安排取得真实回执，保留未完成与未决事实。公共审批、提交和异常恢复遵循 System Prompt。

## 6. 判例

|本轮结果|必须形成的后继工作|
|---|---|
|某个术语译法正确，语境暴露了作品特有的命名槽位|从该槽位形成工程探查，独立判断其它候选的资格|
|对象数相同，但身份、覆盖或 `seed` 改变|重新核验受影响对象与关联方向，继续下一轮|
|宽候选被排除，但显露了可区分的结构边界|以新边界形成窄候选并取得其自己的证据|
|关联前沿稳定，独立方向发现单次出现的新概念|登记新对象，生成后继探查并回到普通循环|
|同一结构在译文中出现关系偏移|在范围内查找相同形成方式，逐项核验实际语义|
|目标集合验收发现合并遗漏了已确认对象|回流覆盖缺口，调整方案并重新核验相关对象|
|中断后只有部分探查证据仍有效|复用有效证据，重建失效部分，继续未完成的后继工作|
