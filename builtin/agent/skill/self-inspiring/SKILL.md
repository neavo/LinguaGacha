# 自启发

使用已经获得的证据和判断，寻找下一步需要调查的问题，再用新证据检查和修正结论。正确结论、被排除的候选和已知对象的新关系，都可能提示其它问题。

业务工作流先确定任务范围、使用的领域标准和提交安排。本技能说明怎样安排调查、保存记录和判断调查是否完成；规则或译文本身是否合格，由对应领域技能检查。

## 1. 安排初始检查

先记录任务范围 `scope`，明确读取哪些内容、处理哪些对象，以及用户要求完成哪些阶段。

建立以下检查：

- 用户指定对象和现有对象中尚待核验的问题。
- 领域技能要求的独立调查方向与互补样本。各方向应在范围或方法上有实质差异，并有工程事实作为依据。
- 符合领域发现资格的种子所提示的关联问题。

将检查写入 `checks`，发现候选时即保存完整来源集合，并将需要判断的对象关联到 `targets`。同一对象持续更新当前结论，尚未判断的对象保留待处理问题，排除保留理由，合并或拆分保留成员去向。领域理由相同的对象可以批量处置并引用成员范围。分页、排序和摘要只控制本次返回内容，剩余对象及继续位置保存在记录中。

当前要做的工作（发现前沿）由尚未完成的 `checks` 与对象问题取得。关联前沿暂时稳定时，补足尚未执行的独立方向，并把全部结果纳入后续轮次。

定点任务也执行相同过程，范围保持在用户指定边界内。范围外线索只用于已授权的语境或边界证据，需要扩大修改范围时交由用户决定。

## 2. 自启发循环

初始探查为第 `0` 轮。每轮完整执行当前前沿，轮内按事实依赖顺序处理；本轮产生的增量进入下一轮。轮次对应一次完整的探查、理解、启发与回流过程，可以跨多次工具调用。

每轮执行：

1. 从当前记录读取待执行检查、待判断对象及具体缺失事实，合批安排已知且独立的调查。
2. 合并范围、方法与事实依据等价的探查。复用同一对象、问题和有效证据上的已有判断；新用法、反例或事实变化进入受影响对象的补证。
3. 完整消费声明的扫描范围与全部分页，保存发现集合、实际计数和证据位置，再按当前判断需要返回新证据及必要旧结论。语义样本记录真实读取范围；计数遵循工具定义。
4. 根据领域判据更新对象结论，将身份、关系、边界、覆盖和拟写值关联到支持它们的证据。未解决问题继续留在记录中。
5. 从事实与判断提炼新的槽位、同系列形式、关系、结构变体、错误模式、替代表达或边界假设；为可执行的后继探查记录具体问题、启发来源、方法和受影响对象。
6. 保存本轮对象与检查结果，把增量及重新核验要求写入下一轮。由发现集合核对成员去向，从当前记录计算进度与变化，继续下一轮。

以下变化全部构成增量：新对象、别名、变体、同名异义、关系、边界反例、覆盖缺口、替代表达、决定性事实，以及对象资格、`seed`、处置、覆盖集合、拟写值、未决集合或后继方向的变化。相同对象可以因其中任何一项变化再次进入判断。

完整计数证明扫描范围；有限样例只证明实际展示和判断过的证据范围。模式推广与覆盖判断必须取得领域要求的完整匹配及必要语义证据。分页中重复出现的关系按身份合并，保留它对相关对象的影响。

## 3. 整轮稳定核验

本轮产生的任何增量都进入下一轮核验；即使本轮已经修正问题，也需继续到最近完整一轮满足下列稳定条件。

第 `0` 轮完成后，至少执行一轮后继探查或稳定核验。当前前沿为空时，明确核对独立覆盖、增量去向和受影响结论；事实依据有效的完整扫描可以复用。

只有同时满足以下条件，才能进入业务结果验收：

- 初始探查和全部后继探查已完成，程序扫描分页完整，样本与截断边界可对账；
- 业务工作流与领域技能要求的独立方向已完整执行，所有结果均已回流；
- 指定范围和检查产生的完整对象集合均已对账，每个成员有领域处置、排除理由、合并归属或完整未决，未决写明决定性缺口、已完成调查和解除方式；
- 新对象、关系、边界、替代表达与判断变化都已重新核验相关对象；
- 最近完整一轮的对象、结论、关系、边界、覆盖、拟写值、`seed`、未决和补查集合保持稳定；
- 完成判定满足 `round > 0`，该轮记录能够证明上述核验确已执行。

没有新增对象时仍须核对其它增量。稳定只证明声明范围内既定独立方向和全部自启发产生的可执行方向已经闭合；程序覆盖与逐项语义判断按各自实际范围报告。

## 4. 最终检查发现问题时继续调查

业务工作流检查规则集合、译文或实际写入结果时，可能发现新事实、边界反例或遗漏。将它们登记为新一轮调查依据，重新检查受影响对象。

保留已完成业务单元的真实结果和仍有效的证据，继续处理相关问题。调查完成后，由业务工作流再次检查结果；交付、提交、审批和阻塞处理遵循 System Prompt。

## 5. 保存任务记录

记录从开始调查起持续更新，任务内标识独立于数组顺序，并保留来源关系。同一对象只维护一个当前结论，汇总计数、反向关系和稳定结论从实际检查结果计算。

|记录|用途和必要内容|
|---|---|
|`scope`|任务类型 `report / apply`、调查范围、处理范围和发现目标；具体字段由业务工作流补充|
|`checks`|每项检查的键、`origin: initial / independent / triggered`、轮次、范围、问题、方法、依据、`pending / complete`、实际扫描或样本范围、计数、完整发现集合与继续位置，以及产生的对象和变化|
|`targets`|对象的稳定身份、来源检查与成员对应、证据位置及其适用事实、当前领域结论和依据、排除理由、合并归属、待解决问题或需要重新核验的内容|
|领域附加记录|业务工作流要求的规则方案、对象覆盖关系、表达式安全证据或完整待写译文|

记录随任务规模调整，能够解释查过什么、怎样处理对象、为何可以结束。后继检查必须指向触发它的对象、证据或判断变化，并说明要验证的问题、范围和方法；没有具体触发依据的泛化补查不进入下一轮。

### 执行过程中

`work/**` 保存任务范围、用户决定、完整过程记录、扫描证据、方案、未决问题和后续调查安排，跨快照刷新和提交保留，提交批次写入 `changes/**`。

完整对象、证据和方案保存在工作文件中，通过稳定键和文件位置关联；按 System Prompt 的 CodeAct 约定返回当前判断或交付所需内容。交付摘要根据检查结果和实际发生的工具结果生成。

### 中断后恢复

结合任务记录、最新工程事实和提交回执恢复调查。材料保留不代表证据始终有效；复用有效部分，把受影响对象和检查重新标为待处理。上下文压缩或中断后，按理解当前问题所需重读结论与证据。

## 6. 后继工作判例

|本轮变化|后继工作|
|---|---|
|译法确定但出现新的命名槽位|调查同槽位对象并独立判断资格|
|身份、覆盖或边界改变|重新核验受影响对象与关系|
|宽候选暴露可区分边界|形成窄候选并取得自己的证据|
|提交或恢复后只有部分证据有效|复用有效部分，重建失效检查并保留继续位置|
