# 文本保护提取与整理流程

本流程在已明确的发现、调整与语境范围内调查、提取和整理保护规则，使用 `references/rule.md` 判断候选和方案。运行时匹配范围以 `ws.contract` 为准。从下文列出的冷启动方向取证并形成种子，通过自启发循环持续调查结构、表达式和覆盖边界。

在 `report` 与 `apply` 中都要形成、核对并交付结构与规则覆盖关系图，随调查结果更新结构判断和表达式，让用户能够审阅保护范围及合并、拆分的依据。

## 自启发循环的概念

|概念|在本流程中的含义|
|---|---|
|冷启动方向|本流程预设的文本保护调查入口，用于从实际材料中形成第一批种子|
|种子|基于结构功能、语法变体、组合关系或命中边界证据形成的调查线索。描述要调查的结构、适用条件和核验方法。种子可以来自冷启动调查，也可以来自后续轮次的结果|
|调查结果|保护资格、安全命中、自然语言反例、漏保和误保的事实与判断。正确案例、错误、反例、关系、排除依据和证据缺口都参与后续种子提炼|
|自启发循环|应用种子取得证据，判断并处理结果，再从结果中提炼新种子或更新已有种子，逐轮继续|
|轮次|以一组种子为输入，完成这些种子的应用、结果处理和后续种子提炼的一次执行过程。一轮可以跨多个批次、工具调用和提交|

调查依据、对象关系、适用条件或核验方法发生实质变化时，形成新种子或更新已有种子。同类实例补充到对应调查结果中，新旧比较覆盖全部历史轮次。

## 冷启动方向

从原始 `items`、现有保护规则和相关 `warnings` 取得结构证据。缺少格式或用途事实时，从 `sources/` 读取必要材料。依据原文和格式证据判断保护资格。

任务包含发现遗漏时，沿以下方向实际取证，并根据规则判据形成种子：

- **结构与用途**：从定界符、标签、控制前缀、转义、固定标记和来源格式调查控制、占位及格式功能，辨认相似写法中的自然语言。
- **变体与组合**：调查同类结构的参数、前后缀、位置和相邻标记，检查重复槽位、行首行尾、容器结构及罕见组合。
- **覆盖与边界**：核对现有表达式的必要覆盖、遗漏和误含，结合正确命中、译文结构损坏、相关警告和自然语言反例判断适用边界。

整理指定规则时，从其结构身份、表达式和覆盖疑点形成种子。实际读取各适用方向的材料，结合罕见结构、无警告内容和自然语言反例补充调查视角。

## 工作记录

在本任务的 `work/` 子目录中，每轮保存一份 `Round` 记录，按执行顺序排列。沿冷启动方向形成的种子填入第一轮的 `seeds`。通过文件位置和对象标识引用证据与业务成果。

```ts
type Seed = {
  id: string;
  description: string; // 调查线索、适用条件及核验方法
  basis: string[];     // 来源证据或结果位置
};
type Round = {
  seeds: Seed[];       // 本轮需要处理的种子
  results: string[];   // 按种子关联的检查范围、处理结果和证据位置
  findings: string;    // 提炼结果及其与已有种子的比较依据
  next: Seed[];        // 下一轮的新种子或更新后的种子
  remaining: string[]; // 尚未完成的工作或受阻原因
};
```

种子通过 `id` 关联记录。更新时记录变化与依据，保留此前轮次的描述和结果。轮次记录同时保存分页位置、已处理对象与剩余工作。

对象记录保存全部发现结构、来源、当前结论、关系证据、表达式方案和规则覆盖依据。图与规则共用这些事实。

## 每轮执行

### 1. 应用种子并核验结构

按本轮种子确定待查结构、范围和核验方法。判断结构身份与逐字保持需求，再选择直接表达、收窄或拆分。随后完成以下取证：

1. 按 `references/scripts.md` 调用本包 `scanPatterns`，对每条候选独立编译，并完整扫描声明范围的原始文本。
2. 保存命中的 `item`、行、片段、文件和文本类型分布。
3. 实际阅读代表片段与必要上下文，判断每类命中。

发现自然语言反例时检查整个对应形态。收窄或拆分后的各表达式重新取得安全证据，保留确定的安全子结构，剩余对象独立判断。未决记录已尝试方案、具体失败原因和继续所需的格式事实。

### 2. 更新关系图与表达式方案

初步判断结构后，形成 Mermaid 结构与规则覆盖关系图，并随结构、表达式和覆盖变化更新：

- 节点标明保护结构或规则，标签使用可辨认的结构样例或规则说明。
- 连线标明已核验的包含、重复或覆盖关系与方向。
- 节点和连线均关联到对象、规则和证据。
- 未确认的关系加入待查记录，尚无安全规则覆盖的必要结构标为未决。

没有发现保护结构时记录调查结果。

检查图中的重复对象、错误连接、覆盖缺口，以及合并、拆分和删除后各成员的去向。按 `src` 对相同正则表达式分组，取得成员证据（示例见 `references/scripts.md`）。分别核验表达式行为、结构关系和保护资格。图与表达式方案同步调整。

### 3. 核对本轮成果

|核对内容|本轮处理要求|
|---|---|
|调查完整|记录实际调查范围、适用冷启动方向的证据与结果，以及本轮种子的应用结果。全部发现对象均有结论，后续问题已处理或有具体未决说明|
|关系可信|必要结构与最终规则均纳入图，包含、重复及覆盖关系有证据，图中暴露的冲突与缺口已处理或明确未决|
|规则成立|各表达式具备独立安全证据，合并、删除或调整后必要结构仍有安全覆盖或明确未决，成员去向可追溯|
|成果一致|关系图、对象记录、最终表达式方案与覆盖对应一致，节点和连线均可追溯到证据，图能正确显示且展示范围明确|

核对发现漏保、误保或归属冲突时，先处理对应结构和规则，恢复确定的安全覆盖，将反例与变化用于后续种子提炼。

### 4. 提炼后续种子

从本轮安全结构、自然语言反例、关系图和表达式变化中检查以下种子来源：

- 已确认的安全结构启发参数变体、固定前后缀、相邻标记，以及其它文件或槽位中的同类用法调查，核验原有保护判断与表达式边界是否适用。
- 用已排除的自然语言和宽表达式中的反例检查对应形态的边界。对收窄后的安全子结构，继续调查相关变体与遗漏。
- 图中的关系冲突、覆盖缺口，以及结构身份、表达式、覆盖归属、处置或未决变化，要求核验相关规则与必要对象，即使对象总数保持不变。
- 同时处理术语时，名称附近的固定标记进入保护候选，结构槽位中的名称交由术语流程调查，各自取得领域证据。

例如，从一个固定标记提炼调查参数变体的种子。若反例显示相同定界符也用于自然语言，将所在槽位或位置条件纳入种子更新，再核验相关形态。正确覆盖与收窄后的安全子结构都参与提炼。

按以下步骤整理本轮提炼结果：

1. 从本轮结果中提炼种子，与全部已有种子比较，在 `findings` 中记录依据。
2. 合并等价种子，复用有效证据。条件或证据变化时，记录种子的更新。
3. 对范围外发现单独说明理由，交由用户决定。
4. 将新增或实质更新的种子写入 `next`。

完成本轮处理后，根据 `next` 接续执行：

- `next` 有内容时，建立下一份 `Round`，将这些种子填入新一轮的 `seeds` 并执行。
- `next` 为空时，按下节的自启发循环停止条件作出判断。

## 自启发循环停止条件

完整执行本轮种子的应用、结果处理与后续种子提炼，并与全部已有种子比较后，既无法产生新种子，也没有形成需要继续调查的已有种子更新，自启发循环才停止。

在 `findings` 中记录无法继续提炼的证据与比较依据，此时 `next` 为空。

## 提交与交付

默认在自启发循环结束且完整方案已核对后，按通用的 `业务单元与提交` 流程提交或交付只读方案。

写入后完成以下核对：

- 对照最新事实与回执，核对表达式、说明、排序、重复及覆盖，同步关系图。
- 部分成功时记录实际结果，调整尚未成功的方案。
- 将核对产生的新事实用于种子提炼，继续调查受影响的对象，再提交必要修改。

交付时展示已核对的结构与规则覆盖关系图，并说明：

- 循环轮次、代表性种子、停止或受阻依据，以及轮次记录链接。
- 实际调查、程序扫描和语义判断的范围。
- 结构与规则各自的数量。
- 实际新增、修改和删除的内容。
- 代表性的边界证据与未决事项。

`report` 的图对应最终方案，`apply` 的图对应实际结果。部分成功时，标明实际结果和待完成的方案。

核验全部结构关系，并保存覆盖完整范围的图。大图按结构之间的实际关系分组。

正文展示总览与关键关系，提供完整图链接，并说明各图范围及跨图关系。没有发现保护结构时，说明实际调查结果。
