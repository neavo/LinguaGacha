# 文本保护提取与整理

提取保护结构或系统整理保护规则时，按下文执行自启发循环。执行前读取 `references/rule.md`，按其中的保护资格、字段、表达式安全和覆盖判据判断候选与方案。

## 任务范围

按用户要求确定任务范围：

- 用户未限定范围时，覆盖当前工程全文。
- 用户指定问题时，围绕该问题及其必要关联开展调查。
- 默认进行程序化批量探查。仅在用户明确要求或无法程序化批量探查时逐条进行语义分析。

## 种子定义

种子是用于推进后续调查的具体线索。它来自任务目标、已有材料、调查结果或覆盖缺口，说明接下来调查哪些对象或条件，以及需要核验什么问题。错误、正确案例、反例、关系和未检查范围都可以产生种子。种子的判断结果由后续取证确定。

围绕同一调查问题合并等价种子，同类实例记录在业务工作材料中。出现需要独立核验的新条件、关系或边界时，新增种子或更新已有种子。

## 冷启动

用户指定结构、规则或问题时，先调查指定目标及其必要关联。在任务范围内按以下方式选择冷启动数据：

- 已有保护规则时，从规则条目开始调查，关联原文命中和必要语境，核查结构身份、表达式和覆盖疑点。按规则身份计数，超过一个业务单元时分批处理。
- 尚无保护规则时，从待查原文中分散采样。结合文件结构、来源位置和内容分布选择不同区域，按原文 `item` 身份去重计数，合计至少一个业务单元。范围内材料不足一个单元时，全部读取。

在每个采样位置读取语境完整的连续片段，补齐必要上下文和完整保护结构。一个采样业务单元可以包含多个位置的片段。

从原始 `items`、现有保护规则和相关 `warnings` 取得结构证据。缺少格式或用途事实时，从 `sources/` 读取必要材料。按下文领域要求判断初始材料，再从结果中提炼种子。

## 种子发现思路

冷启动和后续调查都可参考以下思路寻找种子。根据任务目标和当前证据按需选择，也可沿材料揭示的其他关系展开。

- **结构与用途**：从定界符、标签、控制前缀、转义、固定标记和来源格式寻找控制、占位及格式功能，辨认相似写法中的自然语言。
- **变体与组合**：从已确认结构的参数、前后缀、位置、相邻标记和不同文件中的用法寻找变体，包括重复槽位、行首行尾、容器结构和罕见组合。
- **覆盖与边界**：从正确命中、译文结构损坏、相关警告、漏保、误保和自然语言反例寻找适用边界。收窄后的安全子结构可继续启发相关变体与遗漏的调查。
- **关系与方案变化**：从关系图冲突、覆盖缺口，以及结构身份、表达式、覆盖归属、处置或未决变化寻找需要重查的规则与对象。对象数量相同也可能发生这些变化。
- **关联术语**：同时处理术语时，名称附近的固定标记可作为保护候选，结构槽位中的名称可交由术语流程调查，各自取得领域证据。

## 种子账本与循环执行

通过 `workspace_run` 将种子账本保存在 `work/TASKNAME-seeds.json`，并在循环中实时更新：

- 先将种子写入账本，再取证和判断。
- 得出新增或修改种子的结论时，立即写入账本。

### 1. 冷启动后初始化

冷启动完成后，设置 `completedRounds = 1`。从实际结果中提炼种子，将其 `consumed` 设为 `false`，并按目标轮次加入 `seeds`。

提炼示例如下：

|材料|初查发现|
|---|---|
|原文：`ようこそ、{name}さん！`；来源格式说明确认 `{name}` 在运行时替换为玩家姓名，翻译时须逐字保留。|已确认 `{name}` 是需要保护的占位符，可继续调查同类结构及其边界。|

```jsonc
{
  "completedRounds": 1, // 已完成的总轮数，正整数，包含冷启动
  "seeds": {
    "2": [ // 目标轮次，以正整数的字符串形式作为键，每轮对应一个种子数组
      {
        "pattern": "初查根据来源格式说明确认「ようこそ、{name}さん！」中的 {name} 是须逐字保留的玩家姓名占位符。调查任务范围内其他花括号片段，结合来源格式与语境核验哪些也是替换槽位、有哪些参数变体，以及是否存在自然语言用法。", // 非空字符串，描述调查对象或条件，以及需要核验的问题
        "consumed": false // 完成取证、结果处理和后续种子提炼后为 true，尚需处理或受阻时为 false
      }
    ]
  }
}
```

### 2. 每轮推进

1. 通过 `workspace_run` 读取账本，选择 `consumed === false` 的种子。相关模式可以合批调查。若 `completedRounds < 2` 且没有未消耗种子，先补入并保存种子，再取证：
   - 还有材料未检查时，选择尚未检查的业务单元，补入调查种子。
   - 材料已全部读取时，围绕已有结果的关系、反例或适用边界，补入复核种子。
2. 调用工具取得本轮证据，读取返回结果。按下文领域要求判断结构用途与保护资格，更新结构记录、关系图与表达式方案。
3. 按种子定义提炼后续调查方向，复用有效证据。新增种子或新事实要求重查已有种子时，保存相应内容并将其 `consumed` 设为 `false`。发现范围外的问题时，记录调查理由，交由用户决定。
4. 按处理结果更新种子状态：完成取证、结果处理和后续提炼的种子设为 `consumed = true`，调查结论为保留原状时同样适用。仍需补查或受阻的种子设为 `consumed = false`。
5. 本轮完成后，执行 `completedRounds = completedRounds + 1`。

同轮处理多个种子、搜索或采样都计为一轮。仅在完成本轮后更新 `completedRounds`。

在业务工作材料中按轮号保存取证结果的位置、对象结论、方案、实际处理范围、未决事项和后续模式，用对象身份关联种子。没有新增模式时，记录结束该调查方向的依据。

### 3. 继续调查与收敛判断

每轮完成后，通过 `workspace_run` 重新读取账本，核对字段、轮数与逐轮记录，并检查：

- `completedRounds < 2` 时，按「每轮推进」补充调查。
- 仅当 `completedRounds >= 2`、本轮无新种子、全部种子满足 `consumed === true`，且任务范围与成果要求均已满足时，结束循环。
- 有新种子、`consumed === false` 的种子、覆盖缺口或待核验的新事实时，补充或更新种子，不受轮数限制继续调查。

读取工具返回的检查结果，按结果推进。受阻时，对应种子保持 `consumed = false`，记录阻碍与继续条件。在业务工作材料中保存检查结果的位置，以及结束或受阻的依据。

## 领域判断与成果核验

冷启动和种子调查都按以下要求处理目标。

在对象记录中保存全部发现结构的来源、当前结论、关系证据、表达式方案和规则覆盖依据。绘图和制定规则时共用这些事实。

### 1. 取证并核验结构

根据初始材料或当前种子确定待查结构、范围和核验方法。判断结构身份与逐字保持需求，再选择直接表达、收窄或拆分。随后完成以下取证：

1. 按 `references/scripts.md` 调用本包 `scanPatterns`，对每条候选独立编译，并完整扫描声明范围的原始文本。
2. 保存命中的 `item`、行、片段、文件和文本类型分布。
3. 实际阅读代表片段与必要上下文，判断每类命中。

发现自然语言反例时，检查该形态的全部用法。收窄或拆分表达式后，为各表达式重新取得安全证据。保留已确认的安全子结构，逐个判断剩余对象。

用途或格式证据不足时，补查来源格式、槽位及边界用法。仍无法安全表达时，将结构记为未决，记录已查材料、已尝试方案、具体失败原因和继续所需的格式事实。继续处理可独立确定的结构。

### 2. 更新关系图与表达式方案

初步判断结构后，形成 Mermaid 结构与规则覆盖关系图，并随结构、表达式和覆盖变化更新：

- 节点标明保护结构或规则，标签使用可辨认的结构样例或规则说明。
- 连线标明已核验的包含、重复或覆盖关系与方向。
- 节点和连线均关联到对象、规则和证据。
- 未确认的关系加入待查记录，尚无安全规则覆盖的必要结构标为未决。

没有发现保护结构时记录调查结果。

检查图中的重复对象、错误连接和覆盖缺口，并核对合并、拆分或删除后各成员的去向。按 `src` 对相同正则表达式分组，取得成员证据，示例见 `references/scripts.md`。核验表达式行为、结构关系和保护资格，再同步调整关系图与表达式方案。

### 3. 核对成果

|核对内容|当前处理要求|
|---|---|
|调查完整|记录实际调查范围、证据和种子的处理结果。全部发现对象均有结论，后续问题已处理或有具体未决说明|
|关系可信|必要结构与最终规则均纳入图，包含、重复及覆盖关系有证据，图中暴露的冲突与缺口已处理或明确未决|
|规则成立|各表达式具备独立安全证据，合并、删除或调整后必要结构仍有安全覆盖或明确未决，成员去向可追溯|
|成果一致|关系图、对象记录、最终表达式方案与覆盖对应一致，节点和连线均可追溯到证据，图能正确显示且展示范围明确|

核对发现漏保、误保或归属冲突时，先处理对应结构和规则，恢复确定的安全覆盖，将反例与变化用于后续种子提炼。

## 提交与交付

处理每个业务单元后，先保存结构结论与表达式方案。默认采用全局 `业务单元与提交` 中的统一提交安排。结束自启发循环后，核对完整方案中的结构与规则覆盖关系图、各表达式的安全性和必要结构的覆盖情况。通过验收后，从方案生成变更清单，按工具契约安排批次并提交。

`report` 完成相同的调查与验收后，交付方案和关系图。

写入后完成以下核对：

- 对照最新事实与回执，核对表达式、说明、排序、重复及覆盖，同步关系图。
- 部分成功时记录实际结果，调整尚未成功的方案。
- 将核对产生的新事实用于种子提炼，继续调查受影响的对象，再提交必要修改。

交付时展示已核对的结构与规则覆盖关系图，并说明：

- 代表性模式、循环结束或受阻依据，以及种子账本和业务工作材料链接。
- 实际调查、程序扫描和语义判断的范围。
- 结构与规则各自的数量。
- 实际新增、修改和删除的内容。
- 代表性的边界证据与未决事项。

`report` 的图对应最终方案，`apply` 的图对应实际结果。部分成功时，标明实际结果和待完成的方案。

记录扫描命中次数、命中条目数、实际语义阅读范围，以及结构与规则各自的处置数量。多个命中关联到同一结构时，按结构去重。按规则身份统计规则数量，并说明表达式之间的重叠命中和覆盖关系。每个对象只计入一种处置时，核对各类数量的合计是否与对象总数一致。

核验全部结构关系，并保存覆盖完整范围的图。大图按结构之间的实际关系分组。

正文展示总览与关键关系，提供完整图链接，并说明各图范围及跨图关系。没有发现保护结构时，说明实际调查结果。
