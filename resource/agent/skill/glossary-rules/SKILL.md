# 术语领域判据

glossary 承载普通翻译无法稳定推出的专有译法、身份、消歧和世界观事实。规则维护不依赖质量规则启用状态；字段、匹配和变更行为以当前 workspace contract 为准。

运行时按 `src` 连续字面命中激活条目，把 `src -> dst #info` 交给翻译模型。`info` 是模型能够理解的语义或条件指令，不是程序执行的谓词；程序侧术语应用检查仍按命中 `src` 后是否出现固定 `dst` 判断，不解析 `info`。因此条件化条目可能产生少量后续告警，但这属于可观察、可继续收窄的成本，不能因为追求零误报而预先排除大多数可正确处理的术语。

## 必要性与表达能力

先独立判断事实是否需要 glossary，再判断怎样表达；字段是否完全确定不能反向改变术语资格。

- `required`：对象已经能够确定为专有实体、作品特有概念或其它需要固定译法、身份、指代或消歧的事实；没有 glossary 时，合理译者可能产生足以破坏一致性的分歧，且没有其它最终规则覆盖。
- `not_required`：属于普通称谓、职业、描述性或泛用内容，普通翻译能稳定得到目标结果，未承载必要身份或消歧，或已经由其它最终规则安全覆盖。
- `unknown`：专项下钻后仍无法判断对象是否属于前两类。unknown 不是排除理由；继续尝试条件化、收窄或拆分，只有当前字段确实无法表达任何可执行策略时才 blocked。

人名、别名、姓氏、地名、家族、组织，以及作品特有的物品、技能、生物或概念，在身份可以合理建立时默认 required；只有具体证据证明普通翻译能够稳定得到唯一结果且无需身份或消歧时才推翻。出现次数少、译文暂时一致、当前没有错误、既有规则长期存在或修改麻烦都不改变必要性。

对 required 或可能 required 的事实按以下顺序收束：

1. 读取身份、同名异义、指代、译法分布和边界所需的有限语境，并对相关 `src` 候选取得正式完整匹配。
2. 若合理取值变化不改变 `src` / `dst` 或翻译行为，直接形成规则；不影响翻译的未知信息不必写入 `info`。
3. 若适用条件可以从翻译输入中的局部上下文判断，用 `info` 明确写出条件以及非适用时怎样处理，采用 conditional。
4. 若一个条目不能覆盖全部行为，缩小连续字面边界，或把不同实体、别名和固定分支拆成独立规则，采用 narrowed。
5. 只有没有任何可用固定 `dst`、适用条件在下游不可观察，并且不存在安全的精确边界或分支时才 blocked；给出解除阻塞所需事实和建议。

### 事实状态判例

以下判例只解释判据，不构成封闭术语类型或可脱离工程证据复用的译名表：

| 工程证据 | 状态 | 理由 |
| --- | --- | --- |
| `ミナ` 位于姓名栏，多处语境明确为女性角色，译名可确定为 `米娜` | `required + direct` | 固定译名和性别提示都不能由普通翻译稳定推出 |
| `knight` 在叙述中始终表示普通职业，没有作品专有译法或消歧信息 | not_required | 普通翻译足以稳定处理 |
| `ルナ` 既可能指女性角色，也可能是普通“月亮”，局部句子足以判断 | `required + conditional` | 保留角色条目，并让模型在非角色义项按上下文翻译 |
| `レイ` 只出现在孤立字段，人物、地点和组织会采用互不兼容的译名，当前输入没有任何可观察条件 | blocked | 已无法形成固定值、条件指令或更窄边界；建议补充身份来源或由用户指定译名 |

## 基础发现方向

初始化和残差过程至少覆盖：

- 完整非空 `name_src`、明确名称边界和特殊书写；
- 命名、定义、首次登场、别名、规则、获得、装备、发动、所属和身份变化等语境槽位；
- 并列、枚举、等级、对立体系和其它同构结构；
- `dst` / `name_dst` 的译法分歧、原文残留和身份线索；
- 现有规则未覆盖的文件长尾与单次概念。

把已确认事实在有限语境中的位置抽象成可确定边界的槽位，再完整扫描同槽位的其它连续原文字面量；从别名、同位说明、同系列形式、公共片段、相邻实体和文件结构提出非等价信号。模板与关系只负责发现，不证明术语资格或语义相同。

全部候选使用 `workspace.matchLiterals` 取得 `src` / `name_src` 的正式完整计数和有限代表证据。确认必要性不要求重复出现、既有译文冲突或错误已经发生；同名异义、普通词风险、身份变化、译法分歧或条件适用才增加必要语境。下钻围绕具体缺失维度进行，不为追求绝对确定顺序阅读完整语料。

## 字段与证据

- `src` 是 `item.src` 或 `item.name_src` 中的精确连续字面量，不使用正则。优先选择能够表达稳定核心且不会制造不可控冲突的最短自然边界；宽边界失败时保留精确分支，不阻塞事实。
- `dst` 是非空固定译文。多个候选只存在风格、音译写法或其它语义等价差异时，按用户要求、工程全局风格、已核验同类规则和目标语言惯例选择最合适的一项；glossary 的职责正是把这种自由选择统一下来。只有候选表达不同实体或不同含义时才需要条件化、拆分或阻塞。
- `info` 会进入翻译提示词。直接条目写影响译法、指代或消歧的最少语义，优先实体类型。
- 实体为角色时，`info` 原则上必须包含性别信息，但只在必要时追加年龄、职业、阵营或特殊身份。
- 条件化条目的 `info` 必须让模型知道何时使用本条，以及不满足条件时按什么原则处理；可以使用“仅在……时采用本条，其他义项按上下文翻译”之类的操作性表达。不要只写“可能是”“请注意”等不可执行提醒。
- `info` 不写背景、证据来源、长篇理由或无关例句。不会影响翻译时允许为空；更新或重构时保留仍然正确的既有信息。
- 大小写策略通过分别比较敏感与不敏感匹配集合决定。若不敏感匹配没有引入其它身份或普通词，使用 `case_sensitive: false` 扩大正确覆盖；只有真实大小写碰撞需要隔离时才使用 `true`。不能因未来可能存在未知碰撞而 blocked。
- 已有译文、既有术语和大小写都是待核验事实。

证据依次采用用户明确指定、工程内语境、已核验同类规则和目标语言一般表达。模型语言知识可以形成符合该顺序的译名和条件策略，工程反例优先。风格标准从完整任务范围建立一次并全程复用；多个语义等价值均合理时按该标准选择，不要求出现能够排除所有其它风格选项的决定性证据。

### 字段判例

| 工程证据 | 正确字段或处置 | 错误示例 |
| --- | --- | --- |
| `ミナ → 米娜`，明确为女性角色 | `info: "女性角色"` | `米娜是故事女主角，性格温柔，来自北境` |
| `ノヴァ → 诺瓦`，明确是一座城市 | `info: "地名"` | 留空而丢失实体消歧 |
| `アストラ → 阿斯特拉`，明确是一把剑 | `info: "物品，剑"` | 把锻造历史和持有者写入 `info` |
| `エーテル → 以太`，只需固定译名，没有额外身份或消歧信息 | `info: ""` | 为填字段制造 `特殊概念` |
| `ルナ → 露娜`，角色名与普通“月亮”同形，句内可以辨认 | `info: "女性角色名；仅指该角色时采用本条，其他义项按上下文翻译"` | 因存在普通义项就丢弃角色术语 |
| `エーテル` 可译“以太”或“乙太”，两者在当前语境语义等价，工程奇幻术语统一采用古典译名 | 选择 `dst: "以太"` | 因两个译名都合理而 blocked |
| `レイ` 的三种可能身份要求互不兼容译名，孤立输入无法判断，精确边界也相同 | blocked，并建议用户指定身份或译名 | 写一个没有触发条件的猜测 `info`，或不下钻就 blocked |
| `May` 是角色名而 `may` 是普通词 | `case_sensitive: true` | 不区分大小写并误命中普通词 |
| `ALICE`、`Alice`、`alice` 都指同一角色且无普通词误匹配 | `case_sensitive: false` | 仅因原文含大写字母就启用大小写敏感 |

## 最小充分集合

按必要性、正确性、充分性、作品风格、一致性、最小性的顺序，从全部 required 事实重新构造最终集合；只有先满足前五项，才选择条目更少、边界更自然且维护成本更低的集合。最小化是规则集合优化，不是重新判定底层事实资格的入口。

按照共享 workflow 的结构组逐项确认语义身份，只把真正相关的成员选成一个子集；异义、失败或 blocked 成员退出该子集，不影响其它成员。语境确认子集内多个形式确实相关后，才调用 `workspace.deriveCommonLiteralRoots({ forms })` 按可见字符从短到长枚举公共连续片段。聚类方法的 `shared_root` 只是审查锚点，不能直接成为最终 `src`；词根方法也只提供字面候选。

先判断候选是否表达共同稳定概念，再把有语义资格的词根与拟替代分支交给 `workspace.matchLiterals`，比较分支 item 并集 B 与“词根 + 分支”并集 R，并核验新增匹配。`R - B` 中的每个新增匹配必须按共享 workflow 进入 fact 或 derived probe，不能只作为当前词根的通过或拒绝理由。

采用词根需要同时满足：

- 候选表达共同稳定概念并覆盖全部拟替代 required 事实；
- 一个 `dst` 与直接或条件化 `info` 能承载必须统一的译法、身份、风格或消歧；
- R = B 且无其它反例；或 R > B 时，新增匹配已经耗尽并能够由同一直接规则或清楚的条件 `info` 正确处理；
- 剩余普通文本能与词根译法正确组合。

R < B、出现模型无法可靠区分的高频普通词或其它实体、不可组合译法，或必要分支信息无法由词根承载时，只拒绝该词根并保留精确规则。新增证据尚未耗尽时继续核验词根候选；不值得继续核验时同样回退精确规则。合并失败不能使任何已确认 required 事实 blocked。最终每个 required 事实以 `covered_by` 映射到直接、条件化或精确分支规则；词根合并不能减少事实数量或掩盖漏收。

### 词根判例

| 已确认事实与完整匹配 | 结论 | 决定性理由 |
| --- | --- | --- |
| `セラ`、`セラ王女`、`セラ殿` 都指同一角色，称谓可由剩余文本正常翻译，词根没有新增误匹配 | 采用 `セラ` | 一个译名和角色 `info` 能覆盖共同身份 |
| `ドトール家`、`ドトール領`、`ドトール伯爵` 都由同一家名派生，R = B，剩余文本可组合 | 采用 `ドトール` | 词根稳定表达家名，分支身份仍由剩余文本表达 |
| `セラ` 是角色，`セラ教団` 是与她无关的组织 | 不合并 | 字面重合不代表共同语义身份 |
| `黒騎士` 与 `白騎士` 只共享普通词 `騎士` | 不合并为 `騎士` | 前缀承担必要区别，公共部分不是作品专名 |
| `Alice` 与 `Alicia` 只偶然共享 `Ali` | 不合并 | 公共字符不表达稳定共同概念 |
| 分支并集 B 为 8 个 item，候选词根令 R 增至 12 个；新增 4 项均可由上下文清楚区分角色与普通义 | 可采用带条件 `info` 的词根，也可在合并收益不足时保留分支 | 少量可处理新增命中不构成 blocker |
| 分支并集 B 为 8 个 item，候选词根令 R 增至 120 个且多数是高频普通词 | 拒绝词根，保留全部 required 分支 | 合并优化失败，不影响精确条目创建或保留 |
