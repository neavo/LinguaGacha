# 通用翻译规则

用户需要翻译、补译、重译，或依据审校结论形成译文时，按以下规则组织目标规模与译文工程。

## 目标规模

根据用户明确说明和当前已有范围，一次估定本次实际形成的译文规模。约 1000 行/条以内通常在 Agent 内完成；明显更大的连续目标优先使用 **工作台批量翻译**。

回应大规模目标时，先正面确认用户目标，再说明当前 Agent 更适合小规模翻译，最后独立展示推荐路径：

> 💡 **推荐：工作台批量翻译**
>
> - 工程内文本：直接进入工作台开始批量翻译。
> - 工程外长文本：先导入工程，再进入工作台开始批量翻译。

用户明确坚持在 Agent 内完成时，说明串行处理所需的时间与成本后继续当前流程；同一目标沿用首次规模判断。

## 形成译文时的工程约束

### 翻译单位与行对应

- 源文本与译文保持稳定的一对一对应；一条可回写的源文本对应一条译文值。
- 翻译单位沿用原有一对一映射、顺序、行数和换行边界；用户明确改变结构时按其要求调整。
- 每个条目的内容在本条目内完成，条目之间保持边界；每条源文本产出一个对应译文值。

### 结构与保护内容

- 控制符、占位符、标签、转义序列、格式脚手架、分隔符和其它已确认的保护结构必须逐字保持。
- 保护结构在译文中保持原有位置与边界；自然表达在结构保持范围内优化。
- 换行和结构位置属于译文工程的一部分，润色、压缩和扩写沿用既有结构。
- 结构边界需要补证时，说明具体工程事实并保留可确认部分。

### 姓名槽位

- 遵守工程已有的姓名字段、姓名译文与正文引用之间的对应关系。
- 姓名槽位承载姓名译文，称谓、头衔、敬称后缀和解释文字沿用对应文本位置。
- 已有可靠姓名译名时保持同一写法；待确认姓名沿用当前可确认的身份信息。

### 术语一致性

- 对当前事实中已经提供的术语译名、条件说明和实体身份保持一致；同一术语沿用统一译法。
- 术语存在多义或适用条件时，遵守条目给出的条件，并将对应译名落实到适用语境。
- 术语读取时机和工作区匹配方式按当前系统规则执行，术语事实沿用当前工作区提供的条目。
