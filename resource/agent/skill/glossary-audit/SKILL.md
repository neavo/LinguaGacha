# 术语表审校

以数据库事实和原文语境完成「发现—审校—确认—写入—复核」闭环，按全表覆盖、一致性和维护成本评价结果，不为旧条目保留无依据的兼容层。

- 术语按自身 `case_sensitive` 对原始 `src/name_src` 做字面量子字符串覆盖，不识别词边界，包含或重叠条目可同时覆盖。
- 翻译只激活已覆盖且 `dst` 非空的条目，按 `src -> dst #info` 提供给模型。
- 因此 `src` 必须是原文中实际出现的连续子字符串，条目边界、译法和 `info` 直接决定翻译结果。

## 审校范围

- 默认覆盖整张术语表。
- 用户明确限定条目、词语或问题类型时，只为范围内条目形成结论和变更，范围外条目仅作关系证据，范围外冲突列为未决，不得擅自扩大变更。

## 判定规则

### 收录边界

- 先查原文语境再定译名、语义身份和边界；只保留影响翻译一致性、属性判断或世界观理解的核心专有名词。
- 去掉爵位、称谓、职业、所属关系和泛用后缀，截取保证身份和译法所需的最小连续边界。
- 不收录脱离作品设定也能直接理解的泛用词，例如剑、魔法、城堡、怪物、公会、先生、战士。
- 不用正则代替精确边界；同一专名及其同根条目保持同一译法，有意区分必须由语境证明。
- 空 `dst` 条目不激活翻译，须补译或删除，不做无效保留。

### `info` 字段

- `info` 是后续翻译的简短、稳定语义提示。
- 优先使用推荐值保持全表一致：`男性角色`、`女性角色`、`地名`、`家族`、`组织`、`特殊物品`、`特殊技能`、`特殊生物`。
- 推荐值不足以准确表达时填写简短可复用的说明，不得为套用推荐值丢失或扭曲语义。
- 不得仅因 `info` 未命中推荐值而修改条目；只有错误、误导或缺少影响翻译的必要信息时才修改。

### 同根词

把以下关系放进同一组共同判断，避免同根条目得出冲突结论：

- 包含关系：`A` 与 `AB`。
- 共享词根：`AB` 与 `AC`。
- 全名与简称或称谓形式。
- 地名与其派生或附属实体（机构、部门、设施、区域）。
- 团体、家族与其头衔、职务或成员全名等限定形式。
- 专名与说明性后缀。

按优先级处理：

1. 某条从未独立出现：删除，保留实际出现且边界正确的形式。
2. 词根即可覆盖且不会误匹配：只保留词根。
3. 派生词改变了专名身份或译法：保留必要的派生词，统一公共词根译法。
4. 词根过短、会在普通词中误匹配：保留更精确的完整词。
5. 全名和简称都独立出现且译法不能由一条覆盖：两者均保留。

先决定核心实体，再用最少条目覆盖真实翻译需求，不为每个「某地分会」「某人会长」建立补丁式条目。

### 判定示例

| 原文事实 | 结论 |
| --- | --- |
| `临冬城`始终指作品内城市 | 保留为`地名` |
| `秋月集团`始终指作品中的同一家公司 | 保留为`组织` |
| `东京魔法学院`始终指同一所学校 | 保留为`组织`；"魔法学院"虽泛用但不可拆分 |
| `剑`只表示普通武器 | 删除 |
| `艾琳·冯·黑伍德`从未作为连续字符串出现，`艾琳`独立出现 | 删除全名条目，保留`艾琳` |
| `铃兰`指人，`铃兰号`指飞船 | 派生改变了专名身份，两者均保留并分别标注`女性角色`、`特殊物品` |
| `シン`是角色名但作为词根会误匹配`シンジ`等无关词 | 不按共享词根合并，各自保留精确全名 |
| `骑士艾琳`中的“骑士”只是称谓 | 保留`艾琳`，删除完整称谓条目 |
| `感情伝達魔法`与`感情伝達の魔法`共享词根，`感情伝達`可正确覆盖 | 只保留`感情伝達` |
| 同一字符串在不同位置分别指人名和地名 | 不凭字符串强行合并；若单条替换无法安全表达，列为未决并说明工具限制 |

## 工作流

### 1. 建立事实快照

本轮审校开始时调用一次 `query_quality_rules`（`rule_type: glossary`），一次性读取：

- 完整术语表及每条的出现统计（`matched_item_count` / `total_matches`，后者允许大于覆盖条目数）、违规信号（`fact_violations`）和语境样本（`sample`）。
- `structure` 的重复、包含、共享词根三组关系。
- `sectionRevisions` 修订号。

零出现、空译文、重复、包含和共享词根只是审校队列的排序信号，不能据此跳过没有信号的范围内条目。

### 2. 建立关系组并逐项审校

按重复、包含和共享词根把范围内条目组成审校组，其余条目单独成组；组内先按同根词优先级定整体结构，再定单项结果。每条依次确认：

1. **出现事实**：命中条目数、代表样本的 `item_id`、命中字段和完整原文；零出现条目不合法。
2. **语义身份**：在语境中指人、家族、地点、组织、物品、技能、生物还是设定概念。
3. **专有性**：是否构建作品独有世界观，或必须统一才能避免翻译错误。
4. **边界**：按收录边界截取唯一不可拆的正式名称。
5. **译法**：结合已核验语境、既有译名和同根条目选择稳定译法，修正错别字和属性错误。
6. **全局关系**：包含、共享词根、全名/简称、错拼/异体、同名异义。
7. **动作**：保留、修改、删除、新增或未决。

- 新增仅限用户指定的条目或审校证据中反复出现的未收录专名，必须先检索原文确认实际出现，并满足与既有条目相同的收录、边界、`case_sensitive` 和同根规则，不得凭空造词。
- 完整审校必须让范围内每条术语和关系组得到结论；判定依据不足的条目列为未决，不进入可执行计划。

### 3. 证据随取随停

以快照的 `sample` 语境和关系事实作为初始证据，多数收录、边界、`info` 与译法判定可由此完成；判定的标准是第 2 步七项确认都有支撑，而非取样多少。出现以下任一情况时必须启动原文深化：

- 语义身份存在多个候选，单条 sample 无法区分。
- 高频词且命中数高，单条 sample 不足以区分地名、人物、称谓等语义簇。
- 全局关系（同名异义、全名/简称、错拼/异体）无法仅凭快照结构信号判断。
- 修改译名、`info`、边界需要支撑 `item_id`，或删除实际出现的条目需要展示原文证据。

深化方式与预算：

- 先用 `query_items` 按 `item_id` 精读 sample 已有条目。
- 仍不足时用 `query_items` 按 `src` 正文精确检索（非正则、`case_sensitive` 沿用条目设置），首屏按工具默认每页 20 条。
- 同一条术语沿返回的 `cursor` 最多翻 3 页，仍无法定性时列入未决，写明已核验样本量与残留候选语义，不无限取证。

约束：

- `sample === null && matched_item_count > 0`：全部命中条目都缺少有效同条目语境，不重复搜索期待不存在的语境，直接列为未决或仅使用关系事实。
- `matched_item_count === 0` 的条目不查询原文，以零出现和关系事实作为证据。
- 任一深化查询返回的 `items` 或 `quality` 修订号与初始快照不同，丢弃本轮原文证据并从第 1 步重建快照。
- 每项修改或删除至少保留一个支撑判断的 `item_id`；删除实际出现的条目时展示其属于泛用词、称谓、冗余派生词或错误边界的原文证据。

### 4. 形成并交付方案

- 根据逐项审校结论形成准确的 create / update / delete 集合；create / update 包含完整条目（`src` / `dst` / `info` / `case_sensitive`），修改或删除均有已核验事实支撑，未决项不进入变更集合。
- 变更集合只表达与原快照的差异，不重写未变条目，不夹带格式整理，仅删除零出现的既有条目可以没有 `item_id` 证据，理由须为未出现或被有效同根条目取代。
- 若没有可执行变更，报告整体结论、保留与未决数量，逐项说明重要歧义和全部未决项后结束，不进入批准和写入。
- 若存在可执行变更，先报告整体结论、create / update / delete / retain / unresolved 数量与变更前后数量（`快照条目数 + create 数 - delete 数`）。可执行变更组的数量之和必须与完整变更集合一致。
- 按术语处理原因归组，例如零出现、泛用词、冗余称谓或派生形式、同根合并、译法修正、`info` 修正和边界修正。每组说明共同处理、语义理由和对翻译的影响，并用实际 `src` / `dst` / `info`、命中统计和可用的原文片段提供能证明结论的最少证据，定位信息只附着于证据。
- 用户明确点名要求判断的条目、无法由组结论准确覆盖的变更、具有独立译法 / 边界 / 语义取舍的变更、保留项中的重要歧义和全部未决项必须逐项说明，普通保留项和重复证据不展开。
- 明确声明尚未写入并停止，等待用户批准，用户修改方案时，重算完整变更集合和受影响的分组，再次交付并等待批准。

### 5. 写入并复核

- 获得明确批准后调用一次 `update_quality_rules`（`rule_type: glossary`），提交且仅提交批准方案对应的完整 changes，携带快照修订号 `expected_section_revisions: { quality: sectionRevisions.quality }` 原子写入，不夹带未批准条目。
- 写入成功后以返回的 `accepted` / `affected_entries` / `deleted_entry_ids` / `sectionRevisions.quality` 逐项核对完整 changes；最终数量沿用批准方案计算，不追加查询。最终只报告执行结果、数量、新修订号、异常和未决项，不重放方案。
- `RevisionConflictError`：不得覆盖或强写，从第 1 步重建快照，按原审校范围重做方案，回到第 4 步重新取得批准。
- 返回与批准方案不一致：报告写入响应异常并停止，不补写。
