# 文本保护领域判据

text_preserve 不承载语义，只保护翻译过程中必须逐字保持的控制符、占位符和格式脚手架；仅在文本保护模式为自定义时参与翻译，维护资格与生效状态互不影响。字段、匹配和变更行为以当前 workspace contract 为准。

自定义规则按 JavaScript 正则确定性匹配，`info` 不参与运行时判断。因此最终表达式的每个真实命中都必须可以原样保留；但一个宽候选存在反例，只能证明候选边界太宽，不能证明其中的结构对象不值得保护。先细化或拆分表达式，再判断是否仍需补充信息。

## 保护资格

先判断结构对象是否必须原样保留，再判断怎样用安全正则表达：

- **必须保护**：已经确认存在必须逐字保持的非语义结构，普通翻译不能稳定保持目标行为。宽候选正则尚未安全，不改变该结构对象的保护资格。
- **无需保护**：当前对象属于自然语言或其它规则类型，普通翻译能够稳定处理，或者补充调查后确认其中不存在必须逐字保持的结构。某个宽表达式会吞正文，只能否定该表达式，不能单独证明结构对象无需保护。
- **尚不能判断**：补充调查后仍无法判断命中是否为非语义结构；继续尝试按形态、位置或固定前后缀缩小范围，只有无法得到任何安全表达式时才列为需要补充信息。

出现次数少、当前没有损坏、当前未启用、既有规则长期存在或修改麻烦都不改变保护资格；零命中不能单独证明既有规则无效。

## 基础发现方向

候选来自控制符、占位符、格式脚手架、相关 warning、已有译文的结构损坏，以及 glossary 路径发现的重复名称槽位或相邻固定标记。每个候选：

1. 只扫描原始 `item.src` 并按 `\n` 拆行，不扫描 `name_src`。
2. 以 `new RegExp(source, "giu")` 编译，拒绝非法或零长度表达式。
3. 完整聚合 item、行、片段、`text_type` 和文件分布。
4. 保留有限代表片段、位置和必要上下文。
5. 把命中按结构形态和实际保护行为分为必须保护、自然语言或其它行为、仍需核验三类，再决定直接采用、缩小范围、拆分、无需保护或需要补充信息。

不同候选的重叠命中分别计数；不推演多条规则的组合应用、先后顺序或全局覆盖率。只有身份完全重复或保护边界直接冲突的规则共同处理。

按照共享工作流的结构组安排审查顺序。text_preserve 的 `src` 是正则源码，不能用源码包含或公共字符片段推断执行关系；当前规则共用同一执行配置，因此只有源码完全相同的条目可以作为 `equivalent` 共同检查重复。每条规则的真实命中、安全边界和最终处理仍分别验证。

## 表达式收束阶梯

1. **直接表达**：候选合法、不会产生零长度或危险回溯，且完整扫描中的全部真实命中都必须原样保留时，直接形成规则。
2. **形态分组**：候选同时命中结构和正文时，按已观察到的标签名、控制符前缀、参数字符集、定界符、固定长度、位置或 `text_type` 分布分析差异。`text_type` 只提供证据，不能成为运行时隐藏条件。
3. **缩小范围或拆分**：为确定安全的结构子集生成一个或多个更窄正则，分别重新编译和完整扫描。宽候选本身可以不采用或删除，安全子表达式作为独立保护对象创建或更新。
4. **保留确定部分**：仍有未知形态时，不让未知尾部影响已经验证安全的规则；把剩余形态作为独立对象继续调查。调查中发现的新结构形态、匹配或边界反例必须交回共享工作流，作为新的待判断对象或范围与方法明确的补充调查。
5. **需要补充信息**：只有某个已确认必须保护的结构无法由任何合法、非零长度、不会吞正文的正则隔离时，才列为需要补充信息，并给出缺少的格式事实或建议的手工边界。不能只写“没有核验全部命中”。

## 字段与安全边界

- 每条 `src` 独立按 JavaScript 正则语义执行；`text_type` 和文件只解释分布，不改变匹配结果。
- `info` 只供用户识别规则，不参与编译、匹配、覆盖或必要性判断。能确认结构身份时使用简短说明；保留仍然正确的既有说明，表达式含义改变时同步更新，无法可靠命名时允许为空。
- 非法、零长度、无界通配、嵌套量词回溯或会吞掉自然语言正文的表达式不得进入最终规则。
- 表达式修改后必须作为新值重新完成完整扫描，旧证据不可复用。
- 最终集合逐项来自必须保护对象的直接或缩小范围后的表达式；需要补充信息的对象、范围外观察以及 pre_replacement / post_replacement 不进入 change。宽候选失败时，已经验证的安全子对象仍然进入 change。

## 正则边界判例

以下判例的结论依赖所述完整扫描事实，不能脱离真实工程直接套用表达式：

|候选与完整扫描证据|状态|理由|
|---|---|---|
|`\{player_name\}` 的全部命中都是同一角色名占位符|必须保护并直接形成规则|边界确定且每个真实命中都必须原样保留|
|`\{\d+\}` 的全部命中都是编号占位符|必须保护并直接形成规则|参数变化已由窄表达式覆盖，未吞掉自然语言|
|`\{.*\}` 同时覆盖占位符与正文|拒绝宽表达式，尝试 `\{[a-z_][a-z0-9_]*\}` 等由真实形态支持的窄候选并重新扫描|宽候选不安全不代表占位符无需保护|
|`^` 或 `.*?` 会产生零长度命中|新候选直接拒绝；现有规则判定为无需保护|零长度规则不能进入候选对象或最终集合|
|`<[^>]+>` 同时命中已确认 HTML 标签和比较表达式|根据实际标签集合拆出如 `</?(?:b|i)>` 的安全规则；比较表达式不保护|混合命中不影响已确认标签形成规则|
|某控制结构必须保护，但它与自然语言使用完全相同的字符和位置，任何正则都会同时吞掉正文|列为需要补充信息，并建议补充格式标记或改用可区分边界|未尝试窄表达式就搁置|
