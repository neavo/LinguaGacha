# 术语表审校

对现有术语和有界补漏事实使用同一领域判据：加载规则与快照 → 中性分类事实 → 构造最小充分集合 → 计算差异 → 原子写入。

## 必读领域规则

进行任何术语判断前，检查当前模型上下文是否已经包含 `glossary-rules` 的完整正文。若尚未包含，从 `<available_skills>` 中按名称精确找到它的 `location`，调用 `read_skill` 读取其 `SKILL.md`；同一独立任务只读取一次。

若 `glossary-rules` 不存在、不可读取或正文无效，进入“无法继续”，不得从本技能、旧对话或经验重建术语定义。

## 范围、所有权与事实模型

- 本技能只写术语规则。默认评价整张现有术语表；用户限定范围时，只处理各组 `targets` 中的目标条目。
- 被 `glossary-create` 以明确 `targets` 调用时，只处理这些目标所在的完整关系闭包并覆盖默认全表范围；证据产生的新事实加入调用方的候选前沿，不另建账本，不重新扫描全工程，也不要求用户另开任务。
- 用户明确要求不修改的术语从目标集合排除，保持原样且不计入处置；同组排除项和其它范围外条目只作为关系证据。范围外冲突又无法越权处理时，受影响事实未决。
- 先把范围内每条现有条目还原为它声称覆盖的事实，再与有界补漏事实统一进入 `需规则承载`、`无需规则承载`或`未决`；条目是否存在不属于事实状态。所有需承载事实共同生成最终规则集合后，才计算保留、修改、删除、新增或移动。
- 当前范围内每条现有术语最终且只能映射为 `保留`、`修改`、`删除`或`未决`；四类数量之和等于目标总数。事实分类计数与变更计数分别报告，不混算。
- 用户收窄范围时只报告实际覆盖范围，不把局部结论写成全表或全工程完成。

## 有界事实发现

审校必须检查当前证据内的充分性，但只从已经读取的关系和语境发现事实：

- **关系事实**：同组或替代单元中的别名、简称、同一实体其它形式、必要独立分支或安全公共词根。
- **语境事实**：代表例句和必要邻近文本中身份明确、边界和具体值可核验的专名或作品特有概念，包括单次出现者。
- **姓名事实**：已读取 item 的非空 `name_src` 尚未安全覆盖，且身份、边界和具体值可以核验。

这些事实直接按 `glossary-rules` 的统一判定进入同一事实集合，不要求重复出现、已有译文冲突或错误已经发生。不得为补漏扫描全部 item 或建立全工程候选账本；需要脱离现有术语关系主动发现时使用 `glossary-create`。

## 零出现

- 现有目标在当前语料中零出现时缺少核验其身份、边界和具体值的工程证据，列为未决；不补查、不写入，也不由未命中推导删除。
- 整组零出现时，范围内成员全部未决。混合组中的零出现成员自身未决；若未知成员可能改变最终集合，受影响目标同样未决，否则有出现成员正常审校。
- 用户明确指定新增、修改或删除及最终值时，按用户指令检查字段与关系，不以零出现阻断。

## 结构组

质量查询以 `entry_fields` 声明规则行列顺序，每个 group 直接包含 `targets` 目标行和 `evidence` 范围外证据行。后端先合并原文字面量完整覆盖或匹配等价的强关系，再以单一公共连续词根补足相关形式；每个 group 是有界、互斥且包含单例的共同审校范围。

- 结构组只确定共同核验范围，不表示成员语义相同，也不为旧条目提供保留理由；只有 `targets` 行的 `id` 属于处置范围。
- 模型不得重新计算、拆分或另建结构组；关键词搜索展开直接命中目标所在的完整结构组。
- 先程序化完成由字段事实或确定规则唯一决定的筛选、计数和变换，再审查剩余语义目标；`evidence` 行不计入目标数量。
- 多个审查组累计处理时，维护统一的事实分类、目标处置和计数账本，每组完成后更新，不依赖自然语言回忆重建全局状态。

## 工作流

### 1. 建立事实快照

1. 调用 `workspace_load`，根据摘要和 contract 确认权威语言、完整数量和数据集语义。
2. 取得 glossary 正文、命中、代表例句和完整后端关系组；用户未限定原文时覆盖整张术语表，明确限定或排除时以各组剩余 `targets` 建立范围。
3. 先完成程序化处理，再为剩余语义目标组成审查组并在 system 要求时确认范围。
4. 从完整任务范围建立一次全局风格标准，所有审查组复用，不按局部多数重新定义。

### 2. 中性分类与有界补漏

不能按 entry 顺序逐条检索。先忽略条目当前存在以及预期动作，按组核验各项事实的身份、边界、具体值、合理分歧风险和安全覆盖关系，并按 `glossary-rules` 分类；此阶段不得直接用“保留”“删除”代替事实结论。快照 examples 可以证明这些事实，但“当前译法可接受”或“没有发现冲突”不能单独证明需要规则承载。

证据不足以判决有出现目标时，以纯字面量 OR 匹配该组全部待核验原文，读取按 item 去重的最少代表证据；同名异义、高频短词根、身份变化或具体反例才扩展邻近语境，不重复等价查询期待结论改变。审阅过程中发现的有界事实按同一标准分类。

### 3. 构造最终集合并验证公共词根

从全部需承载事实重新构造最小充分规则集合，不以当前条目为起点。准备以一个候选词根替代多个现有分支时，把词根及拟替代分支视为一个替代单元，在相同工作区和原文范围执行两次组级查询：

1. 只用全部拟替代分支做 OR 查询，返回至多一个代表语境，以完整匹配总数记为基线数 B。
2. 用候选词根和全部拟替代分支做 OR 查询，返回至多五十个语境，以完整匹配总数记为候选数 R。

`total_item_count` 表示完整匹配集合数量，返回的 `items` 只表示证据窗口；查询结果按 item 去重，以 `matched_keywords` 区分词根和完整分支命中。

| 完整计数与语境 | 结论 |
| --- | --- |
| R = B，且没有不可组合、风格或消歧证据 | 采用词根 |
| R > B，全部新增匹配已返回且均安全 | 采用词根 |
| R > B，发现具体误匹配 | 放弃词根，保留必要边界 |
| R > B，仍有未返回的新增匹配 | 相关事实未决，并点名缺少的语境 |
| R < B | 词根不满足覆盖要求 |

已核验词根所替代的冗余分支不再分别补证。

### 4. 计算差异并形成方案

把最终集合与当前 glossary 比较：需承载且规则相同则保留；需承载但规则值不同则修改；需承载但缺少规则则新增；现有边界不属于最终集合则删除；事实未决则不写入。必要排序另映射为移动，不改变事实分类。

- 最终词根已存在时保留或更新；不存在时，用一个范围内拟替代分支的 `id` 修改为词根并删除其余分支，不新建词根后再删除全部旧条目。
- 新增和修改给出完整原文、译文、语义提示和大小写策略；未变条目不得重写，未决不得进入 change。
- 最终集合中的每条规则都必须指向需承载事实；额外完整分支还必须给出不可由词根安全承载的具体证据。
- 报告审校范围、事实分类计数、目标处置和最终变更计数、变更前后总数、词根关系、预期覆盖变化、全局风格依据和最少代表证据；用户点名事实、独立取舍和全部未决逐项说明。

有可执行变更但尚未授权时使用 system 的“写入确认”；已有授权时直接执行；没有变更时使用“审查结果”。

### 5. 写入并核对

获得明确授权后，用 `workspace_script` 分别写入 `workspace.contract.changes.glossary` 下的 creates、updates、deletes 和 moves；不得修改其它 quality kind。质量规则提交不设数量上限，默认用一次 `workspace_apply` 原子提交完整方案。

核对 apply 回执中的新增、修改、删除、排序计数和新 revision。事务回滚可安全重试；stale 或 revision 冲突后重新 load 并重做受影响方案；`data.committed_sync_failed` 按已经写入处理并要求重新加载工程，绝对不得重试 apply。响应与授权方案不一致时停止，不自行补写。
