# 术语表审校

以当前工程事实快照和原文语境完成“建立快照—关系审校—证据深化—方案确认—原子写入—结果核对”闭环。默认按全表覆盖评价；用户限定范围时，按确认范围的完整覆盖、一致性和维护成本评价。不为旧条目保留无依据的兼容层，也不为相同根因建立多条补丁式术语。

## 术语行为

- 术语按自身大小写设置对原文正文和原文姓名做字面量子字符串覆盖，不识别词边界。
- 包含或重叠条目可以同时覆盖。
- 翻译只激活已覆盖且术语译文非空的条目，并使用术语原文、译文和语义提示。
- 术语原文必须是语料中实际出现的连续字符串。
- 边界、译法、语义提示和大小写设置共同决定翻译效果。

## 工具映射

- 使用 `query_quality_rules` 读取或分析术语规则，规则类型固定为 `glossary`。
- 使用 `query_items` 补充原文证据。
- 使用 `update_quality_rules` 原子写入获批的术语差异。
- 工具调用参数始终以当前 Schema 为准。
- 本技能中的业务名称不代表额外字段。

## 审校范围

- 默认覆盖整张术语表。
- 用户明确限定条目、词语或问题类型时，只为范围内条目形成结论和变更。
- 范围外条目只作为关系证据，范围外冲突列为未决。

## 收录与字段规则

- 先查原文语境，再判断语义身份、必要边界和译名。
- 保留会影响翻译一致性、属性判断或世界观理解的专有名称和设定术语。
- 删除脱离作品设定也能直接理解、且无需统一译法的泛用词。
- 选择能够稳定表达实体身份和译法的最小连续边界。爵位、称谓、职业、所属关系和泛用后缀只有在不改变身份、译法或安全覆盖时才移除。
- 不用正则代替精确边界。
- 同一专名及其同根条目保持公共部分译法一致，有意区分必须由语境证明。
- 术语译文为空的条目不会参与翻译，应补译或删除。
- 语义提示应简短、稳定并可复用。
- 优先使用 `男性角色`、`女性角色`、`地名`、`家族`、`组织`、`特殊物品`、`特殊技能`、`特殊生物`。
- 推荐值不足时使用准确的短说明。
- 不因语义提示未命中推荐值而机械修改。
- 只有错误、误导或缺少影响翻译的必要信息时才改。

## 关系组与独立覆盖

关系组来自快照中的重复、包含和结构候选，以及审校时从术语结构和语境中识别的共享词根、派生与身份关系。以下关系只表示需要共同审校，不直接证明应该合并：

- 重复原文。
- 包含关系，例如 `A` 与 `AB`。
- 共享词根，例如 `AB` 与 `AC`。
- 全名、简称和称谓形式。
- 地名及其派生实体，团体或家族及其职务、成员或设施。
- 专名及其说明性后缀。

“安全覆盖”指删除或缩短某条术语后，目标形式仍能命中，不增加普通词或其它实体的误匹配，也不丢失独立译法或语义身份。

“独立覆盖”指某条术语相较同组其它条目，是否增加新的命中范围、译法约束或语义身份。按以下顺序决定组内结构：

1. 先确认各条目的实际覆盖、语义身份、译法和大小写行为，不能只比较出现次数。
2. 某条目的全部命中已被另一条安全覆盖，且没有增加独立译法或语义身份：删除没有独立覆盖价值的条目。
3. 公共词根能够覆盖所有目标形式且不会误匹配：只保留公共词根，即使它不以完整词形单独出现。
4. 派生词改变了专名身份或译法：保留必要派生词，并统一公共部分的译法。
5. 短词根会命中普通词或其它实体：保留能够排除误匹配的完整形式。
6. 全名和简称都真实使用，且不能由一条安全表达：两者均保留。
7. 同一字符串在不同语境指向不同实体，单条术语无法安全表达：列为未决并说明工具限制。

例如，若 `A` 与 `AB` 的覆盖条目数和实际命中次数相同，则 `AB` 可能没有独立覆盖价值；仍须确认安全覆盖和语义身份，计数不能单独证明应该删除。

若 `AB` 指向不同实体，则仍应保留。

## 工作流

### 1. 建立事实快照

每轮审校开始时建立一份完整术语事实快照；相关修订号变化后，本轮结论失效并重新建立快照。快照包括：

- 完整有序术语表、每条的覆盖条目数、实际命中次数、事实信号和代表语境。
- 重复、包含和共享词根关系。
- 与术语和原文证据关联的修订号。

零出现、空译文和关系信号只用于排序审校队列，不能代替对范围内每条术语的判断。

### 2. 逐组审校

先按关系组成组，其余条目单独成组。每组依次确认：

1. **覆盖事实**：命中数量、字段、代表原文和大小写行为。
2. **语义身份**：人物、家族、地点、组织、物品、技能、生物或设定概念。
3. **收录价值**：是否必须统一才能避免翻译错误或维护误判。
4. **边界与独立覆盖**：最小安全边界、误匹配风险和相邻条目的覆盖价值。
5. **译法与语义提示**：是否准确、稳定并与同根条目一致。
6. **动作**：保留、修改、删除、新增或未决。

新增只限用户指定的条目，或审校证据中反复出现的未收录专名。

必须确认实际出现，并按相同规则检查边界、译法、语义提示、大小写和关系组。

完整审校必须让范围内每条术语和关系组被某项结论覆盖；具有相同事实、根因和处理方式的条目可以归组，不要求逐项展开。

证据不足的条目列为未决，不进入写入方案。

### 3. 按需深化证据

先使用快照中的代表语境和关系事实。仅在以下情况补充原文证据：

- 语义身份存在多个候选。
- 高频词的单个样本不能区分人物、地点、称谓或普通词。
- 同名异义、全名与简称、错拼或异体关系无法确定。
- 现有样本不足以支撑译名、语义提示、边界或删除结论。

快照样本足够时直接使用；缺少决定性字段时才读取代表证据条目。

仍不足时，按术语原文做字面量子字符串检索，不使用正则，大小写设置与术语一致。每条术语最多补充核验 60 个不同条目，快照自带样本不计入。

达到上限仍无法定性时列为未决，不继续分页，也不扩大原审校范围。

- 有命中但没有有效语境样本时，不重复调用等价查询期待同一证据出现。
- 关系事实不足则列为未决。
- 零出现条目不需要继续检索原文。
- 补充证据期间相关修订号变化时，丢弃旧证据并重建快照。
- 每项修改或删除必须关联至少一个有效证据条目。
- 现有代表样本足够时无需重复查询。删除零出现条目可以没有证据条目。

### 4. 形成写入方案

形成新增、修改和删除差异，同时统计保留与未决。

新增和修改必须给出完整术语原文、译文、语义提示和大小写设置。

未变条目不得重写，未决项不得进入变更集合。

使用 system 的“写入确认”模板，并包含：

- 审校范围及是否完整覆盖。
- 新增、修改、删除、保留、未决数量，以及变更前后总数。
- 按零出现、泛用词、冗余形式、同根整理、译法、语义提示、边界等业务原因分组的变更。
- 每组的共同处理、翻译影响和最少代表证据。
- 用户点名条目、独立取舍、重要保留歧义和全部未决项的逐项说明。

没有可执行变更时使用 system 的“审查结果”模板，不请求写入批准。

审查结果包含范围完整性、保留与未决数量、重要歧义、代表证据和验证结果。

### 5. 写入与核对

获得明确批准后，只提交获批差异，并携带方案所依据的质量规则修订号原子写入。

完整获批差异必须一次提交，不拆分为多次写入。

- 核对写入是否接受、实际增删改是否与获批集合一致，以及修订号是否推进。
- 响应缺项或不一致时使用 system 的“无法继续”模板，不补写。
- 使用 system 的“执行结果”模板报告实际变更、验证、异常和未决。
- 默认不重新审校全表结构。
- 在“可选后续”中说明可以再次检查重复、包含、同根关系和事实信号。
- 用户已明确要求写后复核时才继续执行。
