# 术语表审校

在当前工程内完成术语表审查与修复：建立快照 → 组内补证与审查 → 方案确认 → 原子写入 → 结果核对。

## 目标与边界

- 本技能只写术语规则。
- 默认评价整张术语表；用户限定范围时，只为范围内条目形成结论和变更。
- 范围外条目只作为关系证据；范围外冲突影响范围内结论但又不能越权修改时，将受影响条目列为未决。
- 不为旧条目保留无依据的兼容层，也不为相同根因建立多条补丁式术语。
- 完整审校必须让范围内每条术语和关系组被一项结论覆盖。具有相同事实和处理方式的条目可以归组，不要求逐项展开。

## 术语领域模型

- 术语按自身大小写设置，对原文正文和原文姓名做字面量子字符串覆盖，不识别词边界。
- 包含或重叠条目可以同时覆盖。
- 翻译只激活已覆盖且术语译文非空的条目，并使用术语原文、译文和语义提示。
- 零出现术语不参与当前翻译，但仍是可保存的工程规则。
- 边界、译法、语义提示和大小写设置共同决定翻译效果。

## 判断方法

### 处置与计数

先按关系组重建最小充分术语集，再把范围内每条现有术语与最终集合比较，形成一项处置：`修改`、`删除`、`保留`或`未决`。需要未收录的新边界时另行`新增`，新增不占现有术语的处置计数。现有条目只是待比较事实，不享有保留优先级。

修改数、删除数、保留数和未决数之和必须等于范围内现有术语总数。

默认动作：

| 事实 | 默认动作 |
| --- | --- |
| 空译文 | 补译或删除，不得长期保留空转义 |
| 零出现 | 自主审校时删除；用户明确指定时保留并说明当前不生效 |
| 明显泛用词，无需统一 | 删除 |
| 关系组条目 | 重建最小充分术语集；未进入最终集合的旧条目删除 |
| 同根公共部分译法不一致，且语境支持统一 | 修改统一 |
| 审校证据中反复出现的未收录专名 | 新增 |
| 同名异义，单条术语无法安全表达 | 未决，点名冲突证据 |

处置优先级、跨层观察和相似问题归组遵循 system 的通用审查协议。本领域另外要求：

- 不得因“可能误伤”而把已有明确更好方案的条目打成未决。
- 不得因关系组复杂而逃避删除冗余。

未决只用于：

1. 同名异义且无法用单条术语安全表达。
2. 现有证据不足以在两个具体候选集合或字段值之间抉择。
3. 范围外冲突影响范围内结论，但又不能越权修改范围外条目。

### 收录与字段

- 先查原文语境，再判断语义身份、必要边界和译名。
- 保留会影响翻译一致性、属性判断或世界观理解的专有名称和设定术语。
- 删除脱离作品设定也能直接理解、且无需统一译法的泛用词。
- 术语原文只承担最小字面量命中，语义身份由语义提示承载；不得仅为写出类别而保留爵位、称谓、职业、所属关系或泛用后缀。
- 不用正则代替精确边界。
- 同一专名及其同根条目保持公共部分译法一致。有意区分必须由语境证明。
- 术语译文为空的条目不会参与翻译，应补译或删除。
- 语义提示应简短、稳定并可复用。
- 优先使用 `男性角色`、`女性角色`、`地名`、`家族`、`组织`、`特殊物品`、`特殊技能`、`特殊生物`。
- 推荐值不足时使用准确的短说明。
- 不因语义提示未命中推荐值而机械修改。
- 语义提示仅在错误、误导或缺少影响翻译的必要信息时修改。

自主审校新增只限于证据中反复出现的未收录专名，形成新增前必须确认实际出现，并检查边界、译法、语义提示、大小写和关系组。用户明确指定的新增或修改不受当前命中约束；零出现时在方案中说明其不影响当前翻译，并继续检查译法、语义提示、大小写和关系组。

### 重建最小充分术语集

关系组来自工具返回的完整术语包含关系，以及审校时识别的共享连续字符串、派生与身份关系，包括全名、简称、称谓、派生实体和说明性后缀。关系只确定共同审校的事实范围，不为任何现有条目提供保留理由。

审校关系组时，先假设现有条目不存在，从原文事实重新构造只承载普通翻译无法稳定推出的专有信息的术语集合，再与旧条目生成差异。最终集合可以为空，也可以使用尚未收录的公共连续字符串；该字符串可以位于目标形式的开头、中间或结尾，不要求在语料中独立出现，但必须作为连续字符串实际出现。

候选集合必须同时满足：

- 边界具有稳定语义，不会丢失必须统一的译法、身份或消歧信息。
- 没有已核验证据表明边界会误匹配普通词或其它实体。
- 边界与剩余普通文本组合后，能够稳定得到各目标形式的正确译法。
- 集合能够命中所有需要术语承载专有信息的目标形式。

在满足以上约束的候选中，依次选择条目数量最少、原文边界总长度最短的集合。完整形式、派生形式和额外消歧条目都是例外；保留时必须指出更小集合无法成立的具体反例，例如实际误匹配、不可组合的固定译法或必要消歧信息。抽象的“可能出错”、对旧条目的惯性保留和关系组复杂都不构成反例，也不得据此保留冗余或列为未决。

按以下顺序处理关系组：

1. 核对实际命中、大小写、收录价值和译法，不能用命中数量代替语境判断。
2. 提取必须由术语承载的专有信息；没有此类信息时，最终集合为空。
3. 从现有条目及其公共连续字符串构造满足约束的候选集合。
4. 用具体反例排除不安全集合；没有具体反例时，不以抽象风险阻断归并。
5. 按条目数量和边界总长度选择唯一最小集合，再将现有条目映射为新增、修改、删除或保留。
6. 只有同名异义或证据不足导致无法在两个具体最小集合间抉择时列为未决。

派生形式语义更具体或指向不同类别，本身不构成保留理由。例如：

- `ドトール家`、`ドトール伯爵家` 的后缀可正常翻译且没有其它歧义时，只保留 `ドトール`，以语义提示表达家族身份。
- `飛行`、`飛行魔法`、`飛行魔術` 均为无需统一的泛用表达时删除整组；作品设定确实要求统一 `飛行` 时只保留 `飛行`，除非某个完整形式另有不可组合的固定译法。

## 工作流

### 1. 建立事实快照

首次审校当前目标时建立一份完整术语事实快照。方案讨论和调整不使快照失效；相关修订号未变化且当前范围已被快照覆盖时，复用已有快照和证据。相关修订号变化时重建快照；仅范围扩大或现有证据不足时，只补读必要事实。

快照包括：

- 目标范围内的有序术语条目、每条的覆盖 item 数和最多两个确定性代表语境。
- 范围内每条术语的完整包含父项，以及审校时识别的其它关系。
- 与术语和原文证据关联的修订号。

零出现、空译文和包含关系只用于排序审校队列，不能代替对范围内每条术语的判断。快照中的代表语境只用于预览、排队和关系线索，不能单独作为判决证据。

### 2. 分组并补充证据

先按关系组成组，其余条目单独成组。审校单元是关系组；无关系时单条成组。

组内存在实际出现的术语时，形成结论前必须补充原文证据：

- 同组共享一次补证，不要求组内每条各查。
- 按术语原文做字面量子字符串检索，大小写规则与该术语一致，不使用正则。
- 优先核验拟变更项、关系组代表项和高频短词根。
- 每个关系组累计最多额外核验 50 个互不重复的工程文本条目。同一条目被多个术语命中时只计一次；事实快照自带的代表语境不占此额度。
- 达到上限仍无法在具体动作间抉择时列为未决，不继续分页，也不扩大原审校范围。
- 有命中但没有有效语境时，不重复发起等价检索期待同一证据出现。
- 补证期间相关修订号变化时，丢弃旧证据并重建快照。

仅当整组零出现，或范围内无可审条目时，可以豁免补证。零出现删除可以没有原文证据条目。

禁止仅凭快照自带的代表语境形成变更。保留结论涉及高频短词根或关系冲突时，同样先补证。

补证后依次确认：

1. **覆盖事实**：命中数量、字段、代表原文和大小写行为。
2. **语义身份**：人物、家族、地点、组织、物品、技能、生物或设定概念。
3. **收录价值**：是否必须统一才能避免翻译错误或维护误判。
4. **重建最小充分术语集**：从必须由术语承载的专有信息出发构造候选，按条目数量和边界总长度选择最小集合，再与旧条目生成差异。
5. **译法与语义提示**：是否准确、稳定并与同根条目一致。
6. **动作**：新增、修改、删除、保留或未决。

有实际出现的关系组，最终集合及排除更小集合的具体反例必须由已核验语境支持；整组零出现删除可以没有原文证据条目。

### 3. 形成写入方案

形成新增、修改和删除差异，同时统计保留与未决。

- 新增和修改必须给出完整术语原文、译文、语义提示和大小写设置。
- 未变条目不得重写。
- 未决项不得进入变更集合。

使用 system 的“写入确认”交互态，并补充以下术语领域信息：

- 审校范围及是否完整覆盖。
- 新增、修改、删除、保留、未决数量，以及变更前后总数。
- 按零出现、泛用词、冗余形式、同根整理、译法、语义提示、边界等业务原因分组的变更。
- 每组的共同处理、翻译影响和最少代表证据。
- 用户点名条目、独立取舍和全部未决项的逐项说明。
- 有真实附带观察时，说明术语修复后仍可能需要处理的其它层问题。

没有可执行变更时，使用 system 的“审查结果”交互态，不请求写入批准。仍须交代范围是否完整、处置数量、重要歧义与代表证据；有未决或真实附带观察时才写。

### 4. 写入并核对

获得明确批准后，只提交获批差异，并使用方案所依据的同一份质量规则事实快照。完整获批差异必须一次提交，不拆分写入。

核对以下结果：

- 写入是否被接受。
- 实际新增、修改和删除是否与获批集合一致。
- 相关修订号是否推进。

响应缺项或不一致时，使用 system 的“无法继续”交互态报告并停止，不补写。

执行完成后，使用 system 的“执行结果”交互态报告实际变更、验证、异常和未决。默认不重新审校全表结构。

只有存在真实下一步时才提一句，例如再次检查包含、同根关系和覆盖事实，或按附带观察继续处理其它层。用户明确要求写后复核时才继续执行。

## 执行入口

- 使用 `query_quality_rules` 读取或分析术语规则，规则类型固定为 `glossary`；用户以 `@term(src)` 或其它明确原文限定范围时，通过 `filters.srcs` 精确读取。
- 使用 `query_items` 补充原文证据。
- 使用 `update_quality_rules` 并固定 `rule_type: glossary`，通过 `write`、`delete` 和 `move` 原子写入获批差异。
