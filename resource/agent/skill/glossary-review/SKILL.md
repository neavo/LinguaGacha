# 术语表审校

对现有术语形成准确、充分且最小的最终集合：加载规则与快照 → 按结构组审校与有界补漏 → 方案确认 → 原子写入 → 结果核对。

## 必读领域规则

进行任何术语判断前，检查当前模型上下文是否已经包含 `glossary-rules` 的完整正文。若尚未包含，从 `<available_skills>` 中按名称精确找到它的 `location`，调用 `read_skill` 读取其 `SKILL.md`；同一独立任务只读取一次。

若 `glossary-rules` 不存在、不可读取或正文无效，进入“无法继续”，不得从本技能、旧对话或经验重建术语定义。

## 范围、所有权与完整性

- 本技能只写术语规则。
- 默认评价整张现有术语表；用户限定范围时，只为各组 `targets` 中的目标条目形成处置和变更。
- 用户明确要求不修改的术语从目标集合排除，保持原样且不计入当前范围处置；同组排除项仍作为关系证据，其冲突按范围外冲突处理。
- 质量查询返回的同组范围外条目只作为关系证据；其冲突影响目标结论但又不能越权修改时，将受影响目标列为未决。
- 当前范围内每条现有术语必须且只能进入 `修改`、`删除`、`保留`或`未决`；四类数量之和等于现有目标总数。
- 审校证据中发现的补漏候选独立进入 `新增`、`排除`或`未决`；三类数量之和等于补漏候选总数，不混入现有术语处置计数。
- 范围经用户收窄时只报告实际覆盖范围，不把部分现有条目或局部补漏写成全表、全工程完成。

## 有界补漏

审校最终集合必须检查充分性，但补漏只限于本次已经读取的关系和语境证据：

- **关系补漏**：同组或替代单元证据中的别名、简称、同一实体其它形式、必要独立分支或安全公共词根。
- **语境补漏**：代表例句和必要邻近文本中反复出现、身份明确且尚未安全覆盖的专名。
- **姓名补漏**：已读取 item 的非空 `name_src` 尚未被安全覆盖，并且身份与具体译法已有充分证据。

有具体新增值时形成候选；已证明被现有最终集合覆盖或无需术语承载时排除；缺少边界、身份或译法的决定性证据时未决。不得为补漏重新扫描全部 item、建立全工程候选账本或宣称验证了完整语料覆盖；需要脱离现有术语关系主动调查新术语时使用 `glossary-create`。

## 零出现与默认处置

| 事实 | 默认处置 |
| --- | --- |
| 零出现 | 未决；不补查、不写入，不以当前未命中推导删除 |
| 空译文且有出现 | 补译或删除，不长期保留空转义 |
| 明显泛用词，无需统一 | 删除 |
| 多个形式可由同一安全词根承载 | 写入词根并删除被替代分支 |
| 分支有具体不可合并证据 | 保留必要分支并统一公共译法 |
| 译义可接受但明确违背已证实作品风格 | 修改为符合全局风格的具体译名 |
| 当前证据中的未收录必要专名 | 新增 |
| 同名异义，单条术语无法安全表达 | 未决并点名冲突证据 |

- 整组零出现时，范围内成员全部未决。
- 混合组中，零出现成员自身未决；有出现成员若结论不依赖未知成员，仍可正常审校。
- 零出现成员会改变最小充分集合时，受影响目标同样未决。
- 用户明确指定新增、修改或删除及最终值时，按用户指令检查字段与关系，不以零出现阻断。

## 结构组

质量查询以 `entry_fields` 声明规则行列顺序，每个 group 直接包含 `targets` 目标行和 `evidence` 范围外证据行。后端先合并原文字面量完整覆盖或匹配等价的强关系，再以单一公共连续词根补足相关形式；每个 group 是有界、互斥且包含单例的共同审校范围。

- 结构组只确定共同检查和补证范围，不表示成员语义相同，也不为旧条目提供保留理由。
- 关键词搜索展开直接命中目标所在的完整结构组；只有 `targets` 行的 `id` 属于处置范围。
- 模型不得重新计算、拆分或另建结构组；语境中发现的简称、同名异义或身份关联只用于判断和有界补漏。
- 先在完整目标范围内程序化完成由字段事实或确定规则唯一决定的筛选、计数和变换；`evidence` 行不计入现有目标数量。
- 后端结构组是不可拆领域单元，按规则稳定顺序装入 system 规定的审查组；审查组只控制模型上下文，不等于提交单元。
- 多个审查组需要累计处理时，维护统一的目标处置、补漏候选和计数账本，每组完成后更新；不得依赖自然语言回忆重建全局状态。

## 工作流

### 1. 建立事实快照

1. 调用 `workspace_load`。
2. 根据返回摘要和工作区 contract 确认权威语言、完整数量和数据集语义。
3. 取得 glossary 正文、命中、代表例句和完整后端关系组；用户未限定原文时覆盖整张术语表，明确限定或排除时以各组剩余 targets 建立处置范围。
4. 先完成程序化处理，再为剩余语义目标组成审查组并在 system 要求时确认范围。
5. 从完整任务范围建立一次全局风格标准，所有审查组复用，不按局部多数重新定义。

### 2. 按组审校与补漏

不能按 entry 顺序逐条检索。快照 examples 可以支持身份、译法、风格、边界、零出现和没有具体冲突的保留结论；同名异义、高频短词根、风格冲突或具体反例才补充判决证据。

没有候选新边界时，以纯字面量 OR 匹配该组全部需要核验的现有原文，读取足以判决且按 item 去重的证据；有命中但没有有效语境时，不重复等价查询期待同一证据改变。审阅实际读取的关系、例句、目标姓名和邻近文本，按“有界补漏”形成独立候选。

### 3. 验证公共词根

准备以一个候选词根替代多个现有分支时，把词根及拟替代分支视为一个替代单元，在同一工作区和相同原文范围执行两次组级查询：

1. 只用全部拟替代分支做 OR 查询，返回至多一个代表语境，以完整匹配总数记为基线数 B。
2. 用候选词根和全部拟替代分支做 OR 查询，返回至多五十个语境，以完整匹配总数记为候选数 R。

两次查询的 `total_item_count` 表示完整匹配集合数量，返回的 `items` 行只表示当前证据窗口，不得混用两者的完整性。

| 完整计数与语境 | 处置 |
| --- | --- |
| R = B，且没有不可组合、风格或消歧证据 | 写入词根并删除全部被替代分支 |
| R > B，全部候选匹配已返回且新增匹配均安全 | 写入词根并删除全部被替代分支 |
| R > B，发现具体误匹配 | 放弃词根，保留必要边界 |
| R > B，仍有未返回的新增匹配 | 未决并点名缺少的新增匹配语境 |
| R < B | 候选不满足覆盖要求，放弃词根 |

查询结果按 item 去重，以 `matched_keywords` 区分词根和完整分支命中。已核验词根所替代的冗余分支不再分别补证。

### 4. 形成写入方案

- 最终词根已存在时保留或更新；不存在时，用一个范围内拟替代分支的 `id` 修改为词根并删除其余分支，不新建词根后再删除全部旧条目。
- 新增和修改给出完整原文、译文、语义提示和大小写策略；未变条目不得重写，未决不得进入 change。
- 对最终集合中仍被词根覆盖的每个完整分支给出具体不可合并证据，否则删除。
- 按零出现、泛用词、冗余形式、同根整理、译法、风格、语义提示、边界和补漏等业务原因归组说明。
- 报告审校范围、现有条目处置计数、补漏候选计数、变更前后总数、词根关系、预期覆盖变化、全局风格依据和最少代表证据；用户点名条目、独立取舍和全部未决逐项说明。

有可执行变更但尚未授权时使用 system 的“写入确认”；已有授权时直接执行；没有变更时使用“审查结果”。

### 5. 写入并核对

获得明确授权后，用 `workspace_script` 分别写入 `workspace.contract.changes.glossary` 下的 creates、updates、deletes 和 moves；不得修改其它 quality kind。质量规则提交不设数量上限，默认用一次 `workspace_apply` 原子提交完整方案。

核对 apply 回执中的新增、修改、删除、排序计数和新 revision。事务回滚可安全重试；stale 或 revision 冲突后重新 load 并重做受影响方案；`data.committed_sync_failed` 按已经写入处理并要求重新加载工程，绝对不得重试 apply。响应与授权方案不一致时停止，不自行补写。
