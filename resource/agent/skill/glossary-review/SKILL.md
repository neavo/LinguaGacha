# 术语表审校

在当前工程内完成术语表审查与修复：建立快照 → 按结构组审校与补证 → 方案确认 → 原子写入 → 结果核对。

## 目标与边界

- 本技能只写术语规则。
- 默认评价整张术语表；用户限定范围时，只为 `target_entry_ids` 对应条目形成处置和变更。
- `query_quality_rules(glossary)` 返回的同组范围外条目只作为关系证据；其冲突影响目标结论但又不能越权修改时，将受影响目标列为未决。
- 完整审校必须让范围内每条现有术语得到一项处置：`修改`、`删除`、`保留`或`未决`。相同事实和处理方式可以归组说明，不要求逐项展开。
- 修改数、删除数、保留数和未决数之和必须等于范围内现有术语总数；新增不占现有术语处置计数。

## 术语事实

- 术语按自身大小写设置，对原文正文和原文姓名做字面量子字符串覆盖，不识别词边界；包含或重叠条目可以同时覆盖。
- 翻译只激活已覆盖且译文非空的条目，并使用术语原文、译文和语义提示。
- 零出现术语不参与当前翻译，但仍可能是有效工程规则；当前语料无法证明其应删除。
- 术语原文只参与字面量命中，语义身份由简短、稳定的 `info` 承载，不用正则代替精确边界。
- 同一专名及其同根条目保持公共部分译法一致；有意区分必须由原文语境证明。
- 保留会影响翻译一致性、属性判断或世界观理解的专名和设定术语；删除脱离作品设定也能直接理解且无需统一译法的泛用词。
- `info` 为简短辅助信息，比如 `男性`、`女性`、`地名`、`家族`、`组织`、`特殊物品`、`特殊技能`、`特殊生物` 等，仅在错误、误导或缺少必要信息时修改。
- 自主新增只限于证据中反复出现的未收录专名，并检查边界、译法、语义提示、大小写和结构组。

## 结构审校组

glossary 查询返回平铺 `entries` 和 `groups`。后端先合并原文字面量完整覆盖或匹配等价的强关系，再用单一公共连续词根补足没有独立短词根条目的相关形式；每个 group 是有界、互斥的共同审校范围，成员使用 `entry_id` 引用，并包含单例。

- 结构组只确定共同检查和补证范围，不表示组内术语语义相同，也不为任何旧条目提供保留理由。
- 相同原文、按条目自身匹配规则等价的大小写或 NFKC 形式、短词根与完整形式会形成不可拆分的强组；没有独立短词根时，共享足够连续原文且占各自形式足够比例的强组也可能进入同一审校组。后端限制潜在合并规模且不沿相似关系传递扩张；模型不得重新计算、拆分或另建一套结构组。
- 关键词搜索返回的 entries 会展开直接命中目标所在的完整结构组，`target_entry_ids` 才是处置范围；其它成员仅作证据。
- 模型在语境中发现的简称、同名异义或身份关联用于判断和说明，不改变后端结构组身份。

## 处置规则

| 事实 | 默认处置 |
| --- | --- |
| 零出现 | 未决；不补查、不写入，不以当前未命中推导删除 |
| 空译文且有出现 | 补译或删除，不得长期保留空转义 |
| 明显泛用词，无需统一 | 删除 |
| 多个形式可由同一安全词根承载 | 写入词根并删除被替代分支 |
| 分支有具体不可合并证据 | 保留必要分支并统一公共译法 |
| 证据中反复出现的未收录专名 | 新增 |
| 同名异义，单条术语无法安全表达 | 未决，点名冲突证据 |

零出现规则的边界：

- 整组零出现时，范围内成员全部未决。
- 混合组中，零出现成员自身未决；有出现成员若结论不依赖未知成员，仍可正常审校。
- 零出现成员会改变最小集合选择时，受影响目标同样未决。
- 用户明确指定新增、修改或删除及最终值时，按用户指令检查字段与关系后继续，不以零出现阻断。

未决只用于：零出现、同名异义无法安全表达、候选词根产生尚未核验的新增匹配、证据不足以在两个具体候选间抉择，或范围外冲突影响目标但不能越权修改。已有明确更好方案时不得用抽象风险逃避变更。

## 重建最小充分术语集

审校结构组时，先忽略旧术语表，从已核验原文重新构造只承载普通翻译无法稳定推出的专有译法、身份或消歧信息的集合；没有此类信息时，最终集合为空。

候选不局限于现有条目。从组内语义相关的目标形式中提取可复用的公共连续字符串作为词根候选；候选可以位于开头、中间或结尾，不要求在语料中独立出现，但必须在目标形式中真实连续出现。仅共享字符串而不共享专有信息的形式不得共用词根。

只按当前工程快照和本组补证判断候选，不要求证明未来文本绝对安全。候选集合同时满足以下条件即为可行：

- 覆盖所有已核验、确实需要术语承载专有信息的目标形式。
- 不丢失必须统一的译法、身份或消歧信息。
- 完整匹配计数和当前语境没有表明会新增普通词或其它实体匹配。
- 当前证据表明边界与剩余普通文本可以组合出目标形式的正确译法。

在全部可行集合中，必须依次选择条目数量最少、原文边界总长度最短的集合。安全词根能够表达相同专有信息时，写入词根并删除被替代的完整、派生或说明性分支；不得退回“保留全部分支，只统一译法”。删除数量和规则覆盖发生变化是词根替代的预期结果，不构成风险证据。

只有下列具体证据可以支持保留完整形式或额外消歧条目：

- 实际语境表明词根会命中普通词或其它实体。
- 实际语境表明剩余文本无法与词根译法正确组合，或完整形式有不可组合的固定译法。
- 分支承载词根无法表达的必要身份或消歧信息。
- 范围外冲突影响该分支，但当前无权一并修改。

改动或删除数量较多、会影响翻译、旧条目长期存在和结构组复杂都不是保留证据。若最终集合同时保留词根及其可覆盖分支，必须为每个分支指出上述具体证据；无法指出时，该方案不成立。最后将旧条目与最终集合比较，映射为新增、修改、删除或保留。

例如，`ドトール家` 与 `ドトール伯爵家` 的后缀可正常组合且 `ドトール` 没有身份冲突时，只保留词根 `ドトール`；存在不可组合的固定译法或同名异义时保留必要的完整形式。

## 工作流

### 1. 建立事实快照

首次审校时调用一次 `query_quality_rules`，固定查询术语表。用户未明确限定原文时读取整张术语表；只有用户明确限定原文时才以关键词包含搜索建立目标范围。快照包括：

- 平铺 entries、结构 groups，以及限定查询时的 `target_entry_ids`。
- 每条术语的覆盖 item 数和最多两个确定性代表语境。
- 质量规则 revision 与关联的 item revision。

相关 revision 未变化且当前范围已覆盖时复用快照；范围扩大时只补读新范围，revision 变化时丢弃旧证据并重建。

### 2. 用快照审校

先按 groups 处理，不能按 entry 顺序逐条检索。快照样本可以支持：

- 理解组内身份、译法和边界关系。
- 零出现未决。
- 语境充分、没有关系冲突且不准备变更的保留结论。

同名异义、高频短词根或样本中的具体反例需要补充判决证据。候选新边界按下一节验证完整匹配集合；已核验词根所替代的每个冗余分支不再分别补证。

### 3. 按判决目标补证

没有候选新边界时，使用一次 `query_items` 在原文中以纯字面量 OR 匹配该组全部需要核验的现有原文；不得为组内术语发起等价的独立查询。最多读取 50 个互不重复 item，有 cursor 时停止；有命中但没有有效语境时，不重复等价查询期待同一证据改变。

准备以一个候选词根替代多个现有分支时，把该词根及其拟替代分支视为一个替代单元，执行两次组级查询：

1. 只用全部拟替代分支做 OR 查询，`limit: 1`，以完整 `total_item_count` 记为基线数 B。
2. 用候选词根和全部拟替代分支做 OR 查询，`limit: 50`，以完整 `total_item_count` 记为候选数 R，并读取返回语境。

两次查询必须使用相同原文范围，且 items revision 与 glossary 快照的 item revision 一致；不一致时重建快照。`total_item_count` 是完整匹配集合数量，分页 `items` 只是语境样本，不得混用两者的完整性。

候选词根应为每个拟替代分支的连续子字符串，因此基线集合包含于候选集合。按下表形成处置：

| 完整计数与语境 | 处置 |
| --- | --- |
| R = B，且语境没有不可组合或消歧证据 | 写入词根并删除全部被替代分支 |
| R > B，全部候选匹配已返回且新增匹配均安全 | 写入词根并删除全部被替代分支 |
| R > B，发现具体误匹配 | 放弃该词根，保留必要边界 |
| R > B，仍有未返回的新增匹配 | 未决，并点名缺少新增匹配语境 |
| R < B | 候选不满足覆盖要求，放弃该词根 |

工具按 item 去重并返回 `matched_keywords`；在全部候选匹配均已返回时，以只命中词根而未命中任何拟替代分支的 item 识别新增匹配。补证后确认语义身份、收录价值、最小充分集合、译法与语义提示，最后映射处置。

### 4. 形成写入方案

形成新增、修改和删除差异，同时统计保留与未决：

- 最终词根已存在时保留或更新该条目；词根不存在时，用一个范围内拟替代分支的 `entry_id` 修改为词根并删除其余分支，不得新建词根后再删除全部旧条目。
- 新增和修改给出完整原文、译文、语义提示和大小写设置。
- 未变条目不得重写；未决不得进入变更集合。
- 对最终集合保留的每个可被已选词根覆盖的分支，给出具体不可合并证据；没有证据则删除该分支。
- 按零出现、泛用词、冗余形式、同根整理、译法、语义提示和边界等业务原因归组说明。
- 说明审校范围、完整性、处置数量、变更前后总数、词根替代关系、预期覆盖变化和最少代表证据；不要把删除数量或预期覆盖变化描述为风险。
- 用户点名条目、独立取舍和全部未决逐项说明。

方案阶段只负责给出全局最优差异，实际写入仍由用户确认和原子提交保护；不得为了缩小本次变更范围而保留冗余条目或降低方案质量。

有可执行变更时使用 system 的“写入确认”交互态；没有变更时使用“审查结果”，不请求写入批准。

### 5. 写入并核对

获得明确批准后，使用 `update_quality_rules`，以快照的 quality revision 一次原子提交完整获批差异。

核对写入状态、实际新增/修改/删除身份和新 revision。响应缺项或不一致时使用“无法继续”交互态报告并停止，不补写。成功后使用“执行结果”报告实际变更、验证、异常和未决，不默认重新审校全表。

## 执行入口

- `query_quality_rules`：读取 glossary 快照和结构组。
- `query_items`：仅在需要判决证据时按组或替代单元查询原文。
- `update_quality_rules`：原子写入获批差异。
