# 质量规则共享工作流

入口技能先确定 `mode: create | review`、用户允许的 `kinds` 与目标范围，再读取本技能；范围包含 glossary 时读取 `@skill(glossary-rules)`，包含 text_preserve 时读取 `@skill(text-preserve-rules)`。领域技能只提供事实资格和表达判据；本技能是工作区加载、发现、分组、进度和提交的唯一流程权威。

同一任务只调用一次 `workspace_load`。glossary 与 text_preserve 共用每一轮 items 遍历、上下文片段和发现范围，但分别形成事实、决定和 change；加载两个领域技能不表示执行两遍流程。

## 工作对象

当前任务只维护两份 JSONL 快照：

```text
scratch/quality-rule-checks.jsonl
scratch/quality-rule-targets.jsonl
```

核验任务是能在确定范围内实际执行的发现或补证工作：

```text
{ key,
  origin: initial | triggered | independent,
  parent_keys,
  round,
  kinds,
  scope,
  method,
  status: pending | complete,
  scanned_items?,
  raw_matches?,
  rejected_matches?,
  rejection_reasons?,
  new_target_keys?,
  changed_target_keys? }
```

- `key` 在当前任务内唯一；`scope` 说明完整作用面，`method` 说明可以程序执行的筛选、匹配或上下文调查。只写“继续观察”“再检查类似内容”不构成核验任务。
- `initial` 是初始化方向，至少一个不依赖已有规则；`triggered` 必须由具体新事实、关系、新匹配或边界反例产生；`independent` 使用尚未执行的独立方向调查长尾。
- 同一轮所有待执行的核验任务跨 kind 合并到一次 `workspace_script` 遍历中执行；能从已有证据回答的任务不重复扫描 items。`status: complete` 只表示声明的 scope 已完整执行且没有截断。
- 核验任务按 `{ kinds, scope, method }` 去重；等价工作不能通过换 key 重新执行。结果过大时完整写入待核对象，只向模型返回计数、变化 key 和少量代表证据。

待核对象是需要独立决定的业务对象：

```text
{ key,
  kind: glossary | text_preserve,
  origin: candidate | existing,
  id?,
  check_keys,
  evidence,
  decision? }
```

- `key` 跨 kind 唯一且稳定；existing 携带规则 `id`。`check_keys` 保存全部实际发现或补证来源，不再维护重复的 signal 计数与 decision 引用子集。
- 每个有效唯一身份先登记为待核对象，再由领域技能判断；频率、长度、已有译文、现有规则覆盖、证据难度、结构组或预计动作都不是入账前过滤条件。重复身份合并证据和核验来源，不能消失。
- `decision` 分别保存 `necessity: required | not_required | unknown`、`resolution: direct | conditional | narrowed | preserved | blocked`、`action`，以及需要的完整 `value`、`preserve_reason`、`covered_by` 或 `blocker`。
- candidate action 为 `create | discard | blocked`；existing action 为 `keep | update | delete | blocked`。`preserved` 只用于当前工程缺少评价证据的 existing；blocked 只在直接、条件化和收窄或拆分都失败后使用，并说明缺失事实、已执行下钻、失败原因与处理建议。

上述 JSONL 是领域任务资产，不是另一套公开协议。这里定义的文件名、字段、枚举、轮次和分组名称只用于内部执行与恢复，不得出现在面向用户的阶段更新、授权请求或结果报告中。不要为它建立严格字段 validator；脚本按实际结果生成和更新记录，最终 change 仍以 workspace contract 与 `workspace_apply` 校验为准。

## 领域接口

领域技能只负责为具体对象提供业务判据，不理解 JSONL、代数、队列或收敛实现。应用领域判据后，本工作流必须取得：

- 对象是否应由当前领域处理，证据不足时缺少哪个决定维度；
- 能否直接形成最终规则，或是否需要按输入语境处理、缩小边界、拆分对象；
- 判断过程中实际暴露的新身份、结构形态、匹配或边界反例；
- glossary 对象之间由当前工程证据确认、且有助于理解主要实体或规则背景的业务关系；
- 围绕缺失维度可以完整执行的补充调查范围与方法；
- 最终规则对已确认对象的覆盖关系，无法覆盖时需要补充的事实和建议。

本工作流把每个有效唯一对象登记为待核对象，把每项可以完整执行的发现或补证工作登记为核验任务。领域技能提出的新对象或补查不能只用于接受或拒绝当前方案；必须反馈到对应对象或具体核验任务后再继续闭环。

## 任务进度

本工作流属于动态长任务，开始时调用一次 `task_progress` 的 `start` action，至少登记：

```text
discover:initial       基础发现或目标初始化
discover:independent   独立漏项检查
finalize:changes       生成方案、完成授权路径并核对结果
```

初始化结果形成结构组后，在完成 `discover:initial` 的同一次 `advance` 中追加稳定的 `review:<kind>:<group_id>` 工作项。完成审查组时，如果实际结果产生关联补查，在同一次 `advance` 中追加对应轮次的 `discover:rN`；新增待核对象重新聚类后再追加受影响的 review group。不要为每条程序化对象建立进度项，工作项只表示需要模型继续处理的批次或轮次。

`finalize:changes` 只能在无变化结论已经核对，或授权后的 apply 已取得真实回执时完成；等待用户授权期间保持 pending。恢复、压缩或进度不明时先调用 `task_progress` 的 `read`。只有本技能的收敛条件全部满足后才 `finish`；用户放弃或用冲突任务替换当前任务时才 `cancel`。进度工具只防止遗忘已知工作，不证明领域发现完整。

## 确定性结构聚类

对象入账后、模型逐项判断前，按 kind 调用 `workspace.groupQualityRuleEntries(...)`：

- review 既有规则时可以省略 `entries` 并用 `target_entry_ids` 限定目标；范围外成员只作共同审查证据。
- create 或出现 candidate 时，把相关 existing 与 candidate 对象程序化投影为同一 `{ entry_id, src, case_sensitive? }` 数组；两类条目必须使用同一算法。
- 方法返回稳定、互斥、最多 16 条的 group。超大强 component 保留共同 `component_ids` 并分组，通过 `cross_group_relations` 返回被切开的直接边。
- `equivalent`、`contains` 和 `shared_root` 只说明共同审查原因，不证明同义、必要或可合并。弱关系不传递；每个对象独立决定，单项失败或 blocked 不得沿 group、component 或跨组关系传播。

glossary 组内确认一个明确子集语义相关后，才调用 `workspace.deriveCommonLiteralRoots({ forms })` 枚举合并候选，再用 `workspace.matchLiterals` 验证真实覆盖。结构组的机械 shared root 不能直接成为最终规则。text_preserve 的正则源码不参与包含或公共字符关系，只把完全相同的源码作为 equivalent 共同审查。

## 动态发现闭环

1. **初始化**：根据入口模式执行初始发现。create 从分散样本选择领域基础方向后完整扫描；review 枚举全部目标 existing 对象，并在同一次初始化中取得正式命中和有限语境。两个 kind 的程序化核验任务合并遍历。
2. **逐组核验**：按稳定 group 顺序读取必要对象和有限语境，逐项形成 decision。范围包含 glossary 时，同时把语境已经确认的同一实体与别名、人物关系、实体所属、同一体系、派生形式、必须区分的异义实体和规则覆盖关系合并到相关对象的 evidence；关系不需要改变规则决定，只要有助于理解主要实体或规则背景就应保留。每组结束时只从具体新信息提出核验任务：同槽位或系列成员、别名、公共片段、相邻结构、译法分歧、条件分支、正则形态或边界反例。
3. **执行关联补查**：批量执行当前轮全部 pending 核验任务，更新待核对象和证据。新增对象或决策相关证据时重新聚类受影响 kind，只重开实际变化的对象，并继续下一轮。
4. **反馈工具结果**：聚类的范围外关系、词根验证中 `R - B` 的新增匹配、条件化调查发现的义项、text_preserve 收窄发现的结构变体，都必须进入待核对象或具体关联补查，不能只用于接受或拒绝当前方案。
5. **独立漏项检查**：至少执行一次不同于初始发现与既有关联补查的独立方向调查。它按文件、章节、结构层或缺少明显形式信号的单次概念调查未覆盖长尾；有增量时重新进入分组与关联补查。
6. **零增量闭合**：第 0 轮不能直接完成。任一轮产生新对象或决策相关证据，下一轮必须执行；只有之后一个完整轮次产生零新增对象、零变化对象、零新核验任务，才允许收敛。

关联补查不是要求凭空制造新方向。若一个具体模式无法形成可执行核验任务，把它作为当前对象的 evidence；重复证据不建立新轮次。反过来，只要存在尚未执行的具体核验任务，就不能用“已完成一轮”结束。

### 闭环判例

|当前结果|必须追加的工作|不能直接得出的结论|
|---|---|---|
|词根覆盖比分支集合多出 8 个 item|建立核验任务，分类这 8 项是遗漏成员还是边界反例|“词根不安全，所以结束该系列”|
|一个角色名对象暴露同一姓名槽位中的其它字面量|完整扫描该槽位并把有效唯一身份登记为待核对象|“当前角色已处理，所以名称发现完成”|
|宽占位符同时命中结构与正文|按定界符或位置差异建立收窄核验任务|“宽规则失败，所以该结构无需保护”|
|一轮关联补查没有产生新对象、变化对象或新核验任务|若独立漏项检查已完成且对象均已决定，可以收敛|为凑轮次重复同一扫描|

## 从不确定到可执行

对不能直接决定的对象依次执行：

1. 围绕缺失维度批量取得完整匹配与有限代表语境；
2. 合理未知取值不改变最终字段时采用稳健直接值；
3. glossary 的适用条件能由翻译输入判断时，以 `info` 形成 conditional；
4. 缩小连续字面边界或正则，或拆出行为确定的独立事实；
5. 只有上述路径全部失败才 blocked，并保留其它已经闭合事实。

集合优化失败只回退已经验证的精确规则，不改变底层 required 对象。范围外冲突只阻止需要越权修改的具体方案，不传播到能够独立处理的对象。

## 收敛与写入

只有同时满足以下条件才能形成最终方案：

- 初始发现、所有关联补查与独立漏项检查均完整执行且没有截断；
- 所有 group 分页和 task_progress 工作项已经处理，跨组关系没有遗失待核验对象；
- 所有对象都有闭合 decision，且最近完整发现轮次为零增量；
- 每个 required 对象由直接、条件化或收窄后的最终规则覆盖，或在穷尽降级路径后单独 blocked；
- 范围包含 glossary 时，已经从全部闭合对象汇总已确认关系，并确定关系图或无可靠关系结论；
- glossary 最小充分集合与 text_preserve 独立安全集合已经分别重构。

最终化脚本先程序化检查 pending 核验任务、未闭合对象、required 对象的覆盖缺口、独立漏项检查完成状态、最近完整发现轮次的增量和拟写 action 数。任一项不满足时只返回缺口计数与变化 key，不写 change；只有全部通过后，才从对象生成当前 scope 的完整 changes。未选 kind、范围外规则和替换规则 change 文件保持为空，不自动生成 move。没有真实 change 时不 apply；已有授权时默认一次 `workspace_apply` 原子提交完整方案并核对回执，然后完成 `task_progress`。

### 实体关系总览

范围包含 glossary 时，从既有核验结果汇总有助于解释主要实体、消歧或规则背景的已确认关系；
关系暴露新对象或缺失维度时仍进入发现闭环，但不得为了生成图表扩大为世界观抽取；
最终报告根据已确认关系选择最易读的图、表或短结论，原则上至少包含一张 Mermaid 关系图，关系较多时只展示能够解释主要对象和规则判断的主干，并按关系密度自适应展示：

1. 规模较小且关系稀疏时输出一张完整图；
2. 存在多个清晰语义簇时输出簇级总览图，并为需要解释主要实体、规则合并、拆分或消歧的簇输出详情图；
3. 规模很大或关系过密时输出主要实体的主干局部图，并以关系表保留图外的已确认关系；
4. 为保证可读性，每张图的节点数量控制在8-12个，超出后降级展示；
5. 没有已确认的主要实体关系时明确说明当前已核验范围内未确认足以建立关系图的主要实体关系；

对外只使用当前用户语言下的业务表达，报告实际范围与完整性、候选或目标总量、创建 / 保留 / 修改 / 删除 / 无需处理 / 需要补充信息的数量、基础发现、关联补查及独立漏项检查是否完成、变更前后数量、最少代表证据、处理建议和范围外观察。不得展示内部文件名、字段名、枚举、轮次、组标识或状态计数；结构组数与 shared root 数也不得冒充语义合并数。完成只证明声明的发现方向、待判断对象与独立漏项检查已经收敛，不宣称穷尽所有理论规则。
