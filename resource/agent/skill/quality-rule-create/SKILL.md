# 质量规则创建

先读取并遵循 `@skill(quality-rules)` 与 `@skill(quality-rule-workflow)`；本技能只补充候选发现、信号扩展与发现收敛流程。少量分散种子只选择信号，程序完整扫描，模型分片核验候选并从证据提出下一信号。模型内部知识不能代替工程证据。

## 范围

- 泛称“质量规则”或“翻译前规则准备”：处理 glossary + text_preserve。
- 明确“术语/术语表”：只处理 glossary。
- 明确“文本保护/控制符/占位符”：只处理 text_preserve。
- 用户排除的 kind 不进入目标、观察、决策或变更。
- 替换规则与 item 修改只作范围外观察。

## 发现循环

发现任务按种子、循环体和残差信号三段推进，直到 `quality-rule-workflow` 的结论闭合成立：

**种子侦察**（一次）：从不同文件、章节或结构层读取少量分散样本，结合现有规则、warning、`text_type`、name 字段、题材和语言选择初始信号并入账；样本不得定义范围，初始信号至少一个不依赖现有 glossary。

**循环体**（重复执行）：

1. 选择尚未执行的互补信号，由程序扫描其完整作用面；等价信号不重复。执行结果记录扫描 item/文件数、原始命中数、去重候选数、确定丢弃数量及原因、是否截断。
2. 按原文身份去重后把新候选追加为 candidate target 并生成完整 observation；不得直接从模型记忆写 change。
3. 按 `quality-rule-workflow` 分片核验，每个候选映射为 create、discard 或 unresolved；每个片段完成后立即执行模式捕捉——从别名、同位说明、并列成员、同系列形式、公共词根、相邻实体和文件结构提出非等价新信号，发现即入账，下一轮循环体从该信号开始。

**残差信号**（收敛后一次）：循环体不再产生新信号或新候选时，从不同于初始信号的方向检查未覆盖文件长尾和单次概念；产生疑点时选择相应信号完整扫描，重新进入循环体。

只有 `quality-rule-workflow` 的共享完整性条件成立时才能报告完成。完成只证明该过程收敛，不宣称穷尽工程中的所有可能规则。

## glossary 发现与核验

初始信号至少覆盖：

- 完整 `name_src`、明确名称边界和特殊书写。
- 命名、定义、首次登场、别名、获得、装备、发动、所属和身份变化语境。
- 并列、枚举、等级、对立体系和其它同构结构。
- `dst` / `name_dst` 译法分歧、原文残留和身份线索。
- 既有规则未覆盖的文件长尾和单次概念。

全部 glossary 候选使用 `workspace.matchLiterals` 取得正式完整计数和有限代表证据。候选或公共词根涉及既有规则时，只把当前任务确实拥有且明确受影响的规则追加为 existing target；其它规则保持只读证据，冲突按 `quality-rule-workflow` 处理。不要建立预计算关系组。

## text_preserve 发现与核验

候选来自控制符、占位符、格式脚手架、相关 warning 或已有译文的结构损坏证据。每个新增候选：

1. 只扫描 `item.src` 并按 `\n` 拆行。
2. 以 `new RegExp(source, "giu")` 编译，拒绝非法或零长度表达式。
3. 完整聚合 item、行、片段、`text_type` 和文件分布。
4. 保留有限代表片段、位置和必要上下文。
5. 独立决定 create、discard 或 unresolved。

不同候选的重叠命中分别计数；只处理身份完全重复或保护边界直接冲突的既有规则。

## 方案与写入

按 `quality-rule-workflow` 的共享授权和提交协议形成方案或写入。对外报告实际范围、每个信号的覆盖回执、每个 kind 的事实与处置计数、变更前后数量、最少代表证据、全部未决和范围外观察。
