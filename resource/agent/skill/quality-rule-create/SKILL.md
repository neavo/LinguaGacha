# 质量规则创建入口

读取 `@skill(quality-rule-workflow)` 并按创建模式执行其唯一工作流；由共享工作流按实际范围加载领域判据。范围同时包含两个领域时仍只加载一次工作区，并在同一次程序化遍历中取得两类证据。

## 范围

- 泛称“质量规则”或“翻译前规则准备”：处理 glossary + text_preserve。
- 明确“术语、术语表、提取术语表”：只处理 glossary。
- 明确“文本保护、控制符、占位符”：只处理 text_preserve。
- 用户排除的规则类型不进入候选、判断、统计或变更。
- pre_replacement、post_replacement 与 item 修改只作范围外观察。

创建任务只处理当前任务发现的候选；现有规则用于判断覆盖、冲突、结构关系和工程风格，不自动变成修改目标。每个有效唯一候选必须先交由共享工作流登记，再按领域判据处理，不能因频率、长度、已有译文、现有规则覆盖、证据难度或预计动作提前消失。候选已经被现有规则安全覆盖时记录为无需创建；需要清理、改写或删除现有规则才能得到理想集合时，保留当前可以独立创建的精确规则，并把现有规则问题列为范围外审查建议，不借创建任务扩大权限。

## 发现与反馈

从不同文件、章节或结构层读取少量分散样本，只用于选择初始发现方向，不能定义扫描范围。初始发现必须覆盖所选领域技能声明的基础方向，并至少包含一个不依赖现有规则的方向。可以程序定位的候选必须完整扫描声明范围；一次结果放不下时由共享工作流流式保存，不能用 Top-N、频率、长度、证据难度或预计动作提前裁掉候选。

同一证据可以启发两个领域：姓名槽位旁的重复标记既可能产生专名候选，也可能提出占位符调查；译文残留既可能指向术语，也可能暴露必须原样保留的结构。共享证据不表示共享结论，候选仍按各自领域判据分别判断。

每个候选最终形成以下一种业务结果：

- 形成可以直接使用、按输入语境使用、缩小边界或拆分后的完整规则；
- 已有规则完整覆盖或不符合领域收录条件，因此无需创建；
- 补充调查和全部表达降级仍不能形成安全规则，需要说明缺少的信息、已核验内容和处理建议。

按照共享工作流继续处理由具体证据产生的关联调查，并执行独立漏项检查。基础扫描无论发现多少候选都不能直接结束；结构关系、词根新增匹配、适用条件和正则范围调整发现的新身份、新匹配或新形态都必须反馈为新的待判断对象或范围与方法明确的补充调查。

最终只从已经确认需要处理的候选生成所选规则类型的新增；没有真实新增时不 apply。对外使用用户语言报告实际范围与完整性、候选总量、创建、已有覆盖、无需创建和需要补充信息的数量，以及基础发现、关联补查、独立漏项检查和语义合并结果；不能用最终条目数代替候选召回范围，也不得展示共享工作流的内部状态。
