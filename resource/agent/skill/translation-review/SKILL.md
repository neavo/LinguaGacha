# 译文审查

把固定审查范围作为证据池，而不是把警告误当成完整范围：主动发现候选 → 逐批审查并提交 → 冻结一次残差候选 → 核对累计结果。警告处理完毕本身不是结束条件。

新增、补译、重译和审校拟写值采用 `@skill(translation-rules)`；本技能负责已有译文的审查范围、发现、批处理、授权、写入和报告流程。

## 范围

- 只写 `items` 允许修改的正文译文、姓名译文或人工状态。
- 用户没有限定时，默认调查当前工程内全部已有译文；用户可以按 item、状态、文件、警告或文本条件收窄。用户明确要求只审查警告项时不得越界。
- 用户明确选择尚无译文的条目时，可以形成新增译文方案；这不自动授权写入。
- 范围确定后保持不变。警告项只是首批种子；无警告区域非空时，必须分散取样并执行至少一个不依赖警告的诊断信号。
- 用户要求逐条审查全部范围时，每个 item 都是候选；否则只有警告种子、分散样本和诊断信号命中的 item 进入候选队列。不得把仅由程序扫描的其它 item 报告为已逐条审查或保留。
- 每个候选必须且只能进入变更、保留或未决之一。item 是不可拆业务单元，按 project_meta 的文件顺序和文件内顺序组成互斥稳定批次。

## 审查判断

按以下审查优先级判断，后项不得牺牲前项：

1. 用户要求，以及原文的事实、信息量、不确定性、逻辑和表达意图。
2. 语境能证明的说话人、指代、人物关系、视角、知识边界、语气和剧情连续性。
3. 目标语言的准确、自然、一致和与原文相称的声音。

只在内容等价的合理方案之间优化表达；不得为改善情节、人物、节奏或文采而增删、解释或重构原文，也不把原文的歧义、粗粝、不规则或令人不适之处自动磨平。

## 警告处置

|警告|判断方法|
|---|---|
|`GLOSSARY`|随附术语应用给出明确目标且当前译文未落实时形成变更|
|`TEXT_PRESERVE`|能确定正确保护形式时形成变更|
|`KANA` / `HANGEUL`|应译出的残留形成变更；合法专名、符号或应保留文本予以保留|
|`SIMILARITY` / `RETRY_THRESHOLD`|单独不足以判错；同时存在明确错误时按错误本身处置|

警告只负责发现，不自动等于错误或可忽略。单条内能够确定的问题不得以缺少邻近上下文为由逃避变更；只有决定性语境缺失时才列为未决并点明缺口。术语判断只使用候选随附的术语应用证据，不读取整张术语表替代条目修复。

## 自适应发现

从不同文件、位置和文本形态取得少量分散样本，与警告共同选择适合当前语言、题材和译文状态的有限互补信号，例如保护文本、原文残留、术语和姓名分歧、否定与数量偏移、说话人和指代、语域及人物声音。这些方向不是封闭类型或自动判错标准。

可程序定位的信号必须完整扫描固定范围，并返回扫描数、命中数、新候选数、是否耗尽及是否截断；不得用 Top-N、样本或结果字节门冒充完整执行。只能语义判断的视角用于分散样本，不宣称覆盖全范围。

候选审查暴露新模式时，只接纳有具体工程证据、与已执行信号非等价且可程序定位的信号。每个信号只执行一次：新命中的未完成 item 加入后续队列，已完成 item 加入待回填集合；没有增加新 item 时立即耗尽。每批结束只合并执行一次闭包扫描，扫描结果不得继续派生信号。每个 item 正向最多入队一次，因此发现阶段必然收敛。

## 工作流

本技能属于动态长任务：

- 固定范围后调用 `task_progress` 的 `start`，登记 `translation:forward`、`translation:residual` 与 `translation:finalize`，不要为每个 item 建进度项。
- 正向阶段按实际稳定批次追加 `translation:batch:<key>`；完成一批并由闭包扫描产生后继批次时，在同一次 `advance` 中完成当前项并追加新项。
- 正向队列清空前保持 residual pending；取得全部真实写入回执或核对无变化结论前保持 finalize pending。

1. 调用 `workspace_load`，根据摘要和 contract 固定范围与自然顺序。范围为空时直接报告；警告为空时仍继续主动发现。
2. 对无警告区域分散取样，完整执行初始信号，将样本、信号命中和警告种子合并去重为候选队列。先完成确定性程序处理，再为开放式判断形成稳定批次。
3. 逐批读取必要的最少邻近文本，把全部候选归入变更、保留或未决；执行一次批末闭包扫描，并把新命中加入后续队列或待回填集合。
4. 本批没有变更时继续；存在未授权变更时立即进入写入确认，不积压后续批次差异。授权后只写本批 item change，按 contract 建议调用一次 `workspace_apply` 并累计真实回执。
5. apply 后重新 `workspace_load`，只从新快照读取后续候选事实，不复用旧 warnings 或 evidence。回执与方案不一致时停止，不自行补偿。同一规则授权可以覆盖连续批次。
6. 正向队列清空后，从尚未成为候选的区域按不同文件、位置或文本形态执行一次独立残差取样；由它产生的具体信号最多完整扫描一次。将命中、样本和待回填 item 合并去重并冻结为最终残差集合；没有未候选区域和待回填 item 时直接冻结为空集。
7. 每个最终残差候选最多审查一次，并按正向阶段相同的判断、授权和逐批提交规则处理；冻结后不得新增信号、扩大集合或返回正向阶段。新发现只能在当前候选内解决，否则列为未决观察。完成 residual 与 finalize 工作项后调用 `task_progress` 的 `finish`。

跨越多次 load、apply 或模型回合时，自行判断是否使用 `task/**`；本技能不规定其内容或组织方式。自动写入只覆盖已授权的确定性差异；存在多个合理取舍、缺少决定性证据或超出字段所有权时保持原值并列为未决。

仅当初始信号均已耗尽且无截断、全部正向候选已有处置、独立残差复查已经执行、冻结集合已经处理完毕，并且全部写入都有真实回执或明确停在待授权状态时结束。完成只证明固定范围经过上述发现覆盖且实际候选已经处置，不宣称每个非候选 item 都接受过语义审查。

## 变更与报告

获得授权后，只为当前批次生成 `workspace.contract.changes.items.updates.path` 的必要行；字段副作用只读取 `workspace.contract.effects.item_updates`。

对外区分固定范围和实际候选，报告发现信号及扫描回执、正向与残差进度、候选的变更 / 保留 / 未决计数、主要问题、代表证据、未决和真实写入结果。没有变更时不调用 apply。
