# 译文审查

在当前工程内完成条目译文审查与修复：建立完整工作区 → 提取候选 → 本层审查 → 写入确认 → 原子应用 → 核对回执。

## 目标与范围

- 本技能只写 `items` 数据集允许修改的正文译文、姓名译文或人工状态。
- 默认范围是“翻译成功且存在警告”；用户可以改为全部条目、明确 ID、状态、文件、警告类型或文本条件，多个条件按交集执行。
- 用户明确选择尚无译文的条目时，可以形成新增译文方案；这不自动授权写入。
- 每个候选必须且只能进入变更、保留或未决之一，三类数量之和等于候选总数。

### 大批量审查兼容

- item 是领域不可拆单元；按 project_meta 的文件顺序、文件内条目顺序将候选稳定装入 system 规定的批组，不按警告类型或预期处置建立会重叠的范围分组。
- 用户确认处理全部批组时，所有批组复用同一工作区、事实快照和判断方法；形成方案前统一核对各批组处置之和与完整候选总数。

## 判断方法

审查必须覆盖忠实度、目标语言质量、一致性、控制符、占位符、换行、文本保护、源语言残留、警告证据、相似度与重试信号。

| 警告 | 判断方法 |
| --- | --- |
| `GLOSSARY` | 随附术语应用给出明确目标且当前译文未落实时形成变更 |
| `TEXT_PRESERVE` | 能确定正确保护形式时形成变更 |
| `KANA` / `HANGEUL` | 应译出的残留形成变更；合法专名、符号或应保留文本予以保留 |
| `SIMILARITY` / `RETRY_THRESHOLD` | 单独不足以判错；同时存在明确错误时按错误本身处置 |

- 警告是候选入口，不自动等于错误，也不自动等于可忽略。
- 单条内能够确定的错译、语言质量、控制符、占位符、换行和残留问题，不得以缺少邻近上下文为由逃避变更。
- 拟写值依赖说话人、指代、剧情连续性或多义消歧且工作区没有决定性证据时列为未决，并点名证据缺口。
- 术语未落实只使用候选随附的术语应用证据，不读取整张术语表来替代条目修复。

## 工作流

### 1. 建立快照与候选

1. 调用 `workspace_create`。
2. 读取 project_meta 与 contract，确认权威语言、完整数量和 `items` / `warnings` 数据集语义。
3. 按用户条件或默认范围取得完整候选总数和代表证据；结果按 item 去重并按需联结 warning，system 要求大批量范围确认时先按“大批量审查兼容”形成完整批组并等待用户确认。
4. 只有已确认范围内的候选确实依赖说话人、指代、剧情连续性或多义消歧时，才为已经确定的 item 补充同文件邻近文本。
5. 候选为零时直接报告审查结果，不修改可写数据集。

### 2. 审查与写入确认

- 每个候选按判断方法归入变更、保留或未决；具有共同原因和处理方式的候选按业务原因归组。
- 自动修复只允许处理已经明确授权的确定性差异；依赖缺失语境、存在多个合理取舍或超出条目字段所有权的候选保持原值。
- 存在变更时先报告范围、完整性、三类处置计数、共同规则、代表证据、例外和状态副作用，并等待用户明确批准。
- 没有变更时报告审查结果，不调用 apply。

### 3. 修改可写数据集并应用

获得批准后：

1. 用 `workspace_script` 流式修改 `workspace.contract.datasets.items.path` 指向的完整集合，只改变获批字段；脚本返回处置计数、代表差异和未决。
2. 非空正文译文会由后端自动设为翻译成功；同一行显式人工状态优先，状态变化会清零重试次数；只改姓名译文不自动改变状态。
3. 调用一次 `workspace_apply` 应用全部差异，不重新拼装 revision，不拆成多次写入。
4. 以 apply 回执报告真实更新计数和 revision；成功后不重新读取完整工程，也不声称未重新评估的警告已消失。

可写数据集校验失败时先修复当前工作区；`workspace_script` 失败或停止只回滚本次运行，可修正后继续。stale、工作区失效或错误 action 指向 `workspace_create` 时才重新 create。回执与批准方案不一致时停止，不自行补偿写入。
