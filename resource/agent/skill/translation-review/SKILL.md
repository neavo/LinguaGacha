# 译文审查

在当前工程内完成条目译文审查与修复：加载当前工作区 → 提取候选 → 本层审查 → 写入确认 → 局部应用 → 重新加载或核对回执。

## 目标与范围

- 本技能只写 `items` 数据集允许修改的正文译文、姓名译文或人工状态。
- 默认范围是“翻译成功且存在警告”；用户可以改为全部条目、明确 ID、状态、文件、警告类型或文本条件，多个条件按交集执行。
- 用户明确选择尚无译文的条目时，可以形成新增译文方案；这不自动授权写入。
- 每个候选必须且只能进入变更、保留或未决之一，三类数量之和等于候选总数。

### 程序化处理与语义审查组

- 先在完整候选范围内程序化完成由用户规则、字段事实或确定算法唯一决定的筛选与变换，不受审查组大小限制；只把剩余必须逐项判断的候选交给语义审查。
- item 是领域不可拆单元；按 project_meta 的文件顺序、文件内条目顺序将剩余候选稳定装入 system 规定的审查组，不按警告类型或预期处置建立会重叠的范围分组。
- 审查组只控制模型一次判断的上下文，不等于提交单元。用户确认处理全部审查组时，各组复用同一判断方法；已授权差异按 contract guidance 拆分或合并提交，每次 apply 后重新 load，并累计权威回执。

## 判断方法

审查必须覆盖忠实度、目标语言质量、一致性、控制符、占位符、换行、文本保护、源语言残留、警告证据、相似度与重试信号。

| 警告 | 判断方法 |
| --- | --- |
| `GLOSSARY` | 随附术语应用给出明确目标且当前译文未落实时形成变更 |
| `TEXT_PRESERVE` | 能确定正确保护形式时形成变更 |
| `KANA` / `HANGEUL` | 应译出的残留形成变更；合法专名、符号或应保留文本予以保留 |
| `SIMILARITY` / `RETRY_THRESHOLD` | 单独不足以判错；同时存在明确错误时按错误本身处置 |

- 警告是候选入口，不自动等于错误，也不自动等于可忽略。
- 单条内能够确定的错译、语言质量、控制符、占位符、换行和残留问题，不得以缺少邻近上下文为由逃避变更。
- 拟写值依赖说话人、指代、剧情连续性或多义消歧且工作区没有决定性证据时列为未决，并点名证据缺口。
- 术语未落实只使用候选随附的术语应用证据，不读取整张术语表来替代条目修复。

## 工作流

### 1. 建立快照与候选

1. 调用 `workspace_load`。
2. 根据返回摘要和脚本内 contract 确认权威语言、完整数量和 `items` / `warnings` 数据集语义。
3. 按用户条件或默认范围取得完整候选总数和代表证据；结果按 item 去重并按需联结 warning，先完成可程序化处理，再按 system 规则为剩余语义候选形成审查组并在需要时确认范围。
4. 只有已确认范围内的候选确实依赖说话人、指代、剧情连续性或多义消歧时，才为已经确定的 item 补充同文件邻近文本。
5. 候选为零时直接报告审查结果，不写 change 文件。

### 2. 审查与写入确认

- 每个候选按判断方法归入变更、保留或未决；具有共同原因和处理方式的候选按业务原因归组。
- 自动修复只允许处理已经明确授权的确定性差异；依赖缺失语境、存在多个合理取舍或超出条目字段所有权的候选保持原值。
- 存在变更时按“审查范围与完整性 → 变更 / 保留 / 未决统计 → 按业务原因归组的主要问题 → 代表差异与证据 → 例外和未决 → 写入状态或执行结果”组织有真实内容的部分，视觉结构使用 system 的公共规则，并报告 contract 声明的状态副作用；当前差异或确定规则尚未授权时，进入写入确认。
- 没有变更时报告审查结果，不调用 apply。

### 3. 写入显式 change 并应用

获得授权后：

1. 用 `workspace_script` 流式读取 `workspace.contract.datasets.items.path`，只为获批差异生成 `workspace.contract.changes.items.updates.path` 的行；每行包含 `item_id` 和实际更新字段，脚本返回处置计数、代表差异和未决。
2. 字段副作用只读取 `workspace.contract.effects.item_updates`，不得从本 skill、旧对话或经验重建。
3. 按 `workspace.contract.guidance.apply.item_updates` 的软建议组织提交单元；审查组与提交单元不要求一一对应。每个提交单元调用一次 `workspace_apply`，不重传 revision。
4. 以 apply 回执累计真实更新计数和 revision；还有后续提交单元时重新 `workspace_load`，不把上一轮 warnings 当作新事实，也不声称未重新评估的警告已消失。同一确定规则授权可以覆盖技术拆分后的连续提交。

change 校验失败时先修复当前工作区；`workspace_script` 失败或停止只回滚本次运行，可修正后继续。事务回滚可安全重试当前 apply；stale、revision 冲突、工作区失效或错误 action 指向 `workspace_load` 时重新 load。`data.committed_sync_failed` 表示已经写入，只报告并要求重新加载工程。回执与授权方案不一致时停止，不自行补偿写入。
