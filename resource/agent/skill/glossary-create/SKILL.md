# 术语表创建

把工程语料作为可搜索的证据池：利用模型知识提出疑点，以程序化检索和聚合精确定位证据，只在需要语义判断时读取少量语境，再按严格领域标准形成新增术语。允许程序化处理遍历完整数据集，禁止为了证明覆盖而让模型顺序阅读完整语料。

## 必读领域规则

进行任何术语判断前，检查当前模型上下文是否已经包含 `glossary-rules` 的完整正文。若尚未包含，从 `<available_skills>` 中按名称精确找到它的 `location`，调用 `read_skill` 读取其 `SKILL.md`；同一独立任务只读取一次。

若 `glossary-rules` 不存在、不可读取或正文无效，进入“无法继续”，不得从本技能、旧对话或经验重建术语定义。

## 范围与完成标准

- 本技能只创建新术语，不更新、删除或移动现有术语；需要改动现有条目时列为未决，并说明应由 `glossary-review` 处理。
- 默认把当前工程作为证据池；用户可以按文件、item、文本条件或明确排除项收窄证据范围。
- 原始 item 是定位疑点的证据源，不是必须逐项审阅的语义目标；只有实际浮现的疑点才进入候选范围。
- 模型内部知识只用于提出搜索假设、识别语言和题材模式、解释候选及生成译名，不得代替工程内的原文与语境证据。
- 每个候选必须且只能进入 `新增`、`排除`或`未决`；三类数量之和等于实际候选总数。相同事实和处置可以归组说明。
- 完成表示当前候选均已处置、必要关系扩展已经结束，且最近一次定向扩展没有产生合理新疑点；不宣称穷尽了工程中的所有可能术语。

## 疑点调查

先根据权威语言、文件结构、现有术语和少量高信息样本决定如何调查，再按当前工程动态组织程序化检索与聚合。姓名、同根或相关形式、专名形态、译法分歧、特殊复合词和设定句式可以作为线索，但不是固定清单、封闭枚举或收录依据。

- 程序化处理可以流式遍历完整数据集，完成索引、计数、聚合、覆盖判断和出现位置定位，只返回紧凑疑点、计数与少量代表 item，不返回完整语料。
- 对疑点执行纯字面量搜索，核对完整匹配数、文件分布、代表语境、已有译法、同名异义和现有术语冲突；不要按 item 顺序开放式阅读。
- 已确认候选可以扩展出别名、简称、同系列概念、相关实体或公共词根；只有具体证据支持时才继续追踪，不按预设术语类型穷举。
- 默认只读取足以判决的代表语境。身份、指代、剧情连续性、多义消歧、设定定义或译名风格无法确定时，才补充邻近文本或更长连续片段。
- 调查跨越多轮证据扩展时，维护以 `src` 为身份的紧凑候选账本，并在每轮后更新处置、决定性证据定位和待调查关联；不得复制完整命中集合。

收录阶段严格使用 `glossary-rules`：证据充分且需要规则承载时新增；已经证明为泛用词、误边界、无须统一或被现有规则安全覆盖时排除；边界、身份或具体译法缺少决定性证据时未决。

## 工作流

### 1. 建立事实快照与调查入口

1. 调用 `workspace_load`。
2. 根据返回摘要和工作区 contract 确认权威源语言、目标语言、文件结构、数据集语义和现有 glossary。
3. 读取足以选择调查策略的现有术语、强线索与分散样本，程序化建立第一批疑点；不得先把全部非空正文列为候选或语义目标。

### 2. 定向核验与扩展

按疑点批量定位完整出现集合的数量与分布，只向模型返回最少代表语境。结合语言知识、题材知识、已有译文和工程事实判断边界、身份、译名及是否需要规则承载，并从具体证据扩展必要关联疑点。

对每个拟新增边界程序化核对全部字面量匹配的数量与分布；代表证据暴露同名异义或普通词风险时，按风险分布补充语境，仍不足以判断未返回命中的安全性时列为未决。不要重复等价查询期待同一证据改变，也不要为提高形式上的覆盖率扩大连续阅读范围。

### 3. 全局归并与收敛

从已核验候选建立统一风格，并按 `glossary-rules` 选择最小充分集合：去除现有规则已安全覆盖的候选，合并同一实体形式，验证公共词根的组合能力，检查普通词误匹配、同名异义、规则冲突、译文风格和 `info` 身份。

当全部候选已有处置，并且基于已确认候选完成必要关系扩展后不再产生合理新疑点时停止。译文或身份存在多个具体合理值但缺少决定性证据时未决，不以空值创建占位术语。

### 4. 形成写入方案

报告证据范围、使用的疑点来源、候选总数、新增/排除/未决计数、变更前后术语数量、全局风格依据和最少代表证据；明确说明没有逐项语义审阅完整语料。用户点名候选、独立取舍和全部未决逐项说明。

有新增但尚未授权时使用 system 的“写入确认”；没有新增时使用“审查结果”。只读调查和候选发现不构成写入授权。

### 5. 写入并核对

获得明确授权后，用 `workspace_script` 只写 `workspace.contract.changes.glossary.creates.path`：每行完整提供 `src`、`dst`、`info` 和 `case_sensitive`，按需使用 `before_id`；不得写 updates、deletes、moves 或其它 quality kind。

默认用一次 `workspace_apply` 原子提交全部已授权新增，并核对回执中的真实创建数和新 revision。change 校验失败时修复当前工作区；stale 或 revision 冲突后重新 load 并重做受影响方案；`data.committed_sync_failed` 按已经写入处理，报告并要求重新加载工程，绝对不得重试 apply。
