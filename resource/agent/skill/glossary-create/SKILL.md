# 术语表创建

把工程语料作为可程序化扫描的证据池：完整发现可能需要术语承载的事实，只向模型提供聚合候选和足以判决的少量语境，再把新事实及其触及的既有规则共同整理成最小充分集合。程序可以遍历完整数据集；禁止为了证明覆盖而让模型顺序阅读完整语料。

## 必读领域规则

进行任何术语判断前，检查当前模型上下文是否已经包含 `glossary-rules` 的完整正文。若尚未包含，从 `<available_skills>` 中按名称精确找到它的 `location`，调用 `read_skill` 读取其 `SKILL.md`；同一独立任务只读取一次。

若 `glossary-rules` 不存在、不可读取或正文无效，进入“无法继续”，不得从本技能、旧对话或经验重建术语定义。

## 范围与事实模型

- 默认把当前工程作为证据池；用户可以按文件、item、文本条件或明确排除项收窄范围。
- 模型内部知识只用于选择发现信号、解释候选及生成译名，不得代替工程内证据。
- 候选表示可能需要规则覆盖的工程事实，最终且只能进入 `需规则承载`、`无需规则承载`或`未决`；三类数量之和等于实际候选总数。最终 glossary 变更是从全部需承载事实构造出的最小充分规则集合，不与候选数量混算。
- 没有既有规则关系时只创建新条目；新事实触及既有规则时，自动按“协调既有规则”处理最小关系闭包。用户明确要求只新增时，不安全的关系闭包列为未决。
- 完成不宣称穷尽工程中的所有可能术语；候选前沿、关系扩展和独立残差复查必须按本技能收敛。

## 候选前沿

程序化扫描完整适用数据集建立以 `src` 为身份的候选前沿。跨越多轮时把紧凑账本写入 `scratch/**`，只保存发现来源、计数与文件分布、少量代表 item、相关既有条目、当前处置和决定性证据定位，不复制完整语料或命中集合。

- 初始发现必须覆盖全部适用文件和 `src` / `name_src`，并按需利用 `dst` / `name_dst`；少量样本只能帮助选择信号，不能定义发现范围。
- 至少使用一个不依赖现有 glossary 或已确认候选的独立发现信号。候选可以排序和分批，但已经形成的候选不得因 Top-N、结果字节门或全局频率被静默丢弃；超出单次结果时保存在 scratch 后分页处理。
- 每个发现信号返回扫描 item / 文件数、原始命中数、去重候选数、保存候选数、按确定规则丢弃的数量与原因、是否耗尽及是否截断；程序只按确定的无效边界、重复或安全覆盖事实丢弃，语义取舍进入候选账本。
- 新的非等价证据可以重新打开既有处置；不要用重复等价查询期待结论改变。

## 探索语境

以下语境可以帮助提出疑点，但不是封闭清单、收录类型或自动判据。按权威语言、题材、文件结构和实际证据选择适用方向，并主动探索清单之外的模式。

| 语境 | 可探索的疑点 |
| --- | --- |
| 命名、定义、对比或纠正 | “被称为”“所谓”“不是……而是……”暴露的正式名称、规则概念与必要消歧 |
| 首次登场、同位说明、别名或简称 | 人物、组织、地点的完整身份、正式名称及其它原文边界 |
| 并列、枚举、等级或对立体系 | 同系列地点、组织、技能、仪式、阶级与上下位概念 |
| 规则、因果、限制和设定解释 | 作品特有的机制、状态、能力、历法、仪式或世界观概念 |
| 获得、装备、发动、制作和消耗 | 作品特有的物品、技能、材料、招式与状态 |
| 所属、来源、派生和身份变化 | 家族、流派、机构、公共专名词根、真名、伪名与代号 |
| 姓名字段、译法分歧、原文残留和特殊书写 | 未覆盖专名、同一原文的多个译法及普通翻译无法稳定推出的表达 |
| 已确认术语的邻近语境和文件长尾 | 相关实体、敌对项、支线人物、局部地点、章节标题和档案概念 |

命中这些语境只产生待核验候选；出现次数、姓名栏、特殊字形或现有译文都不能单独支持收录。

## 工作流

### 1. 建立快照与候选前沿

1. 调用 `workspace_load`，根据摘要和 contract 确认权威语言、文件结构、数据集语义、完整数量与现有 glossary。
2. 根据语言、题材、已有规则和分散样本选择多个互补的发现信号，程序化扫描完整适用数据集并生成候选账本与覆盖回执。
3. 优先发现结构化姓名、语境形态、未覆盖残差、译法分歧和文件长尾中的高信息候选；频率只决定核验顺序，不构成候选或收录门槛。

### 2. 核验并扩展候选

按候选批量定位完整字面量匹配的数量和文件分布，只返回最少代表语境。结合语言知识、题材知识、已有译文和工程事实判断边界、身份、译名及是否需要规则承载，并把证据支持的别名、简称、同系列概念、相关实体或公共词根加入同一候选前沿。

按 `glossary-rules` 的统一事实判定分类；身份、边界和具体值已经确认的专有实体或作品特有概念，原则上进入需规则承载，不要求重复出现、既有译文冲突或错误已经发生。

代表证据暴露同名异义、普通词风险、身份变化或译法分歧时，按风险分布补充语境；身份、指代、剧情连续性、多义、定义或风格仍无法判断时，才读取邻近文本。对仍有未返回匹配且无法判断安全性的候选列为未决，不扩大连续阅读范围。

### 3. 协调既有规则

对全部需承载事实程序化检查与现有 glossary 的匹配等价、包含、被包含、重叠、公共词根和后端关系组。没有相关既有条目时直接构造新增规则；存在关系时，形成包含全部必要既有目标的最小完整关系闭包。

若当前上下文尚未包含 `glossary-review`，从 `<available_skills>` 精确定位并读取其 `SKILL.md`；同一任务只读取一次。把关系闭包中的既有条目作为明确 `targets`，按 `glossary-review` 审校该限定范围并覆盖其默认全表范围：不得重新发起全工程候选调查或要求用户另开任务，审校证据产生的新事实加入本任务的同一候选前沿并按第 2 步处理。最终把创建、修改、删除和移动合并为一份最小充分方案；范围外冲突或用户排除项导致闭包无法安全处理时列为未决。

### 4. 独立残差复查与收敛

候选前沿暂时清空后，使用不同于初始发现的证据方向复查未被现有或拟定规则覆盖的区域；按文件或章节分层检查长尾，并对缺少明显形式信号的单次概念读取少量分散语境。残差复查产生候选时返回第 2 步。

同时满足以下条件时停止：全部候选已有处置；scratch 中没有待处理候选；所有发现信号均已耗尽且没有截断；关系扩展不再产生候选；独立残差复查没有产生合理新疑点；受影响的既有规则闭包已经完成审校；最终规则安全覆盖全部需承载事实。

### 5. 形成方案并提交

分别报告证据范围、发现信号与覆盖回执、候选的需承载 / 无需承载 / 未决计数、最终的新增 / 修改 / 删除 / 移动计数、变更前后术语数量、公共词根、全局风格依据和最少代表证据；用户点名事实、独立取舍、全部未决和未耗尽范围逐项说明。明确说明没有逐项语义审阅完整语料；前沿未耗尽时只能报告部分调查。

有可执行变更但尚未授权时使用 system 的“写入确认”；没有变更时使用“审查结果”。获得明确授权后，用 `workspace_script` 只写 `workspace.contract.changes.glossary` 下的必要 change 文件，默认一次 `workspace_apply` 原子提交完整方案，并核对真实计数与新 revision。
