# 术语表创建

把工程语料作为可程序化扫描的证据池：程序完整执行任务内发现信号，模型只核验聚合候选和必要的少量语境，再把全部已确认事实整理为最小充分术语集合。禁止为了证明覆盖而让模型顺序阅读完整语料。

## 必读领域规则

进行任何术语判断前，检查当前模型上下文是否已经包含 `glossary-rules` 的完整正文。若尚未包含，从 `<available_skills>` 中按名称精确找到它的 `location`，调用 `read_skill` 读取其 `SKILL.md`；同一独立任务只读取一次。

若 `glossary-rules` 不存在、不可读取或正文无效，进入“无法继续”，不得从本技能、旧对话或经验重建术语定义。

## 目标、范围与账本

- 默认把当前工程作为证据池；用户可以按文件、item、文本条件或明确排除项收窄范围。
- 模型内部知识只用于选择发现信号、解释候选及生成译名，不得代替工程内证据。
- 候选以原文 `src` 为身份，表示可能需要规则覆盖的工程事实；最终且只能进入 `需规则承载`、`无需规则承载`或`未决`，三类数量之和等于实际候选总数。
- 最终 glossary 变更从全部需承载事实构造，不与候选计数混算；没有既有规则关系时只创建新条目，新事实触及既有规则时处理最小完整关系闭包。用户明确要求只新增时，不安全的关系闭包列为未决。
- 跨越多轮时把一个紧凑账本写入 `scratch/**`：每个候选只保存发现信号、计数与文件分布、少量代表 item、相关既有条目、当前处置和决定性证据定位；另保存各发现信号的覆盖回执。不得复制完整语料、完整命中集合或模型已能从证据重新得到的解释。

## 发现循环

### 1. 建立快照并选择信号

1. 调用 `workspace_load`，根据摘要和 contract 确认权威语言、文件结构、数据集语义、完整数量与现有 glossary。
2. 从不同文件、章节或结构层取得少量分散样本，只用来判断哪些发现信号适合当前语言和题材；样本不得定义发现范围。
3. 选择多个互补信号，至少一个不得依赖现有 glossary 或已确认候选。优先考虑：
   - 完整 `name_src`、明确名称边界和特殊书写；
   - 命名、定义、首次登场、别名、规则、获得、装备、发动、所属和身份变化等语境槽位；
   - 并列、枚举、等级、对立体系和其它同构结构；
   - `dst` / `name_dst` 中的译法分歧、原文残留或身份线索；
   - 既有规则未覆盖的文件长尾和单次概念。

这些方向不是封闭类型或自动收录判据。出现次数、姓名栏、特殊字形、现有译文和信号分数只能帮助发现或安排核验顺序。

### 2. 完整执行信号

程序化扫描全部适用文件和 `src` / `name_src`，按需利用 `dst` / `name_dst`，把每个信号发现的连续原文字面量合并进同一候选账本。每个信号必须返回：扫描 item / 文件数、原始命中数、去重候选数、保存候选数、按确定规则丢弃的数量与原因、是否耗尽及是否截断。

- 候选可以排序和分页，但不得因 Top-N、结果字节门或全局频率静默丢弃；超出单次结果时先写入 scratch，再分页核验。
- 程序只按确定的无效边界、重复或安全覆盖事实丢弃候选；需要语义取舍的内容进入账本。
- 一个信号未完整扫描适用范围或回执被截断时，只能报告部分调查，不能进入最终收敛。

### 3. 核验候选并扩展信号

用 `workspace.matchLiterals` 批量取得候选在 `src` / `name_src` 中的正式匹配计数、item 并集和有限证据；不得让通用 includes 搜索冒充正式匹配，也不得为统计向模型返回完整匹配正文。证据不足时，只按代表 item_id 读取判决所需的完整条目或邻近文本。

按 `glossary-rules` 分类候选。身份、边界和具体值已经确认的专有实体或作品特有概念，原则上进入需规则承载，不要求重复出现、既有译文冲突或错误已经发生。同名异义、普通词风险、身份变化或译法分歧才按风险分布增加语境；仍缺少会改变结论的证据时列为未决，不扩大连续阅读范围。

每批新证据核验后，检查它是否暴露新的非等价发现信号：

- 把已确认术语在有限语境中的位置抽象为槽位，保留能够确定边界的相邻文字或结构，再扫描同槽位的其它原文字面量；
- 从别名、同位说明、并列成员、同系列形式、公共词根、相邻实体或文件结构中提出新的关系或长尾信号；
- 信号必须能捕获原文中的连续字面量，并完整扫描适用数据集、生成独立覆盖回执；边界无法程序化确定时只记录残差疑点。

模板和关系只负责发现，不证明候选应收录或彼此同义。已经完整执行的等价信号不重复运行；新的非等价证据可以重新打开既有处置。发现非等价信号时返回第 2 步完整执行，产生新候选后再回到本步骤统一核验。

### 4. 协调既有规则

对全部需承载事实程序化检查与现有 glossary 的匹配等价、包含、被包含、重叠、公共词根和后端关系组。存在关系时形成包含全部必要既有目标的最小完整关系闭包。

若当前上下文尚未包含 `glossary-review`，从 `<available_skills>` 精确定位并读取其 `SKILL.md`；同一任务只读取一次。把关系闭包中的既有条目作为明确 `targets`，按 `glossary-review` 审校该限定范围并覆盖其默认全表范围。审校只处理限定闭包及其有界证据，不重新扫描全工程；调用方把审校发现的新事实加入当前账本，并在审校返回后按第 3 步判断是否需要执行新的发现信号。

最终把创建、修改、删除和移动合并为一份最小充分方案。范围外冲突或用户排除项导致闭包无法安全处理时列为未决。

### 5. 独立残差复查并收敛

候选暂时全部处置后，使用不同于初始发现的证据方向复查未被现有或拟定规则覆盖的区域；按文件或章节分层检查长尾，并对缺少明显形式信号的单次概念读取少量分散语境。残差产生新疑点时，选择相应信号完整扫描，再返回第 3 步。

仅当以下条件同时满足时停止：

- 全部候选已有处置，scratch 没有待处理候选；
- 所有发现信号均已耗尽且没有截断；
- 新核验事实不再产生非等价发现信号；
- 关系扩展不再产生候选，受影响的既有规则闭包已经完成审校；
- 独立残差复查没有产生合理新疑点；
- 最终规则安全覆盖全部需承载事实。

完成不宣称穷尽工程中的所有可能术语；只能证明上述候选、信号和残差过程已经收敛。

## 形成方案并提交

分别报告证据范围、发现信号与覆盖回执、候选的需承载 / 无需承载 / 未决计数、最终的新增 / 修改 / 删除 / 移动计数、变更前后术语数量、公共词根、全局风格依据和最少代表证据。用户点名事实、独立取舍、全部未决和未耗尽范围逐项说明，并明确没有逐项语义审阅完整语料。

有可执行变更但尚未授权时使用 system 的“写入确认”；没有变更时使用“审查结果”。获得明确授权后，用 `workspace_script` 只写 `workspace.contract.changes.glossary` 下的必要 change 文件，默认一次 `workspace_apply` 原子提交完整方案，并核对真实计数与新 revision。
