# 质量规则审查入口

读取 `@skill(quality-rule-workflow)` 并按审查模式执行其唯一工作流；由共享工作流按实际范围加载领域判据。同时审查两个领域时仍只加载一次工作区，并共享程序化遍历和上下文证据。

## 范围

- 未限定规则类型：审查现有 glossary + text_preserve；限定时只处理指定类型。
- 限定目标：只有明确规则进入审查范围；其它规则只作结构、覆盖或语义证据。
- 用户排除项保持原样，不进入目标、统计或变更。
- 不主动扫描全工程发现独立新规则；核验目标时发现的必要替代边界、拆分分支或缺失对象可以进入当前处置。需要系统发现时使用 `quality-rule-create`。

初始化时按用户范围程序化枚举全部现有目标，保持规则稳定顺序；先建立结构组，再在同一次证据编排中取得正式命中和有限语境。glossary 目标使用 `workspace.matchLiterals` 批量匹配；text_preserve 在同一次 items 遍历中累计真实命中、文件、文本类型和代表证据。每个目标必须独立得到结论，共同审查组不能代替逐项判断。

每个现有目标独立决定：

- 仍然需要且最终值相同则保留，需要调整则修改；被其它已验证最终规则完整覆盖时可以删除，并记录覆盖关系。
- 不符合领域收录条件则删除；不能因存在已久、修改麻烦或当前没有报错而保留。
- 当前工程零命中且用户未要求清理预置规则时保持原值，并说明当前没有证据支持修改或删除。
- 只有直接形成、按输入语境处理、缩小边界或拆分都失败时，才把该目标列为需要补充信息；同组其它目标继续处理。

审查中出现必要替代规则时，与现有目标使用同一聚类算法和发现前沿，但范围外新规则只作观察。结构关系、关联匹配和独立漏项检查只扩展目标证据或必要替代对象，不自动扩大用户允许修改的目标。

最终从范围内现有目标与必要替代规则程序化生成新增、修改和删除；不自动生成 move。对外使用用户语言报告全部目标处置、新增 / 保留 / 修改 / 删除 / 需要补充信息的数量、基础核验与关联补查及独立漏项检查是否完成、结构拆分和语义合并结果，不得展示共享工作流的内部状态。
