# LinguaGacha 后端设计

后端负责工程事实与执行结果的一致性。GUI、CLI 和产品 Agent 的工程写入汇入同一提交流程。

- 进程与宿主生命周期见 [ARCHITECTURE](ARCHITECTURE.md)。
- Agent 工作材料见 [AGENT_RUNTIME](AGENT_RUNTIME.md)。
- 源码与验证入口见 [WORKFLOW](WORKFLOW.md)。

## 💾 工程提交与恢复

`ProjectWriteStore` 在同一 `.lg` 事务中处理用户意图、重复条目协调、翻译统计和修订更新。直接修改与被动变化因此能一起进入缓存和事件。

工程修改可能先于 SDK 工具回执持久化。中断恢复以已提交工程事实为准，后续指令重新读取现值。

一次提交分为三个阶段：

1. 提交数据库事务。
2. 更新缓存。
3. 发布公开通知。

数据库提交后的同步失败使用 `data.committed_sync_failed`，携带已提交事实和重载要求。调用方重读数据，避免重复执行已经完成的写入。

HTTP 写入回包与 SSE 承载同一 `ProjectChangeEvent`，到达顺序不固定。前端的去重与恢复见 [FRONTEND](FRONTEND.md)。

### 冲突判断

|写入来源|判断依据|设计目的|
|---|---|---|
|基于查询快照的编辑|所依赖的 `sectionRevisions`|保护用户读到的内容|
|任务启动、按当前事实重置|取得占用后的工程事实|按执行时状态处理|
|Agent 的 `workspace_apply`|目标对象指纹 `fp`|允许长时间调查后提交少量对象，与无关修改共存|

`projectRevision` 汇总各分区修订的最大值。写入冲突仍按实际依赖的分区判断，不能把这个汇总值当成全局写锁。

Agent 提交的两种失败有不同结果：

- 对象冲突：拒绝冲突对象，其余合法对象可以在同一事务中提交。
- 数据库失败：回滚整批事实与修订。

后续工作以回执中实际应用的对象为准。

### 多个存储之间的补偿

应用设置、预设文件与 `.lg` 分别持久化，涉及多个存储的命令持有相应互斥。

- 提交前失败：补偿本次修改。
- 工程已提交后的同步失败：保留提交结果，按重载语义恢复。

补偿覆盖进程内失败，文件与配置之间仍存在崩溃窗口。恢复时需要读取当前持久化事实。

## ⏳ 运行占用与任务完成

`RuntimeOperationGate` 协调翻译、Agent、模型接口测试和工程写入的占用。占用持续到清理结束，避免旧请求仍在写入时启动下一操作。

Agent 内的批量翻译和工程提交复用当前 Agent 占用。

普通设置和模型配置允许在运行中修改。一次执行使用固定配置，修改供后续执行采用，保持同一批请求的处理语义稳定。

### 进度口径

|口径|用途|保存边界|
|---|---|---|
|本轮 `run_progress`|展示本次目标的处理量与用量|当前运行的内存状态|
|工程累计 `progress`|工程重开后继续展示累计统计|随 `.lg` 持久化|
|工程完成率|判断当前工程条目的处理情况|根据当前已保存条目状态计算|

局部重翻的本轮进度不能替代工程完成率。PDF 文件按原页处置统计，工程条目统计仍只汇总文本条目。

### 完成与重试

批量翻译逐批提交有效译文，取消或后续失败保留已有提交。重试预算仅属于本轮运行。

`completion` 等待规划、请求、写入和资源收尾完成。调用方用它决定后续导出或释放，快照负责展示。

恢复分为两类：

- 请求故障：网络调度器在原逻辑请求内等待密钥恢复。
- 内容失败：内容处理针对无效译文重试。

全部密钥不可用时，任务继续等待恢复或取消，前端展示后端提供的恢复状态。

### 计算线程

work-unit、planning 和 compute worker 承担计算，数据库与事件由后端持有。

work-unit 经父线程端口发送模型请求，使线程崩溃和取消能够终止同一次执行的网络请求。

## 📄 原稿、翻译与导出

`.lg` 保存原始资产和编辑事实，使原始输入文件移动后仍能继续工作。格式写回依赖工程中的原始资产，缺失时导出失败。

“全部重置”从已保存资产重新解析内容：

- 可能恢复源文件自带译文，并改变条目数。
- 完整解析成功后才提交替换，避免留下半份重建结果。

### PDF 的原页身份

PDF 按原稿页保存处置与译稿，使调查证据、修改目标和来源冲突都绑定稳定身份。输出页由排版生成，页数可以随译稿长度变化。

不同处置表达不同的工作决定：

|处置|含义|
|---|---|
|`translation: null`|尚未处理，暂时输出原页|
|`keep`|确认无需翻译，保留原页并记录理由|
|`omit`|按用户要求省略原页，并记录理由|
|空 `translate`|内容已归入其它页，本页不再输出译稿|

保存阶段允许暂时没有输出页，便于逐步编辑。整份文档预览和导出要求至少保留一页，保证交付文件有效。

单页预览与整份导出共用排版实现。整份导出会连续排版相邻译稿，因此分页可能与单页预览不同。

来源字节和页级事实持久化。文字、字体和坐标提取作为可再生工作材料。

### 导出的失败边界

GUI 与 CLI 共用导出服务：

- 格式计算或写回失败会终止本次导出，已经写出的文件可能保留。
- 打开输出目录属于完成后的附加动作，失败时保留已生成产物。

## 🔎 查询与质量证据

缓存和质量评估服务于已保存的工程事实。条目、修订与缓存沿同一提交结果更新，查询恢复时可从数据库重建。

翻译、校对、规则统计与 Agent 工具共用匹配和文本准备规则，使同一术语或保护片段在各入口具有相同含义。

校对结果只表示检查发现的证据：

- PDF 页面使用页级处置事实。
- 文本使用文本质量评估。
- 没有警告不能证明译文正确。

校对窗口保留一次查询的成员与顺序，方便编辑时继续阅读：

- 正文修改后继续使用当前窗口。
- 重新查询时重新筛选和排序。
- 文件结构变化后旧窗口失效，按新范围查询。

## 🌐 模型与网络

模型管理、OneShot 与 Agent 共用能力目录和请求策略，避免同一配置在不同入口得到不同能力判断。

ChatGPT 登录只确认身份和套餐授权。模型目录与接口测试由用户独立触发，避免把临时额度和推理故障混入账户状态。

SDK 内置聊天模型提供离线基线，远端聊天目录作为可撤回的供应商覆盖。有效空目录表示撤回旧覆盖，用户模型配置独立保存。

目录联网更新保留已完成的供应商结果，并等待运行空闲后应用，保持在途配置稳定。

模型等级有两项跨入口语义：

- 思考等级属于模型全局配置，引用同一模型的入口共享该值。
- `DEFAULT` 表示沿用供应商默认，`OFF` 表示显式关闭，两者表达不同的用户选择。

### 系统代理

后端 HTTP 与工作区 HTTP 共用系统代理策略。

- 代理解析或连接失败会结束请求，避免静默直连改变用户的网络选择。
- 本机回环请求固定直连。
- 传输层保留 HTTP 状态与重试时间，恢复决策由调用方承担。

### 公开错误

`code` 和 HTTP 状态决定恢复动作，`message` 保留具体原因供诊断。跨 API 与线程传递时保留两者，使展示措辞可以独立变化。公开原因中的凭据由接入边界处理，完整诊断保留在日志。

## 🗃️ 存储与历史工程

`ProjectDatabase` 管理连接和事务。长任务与同步操作共同持有连接，SQLite 在最后连接关闭时完成 checkpoint 和副文件清理。

迁移分别处理应用文件、数据库和工程打开准备：

- 迁移标记与对应数据一起提交。
- 迁移顺序承担历史版本升级语义。
- 已停用能力的旧数据保留物理原值，当前读取只投影现行事实。

日志以正文为恢复依据，索引可以重建。外部编辑使旧游标和详情定位失效，避免读取已经错位的记录。

Agent 日志与会话恢复的关系见 [AGENT_RUNTIME](AGENT_RUNTIME.md)。
