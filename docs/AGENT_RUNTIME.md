# LinguaGacha 产品 Agent 设计

产品 Agent 分别维护模型历史、公开时间线和工作材料，工程事实通过共享后端提交。

- 工程事务见 [BACKEND](BACKEND.md)。
- 进程、宿主生命周期与跨层不变量见 [ARCHITECTURE](ARCHITECTURE.md)。
- 通用前端状态设计见 [FRONTEND](FRONTEND.md)。

## 💬 对话、历史与日志

每个工程保留一个产品对话 `Chat`。`chatId` 关联界面、历史与本机材料，历史修订后沿用。

对话事实随 `.lg` 保存，工作材料按 `chatId` 保留在本机目录。公开时间线保留压缩前的对话，供用户回看工具执行和历史回答。

- 打开历史和修改已保存的助手回复均可离线完成。模型配置与认证在发起模型请求前采用。
- 模型请求采用所属 SDK 分支的供应商身份，因此历史修订后建立独立的供应商关联。
- 日志用于诊断，不参与会话恢复。

### 生命周期

|事件|结果|
|---|---|
|路由切换|保留普通草稿和会话镜像|
|同一工程内的数据提交|保留对话和模型历史，后续工具重新读取工程事实|
|工程切换|关闭旧执行，再恢复目标工程的对话。回到原工程时沿用其身份和历史|
|工程复制、移动或改名|沿用同一对话及本机工作材料|
|普通关闭|保留对话数据及专属目录|
|重开|按 SDK 已提交历史恢复。撤销遗留任务和排队提交，清空待回答与待授权。按历史回执消费已发送草稿，归还未入历史的占用并暂停剩余队列，等待新指令|
|停止或失败|公开终态以 SDK 已提交回执为准，重连和重开使用同一事实。剩余输入暂停，`doing` 保留供后续处理参考|
|用户输入修订|清空队列与 `doing`，避免原后续意图进入新分支|
|助手回复修订|保留队列与 `doing`，延续用户当前意图|
|完整轮次分叉|清空队列与 `doing`，避免原后续任务进入新对话|
|`reset`|删除当前对话数据及专属目录，建立新身份|

历史修订与分叉只改变后续模型上下文，已经发生的工程提交和文件写入仍然有效。

SDK 会话队列必须先于数据库队列取得执行权，避免恢复历史时与已排队的提交相互等待。

## ⏳ 运行、停止与继续

产品轮次覆盖即时输入和截断恢复，共用运行占用直到全部结算。

- 上下文压缩可取消，已提交的有效摘要保留。`workspace_apply` 期间拒绝普通停止，等待工程提交完成。
- 运行中的普通草稿仍可编辑和排队，执行权限由后端会话状态决定。
- 普通输入按队列顺序执行，停止或失败会暂停剩余输入，继续由后端恢复。

`steer` 输入进入当前 SDK 执行。草稿在真实入历史后消费，取消且未入历史时恢复为草稿。重新发送使用新的尝试身份，避免取消回执误伤重试。

### 输入受理

- 一次用户操作的传输重试沿用命令身份。队列内容仍可编辑，实际发送时另建 SDK 输入尝试身份。
- 重连核对受理结果。确认成功后只消费原草稿，保留用户等待期间的新输入。
- 用户输入修订以 SDK 已持久化输入作为受理依据。正常受理与恢复按同一事实切换活动分支并清理旧意图，避免中断丢失已受理输入或提前丢弃原历史。

输入原文、附件引用与投递方式属于历史条目。旧 `inputs` 保留为兼容资料，以维持旧历史身份和分支关系。

### 会话同步

命令回执指向已发布修订，前端统一消费事件与快照，避免命令回包和增量事件各自维护一份会话。先订阅再恢复快照，使恢复期间发生的变化也能按修订顺序处理。

存储或投影故障后，公开历史保留最后成功投影，当前轮次显示实例故障终态。实际副作用退出后才释放运行占用，SDK 关闭后工程仍拥有数据库连接。

输入命令与状态核对都可触发实例恢复。恢复按 [已提交事实优先](ARCHITECTURE.md#已提交事实优先) 先核对持久化回执，再处理原请求，以免重复执行已受理输入或工程副作用。状态核对本身只恢复受理事实。

### Agent 内的批量翻译

Agent 复用共享 `BatchTranslationService`，由批量引擎逐批提交译文。

用户主动停止批量翻译后，同轮后续调用继续保留停止决定。显式继续或新一轮请求再开启执行，避免自动工具循环撤销用户的停止意图。

## 🧠 模型配置与上下文

模型配置在下一次模型操作开始前采用，同一轮工具循环按 [执行内配置固定](ARCHITECTURE.md#执行内配置固定) 使用同一配置。修改配置时保留当前对话历史。

### 容量与用量

- Agent 的上下文与输出预算使用 `agent.context_window`、`agent.max_output_tokens`。
- 模型页通用的输入、输出 token 设置用于 OneShot。
- 容量预算为自动压缩保留空间，界面预警也计入最大输出和压缩预留。
- SDK 选择压缩切点，保留的工具调用与结果须成对，保证后续上下文完整。

两种用量回答不同问题：

|用量|含义|
|---|---|
|累计用量|整个对话已经消耗多少|
|当前上下文用量|下一请求需要携带多少上下文|

- 修订和压缩可以减少上下文，已经发生的模型与压缩消耗仍计入累计用量。批量翻译使用自身统计。
- 公开用量依赖已入账回执，取消时可能缺少供应商消耗。

### 串行压缩与截断恢复

供应商可能按剩余上下文缩减输出上限。连续未取得正常进展时，同一执行最多尝试一次压缩恢复，SDK 显式溢出压缩也消耗该额度。原响应与消耗保留，后续模型上下文先排除该响应。

- 恢复接管的即时输入由当前执行持有冻结正文和已准备附件，草稿持续保持 `sending`。新尝试真实入历史后才消费，停止或普通失败后归还，存储故障则在重开时核对回执。其余草稿仍可编辑和排队。
- 手动压缩允许没有可用摘要，截断恢复必须取得已提交的有效摘要。阻塞自动压缩失败结束当前轮次并暂停剩余队列。

### 批量翻译的模型来源

- 跟随：采用当前 Agent 的生效配置。
- 固定选择：采用指定模型的已保存配置，即使它与 Agent 使用同一模型 ID。
- 每次工具调用重新读取偏好，本次分批请求和重试共用同一配置快照。
- 每次调用默认降到模型可用的最低思考等级，只调整本次副本。Agent 判断失败由思考等级导致时，可以关闭降级。

模型全局等级与 `DEFAULT`、`OFF` 的含义见 [BACKEND](BACKEND.md)。

## 🙋 用户决定与工程授权

- 普通问题的答案回到原工具调用。
- 工程授权针对本批已准备差异，审批摘要和实际提交使用同一份差异。
- `allow_once` 仅允许当前批次。

`agent_approval_mode` 是持久化偏好。`workspace_apply` 在批次开始时读取它，已经展示的审批继续等待原裁决。

自动选择倒计时由前端会话时钟持有。输入聚焦、断线或恢复期间暂停，避免用户暂时无法操作时消耗回答时间。

产品任务边界分为两个层面：

- 模型遵守产品指令中的 `report`、`apply` 范围。
- 后端执行工具权限、参数校验、运行占用和提交约束。

## 📁 工作材料与工程快照

|材料|用途|失效边界|
|---|---|---|
|数据快照与 `changes`|当前工程基线与提交意图|刷新时重建|
|`sources`|工程原始资产的文件投影|工程文件修订变化时重建|
|`work`|程序、证据和中间产物|对话重置或本机工作区数量清理|
|`uploads`|用户交给当前对话的原文件|对话重置或本机工作区数量清理|
|用户技能目录|跨对话、跨工程复用的技能|独立于工作区重置|

原稿按资产身份寻址，容器展开后保留身份中的扩展名，便于 Agent 直接读取已知目标。文件清单独立于原稿生成，保留零条目资产及格式身份。

共享层保留原件，引擎只生成可读视图，使参考失败或路径冲突都不改变原稿证据。

格式元数据 `extra_field` 随后端实现演进，因此不构成模型可见契约。Agent 从原稿和可读视图判断条目语境，并自行消歧重复文本。

原稿准备失败不单独决定 `workspace_run` 成败，因为脚本可能只使用工程快照。`source_issues.jsonl` 向 Agent 说明当前原稿的缺口，它与 `sources` 不一致时阻止脚本执行。身份隔离遵循 [跨层不变量](ARCHITECTURE.md#身份隔离迟到结果)。

附加原稿不产生条目，由 Agent 制作补丁交付。补丁归 `work` 的生命周期，不写回工程。附加原稿清单与资产的一致性见 [BACKEND](BACKEND.md#原生游戏)。

工程路径、加载世代和语言变化用于刷新工程快照。工作材料的保留边界由对话身份决定。

本机按最近使用回收旧工作区，当前激活目录受到保护。仅迁移工程文件或本机材料被清理后，对话历史仍可打开，附件和产物可能缺失。

程序失败、超时或取消后，`work` 中已完成的写入继续保留，便于后续读取和修复。工程写入另经 `workspace_apply` 提交，事务规则见 [BACKEND](BACKEND.md)。

### 上传与图片

上传可与程序并行，程序读取已经发布的原文件。草稿移除只解除引用。

消息发送前固定图片输入。准备失败时保留队列或待修订历史，使重试仍有完整输入。

图片处理分为三个边界：

- 后端决定转换策略，Chromium 宿主执行编解码。
- 模型历史持有固定结果，缓存清理或文件变化不会改写已发送图片。
- 供应商拒绝图片时，沿普通模型失败路径处理。

### 工作区文件交付

文件保存使用用户确认时的当前内容：

1. 等待对话框期间释放工作区互斥。
2. 确认后重新检查来源与会话身份。
3. 通过临时文件替换目标。

这使长时间等待的保存操作能够发现失效来源，并保护目标已有内容。

## 📚 指令、技能与工具契约

### 动态技能

用户包可以覆盖同名内置包，停用用户包后可以恢复内置版本。

展示与模型选择分别生效：

- 隐藏技能仍可供模型使用。
- 禁止自动调用的技能仍可通过显式引用读取。

管理修改与 Agent 执行互斥。工作区程序收尾后刷新集合，使直接写入的技能在后续调用中可见。

已经进入模型上下文的旧正文需要显式重读。管理命令采用文件版本检查和必要补偿，用户技能文件持续保留。

### 模型可读契约

`ws.contract`、模型声明和生成的 `reference` 文档共用 Schema，减少说明与实际校验之间的偏差。

模型按需读取对象主题，领域流程使用技能资源。具体字段和调用示例在这些消费入口维护。

工具参数采用普通 `object` 根，以适配供应商共同支持的结构。

公开工具结果保留模型实际收到的内容。原始异常按共享错误边界进入本地诊断，避免 UI 展示改变模型回执的含义。

## ⚙️ 工作区运行环境

所有工程共用 `userdata/node/`。npm 拥有第三方依赖的清单、锁文件、安装树和失败恢复。种子只负责首次初始化，后续修改归用户管理。

`workspace_exec` 是工作区的命令执行入口，npm 是目前唯一登记的命令。入口统一负责不经 shell 的参数拆分、环境准备、时限、进程监管与回执，命令只决定启动的随附 CLI 和参数语义。新增命令登记到同一入口并沿用这些约定，模型说明按入口约定与各命令行为分开组织。

应用拥有 `@lg/*` 及其依赖，使用户安装不会改变应用业务实现。SDK 随应用更新，历史用户工程中的旧 SDK 和归档保留给用户自行处理。`workspace_run` 保证其加载的模块使用当前应用 SDK。`workspace_exec` 运行的命令保留各自的标准行为，不承诺其子进程能导入应用 SDK。

第三方包缺失时直接失败，避免应用或开发目录掩盖用户的卸载结果。应用资源缺失按安装损坏处理。包导出只界定公开 API，文件权限见下文。

`@lg/pdf/mupdf` 与 PDF API 共用引擎实例。PDF API 仍以字节交换文档，支持跨版本、线程和进程调用。用户另装的 MuPDF 可能产生独立实例，即使版本相同也不能交换类对象。

### 共享占用与进程生命周期

共享租约跟随实际写入者存活。准备程序也纳入监管，宿主退出后必须回收仍在写入共享工程的任务。正常停止由监管程序处理，原生 fork 在登记完成前等待启动许可。

根进程退出不代表后代已经结束。正常结算遵循 [占用持续到收尾](ARCHITECTURE.md#占用持续到收尾)。准备程序在独占租约内回收中断暂存材料，已初始化工程保留 npm 实际留下的状态。

Windows 的下一次租约先回收旧 Job 成员，再允许新目标执行。macOS/Linux 的宿主与监管程序共享锁描述，单端退出后另一端继续持锁并回收进程组。

POSIX 保证不覆盖主动创建新会话的守护进程，也不覆盖宿主和监管程序同时被外部强杀。Windows 同样不控制经外部系统服务代为启动的程序。对应平台的验收入口见 [WORKFLOW](WORKFLOW.md#agent-node-与-npm)。

### 文件与宿主权限

JavaScript 按授权目录写入。npm、CLI、包脚本与原生扩展采用本机可信执行，模型按用户任务限定操作范围。原生扩展可能绕过 Node 文件权限。工程提交仍遵循 `workspace_apply` 的事务与授权流程。
