# LinguaGacha 前端设计

前端通过后端快照恢复工程与任务，用本地状态保存正在进行的交互。状态放置取决于它需要跨越哪些页面和会话边界。

- 共享写入与错误语义见 [BACKEND](BACKEND.md)。
- Agent 会话同步与工作材料见 [AGENT_RUNTIME](AGENT_RUNTIME.md)。
- 进程和打印宿主见 [ARCHITECTURE](ARCHITECTURE.md)。

## 🪟 宿主与后端接入

renderer 通过 `window.desktopApp` 使用按用途划分的宿主能力。

- 原生对话框选择位置，后端执行业务文件写入。
- main 处理外链、系统注意力、原生文本菜单和更新下载。
- Chromium 联网使用 session 的系统代理，后端网络策略见 [BACKEND](BACKEND.md)。

后端地址由启动结果注入，HTTP / SSE 经 `desktop-api.ts` 统一处理，使页面共用连接、错误和恢复行为。

后端就绪后才创建窗口，首帧即可使用有效的后端地址和应用版本。

## 🧩 代码归属

前端按业务责任组织代码，便于判断修改应当放在哪里：

|位置|负责的内容|
|---|---|
|`app`|应用装配、桌面传输、跨页面运行态|
|`features`|多个页面复用的业务交互与适配|
|`pages`|单个页面及其私有实现|
|`widgets`|可组合的界面控件|
|`widgets/interactions`|通用交互与快捷键|

跨页面能力由页面共同消费 `features`。通用交互保持独立于工程状态、页面业务和后端传输，避免复用控件时带入整套运行态。

## 🧠 状态的寿命

|状态|拥有者|保留范围|
|---|---|---|
|工程身份、设置与事件编排|`DesktopStateProvider`|主窗口会话|
|批量翻译、运行占用、工程变化信号|独立 Store|跨页面，按订阅者更新|
|批量翻译详情与译文生成交互|应用会话 Provider|跨页面继续同一次操作|
|阅读位置、筛选等轻量状态|`ProjectSessionUiStateProvider`|当前工程，切换或关闭后清空|
|查询窗口、局部编辑与弹窗|消费页面|随页面或目标内容结束|
|Agent 会话镜像与普通草稿|`AgentChatStore`|按对话边界保留|

高频状态放入独立 Store，只通知实际订阅者。

日志窗口独立查询日志和读取语言。

### 事件与恢复

同一路径的工程也可能重新加载。前端用路径、`epoch` 和初始化阶段识别当前会话，防止旧请求或迟到事件进入新会话。

HTTP 写入结果与 SSE 共用项目事件入口和去重策略：

- 共享层发布轻量变化信号。
- 页面按依赖分区重新查询。
- 完整查询结果由消费页面保存。

失败后的恢复方式按阶段选择：

- 首次查询失败：Toast 提示原因，内容区表达不可用状态。
- 已有内容刷新失败：保留有效内容，由当前操作入口反馈错误。
- 断线重连或事件处理失败：补读后端快照。

### 错误反馈与恢复

- 普通操作失败优先使用 Toast，减少工作区布局变化。标题复用「保存失败 …」等完整公共文案，固定保留末尾的一个空格和 `…`。通知出现时存在定位歧义，再补充来源或阶段。
- 正文保留源头原因，便于诊断和复制求助。操作拥有者负责一次通知，后续步骤依据失败结果停止。连续后台失败只提示一次，成功后恢复通知。
- 恢复优先复用原操作。关闭重开等路径能重新请求且保留用户工作时，省略专用重试入口。初始化、会话恢复和冲突决策按实际需要提供恢复控件。
- 草稿、未保存和冲突属于持续业务状态。自动保存失败后等待新输入或显式保存，离页等待保存成功。字段校验就地定位，任务、对话和日志保留可回看的失败记录。

### 任务反馈

任务活跃状态表示后台执行，命令受理状态表示当前交互。

- 独立批量任务由前端会话层发送完成通知。
- Agent 内的批量步骤通过工具结果汇报。
- Agent 的输入排队与停止边界见 [AGENT_RUNTIME](AGENT_RUNTIME.md)。

## ✍️ 草稿、导航与阅读

### 保存与离页

离页和确认退出等待当前页面保存完成。编辑入口一起持有草稿、成功基线和串行保存，失败时保留草稿供继续编辑或重试。

导航到 Agent 的一次性输入在离页成功后交接，工程选择期间保留。目标编辑器再按请求语义保留或替换已有草稿。

### 范围与顺序

- 查询决定完整筛选范围，虚拟滚动和候选搜索只减少显示内容。
- 选择与计数使用完整范围，避免遗漏尚未显示的结果。
- 工作台表头排序用于阅读，拖动重排保存工程顺序。
- 重排提交后使用后端确认的顺序，保持虚拟索引与持久化结果一致。

### 阅读位置

流式阅读由用户控制跟随状态。上滚后保留阅读位置，正文增长和程序滚动继续尊重该选择。

图表缩放、原生选区和原位编辑使用局部状态，临时阅读动作留在页面内。

文件预览跨路由保留阅读记录，返回时重新读取工作文件，避免展示已经失效的内容。

## 🎨 外观与文案

`AppearanceProvider` 拥有主题、字体与字体大小偏好。外观偏好属于本机用户，跨窗口同步。

外观逐层消费：

- 全局 token 提供主题基础。
- 基础控件提供共用外观。
- 业务组件组合布局和交互。

文案按消费职责归属：通用动作、共享业务和页面说明分别由对应词典分组维护。

完整句子与占位符由词典持有。无障碍属性复用已有可见文案，保持各语言和辅助技术中的表达一致。

视觉工作以当前任务输入、既有界面证据和适用设计流程为依据。`DESIGN.md`、`PRODUCT.md` 可补充背景，工程入口与验证独立于这些文件的生命周期。

## 🔄 开发热更新

|变化|处理|原因|
|---|---|---|
|组件、样式、词典|热更新并保留交互状态|继续当前操作现场|
|Context、Store 及其运行时依赖|刷新窗口并重建实例|避免混用两版状态结构|

类型导入不进入运行时依赖图。保留的内存结构发生变化时，需要显式刷新并重新建立操作现场。

验证入口见 [WORKFLOW](WORKFLOW.md)。

## 📦 Windows 应用更新

更新按顺序执行：

1. 等待页面保存。
2. 准备更新器。
3. 关闭 Backend Runtime 与 PDF 宿主。
4. 启动 `win-berserker`。

关闭完成后才覆盖安装文件，避免覆盖仍被使用的资源。

失败处理分为两个阶段：

- 准备失败：应用仍可继续使用。
- 进入收尾后的关闭或启动失败：原生错误框报告后结束应用。

安装采用直接覆盖，部分失败需要手动覆盖完整发行包恢复。

更新日志位于安装目录的 `log/update.log`，每次运行覆盖旧日志，可与应用日志一起收集。平台验证入口见 [WORKFLOW](WORKFLOW.md)。
